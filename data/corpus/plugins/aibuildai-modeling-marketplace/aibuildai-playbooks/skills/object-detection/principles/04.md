## Principle 4: Train and Infer at Multiple Resolutions to Balance Speed and Small Object Recall

*Consensus: 12/13 top solutions in competitions with multi-scale objects used different train/inference resolutions. Great Barrier Reef 2nd place: training at 2400px, inference at 4800px improved LB by +0.13 F2 despite hurting CV.*

Train at a moderate resolution that fits your GPU, but infer at higher resolution(s) to catch small or edge objects. Ensemble predictions across multiple inference scales using WBF.

**Why this matters:** Small objects are underrepresented in training loss (fewer pixels, fewer anchors match). Higher inference resolution gives the model more detail to detect them, but training at that resolution is often computationally infeasible. The mismatch between train and test resolution can be leveraged: higher test resolution produces tighter, more accurate boxes even if the model was never trained on them.

**When to use:** Always experiment with inference resolution >train resolution when test time allows. Critical when your dataset has multi-scale objects (e.g., wheat heads vary 20-200px, starfish vary 50-400px) or when small objects matter for the metric (high IoU thresholds like 0.7-0.8 penalize loose boxes). Use 1.5-2x train resolution for inference; diminishing returns beyond 2x.

**When NOT to use:** Skip if all objects are consistently large (>200px) and boxes are loose (IoU threshold <0.5). Avoid extreme upscaling (>2x) if it makes inference too slow or if your model wasn't trained with multi-scale augmentation—boxes may become too small relative to anchors. If higher resolution hurts CV, it may still help LB if test labels are tighter than train labels (as in Great Barrier Reef, where training boxes were about 3px too large).

**How to reason about it:**
Plot object size distribution and IoU thresholds. If >30% of objects are <64px or if metric uses IoU>0.6, test higher inference resolution. Start with train_res * 1.5, measure LB impact. If LB improves but CV degrades, inspect whether test labels are tighter (manually check a few test predictions at different resolutions). Ensemble across resolutions (e.g., 1x, 1.3x, 1.6x) with WBF—diversity helps. For video data, balance resolution against inference time budget.

```python
# Multi-resolution inference with WBF ensemble
from ensemble_boxes import weighted_boxes_fusion

def multi_scale_inference(model, image, scales=[1.0, 1.5, 2.0], iou_thr=0.5, conf_thr=0.3):
    """
    Run inference at multiple scales and ensemble with WBF.
    Args:
        model: detection model
        image: input image (H, W, 3)
        scales: resolution multipliers relative to training size
        iou_thr: WBF IoU threshold for merging boxes
        conf_thr: minimum confidence to keep
    """
    h, w = image.shape[:2]
    all_boxes, all_scores, all_labels = [], [], []
    
    for scale in scales:
        # Resize image
        new_h, new_w = int(h * scale), int(w * scale)
        img_scaled = cv2.resize(image, (new_w, new_h))
        
        # Infer and normalize boxes to [0, 1]
        boxes, scores, labels = model.predict(img_scaled)
        boxes[:, [0, 2]] /= new_w  # normalize x coords
        boxes[:, [1, 3]] /= new_h  # normalize y coords
        
        all_boxes.append(boxes)
        all_scores.append(scores)
        all_labels.append(labels)
    
    # Ensemble with WBF
    boxes, scores, labels = weighted_boxes_fusion(
        all_boxes, all_scores, all_labels,
        iou_thr=iou_thr, skip_box_thr=conf_thr
    )
    
    # Denormalize to original image coordinates
    boxes[:, [0, 2]] *= w
    boxes[:, [1, 3]] *= h
    return boxes, scores, labels
```
