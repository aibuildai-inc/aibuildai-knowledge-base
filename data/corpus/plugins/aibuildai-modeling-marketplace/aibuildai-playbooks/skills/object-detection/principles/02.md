## Principle 2: Design Train/Val Split to Match Test Distribution, Especially for Sequential Data

*Consensus: Most top solutions in video-based competitions used sequence-aware splits. In non-sequential tasks, several winning solutions stratified by metadata (source, image characteristics).*

Split data to mirror the test set's structure: by video/sequence ID for temporal data, by source/annotator for multi-site collections, or by stratified metadata when train and test come from different distributions.

**Why this matters:** Random splits leak temporal or spatial correlations that don't exist at test time, creating a false sense of model quality. In video data, adjacent frames are nearly identical—random splits let the model memorize rather than generalize. In multi-site data, source-specific biases (lighting, annotation style, equipment) contaminate validation if not isolated.

**When to use:** Always for video/time-series data—split by sequence or video ID, never by frame. For multi-source datasets (medical imaging with different hospitals, wheat from different regions), split by source if you suspect distribution shift. When train/test are explicitly from different domains, create a validation set that mimics the test domain characteristics.

**When NOT to use:** Use random stratified splits only when data is truly i.i.d. and test comes from the same distribution. If you have <3 sequences or sources, you may need to accept some leakage or use leave-one-out validation, but document the limitation.

**How to reason about it:**
Ask: Does the test set contain entirely new sequences/videos/sites? If yes, split by those IDs. Does the leaderboard behave erratically (high CV but low LB)? Check for data leakage—train and val might share correlated samples. Does metadata like 'source' or 'annotator_id' exist? Validate whether different sources have different characteristics (class distributions, image stats). If they do, stratify by source. For video data, also consider fold balancing by target counts to ensure each fold has similar positive rates.

# For video/sequence data
from sklearn.model_selection import GroupKFold

# Group by video_id to prevent leakage
gkf = GroupKFold(n_splits=5)
