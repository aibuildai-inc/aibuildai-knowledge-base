## Principle 6: Ensemble Diverse Model Architectures with Weighted Boxes Fusion (WBF)

*Consensus: WBF was the standard ensembling method in the box-detection competitions: all 7 Global Wheat writeups and 13 of 17 Great Barrier Reef writeups use it. Hydrogen team (Great Barrier Reef 3rd): 5 different architectures ensembled with WBF.*

Ensemble predictions from multiple detector architectures (e.g., YOLO + EfficientDet + Faster R-CNN) using Weighted Boxes Fusion rather than NMS or soft-NMS. WBF merges overlapping boxes by averaging coordinates weighted by confidence.

**Why this matters:** Different architectures have complementary failure modes: YOLO is fast and good at small objects, Faster R-CNN excels at precise localization, anchor-free models handle extreme aspect ratios. WBF leverages this diversity by merging predictions where models agree (boosting confidence) while preserving unique detections from single models. Unlike NMS, WBF doesn't discard boxes—it fuses them, leading to tighter, more confident predictions.

**When to use:** Default to WBF whenever ensembling >=2 models. Maximize architecture diversity: combine anchor-based (YOLO, EfficientDet, Faster R-CNN) with anchor-free (CenterNet, FCOS). Use WBF iou_threshold 0.5-0.6 for general objects; lower (0.4) for dense/overlapping objects. Ensemble across different training strategies (different augmentations, resolutions, folds) not just architectures.

**When NOT to use:** If you have only 1-2 model types, focus on training better single models first rather than ensembling weaker variants. Avoid ensembling if models are too similar (e.g., YOLOv5-S vs YOLOv5-M trained identically)—they'll agree on errors. For extremely sparse detections (<<1 object/image), NMS may suffice.

**How to reason about it:**
Train diverse models: vary architecture families, input resolution, and augmentation strategies. Validate each model's OOF predictions to ensure reasonable individual performance before ensembling. Tune WBF hyperparameters (iou_thr, skip_box_thr, conf_type) on validation set—optimal values depend on how tightly your models agree. Check if ensemble improves both CV and LB; if only LB improves, you may be overfitting to test distribution. For competitions with tight time budgets, precompute fold predictions and optimize WBF offline.

```python
# WBF ensemble of diverse architectures
from ensemble_boxes import weighted_boxes_fusion

def ensemble_models(models, image, iou_thr=0.5, skip_box_thr=0.3, weights=None):
    """
    Ensemble predictions from diverse detector architectures using WBF.
    
    Args:
        models: list of trained detection models (different architectures)
        image: input image
        iou_thr: IoU threshold for matching boxes across models (0.5-0.6 typical)
        skip_box_thr: minimum confidence to keep a box in output
        weights: per-model weights (default: equal weight)
    """
    boxes_list, scores_list, labels_list = [], [], []
    
    if weights is None:
        weights = [1.0] * len(models)
    
    # Collect predictions from each model
    for model in models:
        boxes, scores, labels = model.predict(image)  # returns [N, 4], [N], [N]
        
        # Normalize boxes to [0, 1] for WBF
        h, w = image.shape[:2]
        boxes[:, [0, 2]] /= w
        boxes[:, [1, 3]] /= h
        
        boxes_list.append(boxes.tolist())
        scores_list.append(scores.tolist())
        labels_list.append(labels.tolist())
    
    # Apply WBF
    boxes, scores, labels = weighted_boxes_fusion(
        boxes_list, scores_list, labels_list,
        weights=weights,
        iou_thr=iou_thr,
        skip_box_thr=skip_box_thr
    )
    
    # Denormalize boxes back to image coordinates
    boxes[:, [0, 2]] *= w
    boxes[:, [1, 3]] *= h
    
    return boxes, scores, labels

# Example: ensemble YOLO + EfficientDet + Faster R-CNN
models = [yolov5_model, efficientdet_model, fasterrcnn_model]
final_boxes, final_scores, final_labels = ensemble_models(models, test_image)
```
