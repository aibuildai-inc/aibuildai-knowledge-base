## Principle 5: Leverage Pseudo-Labeling on Test Data When Competition Permits Code Submissions

*Consensus: Most code competitions' top solutions used pseudo-labeling. Global Wheat 1st place improved from 0.7629 to 0.7656 (+0.0027) with 2 rounds. Severstal 1st place: +0.002 from pseudo labels, noting timing matters—too early hurts.*

Generate predictions on unlabeled test data with your best model(s), filter high-confidence predictions, and add them to your training set for a final retraining round.

**Why this matters:** Test data often comes from a slightly different distribution than training (new sites, annotators, conditions). Pseudo-labeling adapts your model to the test distribution without violating competition rules. It's most effective when the test set is large relative to train, or when you have high confidence in your ensemble predictions.

**When to use:** Apply in code competitions where you can infer on test data. Generate pseudo-labels only after CV is stable and LB score is competitive (>top 10%). Use multiple rounds: first round with high confidence threshold (>0.9), optionally a second round with lower threshold (>0.7) after seeing first round's improvement. Combine predictions from multiple models via WBF to increase pseudo-label reliability.

**When NOT to use:** Skip if test set is tiny (<10% of train size)—insufficient diversity. Avoid if your model is still improving rapidly with better architectures or data cleaning; lock in your best approach first. Don't pseudo-label early (LB <competitive threshold) as you'll amplify errors. If test labels are noisier than train (rare, but seen in some crowdsourced data), pseudo-labeling can degrade performance.

**How to reason about it:**
Check if competition allows test inference (code submission format). Estimate test/train ratio. If test is >=30% of train size and your LB score is competitive, pseudo-labeling likely helps. Generate pseudo-labels with ensemble of your top-K models using WBF. Filter by confidence AND agreement—only keep boxes where multiple models agree (IoU >0.5). Validate that added pseudo-labels improve CV before submitting; if CV degrades, tighten confidence threshold. Monitor whether pseudo-labels shift class distribution; rebalance sampling if needed.

```python
# Pseudo-labeling pipeline
from ensemble_boxes import weighted_boxes_fusion

# Step 1: Generate pseudo-labels from ensemble
def generate_pseudo_labels(models, test_loader, conf_threshold=0.9, iou_threshold=0.5):
    """
    Generate high-confidence pseudo-labels from model ensemble.
    """
    pseudo_labels = {}
    
    for image_id, image in test_loader:
        all_boxes, all_scores, all_labels = [], [], []
        
        # Get predictions from each model
        for model in models:
            boxes, scores, labels = model.predict(image)
            all_boxes.append(boxes)
            all_scores.append(scores)
            all_labels.append(labels)
        
        # Ensemble with WBF
        boxes, scores, labels = weighted_boxes_fusion(
            all_boxes, all_scores, all_labels,
            iou_thr=iou_threshold, skip_box_thr=conf_threshold
        )
        
        # Keep only high-confidence predictions
        high_conf_mask = scores >= conf_threshold
        pseudo_labels[image_id] = {
            'boxes': boxes[high_conf_mask],
            'labels': labels[high_conf_mask],
            'scores': scores[high_conf_mask]
        }
    
    return pseudo_labels
```
