## Principle 7: Investigate and Adapt to Annotation Quality Differences Between Train and Test

*Consensus: RSNA Aneurysm 2nd place manually corrected training labels that mixed up left and right sides and other positions; its improved annotation data raised the private score from 0.825 to 0.857 in its ablation. Great Barrier Reef 3rd place: test labels were 3px tighter on all sides.*

Analyze whether test set annotations are systematically different from training (tighter boxes, different annotators, more/less precise). Adapt by fine-tuning on corrected labels, adjusting box sizes at inference, or training on multiple annotation styles.

**Why this matters:** Annotation inconsistency is common in crowdsourced or multi-annotator datasets. If train labels are loose but test labels are tight, a perfectly trained model will underperform due to systematic mismatch, not model quality. Metrics like mAP at high IoU thresholds (0.7-0.8) are extremely sensitive to box tightness—a 3-pixel error on a 50-pixel object can drop IoU from 0.8 to 0.6.

**When to use:** Investigate if CV and LB diverge: high CV but low LB suggests train labels are easier, or vice versa. Mandatory for datasets collected from several sources or annotators—compute per-source statistics (box sizes, class distributions). If test comes from different sources than train, validate on the data that most resembles test. Check if manual box adjustments (shrink by N pixels) improve LB without hurting CV—this signals systematic offset.

**When NOT to use:** Skip if annotation is automated or single-expert (less variability). Don't chase label noise if CV/LB correlation is strong and consistent. Avoid overfitting to LB quirks if you lack a principled explanation—manual adjustments that work on public LB often fail on private LB.

**How to reason about it:**
Compute annotation statistics: box area distribution, aspect ratios, border proximity by source. If variance is high, check if specific sources dominate train vs test. Validate by manual inspection: are train boxes loose or tight? Do they cut objects or include margins? Test the hypothesis on held-out data that resembles test before you change the training mix. For systematic offsets (e.g., boxes 3px too large), validate on OOF predictions before applying to test.

# Analyze annotation quality by source
import pandas as pd
import numpy as np

def analyze_annotation_quality(df, group_by='source'):
    """
    Analyze systematic differences in annotation style.
    """
    stats = df.groupby(group_by).agg({
        'bbox': lambda x: np.mean([b[2] * b[3] for b in x]),  # mean box area
        'image_id': 'count'  # boxes per source
    })
    
    # Check box size consistency
    print(f"Box area CV by {group_by}:")
    for group, rows in df.groupby(group_by):
        areas = [b[2] * b[3] for b in rows['bbox']]
        cv = np.std(areas) / np.mean(areas)
        print(f"  {group}: {cv:.3f} (n={len(areas)})")
    
    return stats

# Test if tighter boxes improve performance
def adjust_box_size(boxes, delta_pixels=-3):
    """
    Shrink/expand boxes by fixed pixels (negative = tighter).
    Useful when test annotations are systematically tighter/looser.
    """
    boxes_adj = boxes.copy()
    boxes_adj[:, 0] -= delta_pixels  # x_min
    boxes_adj[:, 1] -= delta_pixels  # y_min
    boxes_adj[:, 2] += 2 * delta_pixels  # width
    boxes_adj[:, 3] += 2 * delta_pixels  # height
    
    # Clamp to valid range
    boxes_adj[:, [0, 1]] = np.maximum(boxes_adj[:, [0, 1]], 0)
    boxes_adj[:, [2, 3]] = np.maximum(boxes_adj[:, [2, 3]], 1)
    
    return boxes_adj
