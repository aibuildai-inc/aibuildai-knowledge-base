## Principle 3: Use Retrieval + Reranking Pipeline for Knowledge-Heavy Tasks

*Consensus: 5/5 for tasks requiring external knowledge (LLM Science, Eedi top solutions)*

When correct answers depend on knowledge not in the input (scientific facts, detailed explanations), a retrieve-then-rank pipeline dramatically outperforms pure classification. Sparse retrieval (BM25) finds candidates; dense embeddings refine; LLM rerankers score with context.

**Why this matters:** LLMs have limited parametric knowledge and hallucinate. Pure classification caps at what the model memorized. Retrieval brings external knowledge into context. For LLM Science, retrieval from Wikipedia was the difference between 0.85 and 0.93. For Eedi, retrieval from misconception database was mandatory (2.5k misconceptions, can't memorize mappings).

**When to use:** When the answer requires facts/knowledge not present in the question text alone. Indicators: questions reference specific entities, dates, formulas; evaluation data contains knowledge not in training data; strong pre-trained models plateau below 0.9 accuracy. Common in: science QA, fact-checking, long-tail entity matching, diagnostic question banks.

**When NOT to use:** Skip if all information is in the input (e.g., query-product matching where the product text is given). Skip when the labels form a small fixed set that a classification head can learn directly. Skip if the knowledge base is tiny and fits in the model (< 10k entities - just fine-tune).

**How to reason about it:**
Stage 1 (Retrieval): BM25 for sparse (keyword overlap) + dense embeddings (semantic). Combine or use separately based on your corpus characteristics (BM25 better for exact term matching, dense for paraphrases). Stage 2 (Rerank): Given question + top-K contexts, score each. Use smaller models (DeBERTa-base) for speed, larger (LLama-70B) for quality if inference budget allows. Dynamic K: retrieve more candidates (top-32) but add threshold filtering (similarity > threshold) for high-confidence.
