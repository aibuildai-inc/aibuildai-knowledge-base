## Principle 9: Generate High-Quality Synthetic Data for Unseen Categories

*Consensus: Critical for Eedi (1st place), LLM Science*

When test data contains unseen categories (new misconceptions, rare question types), LLM-generated synthetic data with careful curation dramatically improves generalization. The key is generation quality: use strong teacher models, few-shot examples, and LLM-based filtering.

**Why this matters:** Models overfit to seen categories. For Eedi, 1st place generated 10k synthetic math questions using Claude 3.5 Sonnet with cluster-based generation (grouping related misconceptions) and GPT-4o filtering. This improved out-of-distribution misconception retrieval from 0.43 to 0.47. Pseudo-labeling helps as well: MAP 2nd place generated about 80K extra examples with several LLMs, labeled them with four LLMs trained on the competition data, and used those labels as soft targets.

**When to use:** When: (1) Test data explicitly contains unseen categories (competition description mentions generalization to new X). (2) Validation split by category shows large performance gap on unseen vs seen. (3) You have a strong teacher model (GPT-4, Claude) or ensemble that can label accurately. (4) Domain has verifiable correctness (math, science) allowing quality filtering.

**When NOT to use:** Skip if all categories are well-represented in training (no unseen generalization needed). Skip if you can't verify synthetic data quality (subjective domains like sentiment). Skip if teacher model is weak (pseudo-labels from 0.7 accuracy model hurt more than help). Don't use back-translation for technical domains - it corrupts technical terms and formulas.

**How to reason about it:**
Step 1: Identify what's missing (underrepresented categories, unseen misconceptions). Step 2: Choose generation strategy - direct prompting (with few-shot examples from similar categories), or distillation (pseudo-labeling with strong ensemble). Step 3: Filter aggressively - use LLM-as-judge, human sampling, or verification (for math: check if answer is correct). Step 4: Balance synthetic vs real - start 1:1 ratio, increase synthetic if it helps. Step 5: Validate on out-of-distribution split.

{misconception_cluster}

Reference examples (style/quality guide):
{reference_examples}

Generate 1 new MCQ with clear mapping of incorrect answers to specific misconceptions.'''

        messages=[{'role': 'user', 'content': prompt}],
        max_tokens=1000

# Step 2: Filter with LLM-as-judge
def quality_check(mcq, misconception):
    prompt = f'''Rate the alignment between this wrong answer and misconception on 0-10 scale:
MCQ: {mcq}\nMisconception: {misconception}\nScore:'''
    score = client.messages.create(
        model='gpt-4o',
        messages=[{'role': 'user', 'content': prompt}]
    )
    return int(score.content[0].text.strip()) >= 8  # Threshold
