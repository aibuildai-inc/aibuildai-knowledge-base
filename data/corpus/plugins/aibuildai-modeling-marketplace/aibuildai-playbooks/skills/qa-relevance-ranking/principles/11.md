## Principle 11: Augment the Parts of a Text Input That Can Change at Test Time

*Consensus: Recurring in the source writeups: shuffling answer or candidate order in training (LLM Science 7th, Eedi 3rd and 14th) and training on noisy retrieved contexts (LLM Science 1st); token masking appears in one solution, and another found CutOut and CutMix did not help*

Augment what the model should not depend on: the order of answer options or retrieved candidates, and the exact wording of retrieved context. Treat token-level augmentations borrowed from computer vision (token masking, CutOut, CutMix) as experiments, not defaults.

**Why this matters:** LLM rankers and multiple-choice models are sensitive to where each option sits in the prompt. Shuffling the order in training removes that shortcut: Eedi 14th place shuffled the candidate list for every sample to reduce the positional bias from its retriever, Eedi 3rd place shuffled the misconception order for its reranker and gained a little on both leaderboards, and LLM Science 7th place found that shuffling the choices in training helped a bit. For retrieval-augmented inputs, LLM Science 1st place trained on contexts produced by its own retrieval, as at inference, and found this better than training on the true context each question was generated from. Token-level augmentation is less reliable: Eedi 14th place trained with a mask token probability of 0.1, while LLM Science 21st place listed CutOut and CutMix among the things that did not work.

**When to use:** Order shuffling: whenever the input lists options or candidates whose order carries no meaning. Context noise: whenever inference uses retrieved or generated context, train on the same kind of context. Token masking: small datasets with clear overfitting; keep it only if validation improves.

**When NOT to use:** Do not shuffle when the order carries information the model should use (for example candidates sorted by retrieval score) without testing both versions. Do not train only on clean reference contexts when inference contexts will be noisy. Drop token masking if validation does not improve.

**How to reason about it:**
List the parts of the input whose order or exact content can differ at test time. Randomize each of them in training and remap the label when positions move. At inference, try averaging over several orders: LLM Science 5th place rotated the order of the five choices 5 times and averaged, and packed all rotations into one sequence with a matching attention mask to limit the extra inference time.

```python
import random

# Training: shuffle options and remap the label
def shuffle_options(question, options, answer_idx):
    order = list(range(len(options)))
    random.shuffle(order)
    new_options = [options[i] for i in order]
    new_answer = order.index(answer_idx)
    return question, new_options, new_answer

# Inference: average scores over rotated option orders
def rotated_tta(score_fn, question, options, n_rotations=5):
    n = len(options)
    totals = [0.0] * n
    for r in range(n_rotations):
        order = [(i + r) % n for i in range(n)]
        scores = score_fn(question, [options[i] for i in order])  # one score per shown option
        for pos, opt in enumerate(order):
            totals[opt] += scores[pos] / n_rotations
    return totals

# Optional: token masking, keep only if validation improves
def mask_tokens(input_ids, mask_token_id, p=0.1):
    return [mask_token_id if random.random() < p else t for t in input_ids]
```
