## Principle 13: Parse and Normalize Text Carefully for Feature Engineering Tasks

*Consensus: 2/2 for pre-transformer feature engineering competitions (Home Depot, CrowdFlower)*

For text matching tasks relying on TF-IDF, Word2Vec, and count features, invest heavily in text preprocessing: spell correction using domain vocabulary, synonym normalization, entity extraction, and part-of-speech based filtering. Variation in preprocessing across team members creates ensemble diversity.

**Why this matters:** Home Depot 3rd place: 'Different text processing within one team was a key to getting a high score.' They used spell-checking with product title as vocabulary, manual replacements for 100+ words with multiple spellings ('mailbox' vs 'mail box'), POS tagging to extract key nouns from queries. Top trigrams from query determined the 'most important' words. This level of feature engineering is obsolete for transformer models but critical for traditional ML.

**When to use:** Only for competitions explicitly using traditional ML (gradient boosting, random forest) with text input, typically pre-2019 or resource-constrained. Common in: product search, document matching, retrieval without neural models. Skip entirely if using BERT/RoBERTa - they learn these patterns.

**When NOT to use:** Skip for any transformer-based approach - the model tokenizes and learns patterns itself. Skip if data is small (< 5k samples) and you can use pre-trained language models. Skip if competition allows pre-trained models (use them instead).

**How to reason about it:**
If you're in a feature-engineering competition: (1) Build domain vocabulary from product titles/descriptions. (2) Spell-correct queries against this vocab. (3) Normalize synonyms and multi-word units. (4) Extract structured features: word overlap counts, character overlap ratios, Jaccard similarities, TF-IDF weighted matches, Word2Vec/Doc2Vec similarities, WordNet path similarities for important terms. (5) Create multiple preprocessing pipelines for ensemble diversity.

```python
# Text preprocessing for feature engineering (Home Depot pattern)
import nltk
from nltk.corpus import wordnet
from difflib import SequenceMatcher

# Spell correction using product vocabulary
vocab = set(word for title in product_titles for word in title.lower().split())

def spell_correct(query, vocab):
    corrected = []
    for word in query.lower().split():
        if word not in vocab:
            # Find most similar word in vocab
            best_match = max(vocab, key=lambda v: SequenceMatcher(None, word, v).ratio())
            if SequenceMatcher(None, word, best_match).ratio() > 0.8:
                corrected.append(best_match)
            else:
                corrected.append(word)
        else:
            corrected.append(word)
    return ' '.join(corrected)

# Extract important words via POS tagging
def extract_key_terms(text):
    tokens = nltk.word_tokenize(text)
    pos_tags = nltk.pos_tag(tokens)
    # Keep nouns, verbs, adjectives
    return [word for word, pos in pos_tags if pos.startswith(('NN', 'VB', 'JJ'))]

# WordNet similarity for query-product matching  
def wordnet_similarity(word1, word2):
    synsets1 = wordnet.synsets(word1)
    synsets2 = wordnet.synsets(word2)
    if not synsets1 or not synsets2:
        return 0.0
    return max(s1.path_similarity(s2) or 0 for s1 in synsets1 for s2 in synsets2)
```
