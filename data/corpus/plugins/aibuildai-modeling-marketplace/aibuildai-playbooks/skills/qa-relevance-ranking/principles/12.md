## Principle 12: Set Learning Rates Per Parameter Group and Tune the Head Ratio

*Consensus: Several LLM top solutions set separate learning rates per parameter group; where a head rate was reported, it was lower than the LoRA or backbone rate (LLM Science 1st, MAP 31st, Eedi 14th)*

Give each parameter group its own learning rate: the pretrained backbone or its LoRA adapters, any newly added head, and, when useful, the two LoRA matrices. The best ratio between the groups depends on the setup, so tune it on validation instead of copying a fixed rule.

**Why this matters:** A randomly initialized head on a pretrained encoder is often given larger updates than the backbone. In LLM fine-tuning with LoRA, the source writeups went the other way: LLM Science 1st place used a lower learning rate for its classification head than for its LoRA layers, MAP 31st place trained LoRA at 2e-4 and its heads at 5e-5 and called the learning rate very critical, and Eedi 14th place used 2e-5 for the model and 1e-5 for the head. Eedi 1st place also gave the LoRA A and B matrices different rates (1e-5 and 5e-5) for its retrievers. One global learning rate hides all of these choices.

**When to use:** Always when fine-tuning a pretrained transformer or LLM with an added head. Start from a rate that fits the method: LoRA on LLMs commonly used 1e-4 to 2e-4 in MAP top solutions (8th, 10th, 12th, 22nd); full fine-tuning needs much lower rates (MAP 7th place used 2e-5 for full fine-tuning of Qwen3-8B, after 1e-4 caused convergence problems; an LLM Science DeBERTa solution used 5e-6). Then tune the head rate on validation in both directions.

**When NOT to use:** Skip a separate head rate when there is no new head, for example when scores come from the language-model logits of answer tokens. Do not carry a head-to-backbone ratio from one setup to another without testing it. Very large head rates can destabilize training.

**How to reason about it:**
Group parameters by name: LoRA A matrices, LoRA B matrices, the new head (names such as 'score' or 'classifier'), and any unfrozen backbone weights. Sweep the head-to-backbone ratio over a small grid (for example 0.25, 0.5, 1, 4, 10) on validation. Use warmup and cosine decay. Monitor training: if loss spikes, a rate is too large; if a group does not learn in the first epoch, its rate is too small or the warmup too short.

```python
import torch
from transformers import get_cosine_schedule_with_warmup

base_lr = 2e-4          # LoRA rate; use a much lower rate for full fine-tuning
head_ratio = 0.25       # tune on validation in both directions

groups = {'lora_A': [], 'lora_B': [], 'head': [], 'backbone': []}
for name, param in model.named_parameters():
    if not param.requires_grad:
        continue
    if 'lora_A' in name:
        groups['lora_A'].append(param)
    elif 'lora_B' in name:
        groups['lora_B'].append(param)
    elif 'score' in name or 'classifier' in name:
        groups['head'].append(param)
    else:
        groups['backbone'].append(param)

optimizer = torch.optim.AdamW([
    {'params': groups['lora_A'], 'lr': base_lr},
    {'params': groups['lora_B'], 'lr': base_lr},
    {'params': groups['head'], 'lr': base_lr * head_ratio},
    {'params': groups['backbone'], 'lr': base_lr * 0.1},
], weight_decay=0.01)

total_steps = len(train_loader) * num_epochs
scheduler = get_cosine_schedule_with_warmup(
    optimizer,
    num_warmup_steps=int(0.05 * total_steps),
    num_training_steps=total_steps
)
```
