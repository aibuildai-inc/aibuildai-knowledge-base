## Inference pipeline
retrievers (4 Qwen2.5-14b models ensembled by weighted sum) → 40 misconceptions → reranker (a single Qwen2.5-32b model)→ 25 misconceptions
<br>

## Training details
In general, I find iterative hard negative mining very helpful.

- Use few-shots prompt with chatgpt to generate extra training data: 
   - Added 983 synthetic data samples to fill missing misconceptions. 
   - training data is split in 5 CV-folds by `"QuestionId"`. For each fold, regenerated extra samples to cover unique misconceptions in the valid fold for training. 
- Retriever (Qwen2.5-14b): Finetuned with bnb bit4 + LoRA for FEATURE_EXTRACTION task.  
   - trained on 2 A100s.
   - lora parameters: `r=32, alpha=64, target_modules=['q_proj','k_proj','v_proj','o_proj','gate_proj','up_proj','down_proj']`
   - training paramters: `train_group_size=4, effective_batch_size=64, epoch=7, lr_scheduler_type="cosine"`; 
   - trained in 5 CV-folds.
      - For first 4~5 epochs, model is trained without generated data, with a focus on improving map25. 
      - For the final 2~3 epochs, generated data is added into training, which helps to further improve map25 and recall25.
   - I interfere manually when the valid scores (map25 & recall25) stop improving by following means:
      - reducing learning_rate gradually from 5e-4 to 1e-5
      - reducing negative data pool size from 80 to 4, for more focus on distinguishing hardest misconceptions
- Reranker (Qwen2.5-32b): Finetuned with bnb bit4 + LoRA for CASUAL_ML task,  outputting a “Yes” logit for each query–misconception pair. 
   - trained on 2 A100s.
   - lora parameters: `r=32, alpha=64, target_modules=['q_proj','k_proj','v_proj','o_proj','gate_proj','up_proj','down_proj','down_proj','lm_head']`
   - training paramters: `train_group_size=4, effective_batch_size=64, epoch=4, learning_rate=5e-4, lr_scheduler_type="WarmupDecayLR"`; 
   - full dataset used for training reranker without validation. Negative data is generated by 4 retrievers (emsembled through weighted sum) with negative_count = 40

<br>

## Quantization & Inference details
- Retrieving:
   - 4 retrievers (chosen from 5-fold CV based on LB scores) retrieve 4 times, then ensembled via weighted sum.
   - infer in bnb bit4+LoRA (no need to merge), so that each single retriever can fit in one T4 gpu, 4 retrievers only take 2 T4s running twice.
- Reranking:
   - model is first merged with lora adaptor, with wise-FT hyper parameter alpha=0.8
   - model is then quantized to AWQ (calibrated using 128 samples randomly selected from training data) 
   - VLLM is used for final inference. Each query is paired with 40 misconceptions retrieved, generating 40 queries for reranker to score. "enable_prefix_caching" is  turned on to accerlerate inference.

<br>

## Key improvements (Public LB)
- Add Synthetic data: single retriever public LB score from 0.3~ → 0.49 
- Ensemble retrievers: 0.49 → 0.51
- Add reranker: 0.51 → 0.57  
- Apply Wise-FT on reranker's LoRA merging: 0.57 → 0.59

## Personal reflections
The entire pipeline — from LoRA finetuning to quantization — was very new to me, and I nearly gave up more than once. I started small with Qwen2.5-0.5B to establish a workable process, but the AWQ-quantized model kept producing random letters during inference. After much frustration, I discovered that autoawq didn’t export the im-head-embed layer parameters for Qwen2.5-0.5B, forcing me to add them manually. Without @cdeotte‘s paper proving it could be done, I might have quit altogether. Thanks to that reassurance, I stuck with it and eventually got the pipeline running smoothly.
