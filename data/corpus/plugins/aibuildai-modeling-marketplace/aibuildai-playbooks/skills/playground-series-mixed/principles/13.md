## Principle 13: Clip Probabilities to Avoid Log-Loss Extremes

*Consensus: 3 top log-loss solutions explicitly clipped predictions. Standard practice for log-loss competitions.*

For log-loss metrics, clip predicted probabilities to [epsilon, 1-epsilon] (e.g., epsilon=1e-5 or 1e-15) to avoid infinite loss from 0 or 1 predictions.

**Why this matters:** Log-loss is -log(p) for the true class. If you predict p=0 for the true class, loss is infinite. If p=1 for the wrong class, loss is also infinite. Clipping prevents this while having minimal impact on well-calibrated predictions. The TPS May-2021 winner: 'I ended up clipping the probabilities (below 0.05 and above .95) to help the log_loss metric.'

**When to use:** For all log-loss competitions, clip predictions to [1e-5, 1-1e-5] or [1e-15, 1-1e-15] depending on competition rules (Kaggle clips at 1e-15). Do this as the final step before submission.

**When NOT to use:** Don't clip for AUC metrics (doesn't help, may hurt). Don't clip for regression. Don't clip during training/CV (only for final submission).

**How to reason about it:**
Log-loss penalizes confident wrong predictions exponentially. Clipping is a defensive measure: it slightly hurts well-calibrated predictions but massively helps if you have any extreme 0/1 predictions. Always clip for log-loss, using the epsilon value specified in competition rules (usually 1e-15 on Kaggle).

```python
import numpy as np

# Clip probabilities for log-loss submission
epsilon = 1e-15  # Kaggle's default
predictions = np.clip(predictions, epsilon, 1 - epsilon)

# For multiclass, ensure rows sum to 1 after clipping
predictions = predictions / predictions.sum(axis=1, keepdims=True)
```
