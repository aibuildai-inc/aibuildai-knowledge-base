## Principle 12: Use Rank Transformation When Blending for AUC/Rank Metrics

*Consensus: 2 top solutions explicitly recommended rank blending for AUC tasks.*

When ensembling predictions for AUC-based metrics, convert predictions to ranks before averaging. This handles different prediction scales between models.

**Why this matters:** Different models output probabilities on different scales. One model might predict [0.1, 0.9], another [0.3, 0.7] for the same samples. Averaging raw probabilities weights the higher-variance model more. Since AUC only cares about rank order, rank-transforming before averaging removes scale differences. The TPS Nov-2021 winner: 'the only thing to modify is to use rank when you blend your prediction, since AUC is all about rank.'

**When to use:** For AUC-based competitions (binary or multiclass classification), apply rank transformation to each model's predictions before averaging. Use pct=True to get ranks in [0, 1] range. For regression or log-loss, use raw probability averaging.

**When NOT to use:** Don't use rank transformation for log-loss metrics (it destroys probability calibration). Don't use for regression (RMSE, MAE) where absolute values matter.

**How to reason about it:**
Ask: Is the metric rank-based (AUC, correlation) or absolute-value-based (log-loss, RMSE)? If rank-based, convert each model's predictions to ranks via rank(pct=True), then average. If absolute-value-based, average raw predictions (optionally with learned weights from Ridge stacking).

```python
import pandas as pd

# Rank-based blending for AUC tasks
submissions = [sub1, sub2, sub3]  # Each is a DataFrame with 'id' and 'target'

# Rank-transform each submission
for sub in submissions:
    sub['target'] = sub['target'].rank(pct=True)

# Average ranks
final_sub = submissions[0][['id']].copy()
final_sub['target'] = sum(sub['target'] for sub in submissions) / len(submissions)

# Optionally rank-transform again (usually not needed)
# final_sub['target'] = final_sub['target'].rank(pct=True)
```
