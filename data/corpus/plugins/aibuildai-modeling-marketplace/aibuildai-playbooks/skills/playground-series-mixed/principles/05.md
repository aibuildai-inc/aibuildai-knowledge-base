## Principle 5: Exploit Data Generation Artifacts in Synthetic Datasets

*Consensus: 2 competition-winning solutions (TPS Feb-2022 1st place, playground s3e1 2nd place) explicitly exploited generation flaws.*

Synthetic datasets may contain unintended leakage or patterns from the generation process. Investigate duplicate rows, seed-based correlations, and distributional anomalies that allow shortcuts.

**Why this matters:** Random generation with fixed seeds can create near-duplicates between train/test. The TPS Feb-2022 winner found that train and test used the same random seed with slightly different probability distributions, creating paired rows that differed in only 2-3 positions. Exploiting this with RadiusNeighborsClassifier won the competition. However, this is dataset-specific and won't generalize.

**When to use:** When you notice: (1) many exact duplicates within train or test, (2) CV score << LB score (suggests train/test leakage), (3) simple models (kNN, ExtraTrees) dramatically outperform on LB vs CV. Investigate: check for duplicate rows, run near-duplicate search, analyze residuals for patterns. If found, build a custom pipeline to exploit (e.g., nearest neighbor matching for seed-based leaks).

**When NOT to use:** Most competitions don't have exploitable artifacts. Don't spend >10% of your time hunting for artifacts unless you see the red flags above. This is a high-risk, high-reward strategy that usually fails but occasionally wins outright. Treat it as a parallel exploration track, not your main approach.

**How to reason about it:**
Ask: Are there exact duplicates? (Check with df.duplicated()). Are there near-duplicates? (Use hashing or dimensionality reduction + nearest neighbors). Does a simple kNN model wildly outperform on LB? (Sign of row-level leakage). If yes, investigate the generation process (if code is shared) or reverse-engineer the pattern (e.g., which columns change, which stay the same in near-duplicates). Build a custom matcher/classifier.

```python
# Check for duplicates and near-duplicates
dupes = df.duplicated().sum()
print(f'Exact duplicates: {dupes}')

# Near-duplicate detection via hashing
from sklearn.neighbors import NearestNeighbors
nn = NearestNeighbors(n_neighbors=2, metric='hamming')
nn.fit(X_train)
distances, indices = nn.kneighbors(X_test)
near_dupes = (distances[:, 1] < 0.05).sum()  # <5% different
print(f'Near-duplicates: {near_dupes}')
```
