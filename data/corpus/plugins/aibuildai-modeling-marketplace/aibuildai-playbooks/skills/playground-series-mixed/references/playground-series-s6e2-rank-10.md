## Overview

This write-up explains the end-to-end solution that achieved a **Top-10 finish** on the Kaggle Playground Series S6E2 leaderboard. The strategy combined a diverse set of gradient boosting and neural network models, sophisticated feature engineering, and GPU-accelerated hill climbing to find optimal ensemble weights.

---

## Dataset

The dataset is a synthetic version of the classic **Heart Disease Prediction** dataset, generated by Kaggle for the playground series. Each row represents a patient, with the binary target indicating the presence or absence of heart disease.

| Column | Type | Notes |
|---|---|---|
| Age, BP, Cholesterol, Max HR, ST depression | Numeric | Continuous clinical measurements |
| Sex, Chest pain type, FBS over 120, EKG results, Exercise angina, Slope of ST, Number of vessels fluro, Thallium | Categorical | Low-cardinality discrete features |
| Heart Disease | Target | 0 = Absence, 1 = Presence |

An **original (non-synthetic) dataset** was also available and used as an auxiliary data source for deriving target-encoded features.

---

## Cross-Validation Strategy

All models used **10-fold Stratified K-Fold** cross-validation to preserve the class distribution across folds. This produced robust out-of-fold (OOF) predictions that were later used for ensembling.

```python
skf = StratifiedKFold(n_splits=10,shuffle=True,random_seed=42)
```

## Feature Engineering

Multiple feature engineering strategies were explored across models. Key techniques included:

### 1. Categorical Duplication
Every numeric column was duplicated and treated as a categorical column (label-encoded), allowing tree models and neural networks to discover non-linear ordinal relationships.

### 2. Interaction Features (Bi-grams & Tri-grams)
Pairs and triplets of categorical columns were combined into composite string features (e.g., `Sex-Thallium`, `Chest pain type-ST depression-Thallium`), then target-encoded. Initially, these combinations are used as features to train `LogisticRegression` and selected top 20 features each based on coefficients and manually optimised to 32 features that contributed to improve model CV score. 

### 3. Target Encoding from Original Dataset
Group statistics (mean, median, std, skew, count) were computed from the original non-synthetic dataset for each feature value and merged in as new columns — a powerful way to leverage the original data without blending it directly into training.

### 4. Sinusoidal & Digit Encoding
To attain diversity in feature space, numeric columns were transformed using sine/cosine at multiple periods (p=12, 14, 20) and individual decimal digit extraction as categorical columns— helping the neural network detect periodic or digitally-structured patterns in clinical measurements.

### 5. Count Encoding
For the NN with categorical embeddings model, every categorical column (including all pairwise combinations — 136 total) was count-encoded to capture frequency information.

### 6. Domain-Specific Features
Engineered features grounded in cardiology:
- `cardiac_wrkload_age = BP × Max HR / Age`
- `stress_severity = ST depression × Slope of ST`
- `high_risk = FBS over 120 + bp_over_140 + chol_over_240`

## Models

Nine distinct base models were trained, each producing OOF and test predictions as CSV files.

### Model Details

**XGBoost** — Trained with tuned hyperparameters using GPU (`tree_method=hist, device=cuda`), shallow trees (`max_depth=2`), and up to 25,000 boosting rounds with early stopping.

**CatBoost** — Matched hyperparameters to XGBoost where possible; used CatBoost's native categorical handling with `one_hot_max_size=10` for low-cardinality features.

**XGBoost → Logistic Regression** — A classic stacking approach: XGBoost leaf indices were one-hot encoded and passed to a Logistic Regression, exploiting XGBoost as a non-linear feature transformer.

**RealMLP** — Used the `pytabkit` implementation of RealMLP with early stopping and AUC as the validation metric. Different feature engineering pipelines were tested across the three variants.

**MLP with Categorical Embeddings** — A custom PyTorch MLP with learned embedding tables for all categorical features (including pairwise combos), standardised numerics, and OneCycleLR scheduling. (Ref: [Categorical embedding with NN](https://www.kaggle.com/code/cdeotte/nn-by-gpt5-cv-0-974-wow))

## Ensembling - GPU-Accelerated Hill Climbing

The final and most impactful ensembling step used a **greedy hill climbing** algorithm to find optimal blending weights, implemented on GPU.

**Key implementation details:**
- Predictions were transformed to **logit space** before blending to avoid boundary effects
- The algorithm supports **negative weights**, allowing it to effectively subtract a model if it hurts the ensemble
- Stopping criteria: tolerance of `1e-7` improvement or maximum of 1,000 models

## Key Takeaways

**Diverse models beat homogeneous ensembles.** Blending gradient boosting with neural networks (especially the MLP with categorical embeddings) provided complementary signal, as the NN learned different feature interactions than the tree models.

**Feature engineering quality drove everything.** The bi/tri-gram target-encoded interactions and the use of the original dataset statistics were consistently the most impactful features. Models that leveraged these outperformed bare-baseline models by a clear margin.
