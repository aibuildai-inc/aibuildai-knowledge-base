## Principle 7: Post-Process Predictions Using Domain Constraints

*Consensus: Recurring in top solutions: ECG 1st and 24th corrected leads with Einthoven's law (II = I + III), graph solutions mapped detected points to values through tick labels (3rd, 14th), Bengali 2nd turned whole-grapheme probabilities into component scores.*

Apply domain knowledge after model prediction to validate or correct outputs. Use physical laws between channels, geometric mappings such as axis scales, or the known structure of the label space to fix implausible predictions.

**Why this matters:** Models predict each part of the output separately, so the parts can break rules the domain guarantees: ECG leads that violate Einthoven's law, chart values that ignore the axis scale, component labels that do not form a real character. Domain constraints fix these cheaply without retraining. ECG 1st place reported that TTA added 0.07 and its Einthoven's-law correction added another 0.06. Graph solutions read the tick labels and interpolated point positions to values; 14th place fit that pixel-to-value mapping with a robust regression without hyperparameters (the median slope and intercept over all point pairs), because plain linear regression broke on outliers. Bengali 2nd place predicted whole graphemes, then scored each component value by averaging the probabilities of the graphemes that contain it, which gave about 50 extra LB points and did not restrict predictions to training graphemes.

**When to use:** When the domain guarantees relations between output parts (physical laws between channels, axis scales, a known mapping from fine labels to coarse labels), when the relation can be checked in code, and when validation predictions break it often enough to matter.

**When NOT to use:** When the rule does not always hold in the data: apply it only where predictions nearly satisfy it, as ECG 1st place applied II = I + III only when the mean error was below 0.01. When the test set can hold valid outputs never seen in training: forcing predictions onto the training set of combinations removes correct answers. When the correction does not improve held-out data.

**How to reason about it:**
(1) List the relations the domain guarantees. (2) Measure how often validation predictions break each one. (3) Correct softly: spread the error over all outputs in the relation instead of overwriting one of them (ECG 24th place distributed the Einthoven error with a weight of 0.25). (4) Fit mappings estimated from noisy detections with a robust method. (5) Validate each correction on held-out data, one at a time.

```python
import numpy as np

# ECG: soft Einthoven correction (II = I + III), applied only where it nearly holds
def einthoven_correct(I, II, III, alpha=0.25, max_err=0.01):
    err = II - (I + III)
    if np.abs(err).mean() >= max_err:
        return I, II, III
    return I + alpha * err, II - alpha * err, III + alpha * err

# Charts: robust pixel-to-value mapping from detected tick positions and OCR labels
def robust_axis_fit(tick_pixels, tick_values):
    slopes, intercepts = [], []
    n = len(tick_pixels)
    for i in range(n):
        for j in range(i + 1, n):
            if tick_pixels[i] == tick_pixels[j]:
                continue
            s = (tick_values[j] - tick_values[i]) / (tick_pixels[j] - tick_pixels[i])
            slopes.append(s)
            intercepts.append(tick_values[i] - s * tick_pixels[i])
    return np.median(slopes), np.median(intercepts)

# Bengali: component scores from whole-grapheme probabilities
def component_scores(grapheme_probs, grapheme_to_component, n_values):
    # grapheme_probs: (n_samples, n_graphemes); grapheme_to_component: (n_graphemes,)
    scores = np.zeros((grapheme_probs.shape[0], n_values))
    for v in range(n_values):
        members = grapheme_to_component == v
        scores[:, v] = grapheme_probs[:, members].mean(axis=1)
    return scores.argmax(axis=1)
```
