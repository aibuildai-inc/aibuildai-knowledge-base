## Principle 3: Preserve Full Resolution and Aspect Ratio When Information Density is High

*Consensus: Recurring in top solutions, including Bengali 1st/2nd. Cropping/aggressive resizing lost critical details in dense documents.*

Train and infer at original or near-original resolution, preserving aspect ratio. Avoid aggressive square-crop-and-resize when characters/features are small or densely packed.

**Why this matters:** Document images often have high information density—small diacritics, overlapping strokes, fine graph gridlines. Resizing to 224×224 destroys distinguishing features. Bengali top solutions used 137×236 (original); very large pages are better split into high-resolution crops than downscaled whole. Information loss from resizing is unrecoverable.

**When to use:** When original images are >1000px, when fine details matter (diacritics, stroke order, subscripts), when aspect ratio varies significantly across samples, or when you have GPU memory for larger inputs. Particularly critical for handwriting, historical documents, scientific figures.

**When NOT to use:** When images are already low resolution (<300px), when content is simple/sparse (isolated digits, single objects), when you're memory-constrained and simple content doesn't need high resolution, or when aggressive augmentation (cutmix) requires uniform sizes and content is robust to resizing.

**How to reason about it:**
Check if resizing 224×224 hurts validation accuracy vs original resolution. If yes, train at higher resolution or use multi-scale. For variable aspect ratios, either pad-to-square (wastes compute), use bucketing (group similar shapes, batch separately), or use adaptive pooling in the model. Bengali 1st place: no crop/resize. For very large pages, train on high-resolution crops, or raise the input size progressively during training.

```python
# Preserve aspect ratio with padding
def resize_with_padding(image, target_size=384):
    h, w = image.shape[:2]
    scale = target_size / max(h, w)
    new_h, new_w = int(h * scale), int(w * scale)
    resized = cv2.resize(image, (new_w, new_h))
    
    # Pad to square
    pad_h = target_size - new_h
    pad_w = target_size - new_w
    padded = np.pad(resized, ((0, pad_h), (0, pad_w), (0, 0)), constant_values=255)
    return padded

# Or use bucketing for efficiency
def bucket_by_aspect(images, labels):
    # Group into narrow/square/wide buckets
    buckets = {'narrow': [], 'square': [], 'wide': []}
    for img, lbl in zip(images, labels):
        ratio = img.shape[1] / img.shape[0]
        if ratio < 0.8: buckets['narrow'].append((img, lbl))
        elif ratio > 1.2: buckets['wide'].append((img, lbl))
        else: buckets['square'].append((img, lbl))
    return buckets  # Batch within buckets
```
