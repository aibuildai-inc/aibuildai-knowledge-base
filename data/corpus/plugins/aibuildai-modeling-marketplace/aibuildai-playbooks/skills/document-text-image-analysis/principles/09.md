## Principle 9: Ensemble Diverse Architectures and Training Regimes, Not Just Seeds

*Consensus: Recurring in top solutions. Diversity came from different backbones (CNN vs ViT), input or patch sizes, loss functions, and training data.*

Blend models that differ in architecture, training data, augmentation strategy, or input resolution—not just random seeds. Diversity across fundamentally different approaches yields larger ensemble gains than same-model different-seed.

**Why this matters:** Models trained identically make correlated errors, so extra seeds of one model add only a small gain. Models that differ in backbone, input size, or training data fail on different samples, so their blend corrects more errors (for example ConvNeXt + Swin for graphs, ConvNeXt V2 + HRNet for ECG digitization).

**When to use:** When you have compute budget for multiple models, when single-model performance plateaus, when different architectures show complementary strengths on validation (e.g., one model better on in-distribution samples, another on out-of-distribution samples), or when metric is unforgiving of outlier errors (blending reduces worst-case).

**When NOT to use:** When inference time/cost is constrained (ensembles are slower), when single model is far from optimal (fix it first), when correlation between models is too high (they make same errors), or when you lack diversity axes (all CNNs on same data converge to similar errors).

**How to reason about it:**
Train models differing in: (1) Architecture family (CNN vs ViT, ResNet vs EfficientNet). (2) Input or patch size. (3) Loss function. (4) Augmentation (cutmix vs fmix vs mixup). (5) Training data (different crops, sources, or synthetic folds). Measure validation error correlation—if >0.9, models are too similar. For blending: use hard voting for classification, soft averaging for regression, or train a 2nd-level model (LightGBM on probabilities + metadata).

```python
# Diverse ensemble example
models = [
    # Different architectures and input sizes
    ConvNeXt(input_size=384),
    SwinTransformer(input_size=384),
    HRNet(input_size=512),
    # Different augmentation strategies
    EfficientNetB5(aug='cutmix'),
    EfficientNetB5(aug='fmix'),
]

# Soft voting for classification
preds = [model.predict_proba(X_test) for model in models]

# Or weighted by validation score
```
