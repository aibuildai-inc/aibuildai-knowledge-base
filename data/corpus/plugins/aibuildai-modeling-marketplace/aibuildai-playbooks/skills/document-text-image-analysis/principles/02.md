## Principle 2: Choose Two-Stage (Detect + Classify) vs End-to-End Based on Localization Difficulty

*Consensus: Recurring in top graph solutions. Two-stage wins when localization is easier than recognition; end-to-end (image-to-text) wins when both are hard or tightly coupled.*

Split the problem into detection/segmentation then classification when bounding boxes are easy to predict but content is hard. Use end-to-end image-to-text models when localization and content recognition are interdependent.

**Why this matters:** Two-stage allows independent tuning of localization and recognition, better utilizes context (classify from larger crops containing neighbors), and enables targeted improvements. End-to-end is simpler and better when localization depends on content understanding (e.g., graph data points without clear visual boundaries).

**When to use:** Two-stage: when objects have clear visual boundaries (characters in documents, scatter points, chart axes), when recognition benefits from multi-object context, when validation detection is already close to perfect, or when localization and recognition have different optimal resolutions. End-to-end: when boundaries are ambiguous, when outputs are sequences/structured text, when using vision-language models (Deplot, Matcha), or when localization requires understanding content (overlapping or interdependent elements).

**When NOT to use:** Two-stage: when detection is the bottleneck, when errors compound (bad boxes → wrong classes), when objects lack clear boundaries. End-to-end: when you need fine control over localization, when inference cost is critical (image-to-text models are slower), or when detection alone has high accuracy and recognition is the challenge.

**How to reason about it:**
Train a simple detector first. If validation detection is close to perfect, two-stage likely wins—pour effort into the classification head. If detection errors are frequent or catastrophic, try end-to-end. For structured outputs (graph data series), test whether Matcha/Deplot baselines beat detection+OCR. Use detection for scatter/dots and end-to-end for lines/bars is a valid hybrid (Benetech 1st/3rd place).

```python
# Two-stage: detection then classification with context
# Stage 1: Get bounding boxes (e.g., YOLOX)
boxes = detector(image)  # [(x1,y1,x2,y2), ...]

# Stage 2: Classify each box from a crop with a margin, so the classifier sees context
for (x1, y1, x2, y2) in boxes:
    crop = image[y1-margin:y2+margin, x1-margin:x2+margin]
    class_logits = classifier(crop)  # ResNet/EfficientNet

# vs End-to-end: single model outputs structured text
from transformers import Pix2StructForConditionalGeneration
model = Pix2StructForConditionalGeneration.from_pretrained('google/matcha-base')
output_text = model.generate(image)  # '<chart_type><x>1;2;3<y>4;5;6'
```
