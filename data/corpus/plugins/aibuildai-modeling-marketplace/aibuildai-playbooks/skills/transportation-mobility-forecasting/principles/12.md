## Principle 12: Validate with Time-Aware or Stratified Splits Matching Test Distribution

*Consensus: 3/5 solutions explicitly mentioned (PKDD-15 #3, Walmart #3, Restaurant #1)*

Create validation sets that mimic the test set's structure: for time-based problems, use a time-based split (train on earlier data, validate on later, matching test period). For stratified problems (e.g., synthetic vs. real test data), balance validation to match test distribution. Use out-of-fold predictions for stacking.

**Why this matters:** Random CV can leak future information or create train-test distribution mismatch. Time-based splits prevent lookahead bias (predicting past from future). Matching test conditions (same week-dates, same mix of real/synthetic rows) ensures validation scores correlate with leaderboard scores. Out-of-fold predictions let you train level-2 models without overfitting.

**When to use:** Always use time-based CV for temporal problems (trips, sales, congestion). Use stratified CV if test has different distribution than train (synthetic padding, missing categories). For stacking, always generate out-of-fold predictions (k-fold on training, predict each fold with models trained on the others).

**When NOT to use:** Do not use time-based CV if temporal order is irrelevant (IID data). Do not stratify by outcome if test is truly random—stratification is for distribution shifts, not outcome balance.

**How to reason about it:**
For temporal data: train on all data before date X, validate on date X to Y, matching test period (e.g., if test is specific timestamps, validate on those same week-dates in prior year). For stacking: use 5-fold CV, train each fold's models on the other 4 folds, predict on the held-out fold. Concatenate all fold predictions as level-1 features. For distribution shifts: inspect test data structure (synthetic padding, missing categories) and upsample/weight validation to match.
