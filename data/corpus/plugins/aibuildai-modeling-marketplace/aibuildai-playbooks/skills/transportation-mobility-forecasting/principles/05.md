## Principle 5: Use Nearest-Neighbor Features for Partial Trajectory Prediction

*Consensus: 2/2 taxi trip time competitions (PKDD-15: ranks #2, #3)*

When predicting trip duration from a partial trajectory, find the k nearest historical trips by Euclidean or DTW distance on the trajectory so far. Extract features: durations of those neighbors, kernel-weighted average duration, distances to neighbors. Match on multiple trajectory prefixes (last 100m, 200m, ..., 1000m, full so far).

**Why this matters:** Partial trajectories contain strong predictive information—where you've been hints where you're going. Nearest neighbors in trajectory space directly leverage similar past trips. Matching at multiple prefix lengths captures both local context (recent path predicts immediate next segment) and overall route structure. Kernel regression smooths over neighbors better than raw k-NN.

**When to use:** When you have GPS trajectories and must predict remaining trip time from an incomplete trajectory. Use if training data includes many completed trips covering the region. Match on the last N meters (500m worked best in PKDD-15 #3 solution) to emphasize recent context.

**When NOT to use:** Skip if you only have start/end points without trajectories—use direct distance features instead. Do not use if the region has sparse historical coverage (few neighbors found). Avoid DTW if datasets are large and computational cost is prohibitive—Euclidean distance on coordinates is often sufficient and much faster.

**How to reason about it:**
For each test trip, extract the partial trajectory (GPS points so far). Compute Euclidean distance between this trajectory and every training trip's corresponding prefix (same length or last N meters). Select k=10 nearest. Compute their mean, median, min, max durations as features. Also compute kernel regression prediction (Gaussian kernel on distances). Try matching at multiple prefix lengths (last 200m, 500m, 1000m) and let the model weigh them.

```python
from scipy.spatial.distance import euclidean

def get_neighbor_features(partial_traj, train_trajs, train_durations, k=10):
    # partial_traj: array of (lat, lon) for test trip
    # train_trajs: list of arrays for training trips
    distances = [euclidean(partial_traj.flatten(), t[:len(partial_traj)].flatten()) 
                 for t in train_trajs]
    nearest_k = np.argsort(distances)[:k]
    neighbor_durations = train_durations[nearest_k]
    
    return {
        'nn_mean_duration': neighbor_durations.mean(),
        'nn_median_duration': np.median(neighbor_durations),
        'nn_min_distance': distances[nearest_k[0]]
    }
```
