## Principle 13: Treat Weather and External Data as Weak Signals Requiring Careful Integration

*Consensus: 3/3 competitions with weather data (Walmart #1, Walmart #3, Geotab #2)*

Weather features (precipitation, temperature, snow) often have weak or misleading effects. Integrate carefully: use binary thresholds (rain > 0.2 inches) or rolling averages (7-day mean before/after event). Validate that weather helps—it often doesn't. For external data (TIGER road network, demographics), use it for structural features (road type, population) but avoid overfitting to external IDs.

**Why this matters:** Intuition says weather matters (umbrellas sell before storms), but data often shows weak effects. Weather stations may not match store/intersection locations. Over-relying on weather adds noise. External data (road networks, demographics) can provide topology and context but must be joined carefully to avoid leakage or overfitting.

**When to use:** Use weather features if the problem explicitly mentions weather sensitivity (e.g., Walmart's stormy weather competition). Create binary flags (is_rainy, is_snowy) and rolling averages (7-day mean before, after) rather than raw readings. Use external road network data to extract road type, connectivity, and topology—not raw external IDs.

**When NOT to use:** Do not assume weather helps without validation. If coefficients are near zero or performance doesn't improve, drop weather features. Do not join external data by fuzzy matches that introduce errors. Avoid using external IDs (e.g., external intersection IDs) that don't appear in test data.

**How to reason about it:**
Add weather features: is_precip_high = (precipitation > 0.2), depart_extreme = (temp_departure > 8 or < -8). Compute 7-day rolling means before and after each date for smoothing. Train models with and without weather; validate improvement. For external data: match competition intersections to TIGER roads by coordinates, extract road class (highway, arterial), and compute network features. Never use external IDs as direct features—they won't generalize.

```python
# Weather features
weather['is_rainy'] = (weather['precipitation'] > 0.2).astype(int)
weather['is_temp_extreme'] = ((weather['temp_depart'] > 8) | (weather['temp_depart'] < -8)).astype(int)
weather['precip_7d_before'] = weather.groupby('station')['precipitation'].transform(lambda x: x.rolling(7, min_periods=1).mean())
```
