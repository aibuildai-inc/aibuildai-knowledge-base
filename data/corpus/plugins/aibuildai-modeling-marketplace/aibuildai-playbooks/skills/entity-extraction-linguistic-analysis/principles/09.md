## Principle 9: Validate Cross-Validation Strategy Against Public LB Distribution

*Consensus: Seen in several competitions - Coleridge (4th place LB probing), NBME (many solutions noted CV-LB mismatch)*

Before committing to a CV strategy, verify that it reflects the test set's distribution, especially the prevalence of rare entities. Use public LB probing (if allowed) or analyze public test to estimate private test characteristics, and choose a CV split that matches.

**Why this matters:** If CV over-represents easy cases or under-represents rare entities, optimizing for CV will hurt test performance. Coleridge's 4th place used LB probing to discover that private test had few training-set labels, so they optimized for detecting novel datasets—opposite of what naive CV suggested. NBME's winners switched from 5-fold to 10-fold GroupStratifiedKFold for better case distribution.

**When to use:** Always check CV-LB correlation: submit a pure-CV-optimized model and compare CV vs public LB. If the gap is >0.02-0.03 metric, your CV is biased. Check: (1) Entity frequency: do rare entities appear in CV at the same rate as test? (2) Document types: are all cases/genres represented in each fold? (3) Data leakage: are documents from the same source in both train and test (use GroupKFold by source). Use StratifiedKFold by entity type if entities are imbalanced. NBME: use GroupKFold by case_num (clinical cases). Coleridge: probe LB to estimate test composition.

**When NOT to use:** Skip complex CV if: (1) train and test are from the same i.i.d. distribution (confirmed by organizers), (2) random 5-fold gives CV=LB within 0.01, (3) you have very little data (<500 samples) and complex splits are unstable. For most Kaggle entity extraction, data is NOT i.i.d., so default to GroupKFold or StratifiedKFold.

**How to reason about it:**
Analyze data structure: identify natural groups (document source, author, case ID, time period). If entities cluster by group (e.g., all mentions of dataset X are in papers by the same author), use GroupKFold by that group to prevent leakage. If entity classes are imbalanced (some labels 100x rarer), use StratifiedKFold to ensure each fold has similar class distribution. Test: train on 4-fold CV, submit, compare CV score vs public LB. If they match within 0.01, your CV is good. If CV >> LB, you're overfitting to train distribution; if LB >> CV, test is easier or you're under-representing easy cases. Coleridge's LB probing: submit predictions with only training-set labels to measure their prevalence in test; use that to adjust prediction threshold.
