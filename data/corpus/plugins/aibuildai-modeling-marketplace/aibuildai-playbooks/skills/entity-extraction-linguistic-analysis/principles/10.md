## Principle 10: Tune Per-Label Thresholds and Use Label-Specific Post-Processing

*Consensus: Seen in several competitions - PII (1st, 5th), NBME (9th), Feedback Prize (multiple), Coleridge (2nd, 4th)*

Instead of a single global threshold for all entity types, optimize a threshold for each label independently. Apply label-specific post-processing rules (e.g., emails must have '@', names must be title-cased) to filter false positives without hurting recall on other labels.

**Why this matters:** Different labels have different precision-recall trade-offs. Rare entities (PHONE_NUM) need lower thresholds to achieve any recall, while common entities (NAME_STUDENT) can use higher thresholds to reduce noise. A global threshold under-performs on imbalanced tasks. PII's 1st place: different thresholds per label was core. NBME's 9th: threshold tuning per feature.

**When to use:** Always tune per-label thresholds when: (1) labels are imbalanced (some 100x rarer than others), (2) the metric is micro-averaged (rare labels matter as much as common ones), (3) labels have different error modes (names often over-predicted, IDs under-predicted). Use Optuna or grid search on validation set to find optimal threshold per label. Apply label-specific rules: if label is EMAIL, reject if no '@'; if NAME, reject if not title-case.

**When NOT to use:** Skip if: (1) all labels have similar prevalence and error rates, (2) the metric is macro-averaged (per-label F1 already accounts for it), (3) you have very few validation samples (<100 per label) so threshold tuning is unstable. For single-label extraction tasks (one span per text), global threshold is fine.

**How to reason about it:**
Train model, get predictions with probabilities on validation set. For each label L: vary threshold from 0.1 to 0.9 in steps of 0.05, compute metric (F1, Jaccard) for just that label, keep threshold that maximizes it. This gives per-label thresholds. Check: do rare labels get lower thresholds? (Usually yes.) Apply in inference: for each predicted span, use the threshold for its label. Then apply label-specific rules: for NAME, reject if first char is lowercase; for EMAIL, reject if '@' not in span. Recompute metric; if rules improve it, keep them.
