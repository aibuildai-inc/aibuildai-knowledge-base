## Principle 12: When External Data is Abundant, Prioritize Quality Over Quantity

*Consensus: Seen in several competitions - PII (1st, 5th used curated LLM-generated data), NBME (external data less useful), Coleridge (mixed results)*

If external data is available (scraped datasets, LLM-generated examples), focus on filtering it to match the task distribution rather than using all of it. High-quality matched data beats large noisy data. For LLM-generated data, validate that it covers edge cases and rare entities, not just common patterns.

**Why this matters:** External data often has distribution shift: scraped datasets may use different naming conventions, LLM-generated examples may be too clean. Training on mismatched data hurts more than it helps. PII's 1st place: curated Mistral-generated data was 'by far the most useful'—they selected datasets carefully rather than using all available external data. NBME's top solutions found external medical data less useful than MLM on in-domain unlabeled data.

**When to use:** Use external data when: (1) training data is very small (<1k samples), (2) external data is from the same domain and task (e.g., other PII datasets for PII task), (3) you can filter it to match your distribution (e.g., select only essays similar to your training essays). For LLM-generated data: generate examples that cover rare entity types underrepresented in training. PII used LLM-generated essays to add rare entities (non-English names, unusual formats).

**When NOT to use:** Avoid external data if: (1) it's from a different domain (general text for a medical task), (2) it's noisy and you can't filter it (scraped data with wrong labels), (3) you have abundant training data (>10k samples) and external data doesn't add coverage. NBME's winners found that MLM on unlabeled patient notes beat adding external medical datasets—domain match matters more than volume.

**How to reason about it:**
Evaluate external data: sample 100 examples, check if they match your training distribution (same entity types, similar text style, same label conventions). Compute overlap: what % of entity types in external data appear in training? If <50%, it's off-distribution. For LLM-generated data: identify rare entity types in training (those with <10 examples), prompt LLM to generate examples heavy in those types. Validate: train model with/without external data, compare CV. If external data improves CV but hurts LB, it's overfit to external distribution—filter more aggressively. Best practice: use external data for pre-training (MLM, QA), then fine-tune on in-domain data.
