## Principle 1: Branch Early by Task Structure: Rule-Based vs. Learned Assessment

*Consensus: Deep Past translation solutions combined rule-based normalization and cleanup (orthography rules, name standardization, repeated n-gram removal) with learned ByT5 or LLM translators; most writing assessment solutions use transformer-based models*

Text transformation tasks (translation or generation from noisy, inconsistently written source text) need a hybrid pipeline: deterministic rules to normalize the input and clean the output, plus a learned sequence-to-sequence model for the transformation itself. Writing assessment tasks (subjective scoring) require large pretrained transformers with domain adaptation.

**Why this matters:** Some regularities are known exactly and are cheap to enforce with rules; learning them from scarce data wastes model capacity. In Deep Past translation, the same cuneiform sign appeared in many surface spellings across publications, so a top solution unified the orthography with a rule table before training; the 1st-place solution standardized person and place names against a lexicon and removed repeated n-grams after decoding. Writing assessment evaluates subjective quality without rigid rules, requiring models that understand semantic nuance. Using the wrong paradigm—pure rules on subjective scoring, or a pure model with no normalization on inconsistent source text—wastes either accuracy or data.

**When to use:** Use a rules + learned-model hybrid for tasks with: (a) inconsistent spelling or formatting in the source that has known canonical forms, (b) output constraints that can be checked deterministically (name lists, no repeated phrases), (c) small parallel data. Use transformers for: (a) evaluating writing quality, (b) scoring on rubrics or dimensions like 'content' or 'effectiveness', (c) tasks where context beyond local tokens matters.

**When NOT to use:** Don't use rule-based approaches when the task involves subjective judgment (e.g., 'Is this argument effective?'). Don't add a rule when it has not been validated: in Deep Past, one top solution found lexicon-based name normalization did not help, while the 1st-place solution kept it in its pipeline.

**How to reason about it:**
Ask: Which parts of the transformation are known exactly (canonical spellings, fixed name forms, formatting) and which need learned judgment? Put the exact parts into rules before and after the model, and leave the rest to the model. For hybrids: Layer 1 = source normalization rules, Layer 2 = learned seq2seq model, Layer 3 = output rules (standardize names, remove repeated n-grams). Validate each rule layer separately on held-out data.

```python
import re

def normalize_source(text, rules):
    # rules: list of (pattern, replacement) pairs for canonical spellings
    for pattern, replacement in rules:
        text = re.sub(pattern, replacement, text)
    return text

def remove_repeated_ngrams(text, n_min=2, n_max=7):
    words = text.split()
    for n in range(n_max, n_min - 1, -1):
        i = 0
        while i + 2 * n <= len(words):
            if words[i:i + n] == words[i + n:i + 2 * n]:
                del words[i + n:i + 2 * n]
            else:
                i += 1
    return ' '.join(words)
```
