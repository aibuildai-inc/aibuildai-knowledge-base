## Principle 4: Control Combinatorics with a Coarse-to-Fine Hypothesis Funnel

*Consensus: 6/6 reduced the search in stages—through pairs or tracklets, parameter hypotheses, clustering, extension, pruning, and final assignment.*

Build a funnel that starts with cheap, permissive hypotheses and applies progressively richer geometry only to survivors. Track candidate recall, branching factor, and cost at every transition so pruning is deliberate rather than accidental.

**Why this matters:** Early false negatives are usually irreversible, but retaining every pair or parameter hypothesis causes explosive memory and runtime. Two-hit seeds cheaply estimate direction; three hits permit curvature estimation; longer candidates support stronger topology and residual tests.

**When to use:** Use this pattern in dense events where full combinatorial search is infeasible and measurements arrive on discernible surfaces or can be grouped under sampled trajectory parameters.

**When NOT to use:** A funnel is unnecessary for very sparse events where exact global optimization is affordable. It can also be harmful if the first stage uses a strong assumption that excludes an important trajectory population; branch the funnel instead of tightening one seed family.

**How to reason about it:**
For each stage, measure true weighted candidate recall, candidates per hit, memory, and latency. Set early gates to preserve recoverable score, not to maximize precision. Spend expensive fitting or ML only after cheap geometric and topological filters have reduced the candidate set.

```python
def generate_candidates(event):
    pairs = adjacent_surface_pairs(event, loose_gate=True)
    pairs = cheap_pair_filter(pairs)             # High recall target
    triples = extend_to_next_surfaces(pairs, k_nearest=10)
    triples = curvature_filter(triples)
    tracks = propagate_local_models(triples)
    return tracks
```
