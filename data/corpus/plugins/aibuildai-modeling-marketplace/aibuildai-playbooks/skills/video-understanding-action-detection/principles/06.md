## Principle 6: Use Encoder-Decoder for Sequence Tasks, Direct Classification for Frame/Clip Tasks

*Consensus: 4/4 sequence-to-text or temporal localization competitions used encoder-decoder or CTC. ASL fingerspelling top 3: all encoder-decoder with transformer decoder. YouTube8M: video encoder → segment re-ranking.*

When the output is a sequence (characters, words, segment boundaries), use an encoder-decoder architecture with attention. For frame-level or clip-level classification, use a classification head on top of the encoder.

**Why this matters:** Encoder-decoder architectures learn to align input temporal patterns with output sequences autoregressively, handling variable output length and dependencies between output tokens (e.g., language model prior in fingerspelling). CTC is an alternative for sequence tasks but struggles with output length penalties and doesn't model output dependencies. Direct classification is simpler and faster for tasks where each input frame/clip maps to a single label.

**When to use:** Encoder-decoder: For sequence-to-sequence (fingerspelling → text) or temporal localization (video → segment boundaries). Use transformer decoder (ASL top solutions) or GRU/LSTM decoder. CTC: Alternative for sequence tasks, but top solutions found transformer decoder superior (+0.003 over CTC in ASL fingerspelling 1st place). Direct classification: For frame-level (contact yes/no per frame), clip-level (isolated sign class), or video-level (action present in video) tasks. Use Global Average Pooling + Dense or similar.

**When NOT to use:** Do not use encoder-decoder for simple classification — it's slower (autoregressive decoding) and unnecessary. ASL signs (isolated classification): all top solutions used classification heads, not decoders. Do not use CTC if transformer decoder is feasible — CTC has no length penalty mechanism and doesn't model output dependencies well. ASL fingerspelling 4th place: CTC didn't help even as auxiliary loss.

**How to reason about it:**
Ask: Is my output a sequence with variable length and dependencies? (e.g., spelling out 'hello') → Encoder-decoder with transformer decoder, train with cross-entropy, decode with beam search or greedy. Or is my output a single label per input frame/clip? (e.g., 'contact' yes/no, sign class) → Encoder + classification head, train with CrossEntropy/BCE. If sequence task, prefer transformer decoder over CTC unless inference speed is critical (CTC greedy is O(1), transformer is O(N)).

```python
# Encoder-decoder for sequence generation (ASL fingerspelling)
encoder_output = squeezeformer_encoder(landmarks)  # (batch, time, dim)
decoder = TransformerDecoder(num_layers=2)
output_seq = decoder(target_shifted, encoder_output)  # Autoregressive
loss = CrossEntropyLoss(output_seq, target_seq)

# Classification head for clip-level task (ASL signs)

pooled = GlobalAveragePooling1D()(encoder_output)  # (batch, dim)
logits = Dense(num_classes)(pooled)
loss = CrossEntropyLoss(logits, sign_class)
```
