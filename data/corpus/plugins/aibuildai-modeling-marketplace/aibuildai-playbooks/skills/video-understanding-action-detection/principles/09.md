## Principle 9: For Temporal Localization, Use a Two-Stage Pipeline: Coarse Proposal → Fine Re-Ranking

*Consensus: 2/2 temporal localization competitions (YouTube8M) used two stages. 1st place: video model proposes top 100k videos → segment model re-ranks. 2nd place: video-level pre-train → segment-level fine-tune.*

Temporal localization at scale (finding specific moments in long videos across many classes) requires first narrowing the search space with a high-recall video-level model, then re-ranking proposed segments with a fine-grained segment-level model.

**Why this matters:** Exhaustively evaluating every segment of every video for every class is computationally infeasible. A two-stage approach balances recall and precision: the video model achieves high recall (99.7% in YouTube8M 1st place) by quickly filtering out irrelevant videos, then the segment model achieves high precision by carefully re-ranking only the promising candidates. This also separates concerns: video models can be trained on large-scale video-level labels (cheaper to annotate), segment models on segment-level labels (expensive but high-quality).

**When to use:** When the task is temporal localization (find where actions occur) at scale (many videos, many classes). Stage 1 (video model): Train on video-level labels to predict which videos likely contain each class. Use models optimized for high recall (e.g., last year's winner, mixture of NetVLAD/LSTM/GRU). Propose top K videos per class. Stage 2 (segment model): Break proposed videos into segments, extract segment features, train a re-ranking model (transformer, LSTM, XGBoost) on segment-level labels. Measure mAP within top K proposals.

**When NOT to use:** Do not use two-stage for frame-level or clip-level classification where all input is already at the target granularity (e.g., a task whose input is already frame-level, with no need for video-level filtering). Do not use if the dataset is small enough to directly train segment models on all data. Two-stage adds complexity; single-stage is simpler when feasible.

**How to reason about it:**
Check task scale: How many videos? How long? How many classes? If evaluating every (video, segment, class) tuple is infeasible, use two-stage. Stage 1: Train a video-level model (on video-level annotations if available, or weakly supervised from segments) to output top K videos per class. Optimize for recall, not precision. Stage 2: For each proposed video, generate segments (e.g., fixed 5s windows), extract features with a segment model (same or different from stage 1 encoder), train to re-rank. Ensemble multiple segment models. Post-process: temporal smoothing across neighboring segments.

```python
# YouTube8M two-stage
# Stage 1: Video model for high-recall proposals
video_features = video_encoder(frames)  # Pre-extracted or CNN
video_logits = mixture_of_experts([NetVLAD(video_features), LSTM(video_features), ...])
top_k_videos_per_class = video_logits.topk(k=100000)  # High recall

# Stage 2: Segment model re-ranks proposed segments
for video in top_k_videos_per_class:
    segments = break_into_5s_segments(video)
    segment_features = segment_encoder(segments)
    segment_scores = segment_model(segment_features)  # Re-rank
final_predictions = sort_by_score(segment_scores)
```
