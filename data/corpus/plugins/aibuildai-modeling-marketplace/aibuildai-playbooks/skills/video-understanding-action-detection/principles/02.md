## Principle 2: Engineer Invariant Features for Structured Data Before Model Input

*Consensus: 3/3 pose/landmark competitions (ASL fingerspelling, ASL signs, MABe) used hand-crafted invariant features. 1st place ASL fingerspelling: motion lag1/lag2. MABe 5th place: 58 engineered features including velocities, distances, angles.*

When data is structured (landmarks, tracking coordinates), derive domain-invariant features (distances, velocities, angles, curvature) that are transformation-invariant and physically meaningful, rather than feeding raw coordinates alone.

**Why this matters:** Raw (x, y) coordinates are fragile to translation, rotation, and scale variations across recordings. A 'sniff' action has the same relative nose-to-tail distance regardless of where in the frame it occurs. Engineered features reduce the model's burden to learn these invariances from scratch, improving generalization across domains (different signers, camera angles, arenas). They also inject domain knowledge: body curvature for mice, finger angles for sign language.

**When to use:** When input is structured coordinates (pose keypoints, tracking positions). Always include: (1) motion features (velocity = position[t] - position[t-1], acceleration, higher-order derivatives), (2) pairwise distances (between body parts, between agents), (3) angles (relative orientation, heading), (4) domain-specific features (body elongation for animals, finger tree angles for hands). Normalize each feature type separately.

**When NOT to use:** Do not over-engineer when the model can learn the features easily or when features don't generalize. ASL 1st place found lag > 2 motion didn't help. Raw coordinates may still be useful as additional input (not replacement) when combined with invariant features. Do not use pixel coordinates from video as 'structured' — those need CNN feature extraction first.

**How to reason about it:**
List your structured data's properties. For each coordinate set, ask: (1) What transformations should my model be invariant to? (translation, rotation, scale, flip) → derive invariant features. (2) What domain knowledge exists? (fingers have tree structure, mice have body shape, football players have speed/acceleration) → engineer those. (3) What temporal patterns matter? (smooth motion, sudden changes) → add derivatives. Validate each feature by checking if removing it hurts CV — drop features that don't contribute.

```python
# ASL: Motion features + normalization
mean = landmarks[:, :, nose_idx].mean()
x_norm = (landmarks - mean) / std
motion_lag1 = x[:, 1:] - x[:, :-1]  # velocity
motion_lag2 = x[:, 2:] - x[:, :-2]  # acceleration
features = concat([x_norm, motion_lag1, motion_lag2])

# MABe: Pairwise distances + angles
dist_matrix = pairwise_distances(keypoints)  # all pairs
relative_angle = arctan2(mouse2_y - mouse1_y, mouse2_x - mouse1_x)
velocity = (position[t] - position[t-1]) / dt
features = concat([dist_matrix.flatten(), relative_angle, velocity, ...])
```
