## Principle 10: Smooth Predictions Temporally via Neighboring Context or Post-Processing

*Consensus: 4/7 competitions used temporal smoothing. YouTube8M 1st: size-3 filter over time +0.01. MABe: sliding window with stride=half, average overlaps.*

Actions have temporal continuity: if a frame is classified as 'attack' at time t, neighboring frames t±1 are likely also 'attack'. Use neighboring predictions to smooth outputs, either in the model (attention over neighbors) or post-processing (rolling average, XGBoost on neighbor features).

**Why this matters:** Frame-level models predict each frame independently and may produce flickering (rapid class changes) or missed short segments. Temporal smoothing exploits the prior that actions have minimum duration and smooth transitions. This is especially important when labels carry timing noise relative to the true event. Smoothing can be learned (model uses temporal context) or rule-based (post-processing).

**When to use:** For frame-level or segment-level predictions. Learned smoothing: Use architectures with temporal context (LSTM, GRU, Transformer, or 1D CNN with large receptive field). Sliding window inference with overlap, average predictions in overlapping regions. Post-processing smoothing: (1) Rolling average over ±k frames. (2) Minimum duration filter (remove segments < k frames). (3) Segment merging (merge segments of same class if gap < k frames). (4) Second-stage model (XGBoost) with neighbor predictions as features. Test both learned and post-processing; they stack.

**When NOT to use:** Do not smooth for instantaneous events with no temporal extent (rare in action detection). Do not over-smooth: too large a window or aggressive merging may blur action boundaries and reduce precision. Tune window size via CV. Do not use temporal smoothing as a substitute for a temporal model — learned context is better than post-hoc smoothing.

**How to reason about it:**
Check if your task has temporal continuity (most actions do). Learned smoothing: Use a model with temporal receptive field (CNN, LSTM, Transformer). For inference, use sliding windows with stride < window size, average predictions where windows overlap (ASL, MABe). Post-processing: After inference, apply (1) rolling mean over ±3-5 frames, (2) remove flickers (segments < 3-5 frames), (3) merge nearby segments (gap < 5-10 frames). For high-stakes smoothing, train a second-stage model (LGBM, XGBoost) with features: current frame prediction, ±k neighbor predictions, temporal position. Ablate to measure gain.

# Sliding window inference with overlap
stride = window_size // 2
predictions = []
for start in range(0, len(sequence), stride):
    window = sequence[start:start+window_size]
    pred = model(window)
    predictions.append((start, pred))
# Average overlapping predictions
smoothed = average_overlaps(predictions, window_size, stride)

# Post-processing: Rolling average + minimum duration filter
smoothed = rolling_mean(predictions, window=5)
segments = extract_segments(smoothed > threshold)
segments = [s for s in segments if s.duration >= 3]  # Remove flickers

# Stage-2 XGBoost with neighbor features
features = [pred[t-k:t+k] for t in range(len(pred))]  # ±k neighbors, tune k on CV
stage2_pred = xgb.predict(features)
