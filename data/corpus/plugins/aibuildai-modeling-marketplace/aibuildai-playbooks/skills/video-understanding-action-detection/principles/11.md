## Principle 11: Decode Sequence Outputs with Beam Search and Length Penalties, Not Just Greedy

*Consensus: 3/4 sequence generation competitions used beam search. ASL fingerspelling 4th: beam size 5-6 gave +0.005 over greedy. 2nd place: beam search for attention, greedy for CTC.*

For encoder-decoder sequence generation tasks, use beam search with appropriate length penalties during inference to explore multiple hypotheses and avoid premature termination.

**Why this matters:** Greedy decoding (always picking the highest-probability next token) is myopic and can get stuck in suboptimal paths. Beam search maintains top-k hypotheses, allowing the model to recover from early mistakes. Length penalties prevent the model from favoring short outputs (common in autoregressive models because they maximize per-token probability, which penalizes longer sequences). This is critical when the metric (e.g., edit distance) doesn't penalize length the way the model's loss does.

**When to use:** For sequence generation tasks (ASL fingerspelling, any seq-to-seq). Use beam search with beam size k=4-6 (larger is better but slower; tune to fit inference time budget). Add length penalty: linear penalty = alpha * length (alpha ~ 0.1-0.15), or other heuristics to prevent early stopping. Cache key/value in transformer decoder to speed up autoregressive decoding. For CTC, beam search is possible but less impactful (+0.003 in ASL 2nd place).

**When NOT to use:** Do not use beam search for classification tasks (no sequence output). Do not use without length penalty for tasks where shorter outputs score better than they should (e.g., empty string in edit distance). If beam search doesn't improve CV in ablation, or if inference time is too tight, stick to greedy (ASL fingerspelling: greedy CTC is O(1), beam search is O(L)).

**How to reason about it:**
If your task is sequence generation, start with greedy decoding as a baseline. Measure inference time. Implement beam search with k=4 and length_penalty=0 as a first step. Measure gain on CV. If positive, tune k (try 5, 6) and length_penalty (try 0.1, 0.15). For transformer decoder, add key-value caching to avoid recomputing past tokens. If beam search pushes inference over the time limit, reduce k or revert to greedy. If the metric favors longer outputs, use a length penalty (common in ASR, sign language).

```python
# Beam search with length penalty (ASL fingerspelling)
beam_size = 5
length_penalty = 0.15
beams = [([], 0.0)]  # (sequence, score)

for t in range(max_len):
    candidates = []
    for seq, score in beams:
        logits = decoder(seq, encoder_output)
        top_k = logits.topk(beam_size)
        for token, log_prob in top_k:
            new_seq = seq + [token]
            # Length penalty: penalize short sequences
            new_score = score + log_prob + length_penalty
            candidates.append((new_seq, new_score))
    beams = sorted(candidates, key=lambda x: x[1], reverse=True)[:beam_size]

prediction = beams[0][0]  # Best hypothesis
```
