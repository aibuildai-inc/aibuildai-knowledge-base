## Principle 7: For Video Tasks, Encode Tracking or Metadata Directly into the CNN via Feature Channels

*Consensus: NFL impact detection solutions fed helmet positions to the CNN as extra input channels: 4th place added a heatmap of the helmet of interest and a heatmap of all helmet centers; 2nd place added all helmet boxes as channels for its second-stage model.*

When both video and structured metadata (tracking positions, distances, player IDs) are available, encode the metadata as additional image channels fed to the CNN, rather than fusing modalities in a late-fusion stage.

**Why this matters:** CNNs learn spatial and temporal correlations best when all inputs share the same structure. Encoding tracking as image channels allows the model to learn interactions between visual appearance and spatial relationships (e.g., proximity + visual contact = collision) through convolutional kernels. Late fusion (separate video and tabular models → combine predictions) is harder to optimize and misses cross-modal interactions. The 4th-place NFL impact solution used 5 input channels (RGB plus the two helmet heatmaps) so the network could relate each helmet's appearance to the positions of the others.

**When to use:** When you have video + structured metadata (tracking, distances, IDs, etc.). For each metadata feature: (1) Normalize to [0, 255] or similar range. (2) Render it as an image channel (either spatially aligned like a heatmap, or constant across the image for global features). (3) Concatenate with video frames (grayscale or RGB) as input to 2D/3D CNN. Use uint8 encoding for discrete features to prevent overfitting. Common encodings: player positions → heatmap, distances → constant-value channel, player IDs → masks.

**When NOT to use:** Do not encode tracking if the CNN input and tracking data are misaligned spatially (e.g., bird's-eye tracking but egocentric video — needs separate encoders). Do not encode high-dimensional metadata that doesn't fit the image grid structure — use late fusion or hybrid architecture instead. If tracking features are too complex (many categorical variables), a tabular model in late fusion may be simpler, but try encoding first.

**How to reason about it:**
List your metadata features. For each, ask: Can I represent it spatially? (1) Positions (x, y) → draw as heatmap or circles. (2) Distances, speeds → scale to [0, 255], broadcast as constant channel. (3) Binary attributes → two distinct constant intensities. (4) Object boxes → masks, with a different intensity for the object of interest. Create one channel per feature (or per feature group). Stack with video frames (grayscale or RGB) as input to CNN. If the model overfits to encoded features, reduce precision (e.g., uint8 binning) or use late fusion as fallback.

# Video + detection metadata fusion: helmet-position heatmaps as extra channels
frames_rgb = clip  # (T, H, W, 3)
