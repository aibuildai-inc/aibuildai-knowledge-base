## Principle 13: Post-Process to Align Predictions with Metric Quirks or Handle Corrupted Data

*Consensus: Several competitions used metric-aware post-processing. ASL fingerspelling 1st: replace low-confidence predictions with dummy phrase +0.006. 4th: corrupted data (< 50 frames) → constant prediction +0.005. YouTube8M 1st: filter predictions with non-decreasing function.*

Competition metrics sometimes reward non-honest predictions (e.g., submitting a constant low-distance phrase for corrupted data scores better than empty). Identify these quirks and apply post-processing rules to exploit them.

**Why this matters:** Models trained to be 'honest' (predict empty when they see no signal) score poorly on metrics that don't reward honesty. For example, in ASL fingerspelling with edit distance, predicting '' (empty) for a corrupted 10-frame sequence scores 0.0, but predicting '2 a-e -aroe' scores 0.16 because it has low edit distance to many common phrases. Detecting corrupted inputs and replacing predictions with a metric-optimal dummy is a free +0.005-0.006 gain.

**When to use:** When the metric has exploitable structure. Common cases: (1) Edit distance / Levenshtein: replace predictions for corrupted data (too short, low confidence) with a phrase that has low average edit distance to the test set (e.g., '2 a-e -aroe'). (2) Temporal metrics: apply smoothing filters (YouTube8M: non-decreasing filter over neighboring segments). (3) Confidence thresholding: replace low-confidence predictions with a safe default. Identify corrupted data via heuristics (sequence length < threshold, confidence < threshold, number of valid frames < threshold).

**When NOT to use:** Do not use if the metric is well-aligned with honest predictions (e.g., accuracy, AUC). Do not over-engineer — only apply if ablation shows a clear gain (> +0.002). Do not use post-processing as a substitute for fixing the model — if most predictions are corrupted, improve the model first.

**How to reason about it:**
Analyze the metric: Does it penalize 'I don't know' answers more than wrong-but-close answers? (Edit distance does.) If yes, find a low-cost default prediction that minimizes expected loss. For ASL fingerspelling: '2 a-e -aroe' has low edit distance to many phrases because it contains common characters. For corrupted data (e.g., < 50 frames, < 5 hand frames), replace model prediction with this default. For temporal metrics, check if smoothing or filtering helps (non-decreasing, majority vote). Ablate each post-processing rule to measure gain.
