## Principle 5: Combine Learned Representations with Complementary Chemical Features

*Consensus: 8/12 polymer writeups explicitly used fingerprints or descriptors, while strong minimal-input solutions demonstrated that such features must earn their place.*

In low- or medium-data regression, combine learned graph/string/3D embeddings with compact descriptors that expose complementary local motifs or global chemistry. Select features independently by property rather than concatenating every descriptor by default.

**Why this matters:** Learned embeddings capture distributed context, while fingerprints expose exact substructures and descriptors provide low-variance physical summaries. Their errors differ, but redundant high-dimensional features can overwhelm sparse targets or duplicate what a strong attention model already learns.

**When to use:** Use when labels are scarce, tabular models are competitive, or error analysis shows failures tied to recognizable functional groups, rings, backbone/sidechain structure, or attachment-point topology.

**When NOT to use:** Skip or reduce engineered features when a large end-to-end model already captures the same signal and concatenation worsens validation. In the polymer writeups, RDKit descriptors helped some backbones but hurt GATv2, showing engineered features must be validated per architecture rather than added by default.

**How to reason about it:**
Ablate feature families, not individual columns first. Keep a family only if it improves out-of-fold error and adds residual diversity. Then perform target-specific feature selection inside each training fold to avoid leakage.

feature_blocks = {
    "learned": learned_oof_embeddings,
    "morgan": morgan_bits,
    "descriptors": rdkit_descriptors,
    "topology": custom_polymer_features,
}
# Evaluate additions sequentially using the same folds.
