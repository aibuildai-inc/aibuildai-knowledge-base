## Principle 6: Allocate Capacity According to Target and Group Heterogeneity

*Consensus: 7/12 polymer writeups explicitly used property-specific models or processing.*

Share representation learning only where tasks have common signal; allow separate heads, losses, normalizations, feature subsets, or complete models where target mechanisms and sample counts differ. Evaluate every group separately because aggregate metrics can hide a failing rare target.

**Why this matters:** Polymer properties operate on different scales and mechanisms. Unrestricted sharing can cause negative transfer, while fully separate models discard useful common chemistry and reduce effective data size.

**When to use:** Use separate heads as the default for grouped metrics or heterogeneous properties. Escalate to separate backbones when gradient conflict, missing-label patterns, optimal representations, or validation curves differ materially by target.

**When NOT to use:** Do not split reflexively when each group is tiny and strongly related. A polymer GNN with five heads worked well without full specialization; complete specialization is justified only by measured negative transfer.

**How to reason about it:**
Start with a shared backbone and target-specific heads. Log per-target gradients and errors, compare shared versus separate normalization, and train a single-target control. Separate a target only when its weighted gain exceeds the loss of shared statistical strength and compute.

```python
class MultiPropertyModel(nn.Module):
    def __init__(self, encoder, targets):
        super().__init__()
        self.encoder = encoder
        self.heads = nn.ModuleDict({t: nn.Linear(encoder.dim, 1) for t in targets})
    def forward(self, x, observed_targets):
        z = self.encoder(x)
        return {t: self.heads[t](z) for t in observed_targets}

```
