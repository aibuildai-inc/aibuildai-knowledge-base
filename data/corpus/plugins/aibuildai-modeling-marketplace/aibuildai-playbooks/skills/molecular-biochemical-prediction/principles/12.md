## Principle 12: Use Frequent Checkpointing and Early Stopping on Non-Shared Test Distributions

*Consensus: Solutions facing train/test distribution shift, most clearly on BELKA non-shared building blocks, relied on very early stopping or frequent checkpointing*

When test data has systematically different molecules than training (new building blocks, new scaffolds), validation loss can overfit within a single epoch. Save checkpoints every 0.01-0.1 epochs and select based on validation score, not training loss. The optimal checkpoint is often before epoch 1 completes.

**Why this matters:** Standard early stopping (every epoch) is too coarse when the model memorizes training molecules rapidly. The BELKA 14th-place solution validated every 0.01 epoch for non-shared building blocks and found optimal checkpoint at 0.3 epochs - a full epoch would overfit. This gained 0.05+ mAP. Models generalize best when they've seen patterns but haven't memorized specific molecules.

**When to use:** When test molecules are explicitly different from training: (1) DEL data with new building blocks, (2) leave-scaffold-out CV, (3) small training sets (<5k) with large model capacity, (4) you observe validation improving then degrading within first epoch. Checkpoint every 0.01-0.1 epoch, keep best validation checkpoint even if it's at epoch 0.1.

**When NOT to use:** Do NOT use if train/test distributions are similar (random splits) - standard early stopping is fine. Do NOT use if training is very slow (checkpointing overhead matters). Do NOT select checkpoint on test LB - use validation only.

**How to reason about it:**
IF test molecules are different from training: (1) Set up validation that matches test distribution (e.g., building block split). (2) During training, checkpoint every N batches where N = total_batches / 100 (validate 100x per epoch). (3) Track validation metric at each checkpoint. (4) IF validation peaks before epoch 1 → select that checkpoint. (5) Train with multiple seeds to ensure all data is seen across seeds (each seed sees different data in first 0.3 epochs). (6) Ensemble checkpoints from different seeds.

# Frequent checkpointing for distribution shift (BELKA 14th place)
import torch

total_batches = len(train_loader)

best_val_score = -np.inf

for epoch in range(1):  # Often optimal before epoch 1
    for batch_idx, (X, y) in enumerate(train_loader):
        optimizer.zero_grad()
        loss = model(X, y)
        loss.backward()
        optimizer.step()
        
        global_step += 1
        
        # Checkpoint every 0.01 epoch
