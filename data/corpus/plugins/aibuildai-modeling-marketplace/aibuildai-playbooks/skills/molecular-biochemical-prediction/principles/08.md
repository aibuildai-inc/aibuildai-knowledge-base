## Principle 8: Handle Severe Class Imbalance with Label Smoothing and Reweighting, Not Resampling

*Consensus: 8/8 solutions on imbalanced tasks (MoA, BELKA) used label smoothing + reweighting; none used SMOTE/oversampling*

Molecular datasets often have extreme imbalance (0.5% positives in BELKA, 1-100 positives per target in MoA). Use label smoothing (0.0001-0.001) to prevent overconfident predictions on negatives, and reweight loss by inverse class frequency (log-smoothed to avoid extreme weights). Do not oversample or undersample.

**Why this matters:** Rare positives carry most of the signal, but extreme reweighting causes overfitting. Label smoothing prevents the model from predicting 0.0/1.0 exactly, which collapses gradients and harms calibration. Log-loss is very sensitive to confident wrong predictions (predicting 0.99 on a 0 gets huge loss), so smoothing helps. The MoA 1st-place used smoothing=0.001 + pos_weight=log(F_min+100)/log(F_i+100), improving 0.002 LB over no smoothing. Oversampling duplicates noisy minority examples and overfits.

**When to use:** When you have extreme imbalance (<5% positives) in classification or multi-label tasks. Use label smoothing alpha=0.0001 to 0.001 (tune per task). Use pos_weight = log(n_neg + C) / log(n_pos + C) where C=10-100 smooths the ratio. Larger C reduces weight differences between targets.

**When NOT to use:** Do NOT oversample or undersample molecular data - molecules are not interchangeable and duplicates increase overfitting. Do NOT use extreme pos_weights (>100) - models focus only on rare class and ignore negatives. Do NOT use label smoothing >0.01 - it degrades true positives. For regression, use sample weighting by uncertainty instead.

**How to reason about it:**
For each target with imbalance ratio R = n_neg / n_pos: (1) Add label smoothing: y_smooth = (1 - alpha) * y + alpha * 0.5, where alpha=0.001. This moves 0→0.0005, 1→0.9995. (2) Compute pos_weight = log(R + C) / log(1 + C), where C=100 prevents extreme weights. (3) Use BCEWithLogitsLoss(pos_weight=pos_weight) or weighted loss. (4) Tune alpha and C with Optuna on your CV. (5) Check calibration curve: are predicted probabilities well-calibrated?

```python
import torch.nn as nn
import numpy as np

# Label smoothing transform
def smooth_labels(y, alpha=0.001):
    """y is 0/1, returns smoothed labels"""
    return (1 - alpha) * y + alpha * 0.5

# Compute pos_weight per target (for multi-label)
def compute_pos_weights(y_train, smoothing_constant=100):
    n_pos = y_train.sum(axis=0)  # Per target
    n_neg = len(y_train) - n_pos
    # Log-smoothed inverse frequency
    weights = np.log(n_neg + smoothing_constant) / np.log(n_pos + smoothing_constant)
    return torch.FloatTensor(weights)

# Loss with label smoothing and reweighting
pos_weights = compute_pos_weights(y_train)
criterion = nn.BCEWithLogitsLoss(pos_weight=pos_weights)
```
