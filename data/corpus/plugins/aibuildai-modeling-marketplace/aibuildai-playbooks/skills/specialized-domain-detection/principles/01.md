## Principle 1: Model Both Raw Signal and Domain-Transformed Representations

*Consensus: Camera model ID 10th (image CNNs stacked with sensor-noise feature models), audio tagging 4th/8th (raw waveform, log-Mel and MFCC inputs; spectrogram CNN joined with spectral statistics), scientific image forgery 29th (image plus noise-residual input)*

Train separate model branches on the raw representation and a domain-specific transformed representation (sensor-noise residuals for camera images, frequency domain for audio, 3D volume projections for CT data), then combine their features through a fusion layer or a second-level model.

**Why this matters:** The manipulation or signal often exists in a specific domain where it's more separable. A camera sensor leaves a per-pixel noise pattern that the image content hides; subtracting a smoothed copy of the image exposes that pattern directly, while a model on the raw pixels captures content and compression cues. Together they provide complementary views that either alone would miss.

**When to use:** When your data has a natural multi-domain representation: camera images (pixels + noise residual), audio (waveform + spectrogram + spectral statistics), medical imaging (2D slices + 3D volume), video (spatial + temporal). Indicators: the domain transformation is lossless or the manipulation occurs in the transformed space, and you can efficiently extract both representations.

**When NOT to use:** When the transformation is purely a preprocessing step with no privileged status (e.g., arbitrary color space conversions that don't align with the signal source). The deepfake 1st place used only spatial models because face swaps manifest visually, not in a specific frequency band. Also skip if the transformed representation is too expensive to extract or too weak to carry the task: the camera model ID 10th place's models on sensor-noise features scored 0.898 public / 0.881 private against 0.963 / 0.967 for its best image CNN, so they helped only as extra inputs to the stacker. If compute is limited, bet on the stronger domain first.

**How to reason about it:**
Ask: Does the physical process that creates my signal operate in a specific domain? For camera model identification, the sensor and in-camera processing leave a noise pattern → model the noise residual directly (the 4th place's largest gain came from matching image noise against per-camera reference patterns). For deepfakes, face swaps warp pixels and blend boundaries → spatial model is primary. For audio, the sound class lives in the spectrum → feed a log-Mel spectrogram and add summary spectral statistics as a second input. If both domains carry signal, train both and fuse; if one is derivative, focus there.

```python
# Dual-branch pattern: raw image plus a noise-residual view
import timm

class DualDomainModel(nn.Module):
    def __init__(self, num_classes, kernel_size=5):
        super().__init__()
        # Noise residual = image minus a local average (stride 1 keeps full resolution)
        self.smooth = nn.AvgPool2d(kernel_size, stride=1, padding=kernel_size // 2)

        # Raw branch: content and compression cues
        self.raw = timm.create_model('efficientnet_b0', pretrained=True, num_classes=0)

        # Residual branch: the high-frequency pattern the content hides
        self.residual = timm.create_model('efficientnet_b0', pretrained=True, num_classes=0)

        # Fusion head
        self.fusion = nn.Sequential(
            nn.Linear(self.raw.num_features + self.residual.num_features, 256),
            nn.ReLU(),
            nn.Linear(256, num_classes)
        )

    def forward(self, img):
        residual = img - self.smooth(img)
        raw_feat = self.raw(img)
        res_feat = self.residual(residual)
        combined = torch.cat([raw_feat, res_feat], dim=1)
        return self.fusion(combined)
```
