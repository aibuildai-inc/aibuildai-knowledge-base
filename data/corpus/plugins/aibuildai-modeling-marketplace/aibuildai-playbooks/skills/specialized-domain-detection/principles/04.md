## Principle 4: Design Depth-Invariant Architectures for Volumetric Data

*Consensus: Passenger screening 8th (one 2D encoder shared by all 16 views, features averaged across views); passenger screening 1st concatenated the views instead because threat location mattered, and 4th found a 3D model worse than its 2D model*

For volumetric or multi-view data where the signal can appear at any depth or in any view, encode each slice or view with shared weights (or with a 3D encoder), then reduce along the depth or view axis (max or average pooling) to create depth-agnostic features, and finally apply the task head.

**Why this matters:** The 2.5D approach (treating depth slices as channels and feeding them to a 2D CNN) learns which specific slices contain signal, but this fails when test data has signal at different depths than training. A depth-invariant model learns 'is there signal anywhere along this axis?' rather than 'is there signal at slice 23?', making it robust to depth shifts. Sharing one encoder across slices also multiplies the training signal when data is small: passenger screening had only about 1,200 scans, and every view of every scan trained the same encoder.

**When to use:** When your signal's location along the depth or view axis is unpredictable or varies between train and test: medical imaging (tumors at any depth), seismic analysis (events at varying depths), multi-view scans (an object visible from only some angles), any volumetric segmentation where the Z-coordinate is not semantically meaningful.

**When NOT to use:** When depth or view position is semantically meaningful and consistent (e.g., always segment the kidney at slices 40-60, never elsewhere). The passenger screening 1st place concatenated its per-view features instead of pooling them, because the task asked where on the body the threat was and pooling would discard that. Also skip if you lack 3D models or your data is natively 2D. A full 3D model is not automatically better: the passenger screening 4th place's inflated 3D network scored about 0.06 on its validation set against 0.025 for its 2D model (lower is better). The 2.5D approach (slices as channels) is simpler and works when the depth distribution is consistent across train/test.

**How to reason about it:**
Check if your test data's depth distribution matches training. If not (different scanners, angles, or samples), you need depth invariance. The pattern: shared 2D encoder per slice or view (or a 3D encoder) → features (B, D, C, H, W) → reduce depth via max or avg → (B, C, H, W) → task head. The first stage learns spatial features on every slice; the reduction makes the final prediction depth-agnostic; the head refines. Test whether max vs avg pooling matters: max picks the strongest response along the axis, which suits a small object visible in few slices; average suits evidence spread across many slices (the passenger screening 8th place averaged).

```python
# Depth-invariant pattern: shared encoder per slice or view, pool across depth
import timm

class DepthInvariantModel(nn.Module):
    def __init__(self, num_outputs, pool='max'):
        super().__init__()
        # Stage 1: one 2D encoder shared by every slice or view
        self.encoder = timm.create_model('resnet50', pretrained=True,
                                         num_classes=0, global_pool='')
        self.pool = pool

        # Stage 3: task head on depth-agnostic features
        self.head = nn.Sequential(
            nn.AdaptiveAvgPool2d(1),
            nn.Flatten(),
            nn.Linear(self.encoder.num_features, num_outputs)
        )

    def forward(self, volume):  # (B, D, C, H, W): D slices or views
        b, d = volume.shape[:2]
        feats = self.encoder(volume.flatten(0, 1))    # (B*D, F, h, w)
        feats = feats.view(b, d, *feats.shape[1:])    # (B, D, F, h, w)

        # Stage 2: reduce the depth axis
        if self.pool == 'max':
            feats = feats.max(dim=1)[0]  # strongest response at any depth
        else:
            feats = feats.mean(dim=1)
        return self.head(feats)  # (B, num_outputs)
```
