## Principle 10: Apply Aggressive Test-Time Augmentation with Spatial and Domain-Specific Transforms

*Consensus: Camera ID 1st/2nd/5th (TTA8; five crops with flips or the D4 group; manipulations and rotations), passenger screening 1st (about 100 augmented predictions per scan), audio tagging 8th (predictions over several clip lengths and random spans)*

At inference, apply a comprehensive set of augmentations (rotations, flips, crops, and domain-specific transforms like image manipulations, time spans or depth shifts), collect predictions for each, invert the transforms where the output is spatial, and average the results.

**Why this matters:** TTA exploits the model's learned invariances to improve robustness. The camera model ID 10th place's best DenseNet201 went from 0.975 to 0.980 public LB after intense TTA. Domain-specific TTA (camera manipulations, random spans of a variable-length clip, depth shifts for 3D) further averages over the domain's natural variations. More TTA = more compute but also more stable predictions.

**When to use:** Always, unless inference time is prohibitively expensive. The camera model ID 1st place used TTA 8; the 2nd place used five crops plus a flip (10 TTA), or five crops times the whole D4 group (40 TTA) for its D4-trained models; the 5th place used 11 TTA over the manipulations and rotations with a geometric mean. For variable-length audio, the audio tagging 8th place predicted at six clip lengths with five random spans each. For 3D data, add depth-shift TTA (slide the input window along Z and average).

**When NOT to use:** When your runtime budget is tight (e.g., 9-hour Kaggle kernel limit) and TTA would push you over, spend the budget where it helps most. In video deepfake detection, the 27th place found more frames per video beat TTA, the 2nd place added frames until it reached the 9-hour limit, and the 5th place found skipping alternate frames as TTA did not help. The camera model ID 1st place noted that smaller crops would have allowed more TTA options.

**How to reason about it:**
Ablate TTA on a validation set: predict with no TTA, TTA4 (4 rotations), TTA8 (4 rotations + 2 flips). Measure the score gain vs time cost, drop transforms that give no gain, and spend the saved time on more models, frames or crops. Use only transforms the signal is invariant to: rotations suit most images, but the camera model ID 4th place avoided rotations and flips in training because it expected no gain for sensor noise. For 3D or sequential data, test shift TTA: slide the input window a few slices or samples each way and average.

```python
# TTA with rotations and flips
def tta_predict(model, image, tta_transforms):
    """Apply TTA and average predictions.
    
    Args:
        model: Trained model
        image: (C, H, W) input
        tta_transforms: List of (transform, inverse_transform) pairs
    """
    predictions = []
    
    for transform, inverse in tta_transforms:
        img_aug = transform(image)
        logits = model(img_aug.unsqueeze(0))  # Add batch dim
        logits_inv = inverse(logits.squeeze(0))  # Invert the transform
        predictions.append(logits_inv)
    
    # Average logits, then apply sigmoid
    avg_logits = torch.stack(predictions).mean(dim=0)
    return torch.sigmoid(avg_logits)

# Example TTA transforms (4 rotations)
tta_transforms = [
    (lambda x: x, lambda x: x),  # Identity
    (lambda x: torch.rot90(x, 1, [1, 2]), lambda x: torch.rot90(x, -1, [1, 2])),  # 90°
    (lambda x: torch.rot90(x, 2, [1, 2]), lambda x: torch.rot90(x, -2, [1, 2])),  # 180°
    (lambda x: torch.rot90(x, 3, [1, 2]), lambda x: torch.rot90(x, -3, [1, 2])),  # 270°
]
```
