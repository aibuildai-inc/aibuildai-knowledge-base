## Principle 7: Train Multi-Head Outputs (Binary + Multiclass) Simultaneously

*Consensus: Deepfake 2nd (classification branch plus a segmentation head trained on real-fake difference masks, about 0.01 LB gain); passenger screening 4th (one detector label encodes both the threat and its body zone)*

Add a second head to your model that predicts a finer-grained target (e.g., the type of manipulation, the location of the object, or a mask of the manipulated pixels) alongside the main binary head, and train both with a combined loss.

**Why this matters:** The auxiliary task provides richer supervision signal and acts as a regularizer. In deepfake detection, a mask of the pixels that differ between a fake video and its original tells the model where the manipulation is, so it learns the manipulated region rather than dataset biases, improving the real/fake decision. The additional gradients from the auxiliary head can also speed up convergence and improve the binary head's calibration.

**When to use:** When your positive class has natural sub-categories or localizable evidence (multiple manipulation types, manipulated regions, multiple object classes or locations) and you have the labels or can derive them. The deepfake 2nd place derived masks from pixel differences between each fake and its original video and trained a UNet with a classification branch, an idea it carried over from an earlier segmentation competition. The passenger screening 4th place labeled each threat box with its body location, so one detector learned both detection and location.

**When NOT to use:** When your positive class is homogeneous or you lack sub-labels. The deepfake competition had real/fake labels but no sub-labels for manipulation type (training data was annotated only as REAL/FAKE), so a manipulation-type head wasn't applicable. Also skip if the auxiliary task is too hard or overfits and hurts the main task (test by ablation): the deepfake 1st place's UNet with SSIM-difference prediction got the same LB score as a plain classifier, and the 5th place's pixel-segmentation network overfit (LB ~0.5) and did not help its ensemble.

**How to reason about it:**
Check if your positives have sub-labels or labels you can derive (difference masks, locations). If yes, train a multi-head model and compare to a single-head baseline on a validation fold. If you see faster/better learning, keep it. If the auxiliary head's loss dominates or confuses the model, reweight the losses or drop it. Start with a moderate weight on the auxiliary loss and tune it on validation.

```python
# Multi-head training: binary label plus an auxiliary difference mask
import segmentation_models_pytorch as smp

class MultiHeadModel(nn.Module):
    def __init__(self, encoder_name='efficientnet-b4'):
        super().__init__()
        # UNet decoder for the mask, classification branch on the encoder output
        self.net = smp.Unet(encoder_name, classes=1, aux_params={'classes': 1})

    def forward(self, x):
        mask_logits, cls_logits = self.net(x)
        return cls_logits, mask_logits

# Training loop
aux_weight = 0.5  # tune on validation
for img, label, diff_mask in dataloader:
    cls_pred, mask_pred = model(img)
    loss_cls = F.binary_cross_entropy_with_logits(cls_pred.squeeze(1), label)
    loss_mask = F.binary_cross_entropy_with_logits(mask_pred, diff_mask)
    loss = loss_cls + aux_weight * loss_mask  # Weighted combination
    loss.backward()
```
