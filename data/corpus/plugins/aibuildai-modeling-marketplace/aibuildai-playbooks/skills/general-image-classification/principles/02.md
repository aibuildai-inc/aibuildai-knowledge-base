## Principle 2: Scale Batch Size Aggressively for Large Noisy Datasets

*Consensus: 4/8 QuickDraw solutions explicitly used large batches (400-10K)*

For datasets with millions of noisy samples (sketches, crowd-sourced labels), train with very large batch sizes (400-10,000) using gradient accumulation if needed. Larger batches smooth noisy gradients.

**Why this matters:** Noisy labels and high intra-class variance in large datasets (50M QuickDraw samples) cause high gradient variance. Small batches amplify this noise. Large batches average over more samples, providing more stable gradient estimates and better generalization.

**When to use:** When dataset size is >10M samples AND labels are noisy (crowd-sourced sketches, user-uploaded images). QuickDraw winner used gradient accumulation to reach huge effective batch sizes. Also when training on simplified/preprocessed data where individual samples have high variance.

**When NOT to use:** Small clean datasets (<100K samples) where large batches hurt generalization (sharp minima). Also when you have limited memory and cannot implement gradient accumulation. State Farm (small dataset, video frames) used standard batches (64-256).

**How to reason about it:**
Start with the largest batch your GPU supports. If validation loss is noisy or you see high variance in training, increase batch size via gradient accumulation. Monitor: (1) gradient variance across batches, (2) validation curve smoothness. Trade-off: larger batches need fewer updates, but each update is more expensive. For 50M samples, one solution went from batch=256 to batch=10K across snapshots.

```python
# Gradient accumulation for large effective batch size
accum_steps = 8  # 8x accumulation
effective_batch = batch_size * accum_steps  # e.g., 512 * 8 = 4096

optimizer.zero_grad()
for i, (X_batch, y_batch) in enumerate(dataloader):
    loss = model(X_batch, y_batch) / accum_steps  # Scale loss
    loss.backward()  # Accumulate gradients
    
    if (i + 1) % accum_steps == 0:
        optimizer.step()  # Update once per accum_steps
        optimizer.zero_grad()

# QuickDraw 5th place: increased batch size with each snapshot to 10K
```
