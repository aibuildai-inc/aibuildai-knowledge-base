## Principle 6: Add Domain-Specific Auxiliary Features When Core Signal Is Weak

*Consensus: QuickDraw solutions added non-visual stroke information: the 1st place added time features (the most significant was the maximum stroke timestamp), and other solutions encoded stroke order, speed, or stroke count as image channels*

When certain classes are hard to distinguish from pixels alone, add auxiliary features from information the raw data carries beyond the image: drawing order and timing for sketches, or other recorded metadata.

**Why this matters:** A rendered image discards information that can separate confusable classes. Two doodles can look alike yet differ in stroke order or drawing time. Auxiliary features restore that signal. The gain is often concentrated in a few hard classes, so measure it both standalone and when added to the best ensemble.

**When to use:** When domain analysis shows specific hard classes that have rich non-visual signal (sketches with temporal information, recorded metadata). Check confusion matrix: if specific classes have low recall, see if they share a non-visual characteristic.

**When NOT to use:** When the core visual signal is strong (facial expressions, clean object photos). Also skip if the auxiliary information exists in training data but not at test time.

**How to reason about it:**
Analyze confusion matrix: which classes are worst? Do they share characteristics (all are drawn in a similar way, all differ mainly in how they were drawn)? For sketches: encode stroke order or speed as color channels, or add scalar time features (total drawing time, number of strokes). Fuse auxiliary features via: (1) multi-input network (image branch + auxiliary branch), or (2) late fusion (ensemble visual + auxiliary models). Measure improvement on hard classes specifically.

```python
# Sketch example: encode stroke order as a channel and add scalar time features
def render_with_order(strokes, size):
    img = np.zeros((size, size, 3), np.uint8)
    for t, (xs, ys, ts) in enumerate(strokes):
        order_value = int(255 * (1 - t / max(len(strokes), 1)))  # earlier strokes brighter
        for i in range(len(xs) - 1):
            cv2.line(img, (xs[i], ys[i]), (xs[i + 1], ys[i + 1]), (255, order_value, 0), 2)
    return img

def time_features(strokes):
    return np.array([strokes[-1][2][-1], len(strokes)], dtype=np.float32)  # max timestamp, stroke count

class ImagePlusAuxiliary(nn.Module):
    def __init__(self, backbone, feat_dim, aux_dim, num_classes):
        super().__init__()
        self.backbone = backbone
        self.aux_fc = nn.Linear(aux_dim, 32)
        self.head = nn.Linear(feat_dim + 32, num_classes)

    def forward(self, img, aux):
        return self.head(torch.cat([self.backbone(img), torch.relu(self.aux_fc(aux))], dim=1))
```
