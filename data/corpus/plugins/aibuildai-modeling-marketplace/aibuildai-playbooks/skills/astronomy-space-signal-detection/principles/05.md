## Principle 5: Address Train-Test Distribution Shift Aggressively

*Consensus: Major theme in PLAsTiCC (top solutions degraded training data to match test), Ariel (foreground correction)*

Astronomy competitions often have severe train-test distribution shifts from synthetic vs real data, different observation periods, or instrument drift. Identify the shift source and mitigate it through data cleaning, matched augmentation, or distribution alignment before the model sees it.

**Why this matters:** Models that achieve high CV but low LB are overfitting to train-specific artifacts rather than learning the target signal. A noise or instrument pattern that differs between train and test can become a shortcut the model uses instead of the signal. Similarly, simulated data often has unrealistic noise or missing real-world effects.

**When to use:** Always run adversarial validation (train binary classifier to distinguish train from test) - if it achieves >0.6 AUC, a shift exists. For time series, compare PSD between train and test; for tabular features, compare per-feature distributions. Use pseudo-labeling cautiously - it helps when test difficulty matches train, but fails if test has novel signal types (pseudo-labels will be wrong). Degrade high-quality training data to match test difficulty rather than trying to upgrade test.

**When NOT to use:** Do not apply domain adaptation blindly without understanding the shift source. The PLAsTiCC winner degraded training lightcurves by modifying redshift, adding gaps, and simulating detection thresholds to make training look like test - this required understanding what made test "worse" (sparser observations, noisier photometric redshifts). Do not use pseudo-labels if test contains out-of-distribution signal types.

**How to reason about it:**
Step 1: Run adversarial validation. If train/test are distinguishable, proceed. Step 2: Analyze what differs - visualize examples, compare summary statistics, check PSD for time series, use dimensionality reduction. Step 3: Categorize shift type: (a) background/noise difference -> clean or normalize it away, (b) test is degraded version of train -> augment training to match degradation, (c) test has new signal types -> add synthetic examples of those types, (d) instrument drift -> correct known systematic (gain drift, foreground). Step 4: Re-run adversarial validation after the fix; the shift is handled when the classifier can no longer separate train from test (one gravitational-wave team confirmed similarity with an AUC of 0.5).

# Adversarial validation
from sklearn.ensemble import RandomForestClassifier
train_features = extract_summary_stats(train_data)  # mean, std, quantiles, etc.
