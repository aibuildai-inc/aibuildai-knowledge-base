## Principle 10: Use Pseudo-Labeling Selectively by Signal Type and Confidence

*Consensus: PLAsTiCC 3rd place: class90-only pseudo-labeling worked, all-class failed; g2net 3rd place used soft pseudo-labels; pattern across 8+ solutions*

Add high-confidence test predictions back to training, but only for signal classes that are well-separated and unlikely to be confused with out-of-distribution types. Use soft labels to preserve uncertainty and avoid reinforcing errors.

**Why this matters:** Pseudo-labeling helps when test data is plentiful and models are well-calibrated, providing extra training signal. But if test contains novel signal types (class 99 unknowns in PLAsTiCC), pseudo-labels will be wrong for those examples and poison training. The PLAsTiCC 3rd place found that pseudo-labeling only the easy, well-separated supernova class (class 90) gave a boost, but including all classes hurt because class 99 was mislabeled.

**When to use:** Use pseudo-labeling when: (1) you have many test samples (>10k), (2) target classes are well-separated (check confusion matrix), (3) you filter by confidence threshold (>0.95 probability), (4) you use soft labels (full probability distribution) rather than hard labels to preserve uncertainty. Apply only to well-behaved classes, not rare or ambiguous ones.

**When NOT to use:** Do not use pseudo-labels if test data contains out-of-distribution examples not represented in training - you will mislabel them and hurt performance. Do not pseudo-label rare classes or those with high confusion rates. Do not use hard labels (argmax) - soft labels preserve the model's uncertainty.

**How to reason about it:**
Step 1: Train initial model on training data. Step 2: Predict on test set with calibrated probabilities. Step 3: Filter predictions: keep only examples with max(prob) > threshold (e.g., 0.95) AND belonging to classes with <5% confusion rate on validation. Step 4: Add filtered pseudo-labeled test samples to training with soft labels (full probability vector). Step 5: Retrain from scratch or finetune. Step 6: Check validation metric - if it degrades, pseudo-labels introduced errors (tighten threshold or drop them).

```python
# Selective pseudo-labeling
def get_pseudo_labels(model, test_data, confidence_threshold=0.95, allowed_classes=[0, 1]):  # Only well-separated classes
    model.eval()
    pseudo_samples = []
    with torch.no_grad():
        for sample in test_data:
            probs = F.softmax(model(sample.signal), dim=-1)
            max_prob, pred_class = probs.max(dim=-1)
            # Filter by confidence and class
            if max_prob > confidence_threshold and pred_class in allowed_classes:
                # Use soft label (full probability distribution)
                pseudo_samples.append((sample.signal, probs))  # NOT hard label
    return pseudo_samples

# Train with mixed real + pseudo data
for epoch in range(epochs):
    for batch in chain(real_labeled_data, pseudo_labeled_data):
        logits = model(batch.signal)
        # Soft label loss (KL divergence or cross-entropy with soft targets)
        loss = F.kl_div(F.log_softmax(logits, dim=-1), batch.soft_labels, reduction='batchmean')
        loss.backward()
        optimizer.step()
```
