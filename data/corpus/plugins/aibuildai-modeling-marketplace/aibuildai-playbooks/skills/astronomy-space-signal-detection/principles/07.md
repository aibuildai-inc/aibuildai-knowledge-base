## Principle 7: Engineer Domain Features for Tabular Models, Let CNNs Learn Them

*Consensus: PLAsTiCC 3rd place used extensive feature engineering (template fitting, luminosity, time differences); gravitational wave solutions split - tabular used features, CNNs used raw signals*

For tree-based models, manually engineer features that capture domain knowledge (peak brightness, lightcurve width, template fits, frequency-domain statistics). For CNNs/RNNs, provide minimally processed signals and let the model learn representations, optionally adding a few global features.

**Why this matters:** Tree-based models cannot learn hierarchical features from raw signals, so you must hand-craft them. The PLAsTiCC 3rd place used sncosmo template fitting (cosmology-specific library) to extract supernova parameters as features, yielding 7 of their top 10 most important features. CNNs can learn these automatically from spectrograms/waveforms, but adding a few global features (redshift, detector metadata) as auxiliary inputs still helps.

**When to use:** Use heavy feature engineering for: LightGBM/XGBoost on time series (extract peak locations, widths, rise/fall times, periodicity), tabular astronomy data (convert raw flux to luminosity using redshift, fit parametric models). For CNNs, provide raw or minimally filtered signals but concatenate global metadata (redshift, detector ID) to the embedding before the final layers.

**When NOT to use:** Do not manually engineer features for CNNs on raw signals - they learn better representations. Do not use tree models on raw waveforms/images without extensive feature extraction. Do not add domain features to CNNs if they are redundant with what the network can learn from raw input (e.g., peak location from a time series the network sees fully).

**How to reason about it:**
Decision tree: (1) Model type? Tree-based -> engineer features aggressively. Neural network -> provide raw signals. (2) Are there domain-specific libraries (sncosmo for supernovae, astropy for astronomy calculations)? Use them to compute physics-grounded features. (3) For neural nets, identify what the network CANNOT learn from the raw input alone (global context like redshift, detector calibration) and provide those as auxiliary features. (4) For time series: peak brightness, width, rise/decay times, template fits, periodicity (Lomb-Scargle). For images: moments, texture statistics.

```python
# Feature engineering for tree models (supernova example)
import sncosmo
from astropy.cosmology import Planck15

def extract_sn_features(lightcurve, redshift):
    features = {}
    # Template fitting with cosmology library
    model = sncosmo.Model(source='salt2')
    result, fitted_model = sncosmo.fit_lc(
        lightcurve, model, ['z', 't0', 'x0', 'x1', 'c'],
        bounds={'z': (redshift-0.1, redshift+0.1)}
    )
    features['template_chisq'] = result.chisq
    features['template_x1'] = result.parameters[3]  # Stretch
    features['template_c'] = result.parameters[4]   # Color
    
    # Luminosity from flux and distance
    distance_mpc = Planck15.luminosity_distance(redshift).value
    flux_peak = lightcurve['flux'].max()
    features['luminosity'] = flux_peak * distance_mpc**2
    
    # Temporal features
    peak_idx = lightcurve['flux'].argmax()
    features['rise_time'] = lightcurve['mjd'][peak_idx] - lightcurve['mjd'][0]
    features['decay_time'] = lightcurve['mjd'][-1] - lightcurve['mjd'][peak_idx]
    
    return features

# Neural network: raw signal + global context
class SignalClassifier(nn.Module):
    def forward(self, waveform, metadata):  # metadata: [redshift, detector_id, ...]
        signal_features = self.cnn(waveform)  # Learn from raw signal
        combined = torch.cat([signal_features, metadata], dim=1)
        return self.head(combined)
```
