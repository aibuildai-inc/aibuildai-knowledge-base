## Principle 4: Handle Multi-Detector/Multi-Channel Data with Physics-Aware Architecture

*Consensus: Critical pattern in gravitational wave (3rd place showed 2bps gain from proper handling), Ariel (multiple channels with different PSFs)*

When data comes from multiple detectors or spectral channels, use separate processing branches for each before fusion, share weights between identical detectors, and respect the physics of how signals appear across channels (time delays, spatial correlation, wavelength-dependent effects).

**Why this matters:** Signals manifest differently across detectors due to physics: gravitational waves arrive time-shifted between spatially separated detectors; two instruments on the same telescope (a photometer and a spectrometer) see the same transit with different point spread functions; exoplanet signals have wavelength-dependent absorption. Early naive concatenation prevents learning these relationships because the model sees randomly-aligned channels, while separate branches can learn detector-specific features before correlating.

**When to use:** Use separate branches when: detectors are physically distinct (different locations, different instruments), signals can be time-shifted between channels, or channels measure fundamentally different quantities. Share weights when detectors are identical by design (e.g., LIGO Hanford and Livingston). Use late fusion (concatenate after feature extraction) when correlation is the signal, early fusion when channels provide complementary measurements of the same phenomenon.

**When NOT to use:** Do not use separate branches if channels are merely different frequency bands of a single coherent measurement with no independent information. Do not share weights between fundamentally different detector types even if they measure the same phenomenon. The 1st place Ariel solution used ONLY the AIRS-CH0 channel because FGS1's distorted PSF was too difficult to utilize effectively - sometimes dropping a noisy channel beats trying to use it.

**How to reason about it:**
Ask: (1) Are the detectors/channels identical by design? If yes, share weights for their branches. (2) Does the signal correlation between channels define the target? If yes, use late fusion (extract features separately, then fuse). (3) Is there a known physical relationship (time delay, spatial adjacency)? If yes, encode it (e.g., a learnable time shift for delayed signals, or a shared wavelength axis for spectral channels). (4) Is one channel much noisier or problematic? Consider dropping it entirely rather than letting it add noise.

```python
# Multi-detector with shared weights and late fusion
class GravitationalWaveNet(nn.Module):
    def __init__(self, n_ligo=2, n_virgo=1):
        # Shared extractor for identical LIGO detectors
        self.ligo_branch = make_extractor()
        # Separate extractor for different Virgo detector
        self.virgo_branch = make_extractor()
        # Fusion after extraction to handle time shifts
        self.fusion = nn.Sequential(
            nn.Conv1d(n_ligo + n_virgo, 64, kernel_size=1),  # Learn correlation
            ResNetBlocks(...)
        )
    
    def forward(self, ligo1, ligo2, virgo):
        # Extract features from each detector
        ligo1_feat = self.ligo_branch(ligo1)
        ligo2_feat = self.ligo_branch(ligo2)  # Same weights as ligo1
        virgo_feat = self.virgo_branch(virgo)
        # Concatenate and fuse - network learns to align shifted signals
        return self.fusion(torch.cat([ligo1_feat, ligo2_feat, virgo_feat], dim=1))
```
