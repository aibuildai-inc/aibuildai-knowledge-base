## Principle 10: Treat Multiple Datasets with Different Characteristics as Separate Modeling Problems

*Consensus: Parkinson's FOG: 5/5 solutions trained separate models for tdcsfog (128Hz, lab) vs defog (100Hz, home); only one used defog's 'notype' unlabeled data via pseudo-labeling.*

Brain signal competitions often merge datasets from different protocols, devices, or environments (lab vs home, different sampling rates, different sensors). Mixing them in one model forces it to learn protocol-agnostic features, which may be suboptimal. Training separate models per dataset and ensembling them exploits dataset-specific patterns.

**Why this matters:** Parkinson's FOG: tdcsfog is 128Hz, recorded in lab during FOG-provoking tasks (high FOG rate); defog is 100Hz, recorded at home during daily tasks (lower FOG rate, noisier). One model for both must handle sampling rate mismatch and environment shift. Separate models: each model specializes, then blend at inference. For defog, the 'notype' data (unlabeled event presence but no event type) can be pseudo-labeled by a defog model (use Event column as weak supervision, predict type with a strong model, retrain on pseudo-labels). Mixing pseudo-labels from defog model with tdcsfog data is risky (different distributions).

**When to use:** Train separate models when: (1) datasets have different sampling rates (requires different resampling/chunking), (2) datasets have different task protocols (lab vs home, different event distributions), (3) one dataset has weak labels (event yes/no) and another has strong labels (event type). Ensemble the separate models at test time (equal weight or optimize on CV). Use pseudo-labeling ONLY on the same dataset (e.g., defog model pseudo-labels defog's notype data).

**When NOT to use:** Do NOT train separate models if datasets are homogeneous (same protocol, same device, just different patients—grouping by patient in CV is enough). Do NOT pseudo-label across datasets (e.g., tdcsfog model labeling defog data) unless you verify distribution match. Do NOT ensemble dataset-specific models if test set is entirely from one dataset (weight that model 100%).

**How to reason about it:**
Step 1: Check if train/test data comes from multiple sources. If yes, check: (1) Are sampling rates different? (2) Are protocols different? (3) Are label types different (strong vs weak)? Step 2: IF all yes → train separate models per dataset. Step 3: For unlabeled data in one dataset (e.g., defog notype), train a strong model on labeled defog data, predict on notype, use predictions as pseudo-labels, retrain. Step 4: Ensemble: if test set is mixed, blend models with optimized weights. If test set is single-source, use only that model or heavily weight it.
