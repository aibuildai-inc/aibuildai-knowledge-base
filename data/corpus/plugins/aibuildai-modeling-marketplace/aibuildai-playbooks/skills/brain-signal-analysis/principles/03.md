## Principle 3: Use Multi-Resolution Temporal Windows to Capture Both Context and Detail

*Consensus: Parkinson's FOG solutions train on short sequences (1000-5000 steps) but infer on long (15000-30000); several Melbourne seizure prediction solutions scored short epochs (20-30s) inside each 10-minute file, and one joined features from several epoch lengths.*

The window a model sees and the window a label covers are two separate choices. Short windows give many training samples and fit in memory; long windows give the model the context around an event. Recording-level labels can be predicted from many short epochs and then combined.

**Why this matters:** A FOG event's onset is clearer when the model sees the gait leading up to it, but training sequence models on very long sequences is slow and limits the batch size. One FOG solution trained on short sequences (1000 steps for one dataset, 5000 for the other) and inferred on much longer ones (5000 and 30000), and this emerged as one of its most useful choices. For seizure prediction, one 10-minute file carries one label; several Melbourne solutions cut it into non-overlapping 20- or 30-second epochs, scored each epoch, and took the maximum or the mean as the file's prediction. Epoch features see short-term detail; joining features from several epoch lengths adds longer context.

**When to use:** Use train-short-infer-long when: (1) sequences vary widely in length (FOG: 5k to 200k steps), (2) memory limits batch size on long sequences, (3) you can overlap predictions and blend (e.g., predict the center 50% of each window, shift by 50%). Use epoch scoring when one label covers a long recording and the evidence may sit in a short part of it.

**When NOT to use:** Do NOT infer on long sequences if your model was trained to predict only the center—retrain or use sliding windows. Do NOT pick max or mean aggregation by habit: max rewards one strong epoch, mean rewards a consistent pattern; compare both on CV.

**How to reason about it:**
Ask: (1) How long is the window one label covers? (2) How much surrounding signal does the model need to decide? (3) What window fits in memory with a useful batch size? For variable-length sequences: train on fixed short windows (reduces memory, allows larger batches, faster iteration), but during inference use the longest window that fits in memory and overlap predictions by 50% to avoid edge artifacts. For recording-level labels: score short epochs, aggregate per recording, and add features computed over longer epochs if CV improves.
