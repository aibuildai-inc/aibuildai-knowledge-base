## Principle 4: Formulate Ordinal Disease Grading as Regression, Not Classification

*Consensus: At least 10/15 prostate grading (PANDA) writeups used regression, binned or ordinal targets, or a kappa loss instead of plain classification; one team found SmoothL1 regression no better than binned BCE*

For diseases with ordered severity grades (diabetic retinopathy 0-4, prostate cancer Gleason scores), treat the problem as ordinal regression rather than multi-class classification. Use regression losses and bound predictions to valid grade range.

**Why this matters:** Grade 2 is closer to grade 3 than to grade 0, but standard cross-entropy treats all misclassifications equally. Ordinal formulation encodes this ordering, reducing severe misclassifications (grade 0 predicted as 4). It also produces continuous predictions that can be thresholded differently post-hoc.

**When to use:** When classes have a natural ordering and distances matter: cancer grades, disease severity stages, anatomical measurements. When evaluation metric is ordinal (quadratic weighted kappa) or when misclassifying adjacent grades is acceptable but distant grades are catastrophic.

**When NOT to use:** When classes are nominal (tissue types, organs, genetic subtypes) with no ordering. When you need calibrated probabilities for each class. When class boundaries are truly discrete (presence/absence, male/female).

**How to reason about it:**
Design output layer: Use a linear layer predicting n_classes-1 logits for binned targets ('is grade >= 1?', 'is grade >= 2?', etc.); the sum of their sigmoids gives a bounded [0, n_classes-1] prediction. Loss: BCE on the binned targets, a regression loss (MSE, logcosh) on the grade, or a kappa loss; compare them on validation QWK, and consider a regression head beside a classification head. Post-processing: Convert continuous predictions to discrete grades by thresholding (optimize thresholds on validation for kappa).

```python
# Ordinal formulation with binned targets
class OrdinalHead(nn.Module):
    def __init__(self, in_features, n_classes=5):
        super().__init__()
        # Predict n_classes-1 thresholds
        self.fc = nn.Linear(in_features, n_classes-1)
    
    def forward(self, x):
        logits = self.fc(x)  # [batch, 4] for 5 classes
        probs = torch.sigmoid(logits)  # P(grade >= k)
        return probs.sum(dim=1)  # Sum gives continuous [0, 4] prediction
```
