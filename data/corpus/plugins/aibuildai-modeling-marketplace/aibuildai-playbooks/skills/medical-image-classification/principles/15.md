## Principle 15: Integrate Metadata Carefully, or Skip It Entirely

*Consensus: 19/21 skin-lesion (ISIC 2024) writeups built GBDT or other tabular models on lesion and patient metadata, often with image-model predictions as extra features.*

Patient metadata (age, sex, anatomical site, image or acquisition metadata) can be incorporated via embeddings or concatenation to image features, or by stacking image-model predictions into a tabular model. However, metadata may not generalize across train/test distributions, so validate every version with and without it.

**Why this matters:** Metadata can provide diagnostic context (disease incidence varies by age and site). Relative features are often stronger than absolute ones: in skin-lesion screening, features that compare a lesion with the same patient's other lesions consistently improved CV and LB. But models can overfit to metadata distributions that differ between train and test, and simple concatenation is architecturally clean but may not be optimal.

**When to use:** When metadata is strongly predictive in clinical practice (age for certain cancers, anatomical site for lesions). When train/test metadata distributions are similar. When one patient contributes many images, so patient-relative features can be computed. Test with ablations - always train both with-metadata and without-metadata versions.

**When NOT to use:** When metadata distributions shift between train/test. When metadata has many missing values requiring imputation. When adding metadata doesn't improve CV. Default to no-metadata first, add only if it helps in validation.

**How to reason about it:**
Architecture: For a single end-to-end model, embed categorical metadata (sex, site) and standardize continuous metadata (age), then concatenate them to the final image feature vector before the classification head. For a two-stage design, train image models first, then feed their out-of-fold predictions and patient-relative features into a GBDT on the metadata. Missing values: use simple imputation, but beware this creates a spurious "imputed" cluster. Validation: compare image-only, metadata-only, and combined versions under the same patient-grouped folds. If metadata helps CV but hurts LB, suspect distribution shift. Leakage: never feed in-fold image predictions to the second stage.
