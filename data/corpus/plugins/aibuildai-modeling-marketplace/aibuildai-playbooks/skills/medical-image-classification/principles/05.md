## Principle 5: Build Stable Validation with Multi-Year Data When Test Set is Small

*Consensus: Skin-lesion (ISIC 2024) solutions pooled earlier ISIC releases for training, and one also used them for validation because validation loss on the competition data alone was unstable.*

Small medical imaging competitions have unstable public leaderboards because the test set holds few positive cases. Build validation from every comparable release of the data (earlier challenge years, the same task from another source), track a pooled score and a current-release score separately, and use repeated CV or larger ensembles to smooth variance.

**Why this matters:** A test set with few positives has random LB variance that can dwarf model differences. CV on the current release alone can be just as unstable when it also holds few positives. Pooling comparable releases increases the number of positives for metric estimation, and averaging over folds, seeds, and models removes per-model noise.

**When to use:** When public LB swings between similar models by more than the differences you are testing. When positive class prevalence is very low and absolute positive counts are small. When earlier releases of a similar challenge exist and can be pooled.

**When NOT to use:** When test set is large and stable. When distributional shift between releases is known and large (e.g., different imaging equipment, acquisition method, or populations). When only one release exists. When you have strong evidence that the current release is the only representative one; in that case pool the earlier releases for training but validate on the current release only, as some skin-lesion solutions did.

**How to reason about it:**
Combine all comparable releases for training, and decide deliberately whether validation also uses them. Use stratified GroupKFold on patient_id to prevent the same patient from appearing in train and validation. Track the pooled score and the current-release score separately: the pooled score is more stable, while the current-release score may better predict the private LB if the test set comes from that release. Select submissions that score well on both, not models optimized purely for public LB. To accept a small change, repeat CV with several seeds and test whether the gain is consistent; one skin-lesion solution ran CV 10 times with different seeds and used a paired t-test to decide.

```python
# Multi-release CV strategy
df_train = pd.concat([df_current, df_prior_releases])  # 'release' column marks the source

from sklearn.model_selection import StratifiedGroupKFold
sgkf = StratifiedGroupKFold(n_splits=5)

for fold, (train_idx, val_idx) in enumerate(
    sgkf.split(df_train, df_train['target'], df_train['patient_id'])
):
    val_all = df_train.iloc[val_idx]
    val_current = val_all[val_all['release'] == 'current']
    metrics = {
        'cv_pooled': score(val_all['target'], val_all['pred']),
        'cv_current': score(val_current['target'], val_current['pred']),
    }
    # cv_pooled is more stable for model selection
    # cv_current may better correlate with the private LB
```
