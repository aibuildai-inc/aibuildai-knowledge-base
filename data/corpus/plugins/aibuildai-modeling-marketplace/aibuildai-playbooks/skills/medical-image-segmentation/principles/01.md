## Principle 1: Choose Architecture Dimensionality Based on Data Structure and Test Constraints

*Consensus: In the 3D blood vessel competition the 1st place used 2.5D models after 3D models did not help; cryo-ET object identification solutions used 3D models*

For volumetric medical data, select between 2D slice-wise, 2.5D (multi-slice channels), or full 3D models based on target characteristics and inference constraints.

**Why this matters:** 2D/2.5D models train faster, require less memory, and often generalize better because they see more examples per epoch. Pure 3D models capture spatial context but risk overfitting on limited 3D volumes. The test set dimensions constrain your choice: if one axis has only 500 slices, high-resolution inference on that axis becomes infeasible.

**When to use:** Use 2.5D (3-5 adjacent slices as channels) when: (a) structures have minimal through-plane variation, (b) you have <10 3D volumes for training, (c) test constraints limit resolution on certain axes. Use pure 3D when: structures are truly 3D with complex topology across all axes AND you have sufficient 3D training volumes (>20).

**When NOT to use:** Avoid 2.5D if the target has strong 3D dependencies (e.g., branching vasculature where connectivity matters across many slices). Avoid pure 3D if training data is limited or test set axis lengths vary widely (causing resolution mismatches).

**How to reason about it:**
1. Count training volumes vs slices (100 volumes × 200 slices = 20k 2D examples vs 100 3D examples). 2. Check test set dimensions: if private test has one axis with <600 pixels and you train at 1024, you'll have severe resolution mismatch. 3. Inspect target topology: does it branch/connect across >5 slices? If yes, consider 3D. 4. Memory budget: can you fit 192³ crops with batch size >2? If no, 2.5D is safer.

```python
# 2.5D: stack adjacent slices as channels
def get_25d_input(volume, slice_idx, n_channels=3):
    pad = n_channels // 2
    slices = []
    for offset in range(-pad, pad + 1):
        idx = np.clip(slice_idx + offset, 0, len(volume) - 1)
        slices.append(volume[idx])
    return np.stack(slices, axis=0)  # Shape: (3, H, W)

# Multi-axis inference for 2.5D
def predict_3d_volume(model, volume):
    preds_x = [model(get_25d_input(volume, i, axis='x')) for i in range(volume.shape[0])]
    preds_y = [model(get_25d_input(volume, i, axis='y')) for i in range(volume.shape[1])]
    preds_z = [model(get_25d_input(volume, i, axis='z')) for i in range(volume.shape[2])]
    return (np.mean(preds_x, 0) + np.mean(preds_y, 0) + np.mean(preds_z, 0)) / 3
```
