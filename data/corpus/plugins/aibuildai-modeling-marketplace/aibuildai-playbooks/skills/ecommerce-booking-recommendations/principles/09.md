## Principle 9: Tune Candidate Count to Balance Recall and Computation

*Consensus: Top solutions generate 100-500 candidates; OTTO 1st uses 1200; 7th OTTO improves LB 0.595→0.598 by increasing 384→1024*

Generate enough candidates to capture 70-85% of true positives (recall@K), but not so many that the reranker drowns in negatives or exceeds memory. Empirically, 100-200 candidates suffices for most tasks; increase to 500-1000 if validation recall is <70%.

**Why this matters:** Too few candidates (<50) caps maximum possible performance — if true items aren't in the candidate set, the reranker can't recover them. Too many candidates (>1000) increases training time, memory usage, and noise (more hard negatives confuse the ranker). The optimal count depends on the diversity and quality of candidate sources.

**When to use:** Always measure recall@K for your candidate set before reranking. If recall@100 is <60%, generate more candidates. If recall@500 is >85% and recall@200 is >80%, use 200 to save computation.

**When NOT to use:** If a single candidate source (e.g., revisit) already achieves >90% recall@20, adding more candidates may not help. Focus on reranking quality instead.

**How to reason about it:**
Compute recall@K for K in [20, 50, 100, 200, 500] on validation. Plot recall vs K. Look for the 'knee' where recall growth slows (e.g., recall jumps 50%→70% from K=20→100, then 70%→75% from K=100→500). Choose K at the knee. Then measure reranker performance (e.g., MAP@K) vs K: if MAP plateaus at K=200, use that. If MAP keeps improving to K=500, compute and memory are the limiting factors — choose the largest K you can afford.

```python
# Measure recall@K for candidate set
def compute_recall_at_k(candidates_df, ground_truth_df, k_values=[20, 50, 100, 200, 500]):
    results = {}
    
    # Group candidates by user
    candidate_dict = (
        candidates_df
        .groupby('user_id')['item_id']
        .apply(list)
        .to_dict()
    )
    
    # Group ground truth by user
    truth_dict = (
        ground_truth_df
        .groupby('user_id')['item_id']
        .apply(set)
        .to_dict()
    )
    
    for k in k_values:
        recalls = []
        for user_id, true_items in truth_dict.items():
            cands = candidate_dict.get(user_id, [])[:k]
            n_hit = len(set(cands) & true_items)
            recall = n_hit / len(true_items) if len(true_items) > 0 else 0
            recalls.append(recall)
        
        results[k] = np.mean(recalls)
        print(f'Recall@{k}: {results[k]:.4f}')
    
    return results
```
