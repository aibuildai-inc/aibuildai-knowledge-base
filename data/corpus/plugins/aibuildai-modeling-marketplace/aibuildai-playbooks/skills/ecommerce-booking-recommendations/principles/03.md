## Principle 3: Apply Strong Recency and Trending Weights to Items

*Consensus: Several top OTTO solutions weight a session's history and its co-visitation counts by recency and action type; one added weekly count trends as features, and another found that trending-item derivatives did not help.*

What a user did most recently says the most about what they will do next. Weight the items in a user's history, and the co-visitation counts built from them, so that later actions and stronger action types (cart, order) count more than earlier clicks. Item-level trend features can add to this, but test them.

**Why this matters:** In the OTTO solutions, candidate scores from a session's history were summed with weights that fall with the item's position from the end of the session, and co-visitation matrices were built in time-weighted and type-weighted variants next to plain counts. A model that treats a click from the start of a session like a cart from its last minute blurs the user's current intent. Item-level trends are less reliable: one team used weekly changes in click, cart, and order counts as features, while another tried trending-item derivatives and found no gain.

**When to use:** Always when interactions have timestamps and the next action is the target. Build at least one time-weighted and one type-weighted variant of each co-visitation source, and let the reranker combine them. Add trend features when item popularity visibly shifts within the training period.

**When NOT to use:** Do NOT add time weighting where nearly all interactions fall in a very short span: one OTTO solution skipped it in its similarity weights because most interactions were within an hour. Do NOT keep trend features that do not improve CV.

**How to reason about it:**
Order each user's history by time. Give each item a weight that decreases with its distance from the last action (for example 1 / rank from the end, or a log-spaced weight), multiplied by an action-type weight. Build co-visitation counts with the same weights. Compare recall of the weighted and unweighted candidate sources on validation, and keep the variants that add unique candidates. Then test weekly trend features in the reranker.

```python
import numpy as np

TYPE_WEIGHT = {'clicks': 1.0, 'carts': 3.0, 'orders': 6.0}  # tune on validation recall

def history_scores(session_events, covisit):
    events = session_events.sort_values('ts', ascending=False)
    scores = {}
    for idx1, (aid, typ) in enumerate(zip(events['aid'], events['type']), start=1):
        for idx2, cand in enumerate(covisit.get(aid, []), start=1):
            scores[cand] = scores.get(cand, 0.0) + TYPE_WEIGHT[typ] / idx1 / idx2
    return sorted(scores, key=scores.get, reverse=True)

def weekly_trend(events, t_end, week_s):
    this_week = events[(events['ts'] >= t_end - week_s) & (events['ts'] < t_end)].groupby('aid').size()
    last_week = events[(events['ts'] >= t_end - 2 * week_s) & (events['ts'] < t_end - week_s)].groupby('aid').size()
    return (this_week / (last_week + 1)).fillna(0)
```
