## Principle 10: Handle Cold-Start Users with Popularity Fallbacks

*Consensus: Top OTTO solutions build dedicated candidate sources for cold-start sessions (first-interaction pairing) and fall back to popularity-based candidates*

A user with little history still has something to start from: the first item they touched. Build a candidate source that pairs items using only each user's first interaction, and fill any list that comes out short with popular items, first within the relevant category and then globally.

**Why this matters:** Co-visitation candidates come from a user's history, so a user with one or two events gets a short list and few interaction features. The OTTO 3rd-place solution built dedicated co-visitation matrices for cold-start sessions: it took sessions that started late in the training period and paired items using only each session's first history item, with separate variants for any action to carts or orders and for all action types. In an acm-sf solution, when the kNN step returned fewer than 5 items, the list was extended with the most popular items in the query's category, then the most popular items for the query, then the globally most popular items. A short list scores lower at every cutoff, and these sources fill it with the most likely items.

**When to use:** When a noticeable share of validation users or sessions have only a few events, or when the main candidate sources return fewer candidates than the cutoff the metric uses. Measure: how many validation users get a full candidate list from the main sources?

**When NOT to use:** When nearly every user already gets a full list from history-based sources, a fallback adds candidates the reranker must score for little gain. Focus on improving recall for active users instead.

**How to reason about it:**
Group validation users by history length (1 event, 2-5 events, more) and measure recall of each candidate source per group. For short histories, compare: (a) first-item co-visitation pairs, (b) popular items within the category of the first interaction, (c) global popularity, (d) no fill. Keep the sources that raise recall for the short-history groups, and give the reranker a feature that says which source produced each candidate.

```python
def first_item_pairs(train_events, min_start_ts):
    # Sessions that start late in the training period behave like new users
    start = train_events.groupby('session')['ts'].transform('min')
    new = train_events[start > min_start_ts]
    first = new[new.groupby('session').cumcount() == 0][['session', 'aid']]
    later = new[new['type'].isin(['carts', 'orders'])][['session', 'aid']]
    pairs = first.merge(later, on='session', suffixes=('', '_next'))
    pairs = pairs[pairs['aid'] != pairs['aid_next']]
    return pairs.groupby('aid')['aid_next'].value_counts()  # top-N per first item

def fill_short_list(candidates, first_category, category_popularity, global_popularity, k):
    for pool in (category_popularity.get(first_category, []), global_popularity):
        for item in pool:
            if len(candidates) >= k:
                return candidates
            if item not in candidates:
                candidates.append(item)
    return candidates
```
