## Principle 4: Create User-Item Interaction Features Across Multiple Time Windows

*Consensus: Several top OTTO solutions built session-item interaction features (counts per action type, time since the last action, last action type) and item counts over several recent windows (11th: 1-day and 3-day windows; 7th: last 1-7 days and last 1-4 weeks); another turned co-visitation counts into one interaction feature per candidate pair (3rd).*

For each user-item candidate pair, compute how the user interacted with that item (how many clicks, carts, and orders; how long ago the last one was; what the last action was) and how popular the item was over several recent windows. These features capture both the user's current intent and the item's recent momentum.

**Why this matters:** A user who carted an item a few minutes ago is far more likely to order it than a user who clicked it once long ago, and the reranker can only learn that difference if the features carry counts per action type and time since the last action. Item counts over several windows let the model separate items that are trending now from items that are steadily popular. In the OTTO solutions these pair-level features sit next to candidate-generation scores (co-visitation counts, embedding similarity) as the reranker's main inputs.

**When to use:** Always for reranking when interactions carry types (view, cart, order) and timestamps. Use several window lengths when popularity changes on a timescale shorter than the training period.

**When NOT to use:** If the data has no repeated user-item interactions (for example one-time event bookings), pair-level counts are almost always zero. Use item-level and similarity-based features instead.

**How to reason about it:**
For each candidate pair, compute per action type: count, time since the last action, and the type of the last action. For each item, compute counts per action type over several windows ending at the prediction time (for example the last day, the last few days, the last few weeks). Fill missing pairs with 0 and a large time gap. Check feature importance: if short-window features rank higher than long-window ones, the task is recency-driven, and shorter windows or stronger recency weighting may help.

```python
import pandas as pd

def pair_features(candidates, events, t_end):
    past = events[events['ts'] < t_end]
    g = past.groupby(['session', 'aid'])
    pair = pd.DataFrame({
        'n_clicks': g['type'].apply(lambda s: (s == 'clicks').sum()),
        'n_carts': g['type'].apply(lambda s: (s == 'carts').sum()),
        'n_orders': g['type'].apply(lambda s: (s == 'orders').sum()),
        'secs_since_last': t_end - g['ts'].max(),
        'last_type': g['type'].last(),
    }).reset_index()
    return candidates.merge(pair, on=['session', 'aid'], how='left')

def item_window_counts(candidates, events, t_end, windows_s):
    out = candidates
    for w in windows_s:
        recent = events[(events['ts'] >= t_end - w) & (events['ts'] < t_end)]
        counts = recent.groupby(['aid', 'type']).size().unstack(fill_value=0).add_suffix(f'_{w}s').reset_index()
        out = out.merge(counts, on='aid', how='left')
    return out.fillna(0)
```
