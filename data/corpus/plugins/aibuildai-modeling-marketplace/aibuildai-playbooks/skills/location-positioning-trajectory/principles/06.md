## Principle 6: Align Training Data Distribution to Test via Filtering and Sampling

*Consensus: 4/4 Lyft solutions, 2/2 indoor navigation solutions that discussed validation*

Match training dataset filters to the test set's known constraints: min/max history frames, sensor availability, trajectory length, device type. For validation, use the same sampling procedure that generated the test set (temporal cutoff, trajectory chopping).

**Why this matters:** Default training sets are artificially clean (full history, complete sensors). Test sets have missing data, variable history, and edge cases. Training on mismatched data causes models to overfit to artificial patterns. Lyft: setting min_history=0 (not 10) jumped the score from 15.9 to 13.0.

**When to use:** Always. Every competition has implicit or explicit test set filters. Indoor navigation: OPPO phones only, no NaN in key sensors, trajectory length >60s. Lyft: min_future=10, variable history. NFL: specific event sequences (snap→pass→arrival).

**When NOT to use:** If the test set is truly random and unfiltered (rare), don't add artificial filters. But verify this—most hosts apply quality filters for evaluation stability.

**How to reason about it:**
Study the test set metadata (if provided) or infer from sample submission shape. What's the min/max trajectory length? Which sensors are always/never present? Are there device/phone filters? Replicate these in training. For validation, use temporal splits or trajectory chopping (not random splits) to match the test generation process. Verify CV/LB correlation.
