## Principle 7: Engineer Relative Motion Features for Trajectory Prediction

*Consensus: 3/3 indoor navigation sensor models, 2/2 NFL trajectory solutions*

Predict displacements, velocities, and accelerations in ego-centric or segment-relative coordinates rather than absolute positions. For sensor-based motion, decompose into distance (magnitude) and angle (direction) and model separately.

**Why this matters:** Absolute coordinates have large dynamic range and no translation invariance. Relative features are smaller, more stationary, and robust to calibration errors. Indoor navigation: predicting segment-to-segment angle change handles phone rotation bias better than absolute angle. NFL: velocity decomposition (vx, vy) improves over speed + direction.

**When to use:** Trajectory prediction with sensor data (IMU, gyro, accelerometer). Relative motion is more reliable than absolute when: (a) sensors drift or have bias, (b) coordinate systems vary (phone orientation), (c) you need translation invariance.

**When NOT to use:** Absolute positioning tasks (check-ins, location matching) need absolute coordinates. If your sensors are well-calibrated and drift-free (rare), absolute modeling can work. Hybrid tasks need both—relative for interpolation, absolute for anchoring.

**How to reason about it:**
What's noisier—absolute position or relative displacement? For IMU sensors, relative is cleaner. Predict delta_x, delta_y between waypoints, then integrate. For orientation drift, predict angle change relative to previous segment, not absolute compass angle. Model distance and direction separately if their errors are independent (often true—distance from speed integration, angle from gyro).

```python
# Relative motion features for indoor navigation
# Instead of predicting absolute (x_t, y_t):
# Predict relative displacement
delta_x = x[t] - x[t-1]
delta_y = y[t] - y[t-1]

# Or segment-relative (handles rotation bias)
seg_AB = [x[t-1] - x[t-2], y[t-1] - y[t-2]]
seg_BC = [x[t] - x[t-1], y[t] - y[t-1]]
# Predict BC in coordinate system where AB is along x-axis
angle_AB = atan2(seg_AB[1], seg_AB[0])
BC_rotated = rotate(seg_BC, -angle_AB)  # rotation-invariant

# Separate distance and direction models
dist_model.fit(sensor_data, euclidean_distance(seg))
angle_model.fit(magnetometer_data, angle_change(seg))
```
