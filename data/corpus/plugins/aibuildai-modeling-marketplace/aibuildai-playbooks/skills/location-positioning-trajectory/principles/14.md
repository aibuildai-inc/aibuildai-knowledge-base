## Principle 14: Validate on Temporally Split or Chopped Trajectories, Not Random Splits

*Consensus: 3/3 Lyft solutions, 2/2 indoor navigation solutions that discussed validation*

Create validation sets by temporal cutoff (before/after a date) or trajectory chopping (truncate trajectories at a random timestamp) to match how the test set was generated. Avoid random row-level splits.

**Why this matters:** Random splits leak future information (same trajectory in train/val) and don't test generalization to new time periods or partial trajectories. Test sets are typically future dates or chopped trajectories. Proper validation had near-perfect CV/LB correlation (±0.1 for Lyft).

**When to use:** Always for trajectory prediction. Temporal splits when data has time trends (traffic patterns, seasonal effects). Trajectory chopping when test set is generated by truncating at a random timestamp (Lyft, indoor navigation).

**When NOT to use:** Static datasets with no temporal structure (image classification, check-ins without time dependence). If the test set is truly random, random validation works—but verify this assumption.

**How to reason about it:**
How was the test set created? Time cutoff → temporal validation split. Trajectory truncation → chop validation trajectories at the same procedure. Example: Lyft uses `create_chopped_dataset` to truncate at random timestamps—replicate this for validation. Indoor: filter validation to match test criteria (device type, sensor availability, trajectory length). Monitor CV/LB correlation—should be within ±0.2 for stable validation.

```python
# Validation via trajectory chopping (Lyft-style)
def create_chopped_validation(trajectories, min_history=0, min_future=10):
    val_data = []
    for traj in trajectories:
        if len(traj) < min_future:
            continue
        # Random chop point with at least min_future remaining
        chop_idx = random.randint(min_history, len(traj) - min_future)
        val_data.append({
            'history': traj[:chop_idx],
            'future': traj[chop_idx:chop_idx + min_future],
            'mask': agents_mask[chop_idx:chop_idx + min_future]
        })
    return val_data
```
