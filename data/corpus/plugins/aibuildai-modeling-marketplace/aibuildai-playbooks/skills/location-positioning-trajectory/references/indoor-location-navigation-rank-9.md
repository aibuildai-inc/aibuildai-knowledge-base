## Wifi models (floor and absolute position)

My wifi model is CNN. Divide ±10 seconds into 5 sections and create (1, 5, rssi) images as input feature.

+ Adding ibeacon's rssi in input features.
+ Site specific models.
+ Use compute_step_positions of host code for data augmentation.
+ Use StratifiedGroupKFold (label=floor, group=path) for both floor and position models.
+ Error estimation based on variance between different models (including public notebooks).
+ My wifi model's performance is poor compared to the models discussed [here](https://www.kaggle.com/c/indoor-location-navigation/discussion/232995). (CV/LB : 7.1 to 7.3) But relatively small gap between CV, public LB and private LB.
+ Thank you very much @higepon for this part.

## Sensor models (relative position)

I also created sensor RNN model. This may be an attempt that many participants have not made.

+ Apply anti-aliasing filter to sensor data and resample them to sampling rate 0.1 seconds to reduce data.
+ Try LSTM and GRU and ensemble them.
+ Error estimation based on ensemble variance.
+ Calibrate scale and rotation for each device using device leak. This boosts public/private LB 0.03m.
+ Adding uncalibrated data didn't work for my model.

## Post-processing

+ My cost minimization notebook is equivalent to Kalman smoother (See [this notebook](https://www.kaggle.com/saitodevel01/background-ideas-of-cost-minimization-notebook) for detail).
+ Parameters of cost function are determined by error estimation of wifi and sensor models.
+ Heuristics that gradually replace wifi predictions with nearest neighbor grid points.
+ Use additional grid points generated by [this code](https://www.kaggle.com/saitodevel01/generate-extra-grid-points).
