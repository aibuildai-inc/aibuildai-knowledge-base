## Principle 8: Apply Domain-Specific Augmentations Carefully with Physical Validity

*Consensus: 5/10 waveform inversion solutions used domain-specific augmentation to preserve physical validity.*

Augmentation must respect physics. For seismic images, horizontal flip is valid only if you account for source position shifts. For signals, adding calibrated noise is valid but arbitrary scaling/rotation is not. Validate that augmented samples are physically plausible before training.

**Why this matters:** Naive augmentation breaks physical constraints. Flipping a seismic image shifts the source from position 34 to 35 (not symmetric), creating inconsistent training signals. Rotating a gravity-dependent image violates physics, since subsurface structure follows a fixed orientation relative to gravity. Valid augmentations improve generalization; invalid ones add noise and hurt performance.

**When to use:** For image tasks: use flips/crops/brightness ONLY if the target is invariant to that transform. For geophysics: horizontal flip OK if you also flip the source position symmetrically. For time-series: add noise matching sensor characteristics, but don't arbitrarily scale (changes physics). Always test on validation data - if augmentation degrades val score, it's breaking something.

**When NOT to use:** Don't augment when: (1) physical constraints are complex and you don't understand them (better to skip than break), (2) you already have >100k samples (diminishing returns), (3) test-time augmentation (TTA) already gives you the diversity you need. For earthquake time-series, top solutions did NOT augment heavily - the temporal structure is critical.

**How to reason about it:**
**For seismic images (image-to-image)**: 1. Horizontal flip: YES, but account for source position (add extra channel or retrain). 2. Vertical flip: NO (gravity direction is absolute). 3. Random crop: YES if crop includes full context. 4. Rotation: NO (breaks coordinate system). **For seismic time-series (regression)**: 1. Add Gaussian noise (σ=0.5): YES (simulates measurement noise). 2. Subtract segment median: YES (removes baseline drift). 3. Time-stretch: MAYBE (changes frequency content, only if you understand implications). 4. Flip in time: NO (causality matters). **For waveform inversion**: 1. Symmetric flip: YES if you simulate flipped source too. 2. Scaling augmentation: YES (equivalent to different source frequencies). 3. Random affine: LIMITED (small rotations/translations OK, but check forward model still valid).

```python
import numpy as np
from scipy.ndimage import rotate

# Valid augmentation for an image-to-image seismic task
def augment_seismic_image(image, target):
    # 1. Horizontal flip - VALID (target structure is symmetric)
    if np.random.rand() > 0.5:
        image = np.fliplr(image)
        target = np.fliplr(target)
    
    # 2. Vertical flip - INVALID (gravity direction is absolute)
    # DO NOT: image = np.flipud(image)  # This breaks physics!
    
    # 3. Pad to a size the network accepts, avoiding boundary artifacts - VALID
    ph, pw = (-image.shape[0]) % 32, (-image.shape[1]) % 32
    pad = ((ph // 2, ph - ph // 2), (pw // 2, pw - pw // 2))
    image = np.pad(image, pad, mode='reflect')
    target = np.pad(target, pad, mode='reflect')
    
    return image, target

# Valid augmentation for waveform inversion
def augment_velocity_model(velocity, source_pos=34):
    # Symmetric flip ONLY if we also flip the source
    if np.random.rand() > 0.5:
        velocity = np.fliplr(velocity)
        # CRITICAL: Update source position symmetrically
        source_pos = 69 - source_pos  # If original at 34, flipped is at 35
        # Must retrain forward model with new source or use 6 source positions
    
    return velocity, source_pos
```
