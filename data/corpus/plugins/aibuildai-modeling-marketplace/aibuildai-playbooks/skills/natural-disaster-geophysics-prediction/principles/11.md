## Principle 11: Validate with Target Distribution Matching, Not Just Metric Scores

*Consensus: 4/15 earthquake solutions (1st/2nd/12th/15th explicitly compared prediction distributions)*

Beyond achieving a good CV score, check that your out-of-fold prediction distribution matches the training target distribution (KS test p >0.1). If test predictions look radically different, your model has learned spurious patterns. Adjust model complexity or post-process to align distributions.

**Why this matters:** A model can achieve low MAE on validation but still fail on test if it systematically under/over-predicts certain ranges. In earthquake prediction, models trained on all cycles consistently underestimate long earthquakes and overestimate short ones, even with good CV MAE. Matching distributions ensures the model hasn't latched onto a subset pattern.

**When to use:** When: (1) you have a continuous target with known distribution shape (e.g., uniform from 0 to max_duration for earthquakes), (2) CV score is good but public LB is poor, (3) you've subsampled training data and need to verify test will match. Particularly important for time-series regression where temporal sampling can create artificial patterns.

**When NOT to use:** Skip for: (1) classification (distribution is determined by class balance, not model), (2) segmentation (pixel distributions are less informative), (3) when you have no prior knowledge of test distribution shape. Don't over-constrain - if test distribution genuinely differs (e.g., more extreme events), forcing a match hurts.

**How to reason about it:**
1. **Train model**: Get out-of-fold predictions on your validation set. 2. **Plot distributions**: Histogram of OOF predictions vs. training targets. They should roughly overlap (same shape, similar mean/variance). 3. **KS test**: `ks_2samp(oof_predictions, train_targets)`. If p-value <0.05, distributions differ significantly → problem. 4. **Diagnose**: If predictions are too narrow (lower variance), model is under-confident → reduce regularization. If predictions are shifted (different mean), model has systematic bias → check for leaked features or target scaling issues. 5. **Post-process**: If model is well-calibrated on OOF but you know test should have mean=6.5, you can shift predictions to match (risky - only if you have strong external evidence). 6. **Iterate**: Retrain with different feature sets or data sampling until OOF distribution matches train.

```python
import numpy as np
import matplotlib.pyplot as plt
from scipy.stats import ks_2samp

# Assume we have OOF predictions from CV
oof_predictions = []  # Collect out-of-fold predictions
train_targets = []    # Corresponding true targets

for fold in cv_folds:
    model.fit(train[fold.train_idx], targets[fold.train_idx])
    oof_pred = model.predict(train[fold.val_idx])
    oof_predictions.extend(oof_pred)
    train_targets.extend(targets[fold.val_idx])

oof_predictions = np.array(oof_predictions)
train_targets = np.array(train_targets)

# 1. Visual check: plot distributions
plt.hist(train_targets, bins=50, alpha=0.5, label='Train Targets', density=True)
plt.hist(oof_predictions, bins=50, alpha=0.5, label='OOF Predictions', density=True)
plt.legend()
plt.title('Distribution Comparison: Train vs. OOF')
plt.show()

# 2. Statistical test: KS test
ks_stat, p_value = ks_2samp(oof_predictions, train_targets)
print(f"KS statistic: {ks_stat:.4f}, p-value: {p_value:.4f}")

if p_value < 0.05:
    print("WARNING: OOF distribution differs from train (p < 0.05)")
    print(f"Train mean={train_targets.mean():.2f}, std={train_targets.std():.2f}")
    print(f"OOF mean={oof_predictions.mean():.2f}, std={oof_predictions.std():.2f}")
else:
    print("OK: OOF distribution matches train (p > 0.05)")
```
