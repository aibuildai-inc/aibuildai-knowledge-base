## Principle 3: Engineer Features from Multiple Signal Representations

*Consensus: 12/15 earthquake solutions, 2/2 rainfall solutions*

Raw sensor data is rarely the optimal input. Transform signals into multiple representations (time domain, frequency domain, time-frequency, wavelet decomposition) and extract features from each. The best features often come from filtered or decomposed versions of the signal.

**Why this matters:** Physical processes emit signatures across different scales. Earthquake precursors appear in both high-frequency micro-fractures and low-frequency stress accumulation. A single representation misses information; combining statistical features from multiple scales captures the full physics.

**When to use:** For any task with continuous sensor signals: seismic data, radar, weather sensors. Essential when the raw signal is high-dimensional (150k points) but the target is low-dimensional (scalar time-to-failure). Most valuable when you have domain knowledge about what frequencies/scales matter (but even without it, systematic exploration helps).

**When NOT to use:** Skip for: (1) image tasks where raw pixels or spectrograms are sufficient, (2) tasks where a deep model can learn representations end-to-end and you have >100k samples per class, (3) tabular data that's already pre-processed features.

**How to reason about it:**
1. **Time domain**: Basic statistics (mean, std, min, max, quantiles), peak counts at different thresholds, kurtosis, skewness. 2. **Frequency domain**: FFT → bin power spectrum into 10-20 bands, extract mean/max per band. Mel-frequency cepstral coefficients (MFCC) if signal is acoustic. 3. **Time-frequency**: Spectral centroid, spectral rolloff, zero-crossing rate. 4. **Wavelet decomposition**: Decompose signal at multiple levels (e.g., 5 levels), extract statistics from each level's coefficients. Try different wavelets (db4, sym5, coif3). 5. **Filtered signals**: Apply bandpass filters (Butterworth) at different cutoffs, extract features from filtered signal. 6. **Rolling statistics**: Compute std/mean over sliding windows, then take percentiles of the rolling values. 7. **Feature selection**: Use permutation importance or adversarial validation to keep only features with train-test KS p > 0.05.

```python
import librosa
import pywt
from scipy import signal as scipy_signal
import numpy as np

def extract_multi_representation_features(acoustic_signal):
    features = {}
    
    # 1. Time domain: basic stats
    features['std'] = np.std(acoustic_signal)
    features['percentile_95_05'] = np.percentile(acoustic_signal, 95) - np.percentile(acoustic_signal, 5)
    
    # 2. Frequency domain: MFCC (pretend signal is 40kHz for scale)
    mfcc = librosa.feature.mfcc(y=acoustic_signal.astype(float), sr=40000, n_mfcc=20)
    for i in [4, 7, 18]:  # Select informative coefficients
        features[f'mfcc_{i}_mean'] = np.mean(mfcc[i])
    
    # 3. Wavelet decomposition
    coeffs = pywt.wavedec(acoustic_signal, 'db4', level=5)
    for level, coeff in enumerate(coeffs):
        features[f'wavelet_db4_level{level}_std'] = np.std(coeff)
    
    # 4. Filtered signal: high-pass to remove drift
    b, a = scipy_signal.butter(4, 0.01, btype='high')
    filtered = scipy_signal.filtfilt(b, a, acoustic_signal)
    features['filtered_high_std'] = np.std(filtered)
    
    # 5. Peak-based: count peaks above threshold
    peaks, _ = scipy_signal.find_peaks(acoustic_signal, height=50)
    features['peak_count_50'] = len(peaks)
    
    return features
```
