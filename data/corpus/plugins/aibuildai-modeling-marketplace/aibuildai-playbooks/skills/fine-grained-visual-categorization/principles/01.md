## Principle 1: Choose Architecture Based on Task Type: Individual ID vs Species Classification

*Consensus: Both individual identification competitions (Happy Whale, Humpback) are dominated by metric learning (ArcFace, CosFace, triplet, or siamese losses in 22 of their 29 writeups); species and category tasks mostly use softmax.*

Individual identification tasks (re-identifying the same individual across images) require metric learning with embedding-based retrieval, while species/category classification uses standard softmax with cross-entropy loss.

**Why this matters:** Individual ID has an open-set problem where test individuals may not exist in training, requiring distance-based matching. Species classification is closed-set where all test categories are in training. Using softmax for individual ID fails on new individuals; using pure metric learning for species classification underutilizes class supervision.

**When to use:** Use metric learning (ArcFace, CosFace) when: (1) task requires identifying specific individuals, (2) test set contains individuals not in training ('new_individual' prediction required), (3) number of instances per class is highly variable. Use classification when: (1) all test categories are in training, (2) task is species/cultivar/object-type recognition, (3) multiple images can belong to the same category.

**When NOT to use:** Do not force metric learning onto balanced species classification (overhead without benefit). Do not use pure softmax for individual ID without handling the new-individual case (several early solutions failed this way).

**How to reason about it:**
Check the evaluation metric and test set structure. If the metric is MAP@K or requires predicting 'new_individual', you need metric learning + k-NN retrieval. If it's accuracy/F1 over a fixed category set, use classification. When uncertain, read the data description: does each class represent a unique individual or a category?

# Metric learning head for individual ID
class ArcFaceHead(nn.Module):
    def __init__(self, in_features, n_classes, s=30, m=0.3):
        super().__init__()
        self.s = s  # scale
        self.m = m  # margin
        self.weight = nn.Parameter(torch.FloatTensor(n_classes, in_features))
        nn.init.xavier_uniform_(self.weight)
    
    def forward(self, embeddings, labels):
        # Normalize
        embeddings = F.normalize(embeddings)
        weights = F.normalize(self.weight)
        # Cosine similarity
        cosine = F.linear(embeddings, weights)
        # Add margin to target class
        theta = torch.acos(torch.clamp(cosine, -1, 1))
        target_logits = torch.cos(theta + self.m)
        # Scale and return
        return self.s * torch.where(one_hot_labels, target_logits, cosine)

def predict_with_knn(query_embeddings, train_embeddings, train_labels, k=5):
    # Cosine similarity
    similarities = query_embeddings @ train_embeddings.T
    top_k_indices = similarities.topk(k, dim=1).indices
    # Aggregate by class, return top predictions
