## Principle 9: Exploit Dataset Constraints with Post-Processing Rules

*Consensus: 1st place Humpback rebalanced its top-5 predictions toward classes unused as top-1 (+0.001 to 0.002); constraint- and balance-based post-processing can give small gains.*

Competition organizers often state dataset constraints: 'each class has at least 1 test sample', 'max N samples per class', 'class counts follow the training distribution'. Use these as hard constraints in post-processing to correct low-confidence predictions.

**Why this matters:** If the organizer states 'every class appears at least once', then predicting zero samples for a class is provably suboptimal. Similarly, if max samples per class is N, predicting more than N for a class wastes predictions. Even without a stated constraint, predictions that over-use a few frequent classes can be rebalanced: 1st place Humpback gained +0.001 to 0.002 this way.

**When to use:** Use when: (1) the competition overview or data description states constraints, (2) the constraint is enforceable (e.g., class counts, not 'images are high quality'), (3) you have a way to verify the constraint on public LB (submit and check). Common constraints: minimum samples per class, maximum samples per class, known species distribution.

**When NOT to use:** Do not fabricate constraints from assumptions (e.g., 'classes should be balanced' when they are not). Do not apply constraints that contradict your validation set (if validation violates the constraint, it is not a true constraint). Do not over-engineer complex post-processing (diminishing returns; spend time on better models).

**How to reason about it:**
Read the competition overview and data description for constraint statements. Examples: if the test set caps samples per class, reassign the lowest-confidence predictions of a class that exceeds the cap. 1st place Humpback noticed that scores correlated with how many labels were used, so it swapped the top-1 and top-2 classes when their confidences differed by <0.3, the top-2 class was never used as a top-1 prediction, and the top-1 class was used often as a top-2 prediction. Implement the constraint as a rule: (1) collect all predictions, (2) check constraint violations, (3) reassign violated predictions to the next-best class that satisfies the constraint. Validate on a held-out set first.

```python
# Example: enforce a 'max N samples per class' constraint (N = max_per_class)
predictions = model.predict(test_loader)  # (N, n_classes)
top1_classes, top1_probs = predictions.max(dim=1)
top2_classes = predictions.topk(2, dim=1).indices[:, 1]  # second-best class

class_counts = torch.bincount(top1_classes, minlength=n_classes)

# For each class exceeding the limit, reassign lowest-confidence samples
for cls in range(n_classes):
    if class_counts[cls] > max_per_class:
        # Find samples predicted as cls
        cls_mask = top1_classes == cls
        cls_indices = torch.where(cls_mask)[0]
        cls_probs = top1_probs[cls_mask]
        
        # Sort by confidence, reassign the least confident (count - N) samples
        n_to_reassign = class_counts[cls] - max_per_class
        least_confident_indices = cls_indices[cls_probs.argsort()[:n_to_reassign]]
        
        # Reassign to top-2 class
        top1_classes[least_confident_indices] = top2_classes[least_confident_indices]

# Example: enforce 'every class appears at least once'
for cls in range(n_classes):
    if class_counts[cls] == 0:
        # Find the sample with highest probability for this class across all top-5 predictions
        top5_preds = predictions.topk(5, dim=1)
        cls_scores = predictions[:, cls]
        best_sample = cls_scores.argmax()
        # Reassign this sample to cls
        top1_classes[best_sample] = cls
```
