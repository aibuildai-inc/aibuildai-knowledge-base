## Principle 11: Scale Resolution, Model Size, and Data in Stages

*Consensus: 5/6 top waveform solutions used very large synthetic corpora or progressive resolution.*

Start with a configuration that turns over experiments quickly, then continue training at higher resolution, on harder regimes, or with more and more faithful synthetic data. Scale only while validation indicates underfitting and the pipeline remains stable.

**Why this matters:** Early low-cost stages learn broad structure; later stages spend compute on fine boundaries or rare regimes. Progressive scaling reuses weights and avoids paying maximum cost while optimization is still far from a useful basin.

**When to use:** Use when higher resolution or input size gives consistent conditional gains, the model is still underfitting, and data volume is sufficient.

**When NOT to use:** Do not assume bigger is always better. The first-place waveform solution found larger variants overfit in one architecture, and feature ideas that help small models can lose importance at scale. Stop when gains are smaller than variance, inference cost, or domain-gap risk.

**How to reason about it:**
Construct a scaling ladder over data volume, model size, and resolution. Change one axis at a time, record gain per compute unit, and promote only stages that improve both overall and hard-stratum validation.

```python
stages = [
    # Customize values to the task and hardware.
    {"resolution_scale": 1, "data_fraction": 0.25, "lr": base_lr},
    {"resolution_scale": 2, "data_fraction": 1.00, "lr": base_lr / 5},
    {"resolution_scale": 4, "hard_strata_only": True, "lr": base_lr / 25},
]
for cfg in stages:
    model = continue_training(model, cfg)
    if not robust_validation_gain(model):
```
