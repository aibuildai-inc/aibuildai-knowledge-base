## Principle 10: Engineer Throughput Around Information Density, Not Nominal Tensor Size

*Consensus: 6/6 top waveform solutions depended on large-scale simulation or long training.*

Make data access, simulation, and inference efficient before large hyperparameter searches. Store generated pairs compactly, batch and compile the forward operator when it is on the critical path, and avoid spending compute on padding or repeated parsing.

**Why this matters:** Scientific pipelines often waste more compute on repeated parsing, padding, and simulation overhead than on useful learning. Compiled and custom GPU forward operators changed waveform simulation from impractical to central: the 1st-place solution reported that compiling its forward model raised generation from unusable speed to thousands of samples per minute per GPU, and other solutions stored generated inputs in half precision to fit far more training pairs.

**When to use:** Use for large generated corpora, expensive simulators, variable-size inputs, or multi-stage inference. Profile end-to-end utilization rather than model FLOPs alone.

**When NOT to use:** Do not reduce storage precision without checking that it does not change the signal the model relies on. Avoid elaborate kernels before profiling confirms the operator is the bottleneck.

**How to reason about it:**
Measure time in loading, preprocessing, simulation, forward/backward, and padding. Optimize the largest term. For synthetic generation, batch and compile the simulator before distributing jobs; for variable-size inputs, group examples of similar size into the same batch.

```python
import time

def profile_pipeline(steps, n_iters=20):
    totals = {name: 0.0 for name, _ in steps}
    for _ in range(n_iters):
        for name, fn in steps:
            start = time.perf_counter()
            fn()
            totals[name] += time.perf_counter() - start
    return sorted(totals.items(), key=lambda kv: -kv[1])  # optimize the top entry first
```
