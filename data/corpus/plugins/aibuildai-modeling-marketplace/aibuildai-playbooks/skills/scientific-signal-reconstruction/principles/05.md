## Principle 5: Introduce Specialists Only for Observable Physical Regimes

*Consensus: 5/15 waveform writeups explicitly routed by data family.*

If different regimes have genuinely different latent structure, priors, noise, or optimal models, train a router and use regime-specific sampling, heads, priors, or post-processing. The routing feature must be observable at inference and validated out of sample.

**Why this matters:** A single compromise model can waste capacity averaging incompatible inverse mappings. Waveform families ranged from nearly one-dimensional layered fields to textured style fields, each with different latent structure and noise characteristics.

**When to use:** Use when per-stratum residual analysis shows large, stable performance differences and the regime can be inferred reliably without target leakage. Soft routing is preferable when family boundaries are ambiguous.

**When NOT to use:** Do not create experts solely because training labels provide family names that are unavailable at test time. A waveform mixture-of-experts improved local CV but not leaderboard performance in one writeup, illustrating router overfit. Keep one model when strata share the same error mechanism or each expert would be data-starved.

**How to reason about it:**
Measure the oracle gain first: how much would perfect per-regime model selection improve the metric? Then estimate router confusion and propagate it through the pipeline. Add specialists only if expected gain after routing errors exceeds the cost and variance.
