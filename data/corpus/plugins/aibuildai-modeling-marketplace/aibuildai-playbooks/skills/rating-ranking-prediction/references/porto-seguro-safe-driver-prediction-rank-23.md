23rd place solution:

The best of my two final selected submissions scored 0.29144 on the private LB and was my highest scorer on the public LB but only my 28th best on the private.  My actual best scored 0.29157 and would have placed 19th on the private LB had I selected it.  My final public LB rank was 1252, so I was one of the fortunate participants who moved up quite a bit (1229 places) from public to private ranking.  I attribute this boost (and similar ones I got in previous Kaggle competitions that saw a lot of shakeup) to "clean living", by which I mean a strict avoidance of public kernels except for scanning them for potentially useful ideas.  I also credit my silver medal in this contest to a combination of good luck, hard work, persistence, lots of experience, a modest amount of cleverness, ideas generously contributed on the contest forums by my fellow competitors, and fairly powerful hardware.  I think the inventor Thomas Alva Edison was mostly right when he said that "Genius is one percent inspiration and ninety-nine percent perspiration", although in some cases one could usefully add several percent of "desperation".  From my description below you might gather that my approach to this contest involved much more perspiration than inspiration, with my computers doing a lot of the perspiring.

I worked in R on several multi-core Intel Xeon workstations with a total of 74 physical cores and 448 GB of RAM, all running Ubuntu Linux 16.04.  I tried many ML algorithms, including catboost, deepboost, randomForest, glmnet, FactoRizationMachines, lightgbm, mxnet (function mx.mlp), rerf (Randomer Forest), rgf (regularized greedy forest), ranger (A Fast Implementation of Random Forests), softmaxreg (Training Multi-Layer Neural Network for Softmax Regression and Classification), neural networks in pytorch/nn (accessed in R through reticulate package), and xgboost.  But in the end I ended up using only catboost, lightgbm, and xgboost, sometimes stacked together with glmnet.  lightgbm seemed to be the fastest and best performer of the three boosting algorithms.  I tuned the hyperparameters of these algorithms both manually and also in sequences of short holdout runs using my own optimization algorithm (not grid search, but a combination of random steps, gradient descent, and quadratic stepping).

My best submission (0.29157) and my best selected submission (0.29144) were both minor variations on the same theme, which is massive ensembling, and they shared many of the same components.  I choose to describe in more detail the 0.29157 submission, which is an ensemble (blend using weighted averaging) of many sets of predictions, each of which is itself a blend of many separate runs that differ from each other only in their random number seeds, and each of these runs also averaged the predictions of a stack of one or more algorithms run in parallel in separate jobs across multiple cores on the same machine with different random number seeds and different random subsets of the training data. Generally these subsets were "enriched" by selecting a larger fraction of target 1 records than target 0.  For a stacker I developed my own algorithm, which is loosely based on the description of StackNet by kaz-Anova.

All this may sound like ensemble overkill, but I hoped it would boost performance and also provide "safety in numbers" that protected to some extent against overfitting the public LB.  I also did some cross-validation, which involved splitting the training data randomly into 75% modeling and 25% validation sets, measuring the Gini score on the holdouts, repeating this step 100 times with a fixed sequence of random number seeds, and computing the average (and standard deviation) of the Gini scores across all 100 runs.  Those CV runs were used only to help select ML algorithms and tune hyperparameters - none of their models or forecasts were used directly for submissions.

Data pre-processing: I converted the categoric features to binary 1-hots, except for catboost, which I allowed to handle categoric variables directly.  I normalized the numeric features to a mean of 0 and standard deviation of 1, although that step was not important for the tree-based algorithms.  I tried creating some features with PCA, but abandoned that after they failed to boost performance.  My principal method of feature generation was to create a large number (20000 to 100000) of synthetic features using random combinations of 2, 3, or 4 numeric and/or binary variables, evaluate each of them on the training data using at first the magnitude of the spearman correlation with the target and then later the Gini score, and then pick some number of the top scorers (typically 50) to add to my feature set.  The component variables were normalized and then combined linearly using random coefficients or multiplied together after being offset from their means by some random number of standard deviations.  Some of my later runs also transformed some of the component variables via the sigmoid function to add additional diversity.  The random feature generation and evaluation were spread across multiple cores for efficiency.  To reduce the extent to which too many very similar variants of the same synthetic features would be generated and selected, I imposed various rules about how many times the same variable could appear as a synthetic feature component during the selection process.  Because the selection of the highest-scoring synthetic features obviously involves some leakage from the target variable, there is a risk of overfitting.  So the process has to be carefully tuned and monitored.  I have used this method of feature generation for several years; it has proven more useful in some contests than others. Note that each run generates its own set of synthetic features using a separate random number seed; this enhances the diversity of the ensembles in which they are embedded.

Here is an example of a fairly high-scoring (Gini 0.17336918) synthetic feature as an R expression: 0 + (0.6349437 * (((feat_ps_car_13) - 0.8132124) / 0.2245003)) + (0.6690679 * (((feat_ps_car_04_cat_dum_10) - 0.03195052) / 0.1758686)) + (0.511576 * (((feat_ps_reg_02) - 0.4391957) / 0.4043154)).

I also thought of trying more sophisticated methods of feature generation and/or dimensionality reduction, but ran out of time before I could incorporate those into my models.  But with Michael Jahrer's success I plan to look into denoising autoencoders for future contests.

One of my most successful stacks ran catboost, lightgbm, and xgboost in one layer, then used their predictions as features for glmnet, which optimized a linear combination of those features and their first-level interactions.  It turned out that a single ensemble of 15 runs using this stack scored 0.29154 on private LB, which was better than my best selection, although not as good as my best submission, in which it was a prominent component.

Some of the other stacks I blended into my submissions included: a single layer of lightgbm; a single layer of catboost; lightgbm in one layer followed by catboost in a second, with restacking enabled to feed catboost both the original features and lightgbm's predictions as features; and variations on the preceding with lightgbm followed by xgboost and vice-versa;
