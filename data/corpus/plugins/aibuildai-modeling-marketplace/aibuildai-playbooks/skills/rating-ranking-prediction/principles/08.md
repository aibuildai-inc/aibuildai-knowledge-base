## Principle 8: Apply Rigorous Feature Selection to Reduce Overfitting

*Consensus: AmEx 2nd reduced 7k -> 2.5k features via permutation importance; Porto Seguro top solutions filter zero-importance features*

After brute-force feature engineering, aggressively prune features using zero-importance filtering, permutation importance, and forward/backward selection to keep only signal-bearing features and reduce overfitting.

**Why this matters:** More features ≠ better performance beyond a point. High-dimensional spaces increase overfitting risk, especially with limited data. Removing zero-importance features (never used in any split) and low-importance features (noise) improves generalization and speeds up training. AmEx 2nd place: 7k -> 2.5k features improved LB score.

**When to use:** After creating thousands of features via aggregation, interactions, or transformations. Essential when CV and LB diverge (sign of overfitting). Use tree-based importance (LightGBM gain) for initial filtering, then permutation importance for refined selection. Apply before final model training.

**When NOT to use:** Don't prune during early exploration when you're still discovering useful features. Skip if you have very few features (<50) or if regularization (L1, dropout) handles redundancy. Avoid removing features before checking holdout performance—sometimes 'low-importance' features help in ensemble diversity.

**How to reason about it:**
Start with zero-importance: train a model, record feature importance (gain or split count), drop all features with importance = 0. These never contribute. Next, permutation importance: shuffle each feature, measure CV degradation. Drop features with negative or near-zero impact (they add noise). Finally, forward selection: start with top-N features, add features one by one if CV improves. Or backward elimination: start with all, remove features if CV improves or stays flat. Validate on holdout set to confirm selection generalizes.
