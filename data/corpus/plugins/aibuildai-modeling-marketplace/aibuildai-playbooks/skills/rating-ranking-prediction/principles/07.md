## Principle 7: Use Deep Sequence Models for Long Temporal Dependencies

*Consensus: Several top solutions in sequence-heavy tasks (student performance, transaction histories) use RNN/LSTM/Transformer over flattened features*

When each entity has long sequences (>20 time steps) with complex temporal dependencies, use recurrent or attention-based models (RNN, LSTM, Transformer) that process sequences directly rather than flattening to aggregated features.

**Why this matters:** Aggregation loses temporal order and fine-grained patterns. A sequence of [low, low, high, high] is different from [high, low, high, low] even if mean and std are identical. RNNs and Transformers learn these patterns. For credit defaults, the trajectory of increasing debt matters more than the average. AmEx 1st place used RNN features; student performance 1st place used WaveNet (Conv1D for long sequences).

**When to use:** When sequences are long (>20 steps), ordered, and the temporal pattern is predictive. Examples: monthly transactions, game event logs, sensor readings. Essential when order matters (e.g., escalating delinquency) or when interactions span multiple time steps. Combine with aggregated features for hybrid models.

**When NOT to use:** If sequences are short (<10 steps) or irregular (missing many time points), aggregation may be simpler and equally effective. Tree models on aggregated features often beat RNNs on short/sparse sequences. Avoid if you lack the compute for deep learning (RNNs need GPUs, longer training). For pure tabular (no sequences), stick to GBDT.

**How to reason about it:**
Count time steps per entity: if median > 20, consider sequence models. Check if order matters: shuffle time steps—does performance degrade? If yes, order is informative. Choose architecture: (1) RNN/LSTM for moderate length (<100 steps), recurrent patterns. (2) Transformer for long sequences (>100), attention over distant steps. (3) Conv1D/WaveNet for very long sequences (>500), causal convolution. Preprocess: pad sequences to max length or use pack_padded_sequence. Feature engineering: combine sequence model embeddings with aggregated features.

```python
import torch
import torch.nn as nn

class LSTMModel(nn.Module):
    def __init__(self, input_dim, hidden_dim, output_dim):
        super().__init__()
        self.lstm = nn.LSTM(input_dim, hidden_dim, batch_first=True, bidirectional=True)
        self.fc = nn.Linear(hidden_dim * 2, output_dim)
    
    def forward(self, x, lengths):
        # x: (batch, seq_len, input_dim)
        packed = nn.utils.rnn.pack_padded_sequence(x, lengths, batch_first=True, enforce_sorted=False)
        out, (h, c) = self.lstm(packed)
        # Use final hidden state
        h = torch.cat([h[-2], h[-1]], dim=1)  # Concat bidirectional
        return self.fc(h)
```
