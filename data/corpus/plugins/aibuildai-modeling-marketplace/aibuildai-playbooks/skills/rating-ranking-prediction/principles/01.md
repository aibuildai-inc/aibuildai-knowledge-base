## Principle 1: Optimize Directly for the Evaluation Metric

*Consensus: Nearly all top solutions explicitly optimize for the competition metric rather than a proxy*

The evaluation metric fundamentally shapes your modeling strategy. Ranking metrics (Gini, AUC) only care about relative order, while probability metrics (logloss, Brier) require calibrated probabilities. Custom metrics (AmEx's combined Gini + top-4% capture) demand specialized approaches.

**Why this matters:** Using the wrong objective wastes the model's capacity. A Gini-optimized model produces uncalibrated probabilities; an RMSE-optimized model may rank poorly. The metric determines whether you need: (1) accurate probabilities, (2) correct ranking, or (3) both. For example, AmEx's 4% capture component means the top predictions matter disproportionately.

**When to use:** Always. Check the evaluation page before any modeling. Use this principle at model selection (choose loss function), training (set objective), and validation (track the real metric, not a convenient proxy).

**When NOT to use:** During early exploration, a related proxy metric (ROC-AUC for Gini, MSE for MAE) can speed up iteration. But final models and hyperparameter tuning MUST use the real metric. Never submit without verifying performance on the actual metric.

**How to reason about it:**
Ask: Does the metric care about (a) absolute values, (b) ranking only, or (c) calibrated probabilities? For ranking metrics (Gini, AUC): focus on relative order, try LambdaRank or pairwise losses, rank-transform predictions before blending. For probability metrics (logloss): ensure calibration, use proper probabilistic losses, check reliability diagrams. For error metrics (RMSE, MAE): match the loss function (L2 for RMSE, L1 for MAE), consider Huber loss for robustness. For custom metrics: implement the exact scoring function in your validation pipeline and optimize it directly (e.g., Optuna with the real metric).

# Example: AmEx custom metric with Gini + top-4% capture
import lightgbm as lgb

def amex_metric(y_true, y_pred):
    # Weighted Gini calculation
    gini = compute_gini(y_true, y_pred, sample_weight=weights)
    # Top 4% capture rate
    top_4_pct = compute_top_k_capture(y_true, y_pred, k=0.04, weights=weights)
    return 0.5 * (gini + top_4_pct)

# Use custom eval metric, NOT just binary_logloss
lgb.train(params, dtrain, 
          feval=lambda preds, train_data: ('amex', amex_metric(train_data.get_label(), preds), True))
