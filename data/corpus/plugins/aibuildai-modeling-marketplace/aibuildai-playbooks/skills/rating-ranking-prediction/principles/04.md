## Principle 4: Handle Class Imbalance with Weighted Metrics and Sampling

*Consensus: All top solutions in imbalanced tasks (AmEx 20:1 downsampling, Porto Seguro 3.6% positive rate) use sample weights or resampling*

Rating/ranking tasks often predict rare events (defaults, claims, accidents). The raw class distribution misleads standard training. Compensate by adjusting sample weights in the loss function or resampling to balance classes during training.

**Why this matters:** Models trained on imbalanced data default to predicting the majority class. A 96%-negative dataset produces a model that predicts 'no claim' for everyone and achieves 96% accuracy but 0 ranking power. Weighted losses and resampling force the model to learn the minority class. AmEx downsampled negatives 20:1, requiring 20x weight on negatives in the metric.

**When to use:** When positive rate < 10% or when the competition description mentions downsampling. Check the data distribution first. Use sample weights for tree-based models (scale_pos_weight in XGBoost, is_unbalance in LightGBM). Use resampling (SMOTE, random undersampling) for neural networks or when you need balanced batches.

**When NOT to use:** If classes are reasonably balanced (30-70% split) or the metric explicitly accounts for imbalance (e.g., F1, precision-recall AUC). Don't oversample if it creates near-duplicates that leak into validation. Avoid aggressive undersampling that discards too much majority-class information.

**How to reason about it:**
Calculate positive rate: pos_rate = y.mean(). If < 5%: definitely use weighting. If 5-20%: experiment with weighting. If > 20%: probably fine without. For tree models: set scale_pos_weight = (1 - pos_rate) / pos_rate in XGBoost, or is_unbalance=True in LightGBM. For neural networks: use weighted loss (pos_weight in BCEWithLogitsLoss) or oversample minority class during batching. Check metric calculation: if the metric uses sample weights (AmEx 20x for negatives), ensure your validation replicates this.

```python
import lightgbm as lgb
from imblearn.over_sampling import SMOTE

# Tree model: use built-in class weight
pos_rate = y_train.mean()
params = {
    'objective': 'binary',
    'is_unbalance': True,  # LightGBM auto-balances
    # OR set manually:
    'scale_pos_weight': (1 - pos_rate) / pos_rate  # For XGBoost
}

# Neural network: weighted loss
import torch.nn as nn
pos_weight = torch.tensor([(1 - pos_rate) / pos_rate])
criterion = nn.BCEWithLogitsLoss(pos_weight=pos_weight)

# Or oversample minority class
smote = SMOTE(random_state=42)
X_resampled, y_resampled = smote.fit_resample(X_train, y_train)
```
