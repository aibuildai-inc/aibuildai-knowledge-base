## Principle 3: Engineer Heavy Aggregation Features for Sequential Tabular Data

*Consensus: Top tabular solutions (AmEx 1st/2nd/3rd, Elo 7th, Porto Seguro 9th) use 3k-7k features from aggressive aggregation*

For tabular data with sequences (monthly credit statements, transaction histories), create dense feature sets by applying many aggregation functions (mean, std, min, max, last, first, nunique) across the time dimension, plus lag features, differences, and ratios.

**Why this matters:** Sequence-to-tabular aggregation compresses temporal patterns into a fixed feature space that tree-based models can exploit. A customer's payment behavior over 13 months contains hundreds of signals: trends (increasing debt), volatility (std of balances), recency (last payment), and change points (diff from previous month). Models learn which aggregations matter.

**When to use:** When you have tabular sequences: multiple rows per entity (customer, card, player) with measurements over time. Essential for credit scoring, transaction prediction, and time-varying features. Combine with tree-based models (LightGBM, XGBoost, CatBoost) that handle high-dimensional sparse features well.

**When NOT to use:** Skip if data is already aggregated (one row per entity) or if deep learning models (RNN, Transformer) process raw sequences directly. Don't brute-force aggregate for image or text data. For very long sequences (>100 time steps), consider sequence models instead of flattening.

**How to reason about it:**
Map out the temporal structure: how many time steps per entity? Which features vary over time? Then design aggregations: (1) Distributional: mean, std, min, max, median, quantiles—capture the range and shape. (2) Positional: first, last, nth—capture recency and initial state. (3) Change: diff(last - first), diff(last - previous), ewm (exponential weighted mean)—capture trends. (4) Ratios: last/mean, max/min—capture relative position. (5) Counts: nunique, count_zeros—capture diversity. Apply feature selection after: zero-importance filtering, permutation importance, forward selection.
