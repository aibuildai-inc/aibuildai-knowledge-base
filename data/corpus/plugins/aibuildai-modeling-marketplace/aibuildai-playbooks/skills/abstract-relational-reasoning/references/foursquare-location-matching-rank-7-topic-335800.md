# overview
We preprocessed "name" and "address", according to each language, and converted them to embedding.
We generated candidates from distance, name similarity, word and character precision, and recall based on multiple regression.
Prediction was made by LightGBM binary classification
In the post-processing, the edge whose predicted value exceeds the threshold is divided into subgraphs by Union Find Tree (Disjoint Set), and then the one whose shortest distance is within 2 is selected.

# Preprocessing
## Natural language preprocessing
Since the name and address were multilingual, I prepared three separate processes.

1. Almost raw text
2. Text for each language with lowercase letters, removal of symbols, and digitization of numerals
3. About 2. Text converted to [0-9a-z &] with unidecode

Also, since there were many nans for the address, we complemented by connecting three neighborhoods of the distance.

### Processing for each language
Basically, all languages ​​have uniform removal of symbols-> lowercase letters / digitization of numbers-> alphabetization.
Since Japanese, Chinese, and Thai are languages ​​that require word-separation, they are processed individually.

For Japanese, use the tokenizer [Sudachi] (https://github.com/WorksApplications/Sudachi) to get the word-separation and reading, and then use [Pykakasi] (https://github.com/miurahr/pykakasi) to convert it to romaji. did.
Chinese was divided by [zh_segmehntation] (https://tfhub.dev/google/zh_segmentation/1) and converted to romaji by unidecode.
Thai is divided and romanized using [PyThaiNLP] (https://pythainlp.github.io/).

## city, state pre-processing
For city and state, we took out about 2000 in order of the number of appearances and put them in the category of fitting to any of 2000 in the vicinity of the distance.
We also converted it to the top 2000 place names using the [cities1000] (http://www.geonames.org/) dataset and made it into a category. (Hereafter referred to as geo_name)

## Creating an embedding
For the text of 3 in the previous section, the name and address were divided into 32000 subwords using different sentence pieces.
On top of this, we learned embedding by the following three unsupervised pre-learning based on word2vec.

* About name Skip-gram task
* Task to predict categories from name, address, city, state, geo_name
* A contrasting learning task that mixes name, address, city, state, geo_name, categories and guesses itself by [SimCSE] (https://arxiv.org/abs/2104.08821)

When doing these learnings, the method of obtaining negative samples was very important.
We were able to perform high-quality learning by generating a negative sample with a random walk for each sample, using the probability based on the negative logarithm of the hadsine distance as the edge for the vicinity of 128 of each sample.

### Fill in missing values ​​in a category
Now that we have a good model for category prediction, we filled in the missing values ​​by making predictions for those with blank categories.

### Clustering / one-dimensional
Each embedding was divided into about 2000 clusters by spherical kmmeans ++.
We also implemented kmeans ++ based on the hadsine distance and divided it into about 2000 clusters as well.

After splitting the cluster, we embedded the information in one dimension by solving the traveling salesman problem for the distance between each vertex.
This is a technique called [Word Tour] (https://arxiv.org/abs/2205.01954), which allows you to transform embedding into a form that GBDT can easily interpret in just one dimension.
Each category was sorted by TSP based on the similarity of each kmeans, the similarity of names and addresses with the number of occurrences top2000, and the haversine distances of city, state, and geoname, and used as continuous values.

# Feature generation

## haversine distance
The logarithm of the distance between two points was taken and used as a feature. The conversion to logarithm will be useful in later candidate generation.

## name, address
We have created various comparative features for both.

### Obtained from a public notebook
Gestalt Pattern Matching (SequenceMatcher), levenshtein, jaro_winkler (I will omit it because it was introduced in various kernels)

### Bag of Words, Bag of Char
For the word that was divided and normalized, TfIdfVectorizer was set to binary = True, use_idf = False, and 1-gram and 2-gram sparse vectors were created and the similarity was compared.
Also, considering the case where characters have meaning like Japanese and Chinese, we created sparse vectors for each character and compared the similarity.

### ROUGE-N, ROUGE-L
ROUGE is an index often used to evaluate sentence summarization tasks. Measure the degree of agreement between sentences and give precision, recall, f1 value.
ROUGE-N was compared using N-GRAM, ROUGE-L was compared using LCS, the former was implemented using tensorflow's Ragged Tensor, and the latter was implemented using tensorflow-text's rouge_l function.

### Cosine similarity, one-dimensional distance
For each embedding, the cosine similarity and the distance after dropping to one dimension are added as features.

## city / state
Similar to embedding, the top 2000 cities and states are listed as features in the order of Count Encoding and traveling salesman problem.

## categories
I also got the category embedding by doing metric learning about the category prediction task during pre-learning.
Like the other features, the category embedding is based on the count encoding as the features arranged in the traveling salesman problem.

## phone / url
Only whether or not they match after normalization was added as a feature quantity.

# Candidate generation
Candidate generation for learning and prediction combines multiple logics.

* haversine 4 nearest neighbors of distance
* Haversine 12 multiple regressions of distance logarithm and embedding cosine similarity such as name, address, categories, etc.
* About name Similarity by rouge-1 in word unit, precision, recall Total 4
* About name A total of 8 similarities, precision, and recall by rouge-2 in character units
* Top 4 cosine similarity of name

# Post-processing
The graph was constructed for each group by UnionFind after removing some edges based on the mediation centrality of the graph, with the predicted values ​​of the pair being above a certain level.
For each group, the shortest distance to all pairs of unweighted graphs was calculated, and the predicted value was within 256 vertices within 2 distances from each vertex.
