## Principle 4: Bound the Search with Complementary High-Recall Proposal Channels

*Consensus: 11/12 ARC writeups searched a bounded DSL or operation family; 15/16 substantive Foursquare writeups combined one or more blocking channels.*

Cover qualitatively different ways a true relation can appear, then prune aggressively: object, tile, pixel, or macro operations for transformations; spatial, lexical, exact-field, and learned-embedding retrieval for entity matching. Allocate candidate budgets by marginal recall rather than using one globally large neighborhood.

**Why this matters:** Naive symbolic composition grows exponentially, while all-pairs entity matching grows quadratically. A union of complementary channels achieves high recall more efficiently because each channel recovers cases that violate another channel's assumptions.

**When to use:** Use multi-channel proposals when positives can be close under different notions—for example, geometrically close but textually corrupted, or textually similar but spatially displaced. In program search, use typed operations, output-shape constraints, and task properties to prevent invalid compositions.

**When NOT to use:** Do not add a proposal channel merely because its standalone recall is high; it may contribute no new positives and flood the verifier with hard false positives. Skip expensive semantic retrieval when exact keys and local geometry already saturate coverage.

**How to reason about it:**
Plot cumulative oracle coverage against candidate count for each channel and their unions. Prefer channels with high marginal positives per added candidate, then use a cheap first-stage model to prune before expensive verification.

```python
channels = [propose_by_structure, propose_by_geometry, propose_by_text]
seen, candidates = set(), []
for fn, budget in allocate_by_marginal_recall(channels, validation_data):
    for candidate in fn(query, k=budget):
        if candidate.key not in seen:
            candidates.append(candidate)
            seen.add(candidate.key)
return cheap_filter(candidates, keep=second_stage_budget)
```
