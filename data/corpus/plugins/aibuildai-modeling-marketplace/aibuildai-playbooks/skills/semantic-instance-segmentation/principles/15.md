## Principle 15: Validate with Stratified Splits and Monitor CV-LB Correlation

*Consensus: 4/5 competitions - solutions explicitly mentioned CV strategy and tracked CV-LB gap*

Create validation set with stratified sampling to match class distribution (and key attributes for multi-class). Track the gap between local CV and leaderboard; if CV >> LB consistently, your validation is too easy.

**Why this matters:** Instance segmentation datasets often have structure: images of same scene/object, class co-occurrence, temporal sequences. Random splits leak information (Carvana: train/val had different cars but 5th place accidentally used random split per-image and noticed CV overstated LB). Stratification ensures validation represents the full distribution. CV-LB correlation tells you if your validation is trustworthy - if it is, you can iterate locally without leaderboard probing. Fashion 1st: 450-image stratified validation, CV predicted LB accurately. Open Images 7th: validation score >> LB but delta was stable, so it was still useful for relative comparison.

**When to use:** Always. Stratify by: primary class (required), rare classes (oversample to ensure >10 examples in val), and attributes if they affect metric (Fashion: ensure each attribute has ≥10% val examples). Track CV-LB gap on every submission - if gap is unstable or grows, your CV is broken.

**When NOT to use:** Do not use random splits for datasets with groups (same object across frames, same person in multiple images) - use grouped/stratified splits. Do not use validation set for threshold tuning if it is too small (<500 images for multi-class) - you will overfit. Do not skip validation even if you have LB - LB has limited submissions and can mislead (public/private split).

**How to reason about it:**
1. Identify grouping structure:
   - Carvana: group by car ID (same car in train/val leaks)
   - Fashion: no groups, stratify by class
   - Open Images: stratify by class, ensure rare classes represented
   - NFL: group by video (same video in train/val leaks)
2. Stratified split:
   - For balanced classes: StratifiedKFold on class labels
   - For imbalanced: use iterative-stratification (ensures minority classes in all folds)
3. Validation size: 10-20% of training data, min 500 images for multi-class
4. CV-LB tracking:
   - Plot (CV, LB) for each submission
   - If correlation <0.9, investigate: different distributions? Data leakage? Overfitting to val?
5. If CV >> LB consistently by a fixed offset (e.g., +0.05), validation is still useful for relative ranking
