## Principle 4: Decompose Into Multi-Stage Pipelines with Intermediate Scoring

*Consensus: Seen in 7/8 physics/optimization solutions, 5/7 audio solutions, and 3/4 fraud solutions. TrackML had 5 stages, Santa had 2-3, BirdCLEF separated models by class size.*

Break the problem into sequential or conditional stages where each stage solves a well-defined subproblem and can be scored independently. Use intermediate metrics to identify bottlenecks and iterate on the highest-ROI component.

**Why this matters:** End-to-end models hide failure modes and make debugging impossible. Staged pipelines let you pinpoint where errors originate, swap components independently, and allocate compute to bottlenecks. TrackML's 1st place had stages: pair candidates → triplets → full tracks → duplicate removal → final assignment, scoring each stage to find that triplet formation was the bottleneck. BirdCLEF winners used different models for small-sample vs large-sample classes because their error modes differed (focal loss for rare species, BCE for common ones).

**When to use:** When the problem has natural sequential structure (solve special cases first, then generalize), when different subproblems have different difficulty or data availability, when you need to debug a complex system, or when different stages benefit from different model types (e.g., rule-based + ML, or multiple ML models with different objectives).

**When NOT to use:** When stages introduce irrecoverable errors (a hard classification gate that discards candidates before refinement), when the problem is truly end-to-end perceptual (single image classification with no intermediate structure), or when you have so little data that splitting it across stages starves each one.

**How to reason about it:**
Ask: What are the natural subproblems? Can I solve easy cases first and use those solutions to constrain harder ones? Do different subsets of data/classes have different optimal strategies? Can I score intermediate outputs against ground truth? If yes, design stages with clear inputs/outputs and score each stage separately. Iterate on the lowest-scoring stage first.

```python
# TrackML-style staged approach\nclass MultiStageTracker:\n    def __init__(self):\n        self.pair_builder = PairCandidateModel()\n        self.triplet_extender = TripletModel()\n        self.track_completer = FullTrackModel()\n        self.deduplicator = DuplicateRemoval()\n    \n    def predict(self, hits):\n        pairs = self.pair_builder(hits)  # Stage 1\n        score_pairs(pairs, truth)  # SCORE intermediate\n        triplets = self.triplet_extender(pairs)  # Stage 2\n        score_triplets(triplets, truth)  # SCORE intermediate\n        tracks = self.track_completer(triplets)\n        tracks = self.deduplicator(tracks)\n        return tracks
```
