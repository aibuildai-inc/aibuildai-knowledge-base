## Principle 9: Optimize Post-Processing and Thresholds Separately

*Consensus: All CMI top solutions optimized sii thresholds; 1st Parkinson's picked class minimizing SMAPE per prediction*

For metrics like SMAPE, quadratic kappa, or custom scoring, the optimal prediction may not be the raw model output. Post-process by finding the value that minimizes the metric given the predicted distribution.

**Why this matters:** Many competition metrics are non-differentiable or have quirks (SMAPE+1 prefers integers). Optimizing the model's loss doesn't optimize the evaluation metric. Separate optimization recovers 0.01-0.05 metric points.

**When to use:** When the metric differs from your loss function. When you're doing classification but the metric is continuous (convert probabilities to class via optimized threshold). When the metric has clipping or transformations.

**When NOT to use:** When your loss function exactly matches the metric. When you can directly optimize the metric as a differentiable loss.

**How to reason about it:**
Train model with a standard loss (logloss, MAE). On validation, for each prediction, search over possible output values to find which minimizes the evaluation metric. For classification with custom thresholds, use OOF predictions across all CV folds to find the global optimal threshold.

```python
# SMAPE+1 post-processing: pick integer minimizing metric
def find_best_prediction(probs, possible_values):
    """Given probability distribution over classes, pick value minimizing SMAPE+1."""
    best_val = possible_values[0]
    best_score = float('inf')
    
    for val in possible_values:
        # Compute expected SMAPE+1 under this choice
        expected_error = sum(probs[i] * smape_plus_1(val, i) 
                           for i in range(len(probs)))
        if expected_error < best_score:
            best_score = expected_error
            best_val = val
    
    return best_val
```
