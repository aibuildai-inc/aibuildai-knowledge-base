## Principle 1: Assess Feature-to-Sample Ratio Before Feature Engineering

*Consensus: 5/5 top Parkinson's solutions, 3/3 top ICR solutions explicitly discussed this*

The curse of dimensionality begins when features exceed samples/10. With 248 patients and 1195 protein/peptide features, random columns boost CV as much as real features.

**Why this matters:** High-dimensional features create spurious correlations in small datasets. Forward feature selection on random data produces the same CV lift as real features when the ratio is violated, making it impossible to distinguish signal from noise through CV alone.

**When to use:** When you have more than 10 features per training sample, or when adding features from external sources (proteomics, genomics, imaging). Critical for medical data where measurements are expensive.

**When NOT to use:** When sample size exceeds 10× feature count, standard feature engineering applies. If you have 10,000+ samples, dimensional concerns relax.

**How to reason about it:**
Calculate features/samples ratio FIRST. If >0.1, either (a) aggressively reduce dimensionality through domain knowledge, (b) use strong regularization, or (c) extract meta-features (visit patterns, temporal indicators) that collapse dimensions. Test candidate features against random columns—if random boosts CV equally, the feature is noise.

```python
# Test if features beat random noise
import numpy as np
from sklearn.model_selection import cross_val_score

# Generate random features
random_features = np.random.randn(X.shape[0], 100)

# Compare real vs random feature CV gain
real_score = cross_val_score(model, X_real, y, cv=5).mean()
random_score = cross_val_score(model, random_features, y, cv=5).mean()

if random_score >= real_score - 0.01:  # Within noise margin
    # Feature has no reliable signal
    pass
```
