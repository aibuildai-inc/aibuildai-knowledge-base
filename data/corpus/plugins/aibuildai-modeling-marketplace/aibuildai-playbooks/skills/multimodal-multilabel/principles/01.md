## Principle 1: Apply Domain-Specific Preprocessing Before Generic Normalization

*Consensus: 4/5 competitions - iMet used RandomCropIfNeeded, Open Problems used CLR/LSI/BM25, Stable Diffusion used CLIP preprocessing, YouTube-8M used precomputed embeddings*

The preprocessing must respect the domain's physical or statistical properties. Generic approaches like standard normalization or random crops can destroy information or amplify noise in domain-specific ways.

**Why this matters:** Domain characteristics determine what constitutes signal vs noise. Random crops on centered artwork lose context; TF-IDF on single-cell data ignores biological count structure; standard normalization on embedded features breaks pretrained model assumptions. Domain-aware preprocessing preserves the relationships the model needs to learn.

**When to use:** Image data: check whether objects are centered (artwork, medical) vs scattered (natural scenes). Biological count data: use domain transformations (CLR, log normalization) instead of z-score. Pretrained embeddings: preserve the preprocessing used during pretraining.

**When NOT to use:** Natural scene images with unconstrained composition can use standard augmentation. Tabular features without physical meaning can use generic normalization. When the domain expert preprocessing hurts your CV, fall back to simpler approaches but investigate why.

**How to reason about it:**
Ask: (1) Does the data have spatial structure I need to preserve? (artwork centered → avoid aggressive crops). (2) Does the data have count structure? (single-cell → use log/CLR, not z-score). (3) Are features pretrained embeddings? (CLIP, sentence transformers → use their normalization). (4) Does the metric care about absolute values or just rankings? (cosine similarity → normalize; MSE on counts → don't).

```python
# iMet artwork: crop only if larger than target, preserving centered objects
class RandomCropIfNeeded(RandomCrop):
    def apply(self, img, h_start=0, w_start=0, **params):
        h, w, _ = img.shape
        return F.random_crop(img, min(self.height, h), min(self.width, w), h_start, w_start)

# Open Problems: centered log-ratio for count data
import numpy as np
def clr_transform(counts):
    # Preserve zero structure, transform non-zero
    log_counts = np.log1p(counts)
    geo_mean = log_counts.mean(axis=1, keepdims=True)
    return log_counts - geo_mean
```
