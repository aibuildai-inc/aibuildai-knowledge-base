## Principle 2: Validate Against the Test Distribution Shift, Not Just Random Folds

*Consensus: 5/5 competitions - Open Problems had day+donor shift, iMet had second-stage size shift, Stable Diffusion needed diverse prompts, YouTube-8M had temporal distribution*

The test set often differs systematically from training (new time points, new annotators, different image sizes, unseen donors). Random k-fold CV will overfit to the training distribution and fail to catch models that don't generalize.

**Why this matters:** A model that scores 0.90 on random CV but 0.80 on out-of-distribution validation will shake down on the leaderboard. The validation strategy must simulate the shift: group by time/donor/batch for biological data, use held-out second-stage data for multi-stage competitions, ensure prompt diversity for generation tasks.

**When to use:** Time-series or longitudinal data: group folds by time. Multi-donor/batch data: leave out entire donors/batches. Multi-stage competitions: if stage-2 data characteristics differ (size, source), create validation matching that. Text generation: ensure validation prompts cover unseen vocabulary/styles.

**When NOT to use:** If the test set is truly i.i.d. from training (rare in real competitions). If computational cost of group-based CV is prohibitive, use it for final model selection even if you train on random folds.

**How to reason about it:**
Identify the shift: (1) Read the data description for mentions of 'later time point', 'unseen donor', 'different annotator', 'second stage larger'. (2) Run adversarial validation (train a classifier to separate train/test) - high AUC means strong shift. (3) Design CV to simulate that shift: GroupKFold on the shift variable. (4) Check that CV improvements transfer to LB; if not, your CV is missing the shift.
