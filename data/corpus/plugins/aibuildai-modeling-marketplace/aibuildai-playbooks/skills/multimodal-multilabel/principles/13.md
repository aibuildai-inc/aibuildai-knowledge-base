## Principle 13: Extract Domain-Specific Features to Complement Learned Representations

*Consensus: 4/5 - iMet used ImageNet predictions + image stats, Open Problems used gene pathway features + cluster means, Stable Diffusion used CLIP embeddings + text retrieval*

Deep learning models learn general features, but domain-specific engineered features (ImageNet classifications for artwork, biological pathways for genes, color histograms for images) capture prior knowledge the model might miss. Combining both often beats either alone.

**Why this matters:** iMet 1st place: adding ImageNet predictions (1000 classes) as features to the second-level LightGBM gave +0.005-0.01 F2. Many iMet tags overlap with ImageNet (dog, cat, person, building), so ImageNet's 1000-class taxonomy provides a structured prior. Open Problems: genes related to target proteins (from pathway databases) were manually selected and added as raw counts, improving CV. The model learns correlations; the features provide the biology.

**When to use:** The domain has known structure you can encode (biological pathways, ImageNet taxonomy, color theory, physical laws). Features are cheap to compute (pretrained models, lookups, simple stats). Features are complementary to learned representations (low correlation).

**When NOT to use:** Domain features are expensive or unavailable. The model already captures the domain structure (adding features doesn't improve CV). Features are highly correlated with learned representations (redundant).

**How to reason about it:**
List domain priors: for images, ImageNet classes, color histograms, EXIF metadata. For biology, gene pathways, protein families, known interactions. For text, entity types, sentiment, readability. Compute these features. Add them to your model's input (for NN) or as extra columns (for GBDT). Train with and without domain features. If CV improves +0.005+, keep them. Check feature importance: if domain features rank high, they're providing signal the model doesn't learn.
