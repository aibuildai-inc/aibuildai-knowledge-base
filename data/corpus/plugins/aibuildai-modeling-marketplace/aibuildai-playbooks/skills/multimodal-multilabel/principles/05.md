## Principle 5: Use Different Decision Thresholds Per Label Group When Label Characteristics Differ

*Consensus: 4/5 - iMet separated cultures (0-3 labels) from tags (1-8 labels) with different thresholds; Open Problems treated Multiome and CITEseq separately*

When the label space has subgroups with different statistical properties (sparsity, annotation completeness, difficulty), a single global threshold is suboptimal. Per-group thresholds tuned on validation data can gain 0.01-0.02.

**Why this matters:** In iMet, cultures were optional (0-3 per image) while tags were mandatory (1-8 per image). A threshold of 0.5 would over-predict cultures and under-predict tags. Setting culture_threshold=0.28, tag_threshold=0.1 with per-group min/max counts matched the empirical distributions and improved F2 by +0.01-0.02.

**When to use:** Labels have known subgroups with different properties (e.g., 'culture' vs 'tag', 'common' vs 'rare', modality A vs modality B). Evaluation metric is threshold-sensitive (F-score, precision@k). You have a validation set to tune thresholds.

**When NOT to use:** Evaluation uses ranking metrics that don't require thresholds (AUC, mAP). All labels have similar statistical properties. You're predicting embeddings or continuous values, not binary decisions.

**How to reason about it:**
Analyze training label statistics: compute mean labels per group, sparsity, co-occurrence patterns. If groups differ, tune thresholds separately: for each group, sweep threshold on validation and pick the value maximizing the metric. Optionally add min/max count constraints if the competition description or EDA reveals them.
