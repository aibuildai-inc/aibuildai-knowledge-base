## Principle 5: Treat Gene Ontology as a Structured Output Space

*Consensus: 6/9 CAFA writeups explicitly enforced hierarchy through graph models, hierarchy-aware modules, conditional factorization, or post-processing.*

For ontology targets, make parent-child relationships part of prediction, stacking, or inference. At minimum enforce the true-path constraint that an ancestor's score cannot be below a descendant's score; stronger options include graph stackers or hierarchy-aware losses.

**Why this matters:** Independent term classifiers can produce logically impossible score orderings. The graph also lets evidence flow between frequent ancestors and rare descendants and allows predictions from heterogeneous models to be reconciled in a common structured space.

**When to use:** Use this whenever labels live in a DAG and ground truth is ancestor-propagated. Choose lightweight max propagation when resources are limited; use graph layers or hierarchy-aware loss when validation shows that learned dependencies add value.

**When NOT to use:** Do not use ontology propagation for scalar property tasks. Avoid memory-heavy dense descendant matrices when the label set is large unless sparse operations or aspect-specific batching are available; one CAFA solution observed quadratic memory scaling for its constraint module.

**How to reason about it:**
First reproduce the organizer's graph direction and propagation rules. Then compare: independent predictions, inference-only max propagation, hierarchy-aware loss, and graph stacking. Keep the simplest mechanism whose gains persist under realistic validation.

```python
def propagate_to_ancestors(scores, parents, reverse_topological_terms):
    out = dict(scores)
    for child in reverse_topological_terms:  # leaves toward roots
        for parent in parents.get(child, []):
            out[parent] = max(out.get(parent, 0.0), out.get(child, 0.0))
    return out
```
