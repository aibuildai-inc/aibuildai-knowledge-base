## Principle 12: Enforce Biological Consistency at the Cheapest Reliable Stage

*Consensus: 8/14 explicitly used GO true-path constraints, taxon filters, geometric equivariance, or WT↔mutant antisymmetry.*

Encode hard biological invariants in preprocessing, model design, or post-processing, choosing the least expensive stage that reliably enforces them. Examples include ontology ancestor consistency, taxon-term compatibility, rigid-motion invariance, and sign symmetry for reversible mutations.

**Why this matters:** A model should not spend scarce data learning rules already known to be exact or nearly exact. Constraint enforcement reduces impossible predictions and variance, but incorrectly assumed constraints can also suppress legitimate biology.

**When to use:** Apply constraints that match the evaluator and domain definitions: GO child-to-parent propagation, organizer-compatible taxon exclusions, rotation-safe structural descriptors, and mutant-minus-WT features. Validate softer rules such as evidence-code reliability rather than hard-coding them.

**When NOT to use:** Do not impose a rule merely because it sounds plausible. One conditional GO formulation improved diversity despite simplifying parent dependence incorrectly, while an explicitly equivariant stability network underperformed a conventional 3D approach; correctness of an inductive bias does not guarantee useful estimation.

**How to reason about it:**
Classify each rule as exact, evaluator-defined, or heuristic. Enforce exact rules deterministically, test evaluator-defined rules against official code, and ablate heuristics. Prefer post-processing when it guarantees consistency without constraining representation learning.

def apply_constraints(pred, meta):
    if meta.task == "GO":
        pred = propagate_to_ancestors(pred, meta.parents, meta.reverse_topological)
        pred = {t: s for t, s in pred.items() if taxon_allows(meta.taxon, t)}
    elif meta.task == "mutation_effect" and meta.has_reverse_pair:
        # Optional antisymmetric projection: f(a→b) = -f(b→a)
        pred = 0.5 * (pred.forward - pred.reverse)
    return pred
