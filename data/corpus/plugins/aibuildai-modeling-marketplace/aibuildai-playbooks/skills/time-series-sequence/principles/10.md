## Principle 10: Apply Task-Specific Post-Processing to Optimize Metrics

*Consensus: Sleep 1st used greedy post-processing to extract events (huge boost). Optiver used weighted mean subtraction. Critical for top ranks.*

Post-processing transforms model predictions to better satisfy metric or domain constraints. Examples: greedy event selection for event detection, rounding to match discrete values, median adjustment for unbiased forecasts, constraint satisfaction (forecasts must sum to total).

**Why this matters:** Raw model predictions often violate known constraints or aren't optimal for the metric. Sleep 1st got a massive boost (0.768→0.790 public) from optimized event extraction. Metrics like F1 have optimal decision thresholds that aren't 0.5. Post-processing is pure gain if done right, pure loss if leaky.

**When to use:** Event detection: use greedy or optimization-based event extraction (model outputs probabilities, you extract event times). Classification: threshold tuning, especially for imbalanced classes or F1 metrics. Forecasting: adjust for bias, apply domain constraints (sales >= 0), reconcile hierarchical forecasts. Markets: neutralization, cap outliers.

**When NOT to use:** Don't fit complex post-processing on validation set—it overfits. Don't apply post-processing that uses test set statistics (leakage). Don't post-process if you don't understand why it helps (risks making things worse). For simple tasks, well-calibrated models don't need post-processing.

**How to reason about it:**
Ask: what does the metric want? F1 wants optimal threshold (maximize via grid search on validation). Event detection wants precise event times (extract peaks above threshold with min distance). Forecasting wants unbiased predictions (check median error, adjust if biased). Domain constraints? Apply them last (clip negatives, normalize to sum). Validate: does post-processing improve validation score? If not, you're overfitting.

# Greedy event extraction (Sleep detection pattern)
def extract_events_greedy(probs, tolerance_steps=[12, 36, 60, 90, 120]):
    """Extract event times by greedily selecting highest-score points."""
    events = []
    scores = compute_event_scores(probs, tolerance_steps)
    
    while True:
        # Find highest scoring point
        best_idx = scores.argmax()
        best_score = scores[best_idx]
        if best_score <= 0:
            break
        
        # Add to events
        events.append(best_idx)
        
        # Update scores: discount overlapping windows
        for tol in tolerance_steps:
            overlap = (abs(np.arange(len(scores)) - best_idx) < tol)
            scores[overlap] -= probs[overlap] * (1 / len(tolerance_steps))
        
    return events
