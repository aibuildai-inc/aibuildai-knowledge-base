## Principle 11: Use Online Learning or Incremental Updates for Live/Streaming Data

*Consensus: Optiver 1st retrained every 12 days during test period (massive boost). Jane Street had real-time inference. G-Research used online updates.*

For competitions with streaming test data (predictions unlock more data → retrain → predict again), implement online learning: retrain model on newly revealed data and make fresh predictions. Manage memory carefully and optimize for speed.

**Why this matters:** Online learning adapts to the most recent regime, which is highly predictive in non-stationary environments like markets. Optiver's online learning was worth ~0.03 (5.44 → 5.40). Without it, models trained on old data degrade as patterns shift. The trick is doing this within time/memory constraints.

**When to use:** Essential for: (1) streaming competitions where test data arrives sequentially, (2) markets and economics (regime shifts common), (3) competitions with long test periods. More effective when data distribution changes over time. Check: does model trained on recent data beat model trained on all historical data?

**When NOT to use:** Skip if test period is short (no time for distribution to shift). Skip if retraining exceeds time limits. Skip if recent data is too noisy (model needs history). For stable environments, online learning adds complexity without gain.

**How to reason about it:**
Implementation: save training data per day/batch. When new data unlocks, append to training set, retrain, predict next batch. Memory trick: load data day-by-day instead of all at once (Optiver pattern). Speed: use fewer features to allow more retraining rounds. Tradeoff: how often to retrain? More often = more adaptive but slower. Test: compare model trained on [0, T] vs [T-k, T] for recent predictions—if latter is better, do online learning.
