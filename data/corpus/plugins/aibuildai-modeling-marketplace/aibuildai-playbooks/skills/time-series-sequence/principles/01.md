## Principle 1: Design Time-Aware Cross-Validation That Mirrors Test Conditions

*Consensus: Universal across all top solutions. Every winning solution uses time-respecting CV.*

Use grouped time series splits with gaps/purging between train and validation, never random K-fold. The validation period must match the forecasting horizon and test set characteristics.

**Why this matters:** Random CV allows future information to leak into training through similar timestamps in both splits, producing overly optimistic scores that collapse on the leaderboard. Time series data has temporal autocorrelation—validation must simulate the actual prediction scenario where you only know the past.

**When to use:** Always for time series. The specific variant depends on the task: forward-chaining CV for short-horizon forecasting, fixed holdout for long-horizon, group-purged splits when data has batch structure (e.g., different experimental runs, trading days).

**When NOT to use:** Never skip time-aware CV. If your CV doesn't align with LB, the issue is usually: (1) different time periods have different distributions (check stationarity), (2) gap size is wrong, or (3) you're using future information in feature engineering.

**How to reason about it:**
Ask: What does the test set look like temporally? If predicting 28 days ahead from day 1913, validate on day 1885→1913 predicting 1914→1941. If test has a gap (e.g., data ends at T, predict T+gap to T+gap+horizon), include that gap in CV. If data comes in batches/groups (trading days, sensor recordings), use GroupKFold with time ordering + purge overlapping groups. Check: does my validation period have the same statistical properties as test (mean, variance, trend)? If not, the split is wrong.

# Group time series split with purge (Jane Street pattern)
from sklearn.model_selection import GroupKFold
