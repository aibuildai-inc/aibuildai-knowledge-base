## Principle 2: Classify Your Task Type to Choose the Right Approach

*Consensus: Top solutions explicitly identify their task type early. M5 (forecasting), Liverpool (signal classification), Optiver (market prediction) use completely different techniques.*

Time series tasks fall into distinct categories requiring different methods: point forecasting (predict exact future values), probabilistic forecasting (predict distributions), signal classification (label sequences), anomaly/event detection, and regression on sequences. Identify which you have before choosing features or models.

**Why this matters:** A forecasting task needs lag features and recursive prediction; a classification task needs window-based features and softmax outputs. Markets need neutralization; signals need frequency filtering. Using the wrong paradigm wastes time—LSTM for pure tabular forecasting often loses to GBDT, while GBDT can't capture signal patterns that CNNs excel at.

**When to use:** First step after understanding the metric. Check: (1) Is the target continuous or categorical? (2) Do I predict one future point or a sequence? (3) Is the data inherently sequential (sensor readings) or just time-indexed tabular (sales per day)? (4) Are there domain-specific patterns (market microstructure, physiological rhythms)?

**When NOT to use:** Don't over-complicate. If your 'time series' is actually independent cross-sectional data with a date column (e.g., each row is a different store-item, time doesn't matter within-row), treat it as tabular. If data is truly sequential but you can engineer all relevant context into fixed-length features, GBDT often wins.

**How to reason about it:**
Decision tree: IF target is categorical AND data is high-frequency sensor readings THEN signal classification (use CNN/RNN, frequency features). ELSE IF target is continuous AND you predict multiple future steps THEN sequence forecasting (DeepAR, Seq2Seq). ELSE IF target is continuous AND data is tabular with time index THEN point forecasting (GBDT with lag/rolling features). ELSE IF detecting rare events in continuous signals THEN event detection (U-Net, peak finding). Check what worked in similar Kaggle competitions.

```python
# Task classification checklist
if target.dtype == 'category' and sampling_rate > 1Hz:
    # Signal classification: use wavenet/CNN + frequency features
    approach = 'signal_classification'
elif prediction_horizon > 1 and data_is_sequential:
    # Multi-step forecasting: use seq2seq or autoregressive model
    approach = 'sequence_forecasting'
elif data_is_tabular_with_time_index:
    # Point forecasting: GBDT with engineered lag/rolling features
    approach = 'point_forecasting'
else:
    # Event detection: U-Net, find_peaks, or threshold-based
    approach = 'event_detection'
```
