## Principle 6: Handle Non-Stationarity Through Differencing or Adaptive Windowing

*Consensus: M5 1st removed first 85 days due to variance shift. Web Traffic 1st used median normalization. Liverpool solutions all handled drift.*

Time series often have trends, level shifts, or changing variance that violate stationarity assumptions. Address this by differencing (predict changes not levels), adaptive normalization, or training only on recent stable periods.

**Why this matters:** Models trained on non-stationary data learn spurious patterns tied to historical trends that don't generalize. A sales series trending upward in train might flatten in test. Markets have regime changes. Sensor drift creates false patterns. Differencing removes trends while preserving predictive relationships.

**When to use:** Check for non-stationarity: plot rolling mean/std over time, run Augmented Dickey-Fuller test. If mean/variance shifts, use differencing for forecasting tasks or remove unstable periods for classification. Markets and economic data almost always need differencing or returns. Long time series (years) more likely to be non-stationary than short (weeks).

**When NOT to use:** Don't difference if you need absolute levels for submission (transform predictions back). Don't remove data if regime shifts are the thing you're trying to predict. Don't difference already-stationary data (it reduces signal). For short competitions (weeks of data), trends often continue—differencing might hurt.

**How to reason about it:**
Plot target over time: is mean/variance stable? For forecasting, ask: is the best predictor of tomorrow the trend from yesterday, or the absolute level? If trend, difference. For classification, ask: does the distribution of features shift over time? If yes, train only on recent data or use time-based features. Test: does model trained on early data work on late validation? If performance degrades, data is non-stationary.
