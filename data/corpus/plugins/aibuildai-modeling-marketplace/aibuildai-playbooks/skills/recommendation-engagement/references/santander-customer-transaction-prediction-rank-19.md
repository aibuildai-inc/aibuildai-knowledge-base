# Data Insights
Insight of the data is the key to get good result.
Thanks to the kind and mighty kagglers' share, it is not really hard to discover most of them.

1. Features are totally unrelated with each other. (Thanks to [@Chris Deotte](https://www.kaggle.com/cdeotte) ‘s [share ](https://www.kaggle.com/cdeotte/modified-naive-bayes-santander-0-899), and [@Jiwei Liu](https://www.kaggle.com/jiweiliu) 's [share](https://www.kaggle.com/jiweiliu/lgb-2-leaves-augment). and @[Branden Murray](https://www.kaggle.com/brandenkmurray) 's [share](https://www.kaggle.com/brandenkmurray/randomly-shuffled-data-also-works))
2. Some similar property(target distribution) among many features. (same with 1)
3. Real and fake data in test set. (Thanks to [@YaG320](https://www.kaggle.com/yag320) 's [share ](https://www.kaggle.com/yag320/list-of-fake-samples-and-public-private-lb-split).)
4. Fake data can be perfectly generated by shuffling features. (same with 1)
5. Each feature brings a different part of information. (Since all the feature selection method I have tried did not work well.)


So, I got almost all the ideas from reading the public kernel and discussion.

# What I am thinking when competing
Some idea below may be wrong.

1. Independence (totally unrelated) -&gt; any common interaction between two or more features should be avoid
  1. Do feature engineering with one original feature, and repeat 200 times.
  2. Set feature\_fraction == 0.005 in lgb.
  3. Use small leaf\_num in lgb.
2. Similar property (rolling window target probability)
   1. Group the features by similar "rolling window target probability" ,  adjust each feature to have similar distribution, and reshape it to have a (n\_samples * group\_size, 1) sample... bad result.
   2. After reading [@ONODERA](https://www.kaggle.com/onodera) 's [topic](https://www.kaggle.com/c/santander-customer-transaction-prediction/discussion/88939), I think the idea is right in some way.
3. Fake list
    1. Use part of test set in training.
    2. Do count encoding with true samples.
4. Shuffling -&gt; shuffling "0" get perfect "0" sample, vice versa.  -&gt; the unique value comes from "0" and "1" may be different. -&gt; the ratio of "0" an "1" is different. -&gt; count encoding.  (Maybe something is wrong, but this is how I got the idea.)
5. Shuffling -&gt; shuffling "0" together with "1" may produce something between "0" and "1", like a 80% "1" sample.

# Features
The final submission comes from a lgb model with 1200 features.

1. origin values (X200)
2. count encoding (X200)
3. when count == 1 replace origin feature by np.NaN (X200)
4. var * count (X200)
5. SandardNormalized(var) * np.log1p(A * count + B) (X400 for different A and B)
