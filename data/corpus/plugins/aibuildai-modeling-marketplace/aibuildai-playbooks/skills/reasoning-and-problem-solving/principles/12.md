## Principle 12: Multi-Task Training for Shared Representation Learning

*Consensus: 2/2 top ARC solutions using Omni-ARC approach*

When the core challenge is learning the right representation of the problem, train a single model on multiple related tasks that all require that representation. ARC 2nd place trained on: generate output (original task), generate new inputs (learn distribution), examples→code, code→output, verify correctness.

**Why this matters:** A single task may not provide enough signal to learn the underlying representation, especially with limited data. Multiple tasks that require the same conceptual understanding provide different views of that understanding. Omni-ARC: training on input distribution generation (which requires understanding grid patterns) helped the model represent grids better, improving performance on the main output generation task.

**When to use:** When the problem is representation-limited rather than capacity-limited, when you can define auxiliary tasks that share the same core representation, and when the main task has limited training data but auxiliary tasks can be synthesized.

**When NOT to use:** When auxiliary tasks would dilute focus from the main task (check validation performance), when the tasks require conflicting representations, or when you already have abundant data for the main task.

**How to reason about it:**
Task design: What aspects of the problem could be asked about differently? ARC: given inputs → generate input (distribution learning), given examples → describe transformation (code generation), given candidate output → verify (correctness checking). Training: Train a single model with task-specific heads but shared backbone. Balance task frequencies by validation performance. Validation: Does multi-task training improve on the main task compared to single-task training? If not, the auxiliary tasks may not be helping or may need rebalancing.

```python
# Omni-ARC multi-task training (2nd place)
tasks = [
    ('examples + input -> output', 0.4),  # Main task, higher weight
    ('inputs -> input', 0.2),  # Learn input distribution
    ('examples -> code', 0.1),  # Describe transformation
    ('code + input -> output', 0.1),  # Execute transformation
    ('examples + input + output -> verify', 0.2),  # Verify correctness
]

for epoch in range(n_epochs):
    for batch in dataset:
        task, weight = sample_task(tasks)
        if task == 'examples + input -> output':
            loss = model.generate_output(batch.examples, batch.input, target=batch.output)
        elif task == 'inputs -> input':
            # Generate a new input that follows the same distribution
            loss = model.generate_input(batch.inputs, target=batch.new_input)
        # ... other tasks
        total_loss += weight * loss
```
