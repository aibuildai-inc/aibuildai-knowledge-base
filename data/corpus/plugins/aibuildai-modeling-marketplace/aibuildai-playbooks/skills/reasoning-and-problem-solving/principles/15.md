## Principle 15: Validate on Held-Out Test-Like Data, Not Just Training Distribution

*Consensus: 4/5 top math solutions created custom validation sets, 2/2 top ARC solutions validated on evaluation set*

Create validation sets that match test difficulty and format, not just the training distribution. Math 1st place created AMC (easy), AIME (hard), and MATH level 4/5 validation sets to measure performance across difficulty levels and detect overfitting to easy problems.

**Why this matters:** Training loss can improve while test performance degrades if the validation set is not representative. Math solutions: validating only on training data would miss that the model fails on competition-level hard problems. Multiple validation sets at different difficulty levels help detect when to stop training or when to change the approach.

**When to use:** Always. Create test-like validation data before training. When test difficulty is higher than training difficulty, when test format differs from training, or when you're doing test-time adaptation (need to validate the adaptation procedure).

**When NOT to use:** Never skip validation. Even if test data is completely novel (like ARC), validate on the closest available proxy (ARC evaluation set).

**How to reason about it:**
Validation set design: What makes test hard? Match those characteristics. For math: include recent competition problems not in training, span difficulty levels, include integer-answer-only problems if test is integer-only. Size: small representative sets (50-100 examples) can give signal if chosen carefully, use larger sets (500+) for low-variance estimates. Multiple sets: validate on easy, medium, hard separately to see if the model is learning generalizable reasoning or memorizing training patterns. Variance: run with multiple seeds if the set is small (<100) to measure uncertainty.

```python
# Multi-level validation sets (AIMO 1st)
validation_sets = {
    'AMC': filter_integer_answers(AMC_2022_2023),  # 83 problems, ~60-65% expected
    'AIME': problems_from([AIME_22, AIME_23, AIME_24]),  # Recent, hard
    'MATH_level4': filter_integer_answers(MATH_test_level4),  # 750 problems
    'MATH_level5': filter_integer_answers(MATH_test_level5),  # 750 problems
}

def evaluate_model(model):
    results = {}
    for name, val_set in validation_sets.items():
        scores = []
        for seed in range(5):  # Multiple seeds for variance estimate
            acc = run_evaluation(model, val_set, seed=seed)
            scores.append(acc)
        results[name] = (mean(scores), std(scores))
    return results
```
