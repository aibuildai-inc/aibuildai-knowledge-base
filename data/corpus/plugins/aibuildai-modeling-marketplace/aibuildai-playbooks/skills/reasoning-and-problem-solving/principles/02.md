## Principle 2: Choose Problem Representation Before Model Architecture

*Consensus: 5/5 top ARC solutions, 4/4 top math solutions, 3/3 top Game of Life solutions*

The problem representation (text, grid encoding, constraint graph, feature set) determines what patterns are learnable. Grid problems benefit from markdown-style text encoding for LLMs or convolutional features; mathematical problems benefit from code-integrated formats; inverse problems benefit from constraint encodings.

**Why this matters:** Wrong representation makes learning impossible or extremely sample-inefficient. ARC 2nd place used simple text grid encoding (`grid shape: 3x3 / 1 100 / 2 010`) which allowed small LLMs to learn, vs. treating it as pure vision which would require massive models. Math solutions used interleaved reasoning-code-output format which allows verification at each step.

**When to use:** Before any model training. When the raw data format (images, text, game state) could be encoded multiple ways.

**When NOT to use:** When the data format is fixed by competition requirements and pre-processing is not allowed, or when the standard representation (e.g., raw pixels for images) is already optimal for your approach.

**How to reason about it:**
Ask: What invariances matter? (ARC: rotation/flip → text allows easy augmentation). What needs to be referenced later? (Math: intermediate steps → structured format). What relationships are critical? (Games: spatial adjacency → grid or graph). Can humans easily verify/debug this format? Test multiple encodings on a small validation set before scaling up.
