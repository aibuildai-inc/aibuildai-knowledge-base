## Principle 1: Classify by Problem Structure to Choose Architecture

*Consensus: All competitions - each type has distinct winning patterns*

Different reasoning tasks have fundamentally different solution structures: visual pattern recognition needs geometric invariance, mathematical reasoning needs tool integration, strategic games need opponent modeling, and inverse problems need constraint satisfaction.

**Why this matters:** The right architecture choice determines what's learnable. ARC benefits from test-time fine-tuning because each task is novel; math olympiads benefit from code execution because intermediate steps need verification; games need self-play because the solution is relative to opponents. Applying the wrong pattern (e.g., pure supervised learning for inverse problems) hits fundamental limits.

**When to use:** At the start of every reasoning competition. Classify by: Is the answer verifiable? (math, code) vs. Are there multiple valid solutions? (inverse problems) vs. Is there an opponent? (games) vs. Are there visual/geometric patterns? (ARC) vs. Is it language-based reasoning? (prompt recovery).

**When NOT to use:** Not when the problem has clear supervised labels and doesn't require search, verification, or adaptation. Standard classification/regression tasks don't need this framework.

**How to reason about it:**
Ask: (1) Can I verify a solution programmatically? → Use code execution + verification models. (2) Are there geometric invariances? → Use data augmentation + equivariant architectures. (3) Is there an adversary? → Use self-play or imitation from strong agents. (4) Are there exponentially many solutions to search? → Use SAT solvers or constraint satisfaction. (5) Does each test instance have unique structure? → Use test-time fine-tuning or adaptation.
