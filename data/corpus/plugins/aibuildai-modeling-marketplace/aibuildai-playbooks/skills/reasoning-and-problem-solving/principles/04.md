## Principle 4: Use Test-Time Fine-Tuning When Each Test Instance is Novel

*Consensus: 2/2 top ARC solutions (2024 and 2025)*

For tasks where each test instance has unique structure not seen in training (ARC grids, novel tasks), fine-tune the model on the test instance's demonstration examples before making predictions. ARC 2nd place improved from 11 to 33 solved tasks by fine-tuning on n-1 train examples and testing on the held-out example.

**Why this matters:** Few-shot prompting is not enough for truly novel tasks. Test-time fine-tuning allows the model to learn the specific transformation rule from demonstrations, effectively treating each test instance as a mini supervised learning problem. This is the difference between a model that recognizes patterns it has seen vs. one that can learn new patterns on the fly.

**When to use:** When test instances have unique rules/patterns not in training (ARC, novel games, meta-learning tasks), when demonstration examples are provided with each test instance, and when inference budget allows training time (ARC allows 12 hours).

**When NOT to use:** When test instances follow the same distribution as training, when no demonstration examples are available, when inference budget is tight, or when the model is already large enough to few-shot learn in context.

**How to reason about it:**
Check: Do test instances have fundamentally different structure from training? Are demonstration examples available? If yes to both, budget time for fine-tuning. Use existing LoRA adapters (faster than full fine-tuning). Use batch size 1 and high learning rate (8e-5 in ARC) to adapt quickly. Fine-tune for ~300 steps or until the held-out example is solved. Apply data augmentation during fine-tuning to prevent overfitting to the specific demonstrations.

```python
# ARC test-time fine-tuning (2nd place)
for test_task in test_set:
    lora_adapter = pretrained_adapter.copy()
    for step in range(300):  # Quick adaptation
        # Hold out one example for validation
        train_idx = random.choice(range(len(test_task.train_examples)))
        train_batch = test_task.train_examples[:train_idx] + test_task.train_examples[train_idx+1:]
        # Fine-tune with augmentation
        augmented = augment(train_batch)  # rotation, flip, color swap
        loss = model.forward(augmented, adapter=lora_adapter)
        lora_adapter.update(loss, lr=8e-5)
    # Generate predictions with fine-tuned adapter
    predictions = model.generate(test_task.test_input, adapter=lora_adapter, n=96)
```
