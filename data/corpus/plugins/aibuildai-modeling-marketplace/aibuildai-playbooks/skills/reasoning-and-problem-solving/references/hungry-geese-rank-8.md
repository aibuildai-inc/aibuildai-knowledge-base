# 8th place solution

Competition: hungry-geese
Rank: #8
Source: https://www.kaggle.com/c/hungry-geese/discussion/264015

Since we rushed to participate in the competition around the last month of the competition, we had not sufficiently refined our solution and hence were not willing to publish it. However, [this post](https://www.kaggle.com/c/hungry-geese/discussion/263954) urged me to do so (lol), so I'll share it briefly.

The English text is mostly generated by automatic translation. If there are any parts that are difficult to understand, please feel free to ask questions.

The github repository is [here](https://github.com/Lgeu/hungry_geese).

- The solution is based on the AlphaZero method of learning and search.
- I was mainly in charge of the evaluation function part, and @kkt89swa was mainly in charge of the MCTS part.
- As PV-Network, I used NNUE (4-layer MLP with EmbeddingBag as the first layer) based NN instead of CNN.
  - However, to NNUE's credit, I don't think we were able to fully exploit the power of NNUE.
- NNUE's incremental update wasn't used. Instead, we used sparse features.
- As features, we used 44 types of variables (about 2400 binary variables) that can be obtained with light computation.
- The inference of the model is implemented in C++.
  - I explicitly wrote the vectorization of the computation only for the parts with a large number of computations.
  - Since the CPU in the evaluation environment was Broadwell, vector operations up to AVX2 could be used.
- I used PyTorch to train the model.
- For the last agent we submitted, I used as training data a game record of about 200,000 games generated by a self-play with 0.1 second per move.
  - This is probably not enough.
- The model outputs policy/value for everyone in a single inference.
- The difference in value between two agents is considered to be the logarithm of the odds, and the cross-entropy of all six pairs is calculated to be the loss function of value.
  - The expected ranking can be obtained by calculating the win rate for each pair in the same way during inference.
    - The sum of the expected rankings for the four agents is always 10.
- In the tree search, the search is deepened by narrowing down the possible locations where food can appear to three locations.
- In the last day's submission, we have made a change to use the average value of the choices in determining the action, instead of just the number of choices. This has greatly reduced the number of abortive deaths when playing against weaker opponents.
- I think the search speed was about 100k nps when we measured it locally.
  - It seems that about 60% of the search time was used for calculating the evaluation function.
- The name of the team, "TCOR3参加失敗組," refers to the group of people who failed to participate in the Topcoder Open (TCO21) Algorithm Round 3.
  - Both of us had passed Round 2, but I was late getting home and couldn't register in time, and @kkt89swa slept through.

- 解法は、AlphaZero 方式の学習・探索がベースになっています。
- 私は主に評価関数部分を、 @kkt89swa は主に MCTS 部分を担当しました。
- PV-Network として、CNN ではなく NNUE (1層目を EmbeddingBag にした 4層 の MLP みたいなもの)をベースにした NN を使っています。
  - ただし、NNUEの名誉のために書きますが、私は NNUE の力を十分に出せなかったと思っています。
- NNUE の差分計算は行いませんでした。代わりに、スパースな特徴を使用しました。
- 特徴量として、軽い計算で求められる 44 の種類 (バイナリ変数に置き換えて 2400 個程度) の変数を使いました。
- モデルの推論は C++ で実装しています。
  - 計算回数の多い部分だけ計算のベクトル化を明示的に書いています。
  - 評価環境の CPU が Broadwell だったので、AVX2 までのベクトル演算が使用可能でした。
- モデルの学習には PyTorch を使いました。
- 最後に提出したエージェントでは、学習データとして、1 手 0.1 秒の自己対戦で生成した 20 万局程度の棋譜を使いました。
  - 多分足りていません。
- モデルは 1 回の推論で全員分の policy/value を出力します。
- 2 エージェント間の値の差をオッズの対数と考え、全 6 ペアでクロスエントロピーを計算することで value の損失関数としています。
  - 推論時は同様に各ペアに対して勝率を計算すれば、期待順位が求まります。
    - この期待順位は 4 エージェントでの和が必ず 10 になります。
- 木探索において、食べ物が出現し得る位置を 3 箇所に絞ることで探索を深くしています。
- 最終日の提出では、行動決定に選択回数だけでなく平均価値も使うような変更を加えています。これにより弱い相手との対戦において頓死することが大きく減りました。
- ローカルで計測したときの探索速度は 100k nps 程度だったと思います。
  - 探索において、 60% 程度の時間を評価関数の計算に使っていたようです。
- チーム名の "TCOR3参加失敗組" とは、Topcoder Open (TCO21) Algorithm Round 3 の参加に失敗したこと人たちのグループということです。
  - 2 人とも Round 2 を通過していましたが、私は帰宅が遅れ登録が間に合わず、 @kkt89swa は寝過ごしました。
