Competition: hungry-geese
Rank: #5
Source: https://www.kaggle.com/c/hungry-geese/discussion/263702

I want to appreciate the kaggle staff as well as all participants for such as wonderful and exciting competition.

My solution is basically same as a conventional AlphaZero method including policy and value networks, but a different exploration function is used and many features are input to the CNN model. The implementation is here: [https://github.com/takedarts/hungry-geese](https://github.com/takedarts/hungry-geese). My implementation does not use any extra data such as other players game records or pre-trained models. In addition, my implementation does not use any RL frameworks.

# 1. Reinforcement Learning

A process of reinforcement learning is same as AlphaZero. First, game records are generated by playing self matches. Next, a new model is trained using the generated game records. After that, trained models are evaluated through playing games and the strongest model is selected as the model for self matches of next step.

[training process]

In the phase of generating game records, only an agent with the strongest model is used. At each step, the agent makes a search tree that decides all players moves. This procedure is 4 times faster than game simulations with 4 agents, but each goose can select efficient moves avoiding collisions because the goose knows other geese moves. Therefore, a penalty of moving to potential collision segments is adopted in order to force geese to hate the potential collision segments. During this competition, about 350k game records are generated by using a Threadripper 3970X.

At training, a CNN model is trained by using the latest 60k game records. Here, foods are randomly removed from input features. In the tree search, maps where some foods have been eaten appear because the tree search simulates the future movement of the goose. Therefore, the CNN model needs to be trained with maps where food has been removed.

# 2. Multi-Head Convolutional Neural Network

In my implementation, a residual convolutional neural network is used as a policy and value network. Input features are made via following procedure:
（1）Shift the map so that the player head is in the center,
（2）Rotate the map so that the player is heading north,
（3）Convert the map to an input feature array.
The size of the input feature array is `98 x 11 x 11`. The details of input features are shown in a following figure.

[input features]

The CNN model is constructed with a stem block, 8 residual blocks and 2 head blocks. First, the stem block convert input features to `64 x 7 x 7` feature maps. Then, residual blocks convert the feature maps to same size feature maps. Here, each residual blocks is a pre-activation residual block which includes a positional embedding layer. Finally, head blocks make policy and value outputs based on  feature maps converted by residual blocks.

[model architecture]

Outputs of the CNN model are 3 policy outputs and 3 value outputs. Policy outputs are probabilities of left, straight and right moves. Value outputs are probabilities of 1st place, 2nd place and 3rd place. An activation function of a policy output or a value output is sigmoid, and a loss function is mean squared error.

# 3. Tree Search

A tree search algorithm in my implementation is Decoupled Upper Confidence Tree: DUCT which is a MCTS like algorithm for simultaneous move games. Generally, UCB1 is used as an exploration function for DUCT or MCTS. In my implementation, the performance of UCB1, however, does not seem good. Therefore, I uses a different exploration function:
$$\frac{v_r p_i + \sum_k v_{ik}}{(1 + n_i)^{\frac{3}{2}}}$$ where \\(v_r\\), \\(v_{ik}\\), \\(p_i\\), \\(n_i\\) are a value at the parent node, values at descendant nodes following node \\(i\\), a policy of the child node \\(i\\), a visit count of the child node \\(i\\) respectively. My exploration function considers policies but the impact of values to the node selection is larger than policies. 

The value of each node is normalized as:
$$\sum_p v_{ip} = 1$$ where \\(v_{ip}\\) is a value of player \\(p\\) at node \\(i\\). Because of this normalization, my agents move to not only survive but also hunt other geese.

# 4. Heuristics Algorithm and Parameters

My implementation includes a simple look-ahead search that detects dead ends. But, the search algorithm does not predict other players moves, so the look-ahead search is used only to filter moves towards an obvious dead end.

My agents have several parameters that determine the agent characteristic.

- collision: a penalty at moving to a potential collision segment.
- eating: a bonus at eating a food.
- safe: at increase this, the agent aims for survival instead of 1st place.
- policy base: at increase this, the agent searches nodes widely.
- value base: a bonus when the goose is alive.
- value tail: a bonus when the goose head is close to the tail.

I tried to find good parameters in order to win at the leader board. But, I do not know that my settings in submission files are good or not.

# 5. Optimization

In order to optimize my implementation, an optimization library Numba is adapted to several bottle necks. In addition, we set the number of threads in PyTorch to 1. After applying this optimization, the number of search iterations on the submission server is about 40-60.
