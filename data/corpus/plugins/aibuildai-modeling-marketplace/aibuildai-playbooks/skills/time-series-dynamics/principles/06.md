## Principle 6: Make Validation Reproduce Deployment Information Flow

*Consensus: 5/5 competitions treated validation design as central; all used chronological cutoffs or gaps, appropriate to their deployment information flow.*

Construct validation folds that reproduce forecast origin, horizon, entity overlap, delayed labels, regime mix, and any train-to-test gap. Group all rows from an episode or entity as required, and test more than one plausible deployment scenario when future drift is uncertain.

**Why this matters:** Random row splits leak nearby states and make interpolation look like forecasting. Even ordinary walk-forward validation can be optimistic if deployment begins after a long gap, uses a different year, or scores a longer horizon. Conversely, withholding recent data unnecessarily can weaken the final model once model selection is complete.

**When to use:** Always, with the split type conditional on the task. Use rolling-origin folds for future forecasting, gap folds for delayed private periods, held-out years or seasons for climate shift, and group-stratified episode folds when independent episodes are sampled from the same regime distribution.

**When NOT to use:** Do not use chronological splitting mechanically when there is no cross-episode chronology in deployment. Independent episodes (such as trials or runs sampled from the same regime distribution) are better split by episode and balanced by the relevant regime metadata. Also do not use side-by-side entity splits as the only validation for forecasting if the same entities continue into the future; a top web solution found such scores nearly unrelated to future performance.

**How to reason about it:**
Write down an explicit information timeline for training and inference. Match the validation horizon to the scored horizon, include realistic gaps, keep feature computation causal, and report performance by horizon and regime. After selecting the design, retrain on all legally available recent data if deployment permits it.

def rolling_origin_folds(dates, horizon, gap, origins):
    for origin in origins:
        train = dates <= origin
        valid = (dates > origin + gap) & (dates <= origin + gap + horizon)
