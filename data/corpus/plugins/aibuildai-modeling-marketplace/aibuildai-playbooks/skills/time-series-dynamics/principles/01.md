## Principle 1: Classify the Prediction Interface Before Choosing the Model

*Consensus: 5/5 competitions; every successful approach reflected the task's information interface, although the resulting model families differed substantially.*

First determine whether the task is long-horizon forecasting, whole-trajectory response prediction, structured profile emulation, or causal streaming prediction. Select the architecture only after deciding what context is legitimately available at each prediction step.

**Why this matters:** The word “time series” hides different conditional distributions. A climate emulator maps a vertical state profile at one time to tendencies, a web model must generate an unseen future, and a market model must not access future rows but may later receive delayed labels. Treating all three as ordinary autoregression either discards valid information or leaks unavailable information.

**When to use:** Always. Observable indicators are the submission API, whether future covariates are supplied, whether sequences have fixed boundaries, whether labels arrive during inference, and whether the ordered axis is time, height, or another physical coordinate.

**When NOT to use:** Do not force a sequence architecture when rows are conditionally independent given current covariates or when a robust local baseline already dominates sparse/noisy series. Several strong web and COVID solutions used median, linear, quantile-regression, or tree models instead of deep recurrent models because the usable signal was low-dimensional and horizon behavior mattered more than architectural capacity.

**How to reason about it:**
Ask in order: (1) What is one prediction unit? (2) Which observations and future covariates exist when that unit is predicted? (3) Does the evaluator call the model once, by horizon, or timestep-by-timestep? (4) Is the ordered axis causal or merely structured? IF the full exogenous trajectory is known, bidirectional processing may be valid; IF future inputs are hidden, use causal state updates; IF the target is a profile on a known grid, use profile-to-profile modeling; IF the horizon is long and noisy, emphasize stable trend/seasonal structure and conservative extrapolation.

```python
def choose_regime(meta):
    # Customize these flags from the competition data/API.
    if meta["streamed_rows"]:
        return "causal_stream_with_state"
    if meta["full_future_controls_available"]:
        return "whole_trajectory_response"
    if meta["ordered_physical_grid"]:
        return "structured_profile_to_profile"
    return "long_horizon_forecast"
```
