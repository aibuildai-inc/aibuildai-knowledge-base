## Principle 13: Adapt Online Only When Delayed Labels Are Legally Available

*Consensus: 1/5 competitions, Jane Street, used this decisively; it is included because streaming feedback changes the optimal reasoning framework rather than being a generic trick.*

If the evaluation API releases delayed labels or lagged responders, maintain state and update the model or calibration online under the same timing rules. Validate the entire update loop, including warm-up, unscored periods, latency, and failure recovery.

**Why this matters:** In non-stationary streams, a small update on recent labeled data can outperform a larger frozen model because it tracks the current regime. The Jane Street solution gained far more from one daily online update than from its auxiliary targets or architecture changes.

**When to use:** Use only when labels are explicitly supplied before subsequent predictions, the stream is non-stationary, and updates fit the runtime budget. Unscored warm-up rows can still be valuable for updating state if competition rules allow them.

**When NOT to use:** Do not synthesize labels, use current targets before prediction, or assume feedback exists in ordinary batch tests. Skip weight updates when delayed labels are too noisy or sparse; update normalization, calibration, or rolling features instead if those are safer.

**How to reason about it:**
Draw the API event order: receive features, optionally receive prior-period labels, update state/model, predict current rows. Reproduce it exactly in CV with a realistic gap. Tune update learning rate and number of steps for stability, and retain a frozen checkpoint to reset after numerical or distributional anomalies.

```python
def predict_step(batch, delayed_labels=None):
    global model, state
    if delayed_labels is not None:
        model.train()
        optimizer.zero_grad()
        loss = scored_loss(model(delayed_labels.x), delayed_labels.y)
        loss.backward()
        optimizer.step()          # small, bounded update
    state.update(batch)           # causal rolling features only
    model.eval()
    return model(make_online_features(batch, state))
```
