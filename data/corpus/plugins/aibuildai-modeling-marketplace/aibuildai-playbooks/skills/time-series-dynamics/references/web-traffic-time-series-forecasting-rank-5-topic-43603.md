# Description of 5th place solution

Competition: web-traffic-time-series-forecasting
Rank: #5
Source: https://www.kaggle.com/c/web-traffic-time-series-forecasting/discussion/43603

**Summary**

Like many other competitors, I log-transformed page views before fitting and predicting, and used mean absolute error (MAE).  Unlike other top  solutions, my main tool was polynomial autoregression.  (Rather than least squares regression, I used median regression, which minimizes MAE.)

**The model** 

I separated my model into 4 parts:

1) Simple, constant, median-based prediction

It was hard to improve on this for low-volume pages (meaning most pages).

2) Median for each day of the week

This is a list of 7 numbers for each page.  The last 35 days were used to calculate medians.  The mean of medians was subtracted.  If a page had no weekly pattern, this list would ideally be all zeros.

3) Nonlinear polynomial autoregression

(Note that when I say page views, I mean logp1 page views.)  Prediction of future page views from past page views was performed as follows.  The past values (denoted by X) were medians of page view histories of various lengths: 2,4,8,16,32,64,128 days in the past.  The future values (denoted by Y) were polynomial median regression coefficients of future page views, over the entire 62 day prediction period.  The polynomial order was 1, in other words constant + trend.  Y was predicted from X using the 150 nearest neighbors in X.

4) Pages with a strong yearly pattern

This part of the model was particularly useful for pages regarding sporting events, holidays, historical events, etc.  The "strength" of a page's yearly pattern was determined by comparing last year's page views with the year before that.  Normally one would use the correlation coefficient for this, but it was a little bit better, and faster, for me to use norm(lastYear - yearBefore)/(norm(lastYear) + norm(yearBefore)), after subtracting the mean from each list.  

Prediction for pages with a strong yearly pattern could be a bit confusing.  The X values describe the future, 365 days ago.  They were polynomial regression coefficients of page views starting 365 days ago and ending 62 days later.  The future Y values were polynomial regression coefficients of future page views, over the entire 62 day prediction period.  For X and Y, the order of polynomial expansion was 2.  Y was predicted from X using median regression.

**Combining the model parts**

Model parts were not selected in binary fashion, but were mixed as follows.  3 vectors of length 62 were mixed to generate a prediction.  Each of the 3 vectors corresponds to the prediction from a part of the model (parts 1, 3 and 4 above).

To get mixing ratios, I used the linear crossover function defined as 

	f(x; x0, x1) = (x-x0)/(x1-x0) for x0 &lt;= x &lt;= x1, 0 for x &lt; x0, 1 for x &gt; x1.  

This function was used to activate the the median model when page views were low and to activate the yearly pattern model when the yearly pattern was strong. Variable x indicates whether a model part should be used.  Parameter x0 is the value at which the function begins to turn on and the model part begins to be used. Parameter x1 is the value at which the model part is fully on (though the other model part could also be on, and then the two would be mixed).  This function was applied separately to the median page views and the yearly pattern strength to get mixing portions for those two models.  Any left-over portion was assigned to the nonlinear polynomial regression model.  The mixing portions were normalized to sum to 1, and model predictions were mixed using these ratios.  (I would have to say more to fully define the mixing method, but it wouldn't be very informative.)  

Of course, model mixing could be done more elegantly with a simple neural net. I tried this, and the neural net learned a 2D activation function that was similar to what I made. But it was slow to train and didn't give better scores.  (Which is not the fault of neural networks, I just need to learn more about them.)

The weekly pattern was then added to the prediction, the prediction were exponentiated to invert the initial log transform, and finally the predicted page views were rounded to the nearest whole number.

**Training**

The training dataset was generated by picking, for each page, a random day to divide future and past.  This day was chosen to give at least 480 past days and 62 future days.  (Note that I accounted everywhere for the gap days between the training dataset and the  test dataset.)

**Cross validation**

I used 10-fold cross validation.  My method would have been too slow for this, so I compiled various functions to machine code.  The functions I compiled include  SMAPE, my fast median regression function, and my function for calculating features.  

**Tuning**

I tuned using 2 passes of line searching.  Tuning resulted in 0.5 points of SMAPE improvement.  (Whenever I add a hyperparameter to an algorithm, I do a little informal tuning motivated by curiosity.  Consequently, the algorithm is close to optimal before I start final tuning.  I would guess most people do this.)

**Ensembling**

I used a 10x ensemble.  The main source of variation for ensembling was the random stop day chosen for each page in the training set.

**What I would do differently next time**

I started with only 2.5 weeks to go until the final submission deadline, because it's much more fun that way.  Seriously, though, I should have started sooner, because I would have had more time to improve short-term predictions.  One thing I could have tried would have been to fit a more complex model for each day of the week, rather than using the simple median of each day.

And of course, neural nets!  I need to learn more about those.
