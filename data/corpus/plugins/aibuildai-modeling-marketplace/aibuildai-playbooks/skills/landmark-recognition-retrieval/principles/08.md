## Principle 8: Extend Index Set Beyond Clean Training Data for Retrieval

*Consensus: 1st place landmark 2020 recognition/retrieval, multiple top solutions. Significant gain.*

During inference, don't use only the clean training set as your index/gallery for retrieval. Include all available images for those classes from extended/noisy datasets (e.g., GLDv2-full contains 2x more images for the same classes as GLDv2-clean). This expands visual coverage without additional training.

**Why this matters:** Test images may depict landmarks from angles, lighting, or contexts not well-represented in the clean training set but present in the noisier extended set. Using a larger index increases the chance of finding a close visual match, especially for rare viewpoints. The 1st place 2020 solution gained significant improvement from this alone. The index doesn't need to be clean—retrieval is robust to some noise if the query is good.

**When to use:** When an extended/noisy version of your dataset exists with the same classes but more images per class. When your inference framework allows flexible index sets (not constrained by what was used in training). When retrieval quality (finding the best match) matters more than speed.

**When NOT to use:** When adding the extended set would exceed computational limits (memory for storing embeddings, time for similarity search). When the extended set is extremely noisy and validation shows it hurts more than helps (rare—most solutions found benefit). When your task is pure classification without retrieval, the index set is irrelevant.

**How to reason about it:**
1. Identify extended datasets: for GLDv2, 'clean' has 1.6M images but 'full' has 4.1M with 3.2M belonging to the same 81K classes. 2. Compute embeddings for the extended set once (offline). 3. Build index from extended embeddings. 4. At test time, retrieve from extended index. 5. Validate on a hold-out set: does extended index improve mAP? If yes by >0.01, use it. 6. For extremely large indices, consider approximate nearest neighbor search (FAISS) instead of exact search.

```python
# Training: use clean data
train_on_clean_data(model, gldv2_clean)

# Inference: use extended index
index_images = load_dataset('gldv2_full', classes=gldv2_clean.classes)  
# This loads all images from full dataset matching the 81K classes in clean
# Result: 3.2M index images instead of 1.6M

index_embeddings = []
for batch in dataloader(index_images):
    embeddings = model.encode(batch)
    index_embeddings.append(embeddings)
index_embeddings = np.vstack(index_embeddings)

# Build retrieval index
import faiss
index = faiss.IndexFlatIP(embedding_dim)  # Inner product = cosine for normalized
index.add(index_embeddings)

# Retrieve
for test_image in test_set:
    test_emb = model.encode(test_image)
    distances, indices = index.search(test_emb, k=5)
    # Now searching over 3.2M images instead of 1.6M
```
