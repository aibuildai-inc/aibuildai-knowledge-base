## Principle 13: Validate with Task-Appropriate Data Splits: Use Previous Competition Test Sets When Available

*Consensus: 2021 1st place, 2020 3rd place both used 2019 test set for validation. High correlation with LB.*

For landmark competitions, use the labeled test set from a previous year's competition as your validation set rather than a random split of training data. This provides more realistic evaluation since test sets are curated differently than training data (different distribution, different labeling quality).

**Why this matters:** Random splits of training data don't capture the distribution shift between training and test. Previous competition test sets undergo similar curation to the current test set and better represent the real challenge: landmarks from different angles, lighting, mixed with non-landmarks. Solutions validated on previous test sets showed high correlation with leaderboard, while random splits often had poor correlation.

**When to use:** When previous competition test sets are available (e.g., Google Landmark 2019 test for 2020/2021 competitions). When the task and dataset are iterative versions (year-over-year competitions). When test distribution differs from training (non-landmarks in test but not training).

**When NOT to use:** When no previous test sets exist (new competition). When the current competition significantly changed the task or data distribution. When previous test sets are too small to be statistically reliable (<500 images). In these cases, create a validation set that mimics test characteristics: sample rare classes, include non-target images if present in test.

**How to reason about it:**
1. Check if previous competition test sets exist for your task. 2. Verify the task is similar (same metric, same rough data distribution). 3. Use the previous test set as-is for validation; do NOT include it in training. 4. Compute your target metric on this validation set after each training epoch. 5. Track correlation: do changes that improve validation also improve leaderboard? If correlation is high (>0.9), trust the validation. 6. For stratified validation, create multiple folds from different previous years if available.

```python
# For Google Landmark Recognition 2021
# Use 2019 labeled test set as validation

# Load previous competition test set
val_data = load_dataset('landmark_recognition_2019_test')
val_queries = val_data['queries']  # Images to classify
val_index = val_data['index']      # Gallery images
val_labels = val_data['labels']    # Ground truth

# Do NOT include in training
train_data = load_dataset('landmark_2021_train')
assert not any(img in train_data for img in val_queries), "Validation leak!"

# Evaluate after each epoch
for epoch in range(num_epochs):
    train(model, train_data)
    
    # Compute GAP on 2019 test set
    val_embeddings = model.encode(val_queries)
    index_embeddings = model.encode(val_index) 
    predictions = retrieve(val_embeddings, index_embeddings, val_index.labels)
    gap = compute_gap(predictions, val_labels)
    
    # High correlation: if val_gap improves, LB likely improves
    print(f'Epoch {epoch}: Validation GAP = {gap:.4f}')
    
# Alternative when no previous test exists:
# Create validation mimicking test characteristics
val_data = create_validation_set(
    train_data,
    strategy='stratified',  # Equal samples per class
    include_rare_classes=True,
    include_nonlandmarks=True,  # If test has them
    size=0.05  # 5% of training
)
```
