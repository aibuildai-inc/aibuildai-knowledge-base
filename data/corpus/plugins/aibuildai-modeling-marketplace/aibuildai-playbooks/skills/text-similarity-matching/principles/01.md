## Principle 1: Prevent Leakage with Structure-Aware Cross-Validation

*Consensus: Source writeups that described their CV split kept related items together (Shopee GroupKFold by label_group, Avito non-overlapping items)*

Use GroupKFold or StratifiedGroupKFold to group by anchor, query, or entity ID, ensuring that all instances sharing the same anchor appear in the same fold.

**Why this matters:** Standard random splits leak information because the model sees related queries/anchors in training that appear in validation. This creates false confidence in CV scores that doesn't transfer to test data, especially when the test set contains entirely new anchors.

**When to use:** Any competition where multiple targets/candidates are compared against the same anchor/query (products in the same label group, questions with same asker, products from same seller). If the data has a natural grouping field (anchor, qid, user_id), group by it.

**When NOT to use:** When every pair is truly independent with no shared anchors or when the test set is guaranteed to contain the same anchors as training (rare). If CV and LB correlation is strong without grouping, standard stratified CV may suffice.

**How to reason about it:**
Ask: Do multiple rows share an anchor/query field? If yes, does the model need to generalize to NEW anchors at test time? If both yes, use GroupKFold. Then verify: does grouped CV correlate with LB better than random CV? If not, investigate whether test anchors overlap with train.

from sklearn.model_selection import StratifiedGroupKFold

# Group by label_group to prevent leakage
skf = StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=42)
for fold, (train_idx, val_idx) in enumerate(skf.split(X, y, groups=df['label_group'])):
    # All rows with same label_group stay in same fold
    train_data = df.iloc[train_idx]
    val_data = df.iloc[val_idx]
