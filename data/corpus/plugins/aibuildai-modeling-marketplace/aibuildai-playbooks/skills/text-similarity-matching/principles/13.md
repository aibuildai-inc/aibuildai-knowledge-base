## Principle 13: Weight Samples by Inverse Group Size for Imbalanced Metrics

*Consensus: 2nd Shopee, mentioned in LightGBM discussions*

When the metric is micro-F1 or per-sample, weight training samples by 1 / group_size^α (α ≈ 0.4) to prioritize small groups, which contribute equally to the metric despite having fewer samples.

**Why this matters:** Micro-F1 averages per sample, so a 50-item group and a 2-item group contribute equally per item. Without weighting, the model overfits to large groups (more training signal) at the expense of small groups, hurting the metric.

**When to use:** When the metric is sample-wise (micro-F1, per-sample accuracy) and group sizes vary widely (e.g., 2 to 50 items per label_group). Particularly important for stage-2 classifiers.

**When NOT to use:** When the metric is macro (averages per group, not per sample)—no weighting needed. If group sizes are uniform, weighting has no effect. For retrieval tasks without explicit groups, this doesn't apply.

**How to reason about it:**
COMPUTE group size for each training sample (e.g., label_group size). ASSIGN weight = 1 / group_size^α, where α ∈ [0.3, 0.5] (tune by CV). α=0 → no weighting, α=1 → fully inverse. APPLY weights in model training (most GBMs and NNs support sample_weight). VALIDATE that small-group performance improves without large-group performance collapsing.

```python
# Compute sample weights
group_sizes = df.groupby('label_group')['posting_id'].transform('count')
alpha = 0.4
sample_weights = 1 / (group_sizes ** alpha)

# Apply in LightGBM
import lightgbm as lgb
train_data = lgb.Dataset(X_train, y_train, weight=sample_weights)
model = lgb.train(params, train_data)

# Apply in PyTorch
loss = criterion(outputs, labels)
weighted_loss = (loss * torch.tensor(sample_weights)).mean()
weighted_loss.backward()
```
