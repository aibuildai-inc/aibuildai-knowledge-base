## Principle 8: Tune Multiple Thresholds Jointly Across Pipeline Stages

*Consensus: 12/15 solutions discussing thresholds (Shopee 1st, 4th, 6th, 7th)*

For multi-stage pipelines, optimize thresholds at each stage (retrieval, blending, final matching) together, not independently. Prioritize tuning later-stage thresholds.

**Why this matters:** Thresholds interact: a loose stage-1 threshold feeds more candidates to stage-2, changing its optimal threshold. Tuning them jointly avoids local optima. Later stages (2-3) often have the largest impact on final score.

**When to use:** When you have a multi-stage pipeline (retrieval → blending → matching, or embedding → kNN → classifier). When the metric (such as F1) is sensitive to threshold choice.

**When NOT to use:** Single-stage models with one threshold can use simple grid search. If CV is unstable, joint optimization may overfit; use LB feedback instead. For regression tasks (predict 0-1 score), no thresholds to tune.

**How to reason about it:**
Start with reasonable defaults for all thresholds. Fix early-stage thresholds, sweep later stages first (stage-2, stage-3 matter most). Once later stages converge, revisit stage-1. For min-k rules (e.g., min-2 matches guaranteed), set that threshold high. Validate on CV; if CV/LB diverge, use LB to tune final thresholds.

```python
from scipy.optimize import minimize

def objective(thresholds):
    t1, t2, t3 = thresholds
    matches = run_pipeline(embeddings, t1, t2, t3)
    f1 = compute_f1(matches, ground_truth)
    return -f1  # minimize negative F1

# Optimize jointly
initial = [0.0, 0.3, 0.35]
bounds = [(0, 0.5), (0.2, 0.5), (0.3, 0.6)]
result = minimize(objective, initial, bounds=bounds, method='L-BFGS-B')
optimal_thresholds = result.x
```
