## Principle 3: Generate Diverse Synthetic Data When Test Distribution is Unknown

*Consensus: 5/5 LLM detection solutions - 1st place generated 160k samples across 40+ models/prompting strategies*

When the test set may contain unseen generation methods, create training data spanning maximum diversity in models, prompting strategies, generation parameters (temperature, top-k, top-p), and fine-tuning approaches. Prioritize diversity over volume.

**Why this matters:** The LLM detection private test included generation methods not represented in the provided training data. The 1st place solution generated essays using proprietary LLMs (GPT-4, Claude), open-source LLMs (Llama, Mistral), fine-tuned models, and varied generation configs. This diversity helped them generalize to unseen methods. A solution trained only on GPT-3.5 outputs scored 0.674 vs their 0.972.

**When to use:** When you suspect the test set contains unseen generation methods, domains, or styles. When the competition description is vague about test composition. When you have compute budget to generate synthetic data but limited real labeled data.

**When NOT to use:** When test distribution matches training (confirmed by organizers or stable CV-LB correlation). When you have abundant real labeled data that spans the test distribution. The 5th place solution initially focused on PERSUADE essays alone and scored poorly (< 0.7) until they added 1.7M diverse documents from Pile/SlimPajama.

**How to reason about it:**
Map the generation space: what models, what prompting styles, what domains could appear in test? Allocate generation budget to cover gaps, not duplicate what you have. For each new generation method, check if it improves CV on a held-out diverse validation set. Stop when marginal CV gain drops below noise threshold. Generate with high temperature, varied top-k/top-p to capture the long tail of generation styles.
