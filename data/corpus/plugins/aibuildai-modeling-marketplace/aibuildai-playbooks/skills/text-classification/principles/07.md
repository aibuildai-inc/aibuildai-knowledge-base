## Principle 7: Optimize Batch Processing for Efficiency Without Sacrificing Accuracy

*Consensus: Common in the kernel-limited Quora competition - 2nd place Quora reduced runtime 40% with adaptive padding*

Instead of padding all sequences to maximum length globally, pad to the maximum (or 95th percentile) length within each batch. This dramatically reduces computation while maintaining accuracy, allowing you to train more models or use larger architectures within time limits.

**Why this matters:** Global padding wastes computation on padding tokens. The 2nd place Quora solution padded to batch-level max or 55 tokens (whichever was less) during training and 70 during inference. This let them train 6 models instead of 5 within kernel time limits, and ensembling 6 beat ensembling 5. The accuracy drop from occasional truncation was negligible (< 0.001 CV) because most sequences were short.

**When to use:** When you have strict runtime limits (kernel competitions, production inference SLAs). When sequence length distribution is highly skewed (many short, few very long). When you want to train more models for ensembling. When using RNNs/LSTMs where padding multiplies compute linearly.

**When NOT to use:** When using transformers with positional encodings that expect fixed-length inputs (though dynamic masking works). When your sequences have uniform length (padding savings are minimal). When truncation would lose critical information (e.g., sentiment often appears at the end of reviews).

**How to reason about it:**
Profile your training: what % of compute is on padding tokens? If > 30%, adaptive batching helps. Plot sequence length distribution: if p95 << max length, batch-level padding saves a lot. Test truncation sensitivity: train with global max, then with 95th percentile, measure CV drop. If drop < 0.001, it's worth it. For RNNs, batch by similar lengths to maximize efficiency.

```python
# Adaptive padding data generator
class AdaptivePaddingGenerator:
    def __init__(self, texts, labels, batch_size, max_len=None, percentile=95):
        self.texts = texts
        self.labels = labels
        self.batch_size = batch_size
        self.max_len = max_len
        self.percentile = percentile
    
    def __iter__(self):
        indices = np.random.permutation(len(self.texts))
        for start in range(0, len(self.texts), self.batch_size):
            batch_indices = indices[start:start + self.batch_size]
            batch_texts = [self.texts[i] for i in batch_indices]
            batch_labels = [self.labels[i] for i in batch_indices]
            
            # Pad to batch-level max or percentile, not global max
            batch_lengths = [len(text) for text in batch_texts]
            pad_len = int(np.percentile(batch_lengths, self.percentile))
            if self.max_len:
                pad_len = min(pad_len, self.max_len)
            
            # Pad and truncate
            batch_texts_padded = pad_sequences(batch_texts, maxlen=pad_len)
            
            yield batch_texts_padded, np.array(batch_labels)

# Usage: train 6 models instead of 5 with same runtime
for seed in range(6):  # Was 5 before adaptive padding optimization

    model.fit(AdaptivePaddingGenerator(X_train, y_train, batch_size=256))
```
