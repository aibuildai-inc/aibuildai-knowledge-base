## Principle 1: Choose Architecture Based on Data Scale and Domain Characteristics

*Consensus: Seen across the source competitions - Quora winners used embeddings+RNN (2018-2019), LLM detection winners used transformers+LLMs (2023+)*

Match model complexity to dataset size and task complexity. Traditional embeddings (FastText/GloVe) + RNN for datasets under 2M samples with clear patterns; transformers (BERT/DeBERTa) for 100k+ samples with subtle patterns; LLM-based approaches for generation detection.

**Why this matters:** Transformers require massive data to avoid overfitting their hundreds of millions of parameters. On small datasets, BiGRU + embeddings can beat transformer approaches because there is too little data to properly train transformers. Conversely, LLM detection tasks need transformer-scale models to capture generation artifacts that embeddings miss.

**When to use:** Dataset size < 500k and task has clear lexical patterns (keywords, n-grams) → embeddings + RNN. Dataset size > 100k with subtle contextual patterns → transformers. Task involves distinguishing LLM outputs → use LLMs themselves (perplexity, token probabilities) or large transformers.

**When NOT to use:** Don't use transformers on tiny datasets (< 10k samples) - they will overfit catastrophically. Don't use embedding-only approaches for multilingual tasks where you need cross-lingual transfer. The Quora competition (1.3M samples) was won with BiGRU+embeddings because compute constraints favored simpler models that could be ensembled 10+ times.

**How to reason about it:**
Ask: (1) How many samples do I have per class? (2) Are the distinguishing features lexical (keywords, character patterns) or semantic (context, tone)? (3) What's my compute budget? If you can train 10 small models vs 1 large model, the ensemble often wins. If the private test includes new generation methods not in training (LLM detection), you need architectural diversity.
