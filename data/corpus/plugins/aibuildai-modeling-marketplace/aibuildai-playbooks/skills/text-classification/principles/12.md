## Principle 12: Use Perplexity and Token Probability Features for LLM Detection

*Consensus: 3/5 LLM detection winners - 8th place scored 0.956 with perplexity+GLTR alone*

For detecting LLM-generated text, use the target LLM (or a similar LLM) to compute perplexity and token-level probability distributions. LLM-generated text has lower, more concentrated perplexity than human text. Combine with GLTR features (count of tokens in top-10, top-100, top-1000 ranks).

**Why this matters:** LLMs generate fluent text by sampling high-probability tokens. This leaves a signature: LLM text has lower perplexity (the model is more confident) and more tokens in the top-10 ranks. Human text has higher variance - creative word choices, context-dependent surprises. The 8th place solution used only perplexity + GLTR features from GPT-2 large (no fine-tuning) and scored 0.956 private LB, beating many fine-tuned transformer solutions.

**When to use:** When you need to detect LLM-generated text. When you have access to an LLM similar to the generation model (GPT-2 to detect GPT-3/4, LLaMA to detect Mistral). When you need a fast, lightweight solution (computing perplexity is 10x faster than fine-tuning transformers). When fine-tuned transformers are overfitting to specific generation styles.

**When NOT to use:** When the generation model is completely different from your detection LLM (e.g., using GPT-2 to detect text from a domain-specific fine-tuned model). When human text in your domain is highly formulaic (technical writing, legal documents) - perplexity gaps shrink. When you have large diverse training data and can fine-tune DeBERTa (usually achieves 0.97+, better than perplexity alone).

**How to reason about it:**
Choose detection LLM: ideally same family as generation model. Larger is better (GPT-2 large > medium > small). Compute text-level perplexity and sentence-level perplexity (humans vary more sentence-to-sentence). Compute GLTR features: for each token, count how many fall in top-10, 10-100, 100-1000, 1000+ probability ranks. Train a lightweight classifier (LightGBM, SVM) on these features. Ensemble with fine-tuned models for best results.

```python
# Perplexity and GLTR feature extraction
from transformers import GPT2LMHeadModel, GPT2Tokenizer
import torch

model = GPT2LMHeadModel.from_pretrained('gpt2-large')
tokenizer = GPT2Tokenizer.from_pretrained('gpt2-large')
model.eval()

def compute_perplexity_and_gltr(text):
    inputs = tokenizer(text, return_tensors='pt')
    with torch.no_grad():
        outputs = model(**inputs, labels=inputs['input_ids'])
        loss = outputs.loss
        perplexity = torch.exp(loss).item()
    
    # Token probabilities for GLTR
    logits = outputs.logits
    probs = torch.softmax(logits, dim=-1)
    
    # For each token, find its rank in probability distribution
    token_ids = inputs['input_ids'][0, 1:]  # Skip BOS token
    ranks = []
    for i, token_id in enumerate(token_ids):
        token_probs = probs[0, i, :]
        sorted_indices = torch.argsort(token_probs, descending=True)
        rank = (sorted_indices == token_id).nonzero(as_tuple=True)[0].item()
        ranks.append(rank)
    
    # GLTR features: count tokens in top-10, 10-100, 100-1000, 1000+
    ranks = np.array(ranks[25:])  # Skip first 25 tokens (no context)
    gltr_features = [
        (ranks < 10).sum(),
        ((ranks >= 10) & (ranks < 100)).sum(),
        ((ranks >= 100) & (ranks < 1000)).sum(),
        (ranks >= 1000).sum()
    ]
    
    return [perplexity] + gltr_features
```
