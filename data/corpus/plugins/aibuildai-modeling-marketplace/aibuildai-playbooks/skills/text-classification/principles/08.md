## Principle 8: Use Custom Loss Functions to Match the Metric and Class Imbalance

*Consensus: Several solutions changed the loss to match the metric or the label structure - 20th place Quora gained +0.002 CV by adding a soft F1 loss to BCE*

When the evaluation metric scores something that plain BCE does not optimize directly (F1 at a threshold, ranking order, an average over classes), add loss terms that target it, or weight samples so the loss counts what the metric counts. Standard BCE optimizes average log-likelihood and can drift from the metric under class imbalance or per-class scoring.

**Why this matters:** The 20th place Quora solution switched from BCE to BCE + soft F1 loss on the last day and gained 0.003 on the public LB and 0.002 on CV, because the competition metric was F1. The 1st place LLM detection solution trained one model with BCE on continuous labels (essays from instruction-tuned LLMs got a score below 1) and another with a pairwise margin loss for ranking. When a metric averages a score over classes (for example macro F1), weighting each class's loss term against its frequency keeps rare classes from being ignored.

**When to use:** When the metric is threshold-based (F1), rank-based (AUC, pairwise order), or averaged over classes (macro F1). When class imbalance is severe and the minority class matters to the metric. When standard training gives high overall accuracy but fails on rare classes.

**When NOT to use:** When the metric is plain log-loss, which BCE already optimizes. When a simpler change does as well: the 1st place Quora solution found focal loss similar to its baseline. When the metric is a micro average that counts every sample equally, class reweighting moves the loss away from the metric.

**How to reason about it:**
Map the evaluation metric to loss components. If the metric is F1, add a differentiable soft F1 term to BCE. If the metric averages over classes, weight each class's term. Start with equal weights across components and tune if one dominates. Monitor the real metric per class during training - if one lags, increase its loss weight.

```python
import torch
import torch.nn.functional as F

# BCE + soft F1 for an F1-scored task
def bce_soft_f1_loss(logits, targets, f1_weight=0.5):
    bce = F.binary_cross_entropy_with_logits(logits, targets)
    probs = torch.sigmoid(logits)
    tp = (probs * targets).sum()
    fp = (probs * (1 - targets)).sum()
    fn = ((1 - probs) * targets).sum()
    soft_f1 = 2 * tp / (2 * tp + fp + fn + 1e-8)
    return (1 - f1_weight) * bce + f1_weight * (1 - soft_f1)

# Class-weighted BCE when the metric averages over classes (multi-label)
def class_weighted_bce(logits, targets, class_freq, power=0.5):
    """
    logits, targets: (batch_size, n_classes)
    class_freq: (n_classes,) positive rate of each class in training data
    power: 0 = no reweighting, 1 = full inverse frequency; tune on validation
    """
    weights = (1.0 / class_freq.clamp(min=1e-6)) ** power
    weights = weights / weights.mean()
    bce = F.binary_cross_entropy_with_logits(logits, targets, reduction='none')
    return (bce * weights).mean()
```
