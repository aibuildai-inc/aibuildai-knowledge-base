## Principle 10: Handle Data Corruption with Targeted Augmentation, Not Cleaning

*Consensus: 3/5 LLM detection solutions - 4th place embraced typos instead of fixing them*

When test data is corrupted (typos, obfuscations, encoding issues), don't spend effort cleaning it. Instead, corrupt your training data in the same way. Add random character insertions/deletions/swaps, spelling errors, case flips to generated samples to match test corruption.

**Why this matters:** The LLM detection test data had random character-level obfuscations (not keyboard typos - truly random). The 4th place solution initially tried spell-checking and saw overfitting (human text was clean, LLM text had typos). Instead, they added random typos to 30% of LLM-generated training samples, which made the model robust to test obfuscations without sacrificing performance on clean text.

**When to use:** When you observe systematic corruption in test data (character-level noise, encoding artifacts, OCR errors). When adversarial validation shows test data has different character distributions. When cleaning test data is forbidden (competitions) or impractical (real-time inference). When corruption affects one class more than another (creates spurious signal).

**When NOT to use:** When test data is clean and your training data is corrupted (then do clean training data). When corruption patterns are complex/structured (e.g., domain-specific obfuscation) and require specialized decoding. When your model architecture is already robust to character noise (e.g., character-level CNNs, subword tokenization).

**How to reason about it:**
First, characterize the corruption: is it random character noise, systematic encoding issues, or adversarial obfuscation? Sample test data and compare character distributions, n-gram entropy, special character frequency to training. Match corruption type and rate in augmentation. If random, add random; if keyboard-typo-like, add neighbor-key swaps. Validate: does augmented training data match test data character distributions?

```python
# Random character corruption (match test distribution)
import random

def add_random_corruption(text, corruption_rate=0.05):
    """
    Randomly insert/delete/swap/replace characters
    corruption_rate: probability of corrupting each character
    """
    chars = list(text)
    corrupted = []
    
    for char in chars:
        if random.random() < corruption_rate:
            corruption_type = random.choice(['insert', 'delete', 'swap', 'replace'])
            
            if corruption_type == 'insert':
                corrupted.append(char)
                corrupted.append(random.choice(string.ascii_lowercase))
            elif corruption_type == 'delete':
                pass  # Skip this character
            elif corruption_type == 'swap':
                corrupted.append(char.swapcase())
            elif corruption_type == 'replace':
                corrupted.append(random.choice(string.ascii_lowercase))
        else:
            corrupted.append(char)
    
    return ''.join(corrupted)

# Apply to synthetic data (match test corruption distribution)
for i, (text, label) in enumerate(train_data):
    if label == 1:  # Only corrupt LLM-generated text if that's what's corrupted in test
        train_data[i] = (add_random_corruption(text, corruption_rate=0.05), label)
```
