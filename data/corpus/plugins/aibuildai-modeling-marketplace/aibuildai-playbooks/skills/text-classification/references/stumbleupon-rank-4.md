# Sharing my solution - Ranked #4

Competition: stumbleupon
Rank: #4
Source: https://www.kaggle.com/c/stumbleupon/discussion/6207

<p>Hello everyone! In the spirit of community learning, I'm sharing the code that I used to produce my top-scoring submission. You can get it on github at&nbsp;<a href="https://github.com/saffsd/kaggle-stumbleupon2013">https://github.com/saffsd/kaggle-stumbleupon2013</a>&nbsp;.</p>
<p>This submission scored 0.87777 (Rank #300) on the public leaderboard and 0.88764 on the private leaderboard (Rank #4).</p>
<p>My original submission was inspired by Abhishek's &quot;Beating the Benchmark&quot; post on the competition forum [2]. I found it quite interesting that such a simple solution was proving so difficult for many people&nbsp;to beat, and that prompted me to start investigating if there was any&nbsp;possibility to do better. The approach I took has previously been described as &quot;overkill analytics&quot; [3] - the plan of action was simply&nbsp;to generate as many derivative features as possible from each webpage,&nbsp;and then use machine learning to establish the best weights for them&nbsp;via the training data.</p>
<p>Feature extraction is implemented in `raw2tsv.py`, and this was used to generate features in a TSV format. I generated three broad classes of&nbsp;features: (1) text-based, where each feature is a string, (2) count-based,&nbsp;where occurrances of particular items were counted, and (3) length-based,&nbsp;where the lengths of particular fields were counted. In the end, based on&nbsp;my internal cross-validation results, I only utilized the text-based features for the submission. Feature extraction relied heavily on parsing&nbsp;the HTML of the document, and extracting the content of various nodes.&nbsp;`raw2tsv.py` was written to be re-usable as a general profiler for HTML&nbsp;documents.</p>
<p>`SEP09b.textstacking.py` implements the actual classifier. I used&nbsp;Abhishek's code as a starting point, and that can be recognized in the&nbsp;choice of some parameters as well as some of the general structure, but&nbsp;I have also modified the code substantially. The biggest change is probably&nbsp;the implementation of a stacking-based approach to combining the features&nbsp;I generated. Details of this approach can be found in a paper I wrote in&nbsp;2012 [4], where I applied it to a different task. The gist is simple - generate &quot;features&quot;, which are chunks of text - for example, the title of&nbsp;the document, the body of the document, etc. For each feature, construct&nbsp;the bag-of-words and use that to train a logistic regression classifier,&nbsp;then use another logistic regression unit to combine the predictions of&nbsp;each individual classifier.</p>
