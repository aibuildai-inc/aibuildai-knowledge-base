# 12th place solution: DeBERTa + TF-IDF

Competition: llm-detect-ai-generated-text
Rank: #12
Source: https://www.kaggle.com/c/llm-detect-ai-generated-text/discussion/470396

Thanks to the organizers for hosting such an interesting competition.
Final Solution used an ensemble of DeBERTa and TF-IDF.

## Key point

1. TF-IDF uses test dataset
2. As broad of data as possible

Let me share my thoughts on TFIDF. This method only considers the n-grams from the test set, which is the set that needs to be predicted. This means that the n-grams we obtain from the test set are definitely clean and useful features. Using these features to train on the training set is very correct and efficient. From another perspective, this is tantamount to leaking data (features) from the test set. In Kaggle competitions, data leakage can be particularly useful, so there's no reason not to employ it.

## Dataset

In the early stage, data was generated for each prompt in the Persuade corpus. However, when I trained the DeBERTa model on this data, I found that it performed poorly on LB. Therefore, I gave up using this part of the dataset for training and used it as my local CV dataset. This competition made me think of Stable Diffusion - Image to Prompts, so I started considering trying to use a more extensive dataset.

In the process of searching for datasets, I found that there were many datasets to choose from. After careful consideration, I selected the tiiuae/falcon-refinedweb dataset. The reason for choosing this dataset is mainly because it has undergone detailed filtering and performed better than other datasets in Falcon's paper.

Because my goal is to find the most comprehensive data possible, I will consider the entire text of the first chunk file in dataset as a starting text pool. For the text in other chunk files, I will calculate the similarity(using BAAI/bge-base-en-v1.5) between the current text and all the text in the previous text pool. Only when the similarity is below the threshold (0.7) will the text be added to the text pool.

After length filtering (>768 tokens), the final dataset contains approximately 600k data.

For each text, I randomly extract a part of the text. Then, the text of random length(128~384) at the beginning is taken as context guidance, while the remaining text is used as training data (generated=0). For the extracted context, input to different LLMs to continue writing the text based on the style of the context (generated=1).

Based on my experience and observation, the quality of LLMs generated by all other models except mistral and llama2 is not very high, so I mainly use these two LLMs and their variations. 

Some LLMs generate very short sequences, and most of these short sequences are of low quality, so I added a length filter(>170 tokens) afterwards.

Finally, LLM generated approximately 410k of data. Therefore, the final data set consists of 820k text with a 1:1 ratio of positive and negative samples.

For a given context, I have a real text and a text generated by LLM, with the lengths of the two texts varying significantly. Therefore, during the training process of DeBERTa, the text is randomly truncated to randint(128, min(origin_len, LLM_len)), which ensures that the length distribution of texts with different labels is consistent during the training process, avoiding the model from learning the irrelevant variable of text length.

## Model

### deberta

  + model id: deberta-v3-large
  + train & infer length: 512
  + epoch: 3
  + head: mean-pooling
  + LLRD

### TF-IDF

copy from [LLM DAIGT Analyse edge cases](https://www.kaggle.com/code/batprem/llm-daigt-analyse-edge-cases)

I attempted to make some modifications, but the improvement was not significant enough for me to adopt them. 
There must be a huge difference between the distribution of local data and test set. In order to avoid overfitting on local data and better utilize the test set, I have decided not to make any modifications.

### Ensemble

TF-IDF : deberta = 0.85 : 0.15

The weights are determined based on the average of local and LB performance.

## Abandoned idea

The following ideas were evaluated after initial attempts and found to be possibly beyond my capabilities or require a significant amount of computation, so they were abandoned halfway through. Perhaps there are better methods among these ideas, but I don't have the time/GPU to try them out.

1. Finetuning LLM to mimic the style of Persuade

  After fine-tuning, I found that the quality of LLM generated has decreased a lot and it did not make DeBERTa more difficult to distinguish, so I abandoned that approach.

2. Adversarial learning

  Let LLM generate data, DeBERTa selects difficult-to-distinguish hard samples, LLM continues to train on the hard samples and generate...

  After evaluating the required computing, I decisively gave up.

3. Finetuning LLM to classify

  It's need too much computing power. I sampled 82k from the 820k dataset to train Mistral-7b. Each epoch takes more than 10 hours using 3090Ti, but the score on LB is only 0.642. I don't have enough resources to keep trying.
