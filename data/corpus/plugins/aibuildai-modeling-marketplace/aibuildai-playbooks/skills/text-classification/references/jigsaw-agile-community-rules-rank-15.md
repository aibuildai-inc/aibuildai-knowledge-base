# 15th Place Solution - Jigsaw Agile Community Rules

First, we thank the organizing team for hosting this competition. It was a great opportunity to learn practical LLM fine-tuning. We also thank our teammates (kfsky, hasibirok0) for competing together over a long stretch.

In this competition, Test-Time Training (TTT) was effectively mandatory, making it quite different in nature from conventional competitions. We treated it as a “game” of maximizing the score by optimizing training and inference within a 12-hour limit, and enjoyed the challenge.

## Overview

Our solution achieved 15th place using an ensemble of seven diverse models (Public LB: 0.93183 / Private LB: 0.92657).  
Qwen3-4B was the only single model scoring above 0.92, but the ensemble brought us to 15th overall. It was interesting to obtain a strong result despite having few high-performing single models.


Ensemble concept:   
We focused on maximizing diversity by varying model architectures, tasks, and training data. Even models with single-model scores in the 0.88x range were included because they helped in the ensemble.  

## Validation Strategy

We did not use CV; we evaluated effectiveness using only the Public LB. The test set (55k) is sufficiently large, and the public/private split is random, so we trusted the Public LB.

## Data Processing

Common preprocessing across models:
- Subreddit field: kept as context (format: `r/{subreddit}`)
- Deduplication: applied to classification models with `subset=[body, rule]`. For causal models, we did not deduplicate to preserve data diversity.
- Test-Time Training (TTT): used test.csv for training. Since train.csv has limited rule variation, we combined it with TTT for some models to supplement diversity.

Synthetic data (kfsky):
- gpt-oss-120b: 4,000
- Qwen3-235B: 7,500
- Qwen3-Next-80B: 7,500
- Used for continued training of DeBERTa and for Qwen2.5-7B

## Key Techniques

### 1. Qwen3-4B: Few-shot focusing on rule compliance (hasibirok0)

Base: The initial approach predicted rule violations and achieved 0.918 Public LB.

Idea: We changed the task from violation prediction to compliance prediction.

Implementation:
```python
# Before (violation prediction, 0.918)
BASE_PROMPT = '''You are given a comment from reddit and a rule. Your task is to classify whether the comment violates the rule. Only respond Yes/No.'''

# After (compliance prediction, 0.920)
BASE_PROMPT = '''You are given a comment from reddit and a rule. Your job is to classify whether the comment complies with the rules or not. Please only answer "Yes" if it complies and "No" if it violates them.'''
```

Prompt format:
```
You are given a comment from reddit and a rule. Your job is to classify
whether the comment complies with the rules or not. Please only answer
"Yes" if it complies and "No" if it violates them.

Subreddit: r/{subreddit}
Rule: {rule}
Examples:
1) {negative_example}
Answer: Yes

2) {positive_example}
Answer: No

---
Comment: {body}
Answer:
```

Training:
- Few-shot with one positive example + one negative example
- Trained the model to predict compliance ("Yes") vs violation ("No")
- At inference, used the probability of the "No" token for submission to maintain consistency

Result: 0.918 → 0.920 Public LB (+0.002)

The exact reason for this improvement remains unclear and requires further investigation.

### 2. DeBERTa-v3: Continued training with synthetic data (kinosuke)

Base: We used a [public notebook](https://www.kaggle.com/code/nahidhossainredom/deberta-v3-base-3-epochs-lb-0-906) that achieved 0.906 as the baseline.

Idea: Two-stage continued training using synthetic data as pretraining.

Implementation:

Stage 1: Pretraining on synthetic data
- Train DeBERTa on 19,000 synthetic examples
- Use 19,000 synthetic samples generated by GPT-oss-120B, Qwen3-235B, and Qwen3-Next-80B for training, and use train.csv for validation.
- 3 epochs
- Save checkpoint weights

Stage 2: Fine-tuning on test data
- Load the Stage 1 checkpoint
- Continue training on test.csv (deduplicated on [body, rule])
- 3 epochs

Result: 0.906 → 0.909 Public LB (+0.003)

---

### 3. Gemma2-2B: Efficient classification via extended LoRA (kinosuke)

We adapted LMSYS's [public notebook code](https://www.kaggle.com/code/emiz6413/training-gemma-2-9b-4-bit-qlora-fine-tuning) for the Jigsaw task and expanded the target modules for LoRA.

Implementation:

Architecture:
- Base: `google/gemma-2-2b-it`
- LoRA: r=16, alpha=32, dropout=0.1
- Expanded target modules to seven: `q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj`

Training:
- 2 epochs
- Learning rate: 2e-5 (with linear warmup)
- Batch size: 16
- Max length: 384

Data:
- test.csv (deduplicated, subset=[body, rule])

Input format:
```
{body}
{url_semantics}
Rule: {rule}
Subreddit: r/{subreddit}
```

Result: 0.914 Public LB / 0.906 Private LB in 90 minutes

### 4. Qwen-2.5-7B (kfsky)
We controlled the number of steps and used it as one component of the ensemble. The original score was PB 0.911, but runtime became a bottleneck during ensembling, so we reduced the number of steps. Reducing steps lowers the single-model score, but increases ensemble diversity, so we included it.


## Ensemble Strategy

### Rank averaging

Convert all predictions to ranks before blending:

```python
r_model = predictions.rank(method='average') / (len(predictions) + 1)
```

### Final weights

```python
blend = (
    0.20 * r_causal_qwen25_7b +
    0.25 * r_causal_qwen3_4b +
    0.20 * r_seqcls_gemma2 +
    0.125 * r_cls_deberta +
    0.075 * r_seqcls_modernbert_base +
    0.075 * r_cls_bge +
    0.075 * r_e_e5
)
```
Note: We found that weight adjustments had minimal impact on the final score.

## Ineffective Approaches

- EMA (Exponential Moving Average): tried because it appears in top MAP competition solutions; no improvement in our experiments
- Ensemble weight optimization: changing weights barely affected the score

- Semantic model ensemble: concatenating embedding vectors + PCA to 1024 dims worsened performance compared to single models

- Synthetic data for TTT
   - Only effective when using more steps with Qwen2.5-7B zero-shot
   - No effect for Qwen3-4B few-shot
   - No effect for other classification models

- Rejected models (due to inference time vs score tradeoff)
   - DeepSeek-R1-7B
   - mpnet 
   - ettin
   - Gemma2-9B

- Prompt changes
   - Step-by-step reasoning prompt
   - Chain-of-thought prompting
