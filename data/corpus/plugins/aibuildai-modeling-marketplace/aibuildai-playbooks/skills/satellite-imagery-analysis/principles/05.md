## Principle 5: Combine BCE and Dice Loss to Balance Pixel-Wise Accuracy and Region Overlap

*Consensus: BCE+Dice combinations were the most common segmentation loss; pure Dice rarely won*

BCE loss optimizes pixel-wise classification but ignores spatial structure. Dice loss directly optimizes the evaluation metric but is unstable with small objects. Combining them (e.g., 0.75×BCE + 0.25×Dice or 0.5×BCE + 0.5×Dice) gives stable gradients and metric-aligned optimization.

**Why this matters:** Pure BCE can produce fragmented predictions (high pixel accuracy, poor Dice). Pure Dice has vanishing gradients when predictions are far from ground truth, slowing convergence. The 1st-place cloud solution used 0.75 BCE + 0.25 Dice. Several top cloud solutions used an unweighted BCE + Dice sum. Focal loss was tried by many but rarely beat BCE+Dice.

**When to use:** Use BCE+Dice when: evaluation metric is Dice/IoU/F-score, objects vary in size, class imbalance exists but isn't extreme. Start with equal weights (0.5/0.5), then tune on validation.

**When NOT to use:** For extreme imbalance (99%+ background), try Focal loss instead of or in addition to BCE. If evaluation metric is pixel accuracy (not Dice), pure BCE is fine. If training is unstable, increase BCE weight (e.g., 0.75 BCE + 0.25 Dice).

**How to reason about it:**
Start with 0.5 BCE + 0.5 Dice. If training is noisy/unstable, shift toward BCE (0.75/0.25). If local CV is good but LB is bad, shift toward Dice (0.25/0.75) to align training with the metric. Monitor both losses separately during training to see which dominates.

```python
def bce_dice_loss(pred, target, bce_weight=0.75):
    bce = F.binary_cross_entropy_with_logits(pred, target)
    pred_prob = torch.sigmoid(pred)
    intersection = (pred_prob * target).sum()
    dice = (2 * intersection) / (pred_prob.sum() + target.sum() + 1e-8)
    dice_loss = 1 - dice
    return bce_weight * bce + (1 - bce_weight) * dice_loss
```
