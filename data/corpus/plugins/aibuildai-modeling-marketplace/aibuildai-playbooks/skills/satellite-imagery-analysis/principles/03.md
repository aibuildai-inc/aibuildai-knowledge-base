## Principle 3: Detect and Handle Spatial Overlaps to Avoid Data Leakage

*Consensus: Top solutions in both competitions with overlapping images (Airbus ships, Draper chronology) explicitly found and used the overlaps*

Satellite images are often tiled from larger acquisitions, creating overlap between train and test, or between train samples. Overlapping tiles must be grouped and split carefully to avoid leakage, or exploited as a regularization signal.

**Why this matters:** The 9th-place ship detection solution found 57,877 groups of overlapping images. Splitting naively (random split) leaks test information into training. The leakage inflates local CV but doesn't transfer to the real test set. Conversely, same-acquisition images can provide weak labels or consistency checks.

**When to use:** Always check for overlaps when: data comes from tiled/windowed large acquisitions, images have spatial metadata (lat/lon), train and test are from the same region. The ship detection winners ran an overlap detection algorithm (finding pairs with matching pixels) then used friend-circles clustering to group all connected tiles.

**When NOT to use:** Skip overlap handling if images are truly independent (different acquisition dates, different geographic regions with no overlap). Independent patches with no overlap can still need grouping by shared metadata for other reasons (see Principle 8).

**How to reason about it:**
Steps: (1) Hash image content or use metadata to find potential overlaps. (2) Build a graph where nodes=images, edges=overlaps. (3) Find connected components (friend circles). (4) Ensure train/val split keeps entire groups together—never split a connected component. (5) Optionally: use overlap as augmentation by training on slightly shifted crops of the same area.

```python
# Detect overlaps by hashing
import hashlib
def image_hash(img):
    return hashlib.md5(img.tobytes()).hexdigest()

# Group overlapping images
```
