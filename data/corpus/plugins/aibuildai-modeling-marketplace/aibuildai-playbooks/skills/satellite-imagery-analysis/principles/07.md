## Principle 7: Optimize Threshold Separately from Model Training Using Validation Data

*Consensus: Many solutions tuned thresholds explicitly on validation, often together with a minimum mask size*

The model outputs probabilities; the threshold for binarization is a separate hyperparameter that should be tuned on validation data. Don't default to 0.5.

**Why this matters:** Dice/F-score metrics are threshold-dependent. A model with 0.70 Dice at threshold 0.5 might achieve 0.72 at threshold 0.45. The ship detection 14th-place varied threshold by ship size: 0.99+ for small ships, 0.95+ for medium.

**When to use:** Always optimize threshold for Dice/F-score/IoU metrics. Grid-search the threshold on out-of-fold predictions, so that every threshold is chosen on data the model did not train on.

**When NOT to use:** If evaluation is log-loss or AUC (rank-based metrics), threshold doesn't matter. If you're ensembling many models, optimize threshold on the ensemble, not individual models.

**How to reason about it:**
Methods: (1) Grid search on validation: try thresholds 0.3-0.7 in steps of 0.05, pick best Dice. (2) Adaptive by size/confidence: high threshold for small/uncertain objects, low threshold for large/confident. The ship detection solutions combined them: a classifier threshold tuned on validation, and a pixel threshold raised for small ships.

```python
# Grid search threshold on validation
thresholds = np.arange(0.3, 0.7, 0.05)
best_th, best_dice = 0.5, 0
for th in thresholds:
    pred_binary = (y_pred_val > th).float()
    dice = dice_score(pred_binary, y_val)
    if dice > best_dice:
        best_dice, best_th = dice, th

# Adaptive threshold
th = 0.5  # default
if ship_size < 100:
    th = 0.99  # very high for small uncertain ships
elif classifier_prob > 0.95:
    th = 0.4  # lower for confident images
```
