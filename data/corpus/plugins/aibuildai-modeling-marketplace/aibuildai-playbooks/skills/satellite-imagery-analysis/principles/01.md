## Principle 1: Choose Architecture Based on Task Type and Data Resolution

*Consensus: Most top segmentation solutions used U-Net-family models; only 2 of the 6 ship-detection solutions used Mask R-CNN successfully*

For segmentation tasks, U-Net with strong encoders (ResNet, EfficientNet, SE-ResNeXt) dominates. For image-level classification on small patches (e.g., land-cover tags on fixed-size chips), pure CNNs work better. Instance segmentation needs special handling of overlapping objects.

**Why this matters:** U-Net's skip connections preserve spatial information critical for pixel-level predictions in satellite imagery. The encoder captures global context while the decoder reconstructs fine details. Mask R-CNN struggles because satellite objects often lack clear instance boundaries and overlap extensively.

**When to use:** Use U-Net/FPN for: segmentation tasks, when objects can touch/overlap, when you need pixel-perfect boundaries. Use pure CNN classifiers for: small fixed-size patches, binary classification tasks, when speed matters.

**When NOT to use:** Skip U-Net if you only need presence/absence classification with no localization. The top Planet Amazon solutions used ensembles of plain CNN classifiers (11 CNN architectures in 3rd place) without U-Net because the task was image-level multi-label classification on fixed-size chips. Avoid Mask R-CNN unless objects are clearly separated instances—it failed in ship detection where ships touch.

**How to reason about it:**
Ask: (1) Do I need pixel-level masks or just class labels? If masks → U-Net family. (2) Are objects separated or overlapping? If overlapping → U-Net handles it naturally via dense prediction; Mask R-CNN will struggle. (3) Is the image size large (>512px)? If yes, consider efficiency: U-Net encoder depth vs input resolution tradeoff.
