## Principle 11: Apply Post-Processing Based on Domain Constraints and Metric Characteristics

*Consensus: Many solutions used post-processing beyond simple thresholding; common: size filtering, morphology, metric-aware pruning*

After the model predicts, apply domain-specific rules: remove blobs smaller than physically plausible (ships <10px), apply morphological operations to separate touching objects (erosion+watershed), or prune predictions that hurt the metric (small uncertain masks with low F2).

**Why this matters:** The ship detection 9th-place used erosion+watershed to separate weakly connected ship masks. The 14th-place computed F2 score by ship size: small ships (<100px) had F2=0.2-0.3, so one false positive wipes out 4-5 true positives—they only predicted small ships if classifier confidence >0.99. Other top solutions kept post-processing minimal: the 4th-place cloud solution used only a minimum mask size, and the 1st-place ship solution avoided watershed because it needed too much post-processing.

**When to use:** Use post-processing when: domain constraints exist (minimum object size, shape regularity), objects should not overlap but model predicts overlaps, or metric penalizes certain errors asymmetrically (small FPs hurt F2 more than large FPs). Common steps: connected components analysis, size filtering, morphological opening/closing.

**When NOT to use:** Skip if the model already handles it (modern U-Nets often learn optimal shapes). Don't over-engineer rules on validation data—easy to overfit. The 11th-place ship solution tried to make predicted masks more rectangular, and the score only got worse.

**How to reason about it:**
Decision tree: (1) Does the metric penalize false positives heavily (F2, Dice)? If yes, consider pruning uncertain predictions. (2) Are there impossible shapes/sizes (ships <5px, buildings >10000px)? If yes, filter by size. (3) Do objects touch in prediction but should be separate? If yes, apply morphology. (4) Validate on holdout: does post-processing improve score? If no, skip it.
