# PAL

A reward-modeling framework, not a policy trainer: fit each user's preference as a point on the convex hull of a small number of shared prototypes, so a 2-layer MLP on frozen embeddings learns both what most people agree on and how individuals differ, instead of training one universal reward model.

**PAL** (Pluralistic Alignment Framework) is a framework for learning reward functions from heterogeneous human preferences, defined by "Chen et al., PAL: Pluralistic Alignment Framework for Learning from Heterogeneous Preferences" as a reformulation of alignment through the lens of the ideal point model and metric learning, replacing the standard assumption of a single universal reward [1]. Its parent is the Bradley-Terry-Luce (BTL) pairwise-comparison model that "most alignment literature" uses to fit one reward function per prompt regardless of who is being asked, including RLHF pipelines built on PPO and, implicitly, DPO, which "bypasses the status quo two-stage reward learning + RL pipeline and directly finetune[s] on pairwise preferences, but still implicitly assumes the BTL model for ranking" [1][2][3]. The paper is at https://arxiv.org/abs/2406.08469 [1]. PAL instead adopts Coombs' 1950 ideal point model, in which a person prefers whichever of two items sits closer, under some distance function, to an unknown per-person "ideal point," and models every user's ideal point as a convex combination of $K$ shared prototypes learned jointly with the distance mapping [1][4]. Three reasons the paper gives for existing: assuming one homogeneous BTL preference sidesteps the question of whose preferences a model is being aligned to; the alternative of hand-picking multiple named reward axes (e.g. helpfulness vs. harmlessness) is a top-down design choice, while real human preference is "more complex than the designer-specified axes"; and casting alignment as an ideal-point / metric-learning problem opens access to a distinct algorithmic toolbox, including generalization guarantees for locating new users with few comparisons [1]. The correct paper was confirmed by an exact title match on Semantic Scholar (52 citations), which also rules out an unrelated, differently-titled "Persona-Aware Alignment Framework" paper with 1 citation that a plain name search on "PAL" can otherwise surface [5].

PAL has no adopting landmark RLHF system in its own text; its own reported use is as a reward-model replacement inside a preference-learning pipeline, benchmarked directly against the personalized reward model of Li et al., 2024, which learns one general user embedding perturbed per user; PAL's own related-work section describes this formulation as still homogeneous, since it "can only generalize to unseen users using the fixed general user embedding" [1]. On the paper's own semi-synthetic Pick-a-Filter dataset, at mixture ratio 1 PAL reaches 95.2% test accuracy against 75.4% for a homogeneous reward model trained the same way — the deciding number showing the group structure is what buys the accuracy [1]. On Reddit TL;DR summarization, compared against Li et al.'s personalized reward model (a fully fine-tuned† 6B-parameter model), the paper's own Table reports PAL, using only 594K trainable† parameters over frozen `all-mpnet-base-v2` sentence embeddings (105M parameters, not trained), scores 59.28-59.66% seen and 59.15-59.45% unseen accuracy across $K=1,5,10$, against Li et al.'s 61.72% seen and 60.65% unseen (†these two parameter counts are not the same quantity: PAL's 594K is a small trainable head on top of a separately-computed, frozen 105M-parameter backbone, while Li et al.'s 6B figure is the full size of a model that is entirely fine-tuned end to end) — the paper calls this "on par performance, especially in terms of unseen accuracy," not an improvement [1]. On Pick-a-Pic v1, PAL's model B on CLIP-H/14 embeddings reaches 71.13±0.31% against SoTA PickScore's 71.85%, and on the "no-leakage" split of Pick-a-Pic v2 (samples with no overlap with PickScore's v1 training data) PAL's model B beats PickScore's own reported accuracy, 70.02% vs 68.04%, using a 2-layer MLP on a single RTX 4090 instead of fine-tuning ~1B CLIP parameters on 8×A100 GPUs [1]. Lineage in one line: BTL (Bradley & Terry, 1952) + ideal point model (Coombs, 1950) -> PAL (2024) [1][2][4]; no successor method building on PAL was found (see While it runs).

**When to pick it**: pick PAL when your preference data carries a per-annotator or per-user identifier and you suspect preferences differ systematically across sub-populations rather than being noisy realizations of one shared reward — it is a reward-model training method, not a policy-training method, and its own reward model must be converted into a standard scalar reward model before use in a downstream RL pipeline such as PPO, per the maintainer's guidance in the repository's issue tracker [7]. Prefer the parent BTL/standard reward model [2] when you have no reliable user identifier or expect preferences to be genuinely homogeneous. Prefer Li et al.'s personalized reward model [6] only if you need per-user personalization but have no reason to expect users cluster into a small number of shared prototypes, since it treats each user as an independent perturbation of one general embedding rather than a mixture member [1]. PAL is not an RL-training alternative to DPO or PPO; it produces the reward signal those methods would consume [1][2][3].

**Variant of**: the Bradley-Terry-Luce reward-modeling approach used across RLHF alignment [2], reframed through Coombs' ideal point model [4].

**Data it needs**: pairwise-comparison preference data where every example carries a user (or worker) identifier, in the reference implementation's own row format `(user_id, prompt, (response_1), (response_2)),y` with $y \in \{-1,+1\}$ [7]. No held-out chosen/rejected split beyond the pairwise label; no scalar per-answer reward is required at training time. Training is offline: it fits a static, pre-collected preference dataset rather than sampling fresh completions from a policy each step, and its output (a fitted reward model) can subsequently be plugged into an on-policy RL loop [1]. Reported training scales: a semi-synthetic Persona dataset with $N=10{,}000$ users per group [1]; a trimmed Reddit TL;DR set following Li et al.'s filtering, keeping only the top 10 workers by comparison count for the seen-user evaluation and holding out the rest for unseen-user evaluation [1][8]; and Pick-a-Pic v1/v2, around a million prompt-image preference pairs with anonymous user IDs, from which the paper additionally constructs a color-filter-injected "Pick-a-Filter" set [1][9].

**Extra models**: none beyond the small learned mapping itself, in the framework's own definition — no value network, no separate frozen reference-policy KL term, and no LLM fine-tuning; PAL trains a lightweight learned function (a one-layer MLP in the synthetic experiments, a two-layer MLP with residual connection in the real-data experiments) on top of a frozen foundation-model embedding (Sentence-BERT `all-mpnet-base-v2` for text, CLIP-H/14 or PickScore embeddings for images) [1][10]. A reward-model judge/annotator is only needed upstream to produce the labeled preference pairs, exactly as for any BTL reward model; PAL adds none beyond that. See Cost for what this buys in practice.

**Shipped by**: PAL's own README describes no trl or verl integration, and this card did not obtain a successful search of either library's own documentation or source for the term "PAL" (both GitHub code-search attempts returned an authentication error, not a result) — so whether trl or verl implements it is not checked, not confirmed absent. What is confirmed is that PAL must be run through its authors' own reference repository, `RamyaLab/pluralistic-alignment` on GitHub, which is a standalone set of training scripts (`main_pal_b.py`, `main_pal_b_fix_llm.py`, `main_pal_b_unseen.py`) plus an `integration/` module (`load_pal_rm_a()` / `load_pal_rm_b()`) that converts a trained PAL model into a standard HuggingFace-style scalar reward model for use in an existing RLHF pipeline [7]. The repository is unarchived and has 17 GitHub stars as of the fetch date; it carries no stated support-tier label such as "experimental" or "maintained" [11].

## How it works

Fit a shared embedding/distance mapping and a small set of $K$ prototype ideal points jointly with each user's mixture weights over those prototypes, by gradient descent on a pairwise ranking loss over batches of (left, right, context, user) comparisons [1].

**General reformulation.** The paper first rewrites the standard BTL-based alignment probability as a special case of the ideal point model, then generalizes it: for a link function $h$ and reward $r_\theta$,

$$ \Pr(\bxl \succ \bxr \mid \bxc) = h\big(r_\theta(\bxr;\bxc) - r_\theta(\bxl;\bxc)\big) $$

where $h$ is any monotonic, appropriately normalized link, recovering the BTL model when $h$ is the logistic sigmoid [1]. Two instantiations follow.

**Model A** (fixed prototypical ideal points, squared Euclidean distance) [1]:

$$ \Pr\nolimits_i(\bxl \succ \bxr \mid \bxc) = h\big(\lVert f(\bxr;\bxc) - f(\ba^{(i)})\rVert_2^2 - \lVert f(\bxl;\bxc) - f(\ba^{(i)})\rVert_2^2\big), \qquad \ba^{(i)} = \bP\bw^{(i)} $$

$f$ is a learned joint mapping of the response and context into a $d$-dimensional space, $\bP=[\bp_1,\dots,\bp_K]$ are $K$ shared prototype ideal points, and $\bw^{(i)}$ is user $i$'s mixture weight vector lying on the $K$-simplex $\Delta^K$ (nonnegative, summing to 1) [1].

**Model B** (prototype functions of the prompt, inner-product distance) [1]:

$$ \Pr\nolimits_i(\bxl \succ \bxr \mid \bxc) = h\big(\langle f(\bxr), z^{(i)}(\bxc)\rangle - \langle f(\bxl), z^{(i)}(\bxc)\rangle\big), \qquad z^{(i)}(\bxc) = \bG(\bxc)\bw^{(i)} $$

where $\bG(\bxc)=[g_1(\bxc),\dots,g_K(\bxc)]$ are $K$ learned prototype functions mapping the prompt into ideal-point space, letting a user's effective ideal point vary with the prompt [1]. The paper's own real-data comparisons use Model A for the text (summary) experiments and Model B for the Persona and image experiments [1]; the reference repository's own training-demo scripts, however, are all named for PAL-B (`main_pal_b.py`, `main_pal_b_fix_llm.py`, `main_pal_b_unseen.py`), and its README documents no PAL-A training script — only a `load_pal_rm_a()` loader for an already-trained Model A checkpoint — so only Model B has a documented training entry point in the repository [7].

**Learning algorithm** (identical structure for both models) [1]: sample a mini-batch of comparisons; compute each present user's ideal point from the current prototypes and that user's weights; compute the distance (Model A) or inner product (Model B) from each of the two responses to that ideal point; take the per-comparison loss $\ell(d_r - d_l)$ (hinge loss on the text experiments, logistic loss elsewhere in the paper) [1]; jointly update the mapping/prototype parameters $\theta,\bP$ (or $\theta,\{g_k\}$) and every user's weight vector $\bw^{(i)}$ by gradient ascent on the summed log-likelihood [1]. Optimization is Adam in every reported experiment, with separate learning rates for the projector and for the prototype/weight parameters [1].

**Worked example** (Model A, using the paper's own synthetic setup [1]): with $K=3$ prototypes and a user whose mixture weight is $\bw=[0.5,0.3,0.2]$, that user's ideal point is $\ba = 0.5\,\bp_1 + 0.3\,\bp_2 + 0.2\,\bp_3$. If a candidate response embedding $f(\bxl)$ lies distance $1.0$ from $\ba$ and $f(\bxr)$ lies distance $2.0$ from $\ba$, the model prefers the left response, since it is closer to the user's ideal point; with the logistic link $h$, $\Pr(\bxl \succ \bxr) = 1/(1+\exp(1.0^2 - 2.0^2)) = 1/(1+e^{-3}) \approx 0.953$ [1]. This arithmetic follows the paper's own stated distance-difference form of $h$; it is not attributed to any specific implementation's numeric convention.

**Seen vs. unseen evaluation.** "Seen accuracy" measures generalization to new comparisons from users already present during training (their weights $\bw^{(i)}$ were fit); "unseen accuracy" measures generalization to entirely new users, for whom the shared prototypes/mapping are frozen and only that user's weight vector is fit from a few of their own comparisons (few-shot localization), or, for zero-shot, a new user is assigned the population-average weighted prototype as their ideal point [1].

## Cost

**Theory, from the method's own math**: relative to fitting one shared BTL reward model, PAL adds only $K$ prototype vectors (Model A) or $K$ prototype functions (Model B) plus one weight vector $\bw^{(i)}\in\Delta^K$ per user — parameter growth is linear in the number of users only through these small weight vectors, not through duplicating the embedding mapping $f$ [1]. Relative to per-user independent models, it removes the need to fit a full mapping per user by sharing $f$ (and $\bP$ or $\{g_k\}$) across the whole population [1]. There is no extra forward pass analogous to a frozen reference-policy KL term and no second trained network analogous to a PPO critic; the formulas show only one trained mapping plus prototypes. A naive reading might expect cost to scale with $K$ times the embedding dimension for every comparison, but the per-comparison update only needs each present user's already-mixed ideal point $\ba^{(i)}$ or $z^{(i)}(\bxc)$, computed once per batch item, not the full prototype set repeatedly re-materialized per comparison.

**In practice, per implementation** (the authors' own reference repository; whether an established RLHF framework such as trl or verl also ships PAL was not checked, see Shipped by, so only this one entry is given [11]): the paper reports that most experiments ran on 4× RTX 4090 GPUs (24 GB VRAM each), that every experiment fits within 16 GB VRAM on a single RTX 4090, and that "a typical experiment can be finished within 2 hours" [1]. This is far below the compute the paper's own comparison points required: Li et al.'s personalized baseline fine-tunes a 6B-parameter supervised-fine-tuned model [1][6], and PickScore fine-tunes roughly 1B parameters of CLIP-H/14 on 8×A100 GPUs [1][9], against PAL's 594K trainable parameters on top of frozen embeddings for the text comparison, and a 2-layer MLP for the image comparisons [1]. The foundation-model embeddings themselves (Sentence-BERT `all-mpnet-base-v2` at ~105M parameters, or CLIP-H/14) are computed once and frozen, not fine-tuned, so their cost is a one-time embedding pass rather than a per-step training cost [1][10].

## How to use it

- Prepare pairwise comparisons with a user identifier attached to every row: the reference implementation's own format is `(user_id, prompt, (response_1), (response_2)),y` with $y \in \{-1,+1\}$ for which response that specific user preferred; it explicitly instructs users to edit `dataset_factory.py` to add a custom dataset, and ships only its own variant of the Reddit TL;DR summary set out of the box [7].
- Choose Model A when ideal points should be fixed per user regardless of prompt (used for the paper's synthetic and summary experiments); choose Model B when a user's effective preference should shift with the prompt (used for the paper's Persona and image experiments) [1].
- After training, convert the fitted PAL model into a standard scalar reward model before handing it to a downstream RL/RLHF pipeline — the repository author states this conversion step (via `integration/pal_integration.py`, exposing `load_pal_rm_a()` / `load_pal_rm_b()`) is required before use with a PPO-style trainer, and confirms trying "other PPO frameworks" is the recommended next step once converted [7].
- Inference requires a `user_id`: in response to a direct question, the repository author confirmed "we NEED to pass the user ID while inferencing the reward for any specific user" [7] — a PAL reward model cannot score a response for an unspecified/average user without falling back to the zero-shot weighted-prototype approximation described in How it works [1].
- Key knobs, with each source's own value ("not stated" = the source was checked and does not give it; "not checked" = this card did not verify that source's value there):

| knob | paper (synthetic setup) [1] | paper (Persona setup) [1] | reference repo default [7][11] |
| --- | --- | --- | --- |
| number of prototypes $K$ | 3 (with $K^\star=3$ true groups) | swept, fixed users/group $N=10{,}000$ | not stated (config-driven, per-dataset) |
| optimizer | Adam | Adam | not checked |
| projector learning rate | $5\times10^{-4}$ | $1\times10^{-4}$ | not checked |
| prototype/weight learning rate | $5\times10^{-3}$ | shared with projector lr | not checked |
| weight decay | $1\times10^{-3}$ | $1\times10^{-2}$ | not checked |
| loss function | hinge | logistic | not stated (`loss_config` folder, per-dataset) |
| user weight constraint | simplex $\bw^{(i)}\in\Delta^K$ | simplex $\bw^{(i)}\in\Delta^K$ | not checked |

  The gap between the synthetic and Persona hyperparameters (projector lr $5\times10^{-4}$ vs $1\times10^{-4}$; weight decay $1\times10^{-3}$ vs $1\times10^{-2}$) is the paper's own choice per dataset, not a framework default versus a paper value — there is only one source (the paper itself) for both columns, and no packaged default is given in the reference repository's README beyond pointing at per-experiment config folders [1][7].
- Group-size trade-off: on the paper's semi-synthetic Persona dataset, raising $K$ toward the true number of latent groups $K^\star$ increases seen accuracy up to 100% given enough users and comparisons per user [1]. Separately, on the paper's fully synthetic numerical-simulation dataset, the paper cautions that "without enough samples per user, learning diverse preferences can harm the performance" relative to a homogeneous model [1] — these are two distinct experiments (semi-synthetic Persona versus synthetic simulation) making a consistent point: larger $K$ needs more comparisons per user to localize each one, and unseen-user localization needs proportionally more few-shot comparisons as $K$ grows, since the weight vector to be learned grows with $K$ [1].

## While it runs

- **Signals and their healthy shapes**: the paper does not describe a live training dashboard or named logged metrics (no `wandb`-style guide was found in the paper or the reference repository's README); the closest first-hand signal is the seen/unseen accuracy split itself, tracked as validation accuracy on held-out comparisons for already-seen users versus a held-out set of entirely new users, which the paper uses throughout its own evaluation [1].
- **Published reference runs**: the paper's own Table for the Reddit TL;DR comparison is the closest published "known-good" reference curve: seen accuracy $59.28\pm0.14\%$ ($K=1$) to $59.66\pm0.09\%$ ($K=5$), unseen (zero-shot) accuracy $59.20\pm0.16\%$ to $59.45\pm0.12\%$, against Li et al.'s reported $61.72\%$ seen / $60.65\%$ unseen [1]. Separately, the reference repository's own README states, without a table, that on Reddit TL;DR "PAL is 1.7% more accurate for seen users and 36% more accurate for unseen users with 20× fewer parameters compared to strong baselines" [7] — a stronger claim than the arXiv paper's own Table above, which shows PAL essentially matching, not exceeding, the baseline on both splits. The README attributes this to the ICLR 2025 camera-ready version (a differently-titled "PAL: Sample-Efficient Personalized Reward Modeling for Pluralistic Alignment," accepted 2025-01-21) [7], which is not the version fetched for this card (arXiv 2406.08469 has only a v1) [12]; readers should treat the README's stronger numbers as belonging to that separate, unfetched revision rather than to the numbers cited elsewhere on this card.
- **Degeneracies and defaults**: a user with only a single available prototype ($K=1$) has nothing to localize — the paper notes that at $K=1$ "there is no further learning needed to generalize to new users," since there are no weights to fit over a single prototype [1]. A new user whose true ideal point lies outside the convex hull spanned by the learned prototypes cannot be represented by any mixture weight vector on the simplex — the paper states this directly as a limitation of the mixture-modeling approach [1]. The paper also separately warns that preference datasets collected under a strict labeling rubric tend to be artificially homogeneous, in which case even $K=1$ already matches state-of-the-art performance, meaning apparent "success" at $K=1$ may reflect low real diversity in the labels rather than the method's mixture structure adding nothing [1].
- **Named successors**: none found. This card fetched the titles and abstracts of all 52 papers citing arXiv:2406.08469 via the Semantic Scholar citations endpoint and read them for any paper that names PAL and frames itself as fixing a documented bias in it; several extend or critique mixture-of-prototypes-style personalization (e.g. "MiCRo: Mixture Modeling and Context-aware Routing for Personalized Preference Learning", "LoRe: Personalizing LLMs via Low-Rank Reward Modeling", "Personalized Alignment Revisited: The Necessity and Sufficiency of User Diversity"), but none frames itself against PAL's specific convex-hull-of-prototypes limitation, and none names PAL as the method it improves on in its own abstract [5]. Absence here reflects that specific search over those 52 abstracts, not an exhaustive one.
- **Known failure modes**: from the paper's own limitations section, the mixture model cannot generalize to a user outside the convex hull of the learned prototypes [1]. From the repository's closed GitHub issues (maintainer replies, checked 2026-08-10): a user asked how to feed a PAL reward model into a PPO fine-tuning pipeline for Llama3-8B, and the maintainer's reply made clear that a raw PAL model is not usable directly — it must first go through the `integration/pal_integration.py` conversion step to become a standard reward model before any PPO framework can consume it, and inference always requires an explicit `user_id`, so there is no direct "average-user" scoring path outside the paper's zero-shot weighted-prototype workaround [7][1].
- **What the gain is - and is not**: the paper's own Pick-a-Pic analysis is explicit that the underlying data collection process, not just the model, drives whether PAL's mixture structure adds value: because existing datasets are gathered under strict rubrics and heavy labeler monitoring, they "may not be heterogeneous," so PAL with $K=1$ can already match state-of-the-art performance on them — the paper frames its real gain as parameter/compute efficiency at matching accuracy (594K–2-layer-MLP-scale models against 1B–6B-parameter fine-tuned baselines), plus the ability to capture genuine preference diversity when it is present in the data, not a guaranteed accuracy improvement over a homogeneous reward model on every dataset [1].
