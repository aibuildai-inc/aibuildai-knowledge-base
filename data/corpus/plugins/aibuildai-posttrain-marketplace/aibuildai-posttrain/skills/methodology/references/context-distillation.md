# Context Distillation

**Item**: https://arxiv.org/abs/2209.15189 (Snell, Klein, and Zhong, "Learning by Distilling Context," submitted 2022-09-30)

Bake a prompt into the weights: sample the model's own completion under a long "teacher" prompt, strip the reasoning, then fine-tune the same starting weights to predict that answer from a short "student" prompt alone.

**Context Distillation**, full name "Learning by Distilling Context," is defined by Snell, Klein, and Zhong as a fine-tuning method built around a teacher template, a student template, a raw-input distribution, and an answer extractor, in which the model is conditioned on "[instructions] + [task-input]" to predict "[scratch-pad] + [final answer]," then the same model is fine-tuned to predict its own "[final answer]" conditioned on the "[task-input]" alone, without the instructions or the scratch-pad [1]. Its parent is classical knowledge distillation [2], which the paper describes as asking a teacher model with parameters $\theta_{TEACHER}$ to generate a label $y$ for input $x$ and training a student with different parameters $\theta_{STUDENT}$ to mimic the teacher by predicting $y$ conditioned on $x$ [1]; the paper's twist is that teacher and student start as the *same* weights, so the training signal comes from the difference between the two prompts and the answer extractor, not from a difference in parameters [1]. Three reasons the paper gives for the method: gains from prompting normally vanish once the context tokens are removed, so every inference call keeps paying for instructions and scratch-pads that can run more than 10x longer than the task input; it is unclear how to use context that exceeds the model's context window at all; and a KL-based fine-tuning objective transfers the teacher's token-level information more faithfully than fine-tuning on the hard extracted label [1].

The paper's own name for the method restates and generalizes two independently-discovered special cases: Askell et al. name the identity-template version "context distillation" for saving inference compute, and Choi et al. name the same special case "prompt injection" for parameterizing a fixed input; both are described as an identity student template and identity output selector inside this paper's more general framework, which also covers explanations, task-index re-association, and multi-context composition [1]. The originating paper's own reported gains are Rouge-L 9.0 to 34.7 for internalizing Natural-Instructions task instructions (teacher upper bound 43.4) with an 11.1x reduction in inference tokens [1]; on SPIDER text-to-SQL, context distillation beat directly fine-tuning on the same in-context examples by gradient descent, 22.1 vs. 13.4 exact-set-match on 4 examples and 27.9 vs. 18.9 on 8 examples (Table 2) [1]; and for 8-digit addition scratch-pads, direct-answer accuracy without a scratch-pad rose from 0% to 94.7% after distillation (rounded to 95% in Table 3), against a teacher using the scratch-pad at 93% (Table 3), with an 8.0x token reduction at inference [1]. Lineage in one line: knowledge distillation (Hinton et al., 2015 [2]) -> context distillation / prompt injection as narrow, identity-template cases (Askell et al. [3]; Choi et al. [4], 2021-2022) -> this paper's general framework (2022 [1]) -> a concurrent work on the step-by-step-reasoning case that the paper cites, under double-blind review at the time, only as "Anonymous, Large language models can self-improve, Submitted to ICLR 2023" [1]. The right paper was confirmed by an exact-title arXiv search for "Learning by Distilling Context," which returns this single paper at 2209.15189 [1].

**When to pick it**: pick context distillation when you already have a prompt (instructions, explanations, in-context examples, or a scratch-pad) that measurably helps the same model, want to keep that gain without paying its extra inference-time tokens, and can synthesize or sample enough unlabeled task inputs to distill on [1]. Prefer plain supervised fine-tuning on the extracted answers (the paper's "directly learning with gradient descent" baseline) only if compute is tight enough that generating and KL-matching against 100 token samples per example is not affordable; the paper's own comparison shows gradient descent on the same examples underperforming context distillation by 8.6-9.0 exact-set-match points on SPIDER [1]. Prefer classical (cross-model) knowledge distillation [2] when the goal is compressing a large teacher into a smaller, differently-sized student rather than removing a prompt from a fixed-size model. The nearest online neighbor is Generalized Knowledge Distillation (GKD): GKD also trains a student on its own on-policy generations scored by a teacher, but the teacher there is a separate, typically larger model, not the same weights under a different prompt [5].

**Variant of**: knowledge distillation [2], specialized to a same-weights, prompt-difference-driven setting; the two narrower prior instances the paper subsumes are "context distillation" [3] and "prompt injection" [4].

**Data it needs**: a raw task input distribution $D$ of unlabeled strings for the target task - the paper draws these from an existing training split (e.g., a task's Natural-Instructions or SPIDER training examples) or synthesizes them by few-shot-prompting the same model [1]. No labels, preference pairs, or scalar rewards are required; the "label" is whatever the teacher template + frozen weights produce, filtered by the answer extractor $f$ [1]. Training scale in the paper's main runs: 4096 distillation examples for 1 epoch, batch size 16, AdamW, no weight decay, except the step-by-step-reasoning transfer experiment (10k distillation examples mixed with 65536 Natural-Instructions examples, 3 epochs) [1]. The method is not on-policy RL: within one context-distillation operation the teacher's parameters $\theta_{TEACHER}$ stay fixed throughout, though the teacher completions used for training are sampled fresh from that fixed model rather than drawn from a static, pre-collected dataset [1].

**Extra models**: one frozen copy of the same weights, used only to sample teacher completions ($\theta_{TEACHER}$, fixed for the duration of one round) [1]; no value network, no separate reward model, and no judge model are part of the method's definition [1]. The only "reward" is the teacher's own generation, so the extra footprint is a second full copy of the model being trained, not a differently-sized model. Sequential distillation reuses the just-updated student as the next round's starting point, and the paper notes a further "recursive" variant, credited to Choi et al., in which the student itself becomes the new teacher next round, avoiding a separate frozen copy altogether [1]. See Cost for the memory implication of holding two copies during a round.

**Shipped by**: no framework in this corpus implements context distillation under this name or definition. trl ships a `DistillationTrainer`, but it implements Generalized Knowledge Distillation - training a smaller, separately-initialized student on its own on-policy generations scored by a distinct teacher model via a chunked Jensen-Shannon-divergence loss - which is the classical-KD-with-on-policy-sampling case this card's "nearest online neighbor" contrast covers, not the same-weights, template-difference mechanism this paper defines [5]. verl ships a related but likewise separate-model trainer, On-Policy Distillation (OPD): its own documentation describes it as training a student model on states drawn from the student's own policy while using one or more separate teacher models as the source of the distillation signal, and its config requires a distinct teacher checkpoint per `distillation.teacher_models.<name>.model_path`, so - like trl's GKD - it is not the same-weights mechanism this paper defines [6]. Building context distillation would mean adding, on top of an existing generation and fine-tuning loop: a teacher-template / student-template pair, an answer extractor $f$, sampling of teacher completions from a frozen copy, and a token-level KL loss (approximated with an empirical distribution over a fixed number of samples per position, 100 in the paper) between the teacher's and student's next-token distributions - a new loss and data-generation pipeline layered on a standard trainer, not a new sampling loop from scratch [1].

## How it works

One round: sample a raw input $x$ from $D$; sample a completion $y$ from the frozen teacher conditioned on $T_{TEACHER}(x)$; fine-tune the trainable student to predict $f(y)$ conditioned on $T_{STUDENT}(x)$ [1].

**The objective** (Eq. 1) [1]:

$$ L_{D,T_{STUDENT},T_{TEACHER},f,\theta_{TEACHER}}(\theta_{STUDENT}) = \mathbb{E}_{x \sim D}\Big[\, \mathbb{E}_{y \sim P_{\theta_{TEACHER}}(\cdot\,|\,T_{TEACHER}(x))} \big[\, \log P_{\theta_{STUDENT}}\big(f(y)\,\big|\,T_{STUDENT}(x)\big) \,\big] \,\Big] $$

$D$ is the raw-input distribution; $T_{TEACHER}$ and $T_{STUDENT}$ map a raw input to the full teacher/student prompt; $f$ extracts the target sub-sequence (e.g., the final answer) from the teacher's full sampled output $y$; $\theta_{TEACHER}$ is held fixed while $\theta_{STUDENT}$ is optimized [1]. In implementation the paper does not fine-tune on the hard extracted label $f(y)$ alone - that "wastes the token logit information and results in noisy gradients" - but instead minimizes the token-level KL divergence between student and teacher; because the vocabulary (50k-100k tokens) makes the full soft-label distribution too large to store per token, the paper approximates it with an empirical distribution over 100 token samples per position [1].

**Combining multiple rounds** [1]: simultaneous distillation sums $K$ per-context losses, $L_{TOTAL} = \sum_{k=1}^{K} L_{D_k, T_{STUDENT,k}, T_{TEACHER,k}, f_k}$, useful when several independent instructions or in-context examples together exceed the context window; sequential distillation instead chains rounds, $\theta_{STUDENT,k+1}$ fine-tuned from $\theta_{STUDENT,k}$ under loss $L_k$, useful for incrementally updating or overwriting earlier updates; the two can be composed arbitrarily, and Choi et al.'s recursive variant additionally makes the student the next round's teacher [1].

**Worked example** (step-by-step reasoning, Figure 2, using the paper's own reported numbers) [1]: the teacher template shows a worked addition with a digit-by-digit scratch-pad and asks it to solve "11 + 41"; the teacher samples a scratch-pad ending in "the final answer is 52"; $f$ extracts "52"; the student template shows only "Perform the following calculation. Input: 11 + 41. Output:" with no scratch-pad; the student is fine-tuned to output "52" directly. Across a T5-small run on this task, the teacher's scratch-pad accuracy is 93%, the student's direct-answer accuracy before distillation is 0%, and after distillation it reaches 94.7%, rounded to 95% in Table 3 [1].

## Cost

**Theory, from the method's own math**: one round holds two full copies of the model at once - the frozen teacher $\theta_{TEACHER}$ used only for sampling, and the trainable $\theta_{STUDENT}$ - both the same size, since the method starts them as identical weights [1]; that is a fixed extra full-model footprint regardless of how small or large the underlying model is, unlike classical KD where the teacher can be much larger and is amortized once. Time-wise, each example requires sampling the (typically longer) teacher completion $y$ first, then a forward/backward pass over the (typically shorter) student prompt for the KL loss; the paper reports the student's inference-time input can be up to 11x shorter than the teacher's, which lowers cost at *use* time but not during the distillation round itself, when the teacher generation still has to run [1]. The 100-token-sample approximation to the soft-label distribution bounds the per-token label size independent of vocabulary size, trading a fixed extra sampling cost for avoiding a full-vocabulary softmax storage blowup [1]. A naive reading of "hold two full models" says memory doubles like PPO's policy-plus-critic; the correction is that the teacher copy here is inference-only (no gradients, no optimizer state), so it costs one weights-sized tensor, not the ~2-3x-weights that a second *trained* copy would need [1].

**In practice, per framework**: no framework in this corpus ships this method (see Shipped by), so there is no framework-reported wall-clock or memory number to cite here; the only concrete cost data available is the paper's own training configuration reported under How to use it.

## How to use it

- Define the four components before writing any training code: raw input distribution $D$, teacher template $T_{TEACHER}$, student template $T_{STUDENT}$, and answer extractor $f$ [1]. $D$ can come from an existing dataset split or be synthesized by few-shot-prompting the same model, as done for the movie-review and addition-question experiments [1].
- Labeling convention: there is no external label. The "label" is $f(y)$, the extractor's output on the teacher's own sampled completion; $f$ is the identity function in every experiment except the step-by-step-reasoning setting, where it strips the scratch-pad and keeps the final answer [1].
- Knobs table - the only source with concrete values is the paper itself, since no framework ships this method:

| knob | paper's main runs [1] | step-by-step transfer run [1] |
| --- | --- | --- |
| distillation examples | 4096 | 10k (mixed with 65536 Natural-Instructions examples) |
| epochs | 1 | 3 |
| batch size | 16 | 16 (T5-small addition run: 8) |
| optimizer | AdamW, 0 weight decay | AdamW |
| learning rate | 1e-5 (TK-Instruct), 1e-4 (Incoder) | not stated for this run; T5-small addition run used 3e-4 |
| KL soft-label approximation | 100 token samples per position | same |

- Trade-off the run designer faces: a more detailed teacher template (more examples, more explanation) raises the in-context margin the student can potentially internalize, but simultaneous distillation is required once that template's tokens exceed the context window, and the paper shows the "naive" way of splitting a template into independent per-task distributions lets the student cheat by keying off the input's topic instead of the intended instruction index - the "mixed" variant that shares one input distribution across all sub-tasks is needed to avoid this (Table 1: wrong-association accuracy 61% naive vs. 16% mixed) [1].

## While it runs

- **Signals and their healthy shapes**: the paper's own diagnostic for whether explanations are being internalized is the correlation between "in-context margin" (how much the explanation helps the teacher, measured in Rouge-L) and "distillation margin" (how much the student improves after distillation); across 10 Natural-Instructions tasks the paper finds a positive, statistically significant correlation ($r = 0.75$, $p = 1\%$) [1]. For the task-id re-association setting, track both correct-association accuracy (should rise) and wrong-association accuracy (should fall after overwriting); the paper reports the naive variant fails to separate these (68% correct / 61% wrong) while the mixed variant succeeds (70% correct / 16% wrong) (Table 1) [1].
- **Published reference runs**: the paper's own tables are the only known-good curves for this method - Table 2 (SPIDER, context distillation vs. gradient descent) and Table 3 (8-digit addition, scratch-pad internalization) - no raw logs beyond the tables are cited by the paper [1].
- **Degeneracies and defaults**: using a "naive" per-sub-task input distribution when distilling multiple task-id associations lets the student associate the surface topic of the input with the task, rather than the intended index, inflating wrong-association accuracy; the paper's fix is to draw a shared, mixed input distribution across all sub-tasks being distilled simultaneously (Table 1) [1]. There is no framework default to diverge from, since none ship this method.
- **Named successors**: none identified from the paper's own text; the paper instead names concurrent, corroborating work (Anonymous, 2023, on step-by-step reasoning at larger scale) rather than a successor that fixes a documented bias [1].
- **Known failure modes**: from the paper's own limitations - not every task benefits from internalizing natural language explanations under the model tested, so the distillation margin can be near zero for tasks where the in-context margin is already small [1]; and in the fact-editing (Counterfact) experiment, the paper's TK-Instruct teacher scores poorly on neighborhood prompts (Table 5), and while GPT-3 scores much better on the same prompts, the paper could not run context distillation on GPT-3 itself due to OpenAI API limitations, so its expectation that GPT-3's neighborhood-score gains would carry over to a distilled model is unmeasured [1]. No maintainer-issue failure modes exist to report, since no library ships this method (checked: trl and verl documentation indexes, searched for "distill"; trl's DistillationTrainer implements GKD and verl's OPD trainer likewise trains against a separate teacher checkpoint, so neither implements the same-weights mechanism this paper defines) [5][6].
- **What the gain is - and is not**: the paper's own framing is that context distillation moves an existing in-context capability into the weights - it internalizes what a longer prompt already lets the same model do, cutting inference tokens by up to 11.1x in the instructions setting and 8.0x in the scratch-pad setting - not a capability the model could not already reach via that prompt [1]. In the SPIDER comparison, the ceiling is the teacher's own in-context performance (27.7-28.2 exact-set-match), and the student's post-distillation score (22.1-27.9) approaches but does not exceed it [1].
