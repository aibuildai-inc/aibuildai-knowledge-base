# SPIRAL

Online self-play REINFORCE: a single shared policy plays both seats of a two-player zero-sum text game against itself, and each seat's advantage is the game outcome minus an exponential-moving-average baseline tracked separately per game and per seat.

**SPIRAL** (Self-Play on Zero-Sum Games Incentivizes Reasoning) is an online reinforcement-learning method for building LLM reasoning by having a model play multi-turn, zero-sum games against continuously improving copies of itself, introduced by Liu, Guertler, Yu et al. as a way to generate "an automatic curriculum of stronger opponents" without human supervision [1]. The paper is at https://arxiv.org/abs/2506.24119 [1]. Its parent is REINFORCE: the paper states it applies "Monte Carlo policy gradient methods" and derives its base update directly from Williams (1992) [2], as cited in [1]. A single shared-parameter policy $\pi_\theta$ plays role $p \in \{0,1\}$ in each turn, conditioned on the game and role through the prompt; when the game ends, the zero-sum outcome $\rho_i(s_T) \in \{-1,0,1\}$ gives $R_0(\tau) = \rho_i(s_T)$ and $R_1(\tau) = -R_0(\tau)$, and the method's own contribution, Role-conditioned Advantage Estimation (RAE), replaces the raw return with a per-(game, role) baseline-corrected advantage to control variance [1]. The paper gives three reasons for existing: RLVR methods depend on human-curated problem-answer pairs and domain-specific reward engineering, which self-play eliminates by generating reward directly from a game's rules [1]; a shared policy that faces itself creates "an automatic curriculum" because the opponent gets stronger exactly as fast as the learner does [1]; and without a per-role correction, multi-agent REINFORCE is unstable — the paper reports that a shared policy training on both sides of a zero-sum game suffers "catastrophic thinking collapse" within 100 iterations unless RAE is used [1].

SPIRAL is a June 2025 preprint; the sources checked here — its own repository (spiral-rl/spiral) and the Oat framework repository it builds on (sail-sg/oat), both read at their `main` branch on 2026-08-09, an unpinned and mutable snapshot that may already differ from what a later fetch of the same branch returns — show no landmark system adopting it, and an arXiv abstract-text search for "SPIRAL" combined with "role-conditioned" returns only the original paper, so no confirmed named successor exists as of this check [1][7][8]. In the paper's own results, multi-game self-play (TicTacToe, Kuhn Poker, Simple Negotiation) took Qwen3-4B-Base from a 34.0% average across eight reasoning benchmarks to 44.5% (+10.5 points), beating a 39.7% average from supervised fine-tuning on 25,000 expert self-play trajectories from the same games (Table 1); Qwen3-8B-Base rose from 39.5% to 49.6% (+10.1 points) [1]. The correct paper was confirmed by an exact-title match on arXiv against the shortlist's title string [1]. Lineage in one line: REINFORCE (Williams, 1992 [2]) -> SPIRAL (2025 [1]); no named successors identified.

**When to pick it**: online RL for building general reasoning when the only supervision available is the win/lose/draw outcome of a two-player zero-sum game the model can play against itself, and you want to avoid curating problems or engineering a reward function [1]. Its parent REINFORCE [2] needs an external per-episode reward from real data or a reward model; SPIRAL instead manufactures reward from game rules. The nearest offline self-play alternative is SPAG (Cheng et al., 2024): SPIRAL's own related-work section describes it as applying self-play to Adversarial Taboo using offline updates on a single game, unlike SPIRAL's continuously-updated, multi-game online loop [1], identified as arXiv:2404.10642 [3]. The nearest online single-agent neighbor is RLVR training such as GRPO, which is also online and reward-driven but is trained on human-curated problem sets with a checkable ground truth (e.g., DeepSeekMath's math problems) rather than on self-generated game trajectories [4]. Two other 2025 methods are distinguished from SPIRAL in its own related-work section: Absolute Zero (Zhao et al., 2025), which SPIRAL describes as generating single-turn coding tasks, rather than SPIRAL's multi-turn games [1], identified as arXiv:2505.03335 [5]; and RAGEN (Wang et al., 2025), which SPIRAL describes as employing single-agent multi-turn RL focused on trajectory-level optimization, rather than SPIRAL's two-seat self-play [1], identified as arXiv:2504.20073 [6].

**Variant of**: REINFORCE [2], adapted to a shared-policy two-player self-play setting with a per-(game, role) EMA baseline (RAE) in place of REINFORCE's usual single global or per-timestep baseline [1].

**Data it needs**: no human-labeled data of any kind — text observations come from the game engine (TextArena environments TicTacToe, Kuhn Poker, Simple Negotiation) [1][9], and the only label is a single scalar reward per finished trajectory, the game outcome mapped to $\{-1,0,1\}$ [1]. Training is on-policy: every batch of trajectories is generated fresh by the current shared policy playing itself, with no replay buffer described in the algorithm [1]. The paper's own scale: 400 policy iterations, 128 self-play trajectories per step, on 8 H100 GPUs, taking about 25 hours for Qwen3-4B and 28 hours for Qwen3-8B [1].

**Extra models**: none required by the method's own definition. There is no value network — the "baseline" $b_{G,p}$ is a scalar EMA per (game, role) pair, not a learned network [1] — and no reward model, since the reward is the game engine's deterministic outcome [1]. The paper's own hyperparameter table sets both `KL loss coefficient` and `KL penalty coefficient` to 0.0, so no reference model is actively used in the paper's reported runs, even though the underlying Oat framework it is built on supports one [1].

**Shipped by**: only the paper's own repository, spiral-rl/spiral, run via `bash run.sh`; it depends on the `oat-llm` package (PyPI, from sail-sg/oat) for the distributed actor-learner infrastructure, vLLM for rollout inference, and TextArena for the game environments [7][8][9][10][11]. No support-status label (stable/experimental) is stated by the authors for this training script [7]. Neither trl's docs index nor verl's README mention "spiral" [12][13]; verl's README does mention self-play in general — a Self-play preference optimization (SPPO) recipe link, and two adopter projects, Absolute Zero Reasoner and Search Self-play, neither of which is SPIRAL [13] — while trl's index page has no self-play mention at all [12]. No established RL library ships SPIRAL by name; building it there would mean adding a second-agent self-play rollout loop (both seats sampled from the same policy, per-role reward bookkeeping) on top of an existing on-policy trainer, not just a new loss function [7].

## How it works

Each policy iteration, K parallel actors play the current shared policy against itself on a sampled game to produce zero-sum trajectories; RAE turns each trajectory's outcome into a per-role, baseline-corrected advantage; the policy is updated on the resulting advantages with a REINFORCE-style objective [1].

**The naive multi-agent policy gradient** (Eq. 1) [1]:

$$ \nabla_\theta J(\theta) = \mathbb{E}_{G\sim\mathcal{G}}\, \mathbb{E}_{\tau\sim\pi_\theta\times\pi_\theta|G}\left[ \sum_{t\in T_0}\nabla_\theta \log\pi_\theta(y_t^{(0)}|s_t,0,G)\cdot R_0(\tau) + \sum_{t\in T_1}\nabla_\theta \log\pi_\theta(y_t^{(1)}|s_t,1,G)\cdot R_1(\tau) \right] $$

$G$ is a game sampled from the training set $\mathcal{G}$; $\tau$ is a full trajectory generated by the shared policy playing both seats; $T_p = \{t : t \bmod 2 = p\}$ is the set of turns where role $p$ acted; $R_p(\tau)$ is the zero-sum outcome for that role. The paper notes this Monte Carlo formulation "suffer[s] from high variance," which self-play makes worse because the opponent (itself) is non-stationary [1].

**RAE baseline update and advantage** (Eq. 2) [1]:

$$ b_{G,p} \leftarrow \alpha\, b_{G,p} + (1-\alpha)\, R_p(\tau), \qquad A_{G,p}(\tau) = R_p(\tau) - b_{G,p} $$

A separate scalar baseline $b_{G,p}$ is tracked for every (game, role) pair and updated by exponential moving average with decay $\alpha$ (the paper's own default is $\alpha=0.95$, Table 6) [1]. The paper motivates the per-role split by structural asymmetries such as first-move advantage in TicTacToe or information asymmetry in Kuhn Poker, which give the two seats different expected returns even under one shared policy [1].

**The variance-reduced policy gradient** (Eq. 3) [1], used for the actual update:

$$ \nabla_\theta J_{\text{SPIRAL}}(\theta) = \mathbb{E}_{G\sim\mathcal{G}}\,\mathbb{E}_{\tau\sim\pi_\theta\times\pi_\theta|G}\left[ \sum_{p\in\{0,1\}} \sum_{t\in T_p} A_{G,p}(\tau)\cdot \nabla_\theta\log\pi_\theta(y_t^{(p)}|s_t,p,G) \right] $$

Every token generated by role $p$ in a trajectory gets the same trajectory-level advantage $A_{G,p}(\tau)$, i.e. the credit assignment is at the full-response level, not per-token. The paper states it deliberately does not normalize advantages by response length, to avoid a length bias documented in prior work [1].

Worked example, using the paper's own $\alpha = 0.95$ [1, Table 6]: suppose TicTacToe's first-move advantage has already pulled the two baselines apart, $b_{G,0}=0.20$ (seat 0 usually wins) and $b_{G,1}=-0.20$. In one trajectory seat 1 pulls off an upset win: $R_0(\tau)=-1$, $R_1(\tau)=+1$. The advantages use the pre-update baselines: $A_{G,0} = -1 - 0.20 = -1.20$ for seat 0's tokens, and $A_{G,1} = 1 - (-0.20) = 1.20$ for seat 1's tokens — a bigger positive push for the seat that was expected to lose than a flat $\pm 1$ reward would give, and a bigger negative push for the seat that was expected to win but did not. The baselines then update: $b_{G,0} \leftarrow 0.95(0.20)+0.05(-1) = 0.14$, $b_{G,1} \leftarrow 0.95(-0.20)+0.05(1) = -0.14$, drifting back toward parity after the upset.

**A gap between the algorithm box and the released hyperparameters**: Algorithm 1 and Eqs. 1–3 present the update as plain REINFORCE with no ratio or clip term, but the paper's own Table 6 lists a `Policy clipping parameter` of 0.2 and an `Inner proximal update epoch` of 2 alongside the RAE settings [1]. That is, the runs actually reported use a clipped-ratio surrogate over 2 inner epochs per rollout batch, not the single unclipped gradient step shown in the equations; the same table sets both `KL loss coefficient` and `KL penalty coefficient` to 0.0 [1].

## Cost

**Theory, from the method's own math**: a full self-play trajectory must be generated by the policy in both seats before any advantage can be computed, so generation sits inside the loop and its length is set by the game (TicTacToe terminates in a handful of discrete moves; Kuhn Poker and Simple Negotiation involve variable-length natural-language turns) [1]. There is no value-network forward/backward pass, since RAE's baselines are scalars, not a network [1]; with the paper's own KL coefficients at 0.0, no reference-model forward pass is added either in the reported runs, though a reference model would be needed if those coefficients were set nonzero [1]. Memory-wise, only one set of policy weights is held, because the same shared policy plays both roles instead of training two separate models — the paper states this "shared-parameter approach ensures efficient use of GPU memory" [1] — plus $2 \times |\mathcal{G}|$ scalar baselines, which is negligible next to model weights.

**In practice, per framework**: the only reported implementation is the paper's own repository. It runs on 8 H100 GPUs with a distributed actor-learner architecture — parallel actors generate self-play trajectories with vLLM while a centralized learner performs synchronous policy updates [1][7]. The paper reports roughly 25 GPU-hours (8×H100) for a Qwen3-4B run, 28 for Qwen3-8B, and 16 each for Llama3.1-8B-Instruct and Octothinker-8B, at 400 policy iterations and a batch size of 128 [1]. No separate framework beyond this repository has published its own cost profile for the method.

## How to use it

- Data prep: no dataset curation — TextArena instantiates the game environments (TicTacToe, Kuhn Poker, Simple Negotiation for training; five additional games held out for out-of-distribution evaluation) and produces the text observations $s_t$ each turn [1][9]. For partially observable games (Kuhn Poker, Simple Negotiation) the paper maintains a Markovian state by concatenating the history of past actions into $s_t$ [1].
- Reward convention: one scalar per finished trajectory, the game's zero-sum outcome mapped to $\{-1,0,1\}$ (win/loss/draw) for each seat, with $R_1(\tau)=-R_0(\tau)$ [1]; role is distinguished in the prompt via a role-conditioning system prompt so the shared policy can learn asymmetric strategies for the two seats [1].
- Knobs table, the paper's own default (Table 6) — this card checked only the paper's repository, so there is no second framework column:

| knob | paper default [1] |
| --- | --- |
| EMA decay rate $\alpha$ | 0.95 |
| policy clipping parameter | 0.2 |
| inner proximal update epochs | 2 |
| KL loss coefficient | 0.0 |
| KL penalty coefficient | 0.0 |
| learning rate | $1\times10^{-6}$ (constant schedule) |
| batch size | 128 |
| discount factor | 1.0 |
| max response length | 8192 tokens |
| sampling temperature | 1.0 |
| optimizer | AdamW, $(\beta_1,\beta_2)=(0.9,0.95)$, weight decay 0.0, grad-norm clip 1.0 |

- Trade-offs a run designer faces: single-game training (e.g., SPIRAL-Kuhn) is cheaper but the paper's own Table 1 shows multi-game training (SPIRAL-Multi, all three games) yields larger reasoning-benchmark gains than any single-game specialist, because different games develop complementary skills [1]. The paper also reports that SFT on 25,000 expert self-play trajectories from the same games underperforms SPIRAL's online self-play at the same games, so trajectory count alone does not substitute for the online, continuously-updating opponent [1].

## While it runs

- Signals and their healthy shapes: the paper's central signal is response (reasoning-trace) length. In the RAE ablation, a shared policy trained without RAE suffers "catastrophic thinking collapse" within 100 policy iterations — trace length falls from about 2,000 characters to near-zero, general reasoning-benchmark accuracy falls from 44% to 40%, and the model starts emitting degenerate outputs like `\boxed{bet}` regardless of the actual game state [1]. With RAE, response length stabilizes around 1,300–1,500 characters and accuracy rises from 40% to 47% over the same run [1]. The repository's `run.sh` additionally reports, during training, win rate against a fixed opponent on the training game, win rate against a fixed opponent on an out-of-distribution game, and accuracy on math reasoning benchmarks, and shows example curves for a 400-step Kuhn Poker run on 8×H100 in its README (image only; this card did not extract numeric values from that image) [7].
- Published reference runs: the paper's own Table 1 numbers (34.0% -> 44.5% average for Qwen3-4B-Base multi-game training, beating 39.7% for SFT-Multi) are the reference curve to compare against when judging whether a new run is working [1].
- Degeneracies and defaults: the paper's documented degeneracy is exactly the thinking-collapse mode above — running multi-agent REINFORCE with a single global (non-role-conditioned) baseline, i.e. without RAE, is what triggers it [1]. Setting the game roster to a single asymmetric game with no RAE role split is a live version of the same trap, since the paper attributes the divergent expected returns specifically to per-role asymmetries like first-move advantage or information asymmetry [1].
- Named successors: none found. This card checked spiral-rl/spiral's closed issues, scoped by GitHub's issue search to `type:issue` to exclude pull requests: 3 closed issues as of 2026-08-09 (#1, #4, #7), none proposing a successor algorithm, plus one open issue (#13) also unrelated to a successor; the broader `state=all` endpoint returns 13 items total, 9 of them pull requests, on the same date. It also checked the sail-sg/oat repository's README and an arXiv abstract-text search for "SPIRAL" combined with "role-conditioned"; the only match was the original paper [1][7][8]. This is an unpinned, live endpoint - a later query may return a different count.
- Known failure modes: from the paper's own limitations section — SPIRAL's reward source shifts the dependency from curated problem sets to hand-designed game environments, and it is unclear how the approach scales to sparse-reward, open-ended environments beyond the simple, dense-reward games tested [1]; training compute is substantial (8 H100s for up to ~28 hours per run) and the paper observed performance gains plateauing after extended training, suggesting diminishing returns from simply running longer [1]; evaluation was restricted to zero-shot academic benchmarks, so in-domain fine-tuning gains were not explored [1]; and the method is susceptible to reward hacking in principle, though the authors state they "did not observe significant instances of this" [1]. Separately, a closed GitHub issue on the released Qwen3-4B checkpoint reports broken generation (missing `<think>` tags, missing end-of-turn tokens, self-repetition) that the maintainers attribute to a chat-template setting (`enable_thinking=False` needed at inference), not to the RL method itself [14].
- What the gain is - and is not: the paper positions SPIRAL as producing reasoning strategies during gameplay (systematic decomposition, expected-value calculation, case-by-case analysis) that transfer to unrelated academic benchmarks, with different games contributing complementary skills in multi-game training [1]; it does not claim the method adds capability beyond what these transferable reasoning patterns provide, and the paper's own limitations section explicitly flags that broader generalization beyond the tested academic benchmarks and games is untested [1].
