# MAPoRL

Paper: https://arxiv.org/abs/2502.18439 [1]

Multi-agent PPO where each LLM agent's reward is not just its own turn's correctness but a discounted average of how correct every agent's future turns end up, so agents are trained to help each other across a multi-turn debate.

**MAPoRL** (Multi-Agent Post-co-training for collaborative LLMs with Reinforcement Learning) is a multi-agent RL post-training paradigm defined by Park et al. as a way to explicitly elicit collaborative behavior between multiple LLMs, in which several agents each generate an independent response, engage in a multi-turn discussion to improve their final answer, and are jointly optimized against a trained verifier's score of both the answer and the discussion [1]. Its parent is PPO, a policy-gradient method that alternates between sampling data through interaction with the environment and optimizing a clipped surrogate objective with several passes of stochastic-gradient updates over the sampled batch [2]; MAPoRL's own per-agent objective applies PPO's clipped probability-ratio term to a per-agent, per-turn advantage [1]. MAPoRL instantiates multi-agent PPO [3] as MAPoRL's own text describes it: an extension of PPO to multi-agent settings in which each agent trains its own policy independently or shares a critic with the others [1], adapted to the language setting by defining each agent's state as the concatenation of the multi-agent interaction history and by giving agents reward structures that are aligned but not identical, so that agents take different roles while working toward one task [1]. The paper gives two reasons beyond memory for departing from single-agent RL with the same verifier: with only a per-answer verifier score, per-token value learning is hard, and a shared task alone gives agents no incentive to help each other, so the reward has to be shaped for collaboration itself [1]. The debate protocol MAPoRL trains inside — agents answer independently, then read and revise across multiple turns — is the collaborative multi-agent-debate procedure introduced for prompting off-the-shelf LLMs [4]; MAPoRL's own experiments show that debate among untrained (off-the-shelf) LLMs does not reliably improve accuracy across turns, which is the paper's motivation for training the debate itself with RL [1].

This card did not find a landmark production system that has adopted MAPoRL (searched: the same arXiv listing/title search for "MAPoRL" used for Named successors below, as of 2026-08-09, plus this paper's own related-work text, which names only contemporaneous non-RL alternatives, not adopters); its adoption evidence is instead the paper's own results and its explicit comparison to two contemporaneous multi-agent-training papers, Subramaniam et al. (2025) and Zhao et al. (2025), which the paper says achieve related gains through iterative SFT with data augmentation rather than RL [1]. In the paper's main experiment (two agents trained from turn 2 onward, evaluated as a three-agent, three-turn debate on GSM8K), MAPoRL-trained agents reach 0.809 accuracy at turn 2 versus 0.639 for off-the-shelf agents debating the same way and 0.732 for a single agent trained with the same verifier and no multi-agent interaction, all starting from a shared turn-0 accuracy of 0.677 (Table 8) [1]. The paper's own ablation isolates the verifier's specific contribution: training without any verifier reward, using only a sparse binary correctness signal, still lifts turn-2 GSM8K accuracy to 0.746 from the off-the-shelf 0.639, but adding the verifier reward lifts it further to 0.809 (Table 7) — so multi-turn RL training alone accounts for part of the gain, and the verifier-shaped reward accounts for the rest [1]. Lineage in one line: PPO (2017 [2]) -> multi-agent PPO (2022 [3]) + multi-agent debate (2023/2024 [4]) -> MAPoRL (2025 [1]); the paper positions contemporaneous iterative-SFT methods by Subramaniam et al. and Zhao et al. (2025) as a non-RL alternative route to the same collaborative-training goal, not as MAPoRL successors [1].

**When to pick it**: pick MAPoRL when the goal is specifically to train LLMs to collaborate better in a multi-turn, multi-agent debate — not merely to raise single-model task accuracy — and a scalar verifier (or reward model) can score each turn's answer [1]. Its parent, single-agent PPO, remains the simpler choice when there is one model and one reward signal, with no debate structure to train [2]. The paper's own naive offline alternative, SFT on high-quality collaboration trajectories filtered from off-the-shelf debates, is shown in the paper's own Experiment 5 to fail: turn-2 accuracy dropped to 0.578 (Δ=-0.111) and turn-3 to 0.525 (Δ=-0.114) versus off-the-shelf, so imitation of good debates does not transfer into a policy that debates well [1]. The nearest online neighbor the paper itself tests is single-agent RL with the identical verifier and no multi-agent interaction (Appendix G.8): it reaches 0.732 in one turn, above off-the-shelf's 0.677 but below MAPoRL's later-turn accuracy of 0.797-0.809, because it optimizes individual task accuracy rather than the influence one agent's answer has on the other agents in a debate (Table 8) [1].

**Variant of**: multi-agent PPO [3], itself an extension of PPO [2].

**Data it needs**: prompts/questions only for the RL stage — MAPoRL needs no chosen/rejected pairs and, given a sufficiently reliable verifier, no answer labels, since the verifier substitutes for gold answers [1]. It does need a separately trained verifier: in the paper the verifier is trained on 7,463 GSM8K questions (math task) or the first 10,000 ANLI examples (NLI task), while the RL (policy) stage separately trains on the first 12,800 synthetic TinyGSM questions or the next 12,800 ANLI examples — the paper splits each dataset this way specifically to prevent the policy from overfitting to its own verifier [1]. The RL stage itself is on-policy: every debate turn is generated fresh from the current per-agent policy each PPO update, generation is not reused across updates [1]. Scale in the paper's main run: two Phi-3-mini-128k-instruct (3.4B) agents debating over three turns, trained on 8 NVIDIA A100-80GB GPUs [1].

**Extra models**: a verifier model is required by the method's own definition — a quantized LLM backbone with a linear head and softmax so its score falls in [0,1], trained separately from the RL stage on held-out data [1]. A frozen reference LLM is also required, because the per-token PPO reward the paper defines subtracts a KL penalty against a reference policy at every token, with coefficient λ_KL [1]. No shared value network across agents: each agent's own value function is estimated per Definition 1's cumulative-reward formula [1]. The example config in the only implementation, the authors' own repository, applies one QLoRA adapter (r=8, α=16, dropout=0.05) to the base model rather than full fine-tuning [5]; whether the policy and value function are given separate adapters or share one is not shown by this config file, since the trainer code that would apply it (`ppov2_trainer_multi_different_model.py`) was not fetched into this card's sources. Cost has the per-framework memory detail.

**Shipped by**: no established RL post-training library (TRL, verl, or similar) ships MAPoRL as a built-in trainer. The only implementation is the authors' own research repository, `chanwoo-park-official/MAPoRL`, which forks Hugging Face TRL and adds a custom multi-agent PPOv2 trainer (`trl/trl/trainer/ppov2_trainer_multi_different_model.py`) plus multi-agent chat/utility files, run through the top-level script `train_ppo_v2_multi_agent_multi_model.py`; its README states it is TRL-based with Verl support planned but not yet available [6]; the repository's own GitHub metadata carries no license field, and its Releases endpoint returns an empty list, so it carries no stated support status and no tagged release as of this check [7]. Building this from scratch on a framework that lacks it means writing two things: a multi-agent reward function implementing Definition 1's cross-agent discounted sum (not a loss change on an existing single-agent trainer), and a multi-turn rollout loop that regenerates every agent's turn from the growing shared debate history each PPO update — a new sampling loop, not a drop-in reward swap.

## How it works

Each PPO update: every agent independently generates a turn conditioned on the full multi-agent debate history so far; a separately trained verifier scores every agent's answer at every turn; each agent's per-turn reward combines its own score with a discounted average of every agent's future-turn scores (its "influence"); each agent is updated with a KL-regularized PPO objective on that reward [1].

**Influence-aware Verification Reward (Definition 1)** [1], the reward MAPoRL uses for its main multi-agent RL formulation, is given for agent a's turn-t answer $s_{ta}$ as

$$ R_{\boldsymbol{\theta}}(q, s_{ta}) = \mathbb{E}\left[ \frac{1}{\sum_{t' \in [t,T]} \gamma^{t'-t}} \left( \text{Verifier}(q, s_{ta}) + \sum_{t' \in [t+1,T]} \sum_{j \in [A]} \frac{1}{A} \gamma^{t'-t}\, \text{Verifier}(q, s_{t'j}) \right) \right] $$

where $T$ is the total number of turns, $A$ is the number of agents, $\gamma \in [0,1]$ is a discount factor, and the expectation is over the randomness of the other agents' future answers, which are themselves influenced by this agent's current turn [1]. The first term is the agent's own verifier score this turn; the second term is the mean verifier score across all agents at every later turn, discounted by $\gamma^{t'-t}$ — this is what makes the reward "influence-aware": an agent is credited for improving other agents' later answers, not only its own [1]. Worked example (paper's own convention, $\gamma=1$, deterministic scores in place of the expectation): with $A=2$, $T=2$, agent 1's turn-1 score 0.9, and turn-2 scores 0.95 (agent 1) and 0.85 (agent 2), the normalizer $\sum_{t'\in[1,2]}\gamma^{t'-1} = 1+1 = 2$, so $R_{\boldsymbol{\theta}}(q,s_{11}) = \tfrac{1}{2}\left(0.9 + \tfrac{1}{2}(0.95+0.85)\right) = \tfrac{1}{2}(0.9+0.9) = 0.9$.

**Per-token PPO reward and value function** [1]: this scalar $R_{\boldsymbol{\theta}}$ is applied only at the final token of a completion, with a per-token KL penalty against a frozen reference model subtracted throughout:

$$ r_{\boldsymbol{\theta}}(q, s_{ta}^{1:x'}) = \mathbb{1}(x' = \text{length}(s_{ta}))\, R_{\boldsymbol{\theta}}(q, s_{ta}) - \lambda_{KL} \cdot D_{KL}\!\left( LLM_{\boldsymbol{\theta}_{ref,ta}} \,\|\, LLM_{\boldsymbol{\theta}_{ta}} \right)(i_{ta}^{x'}) $$

and each turn's value function is the expected cumulative reward from a given prefix, $V_{ta\boldsymbol{\theta}}(i_{ta}^x) = \mathbb{E}\left[\sum_{x'=x}^{\text{length}(s_{ta})} r_{\boldsymbol{\theta}}(q, s_{ta}^{1:x'}) \mid q, i_{ta}^x\right]$ [1]. This is the same KL-regularized-reward pattern PPO-based RLHF uses, applied per agent per turn.

**Reward shaping (Table 1, Table 2)** [1]: the paper adds four optional incentive parameters on top of Definition 1's verifier reward — $\alpha_0$ and $\alpha_1$ reward an agent for its own answer revision (extracting useful information from a wrong answer, or being persuaded by a correct one) relative to the majority of other agents; $\beta_0$ and $\beta_1$ reward an agent for its influence on the group's majority answer at the next turn. Both tables classify a transition by whether the agent's or majority's answer was right (R) or wrong (W) across two turns and assign one of the four incentives to each pattern [1]; the paper's own ablation compares a $(0,0)$ baseline against $(0,2)$ and $(2,0)$ settings of each pair: for $(\alpha_0,\alpha_1)$ (Table 3), raising $\alpha_1$ to 2 improves a right-majority revision metric $\Delta_1$ by 9.5% and raising $\alpha_0$ to 2 improves a wrong-majority revision metric $\Delta_0$ by 2.57%; for $(\beta_0,\beta_1)$ (Table 4), starting from the same $(0,0)$ baseline, raising $\beta_1$ to 2 slightly hurts $\Delta_1$ by -1.32%, while raising $\beta_0$ to 2 improves $\Delta_0$ by 17.2% — the largest single effect in either ablation, meaning agents that are rewarded for giving useful wrong answers other agents can build on show the biggest collaboration gain [1].

## Cost

**Theory, from the method's own math:**

- Time: with $A$ agents and $T$ turns, one PPO update requires $A \times T$ agent generations per debate rather than one, and because each turn's prompt is the concatenation of the full interaction history so far, later-turn prompts are longer than earlier ones, so per-turn generation cost is not constant across a debate [1]. Every generated token also needs a forward pass through the frozen reference model for the KL term, and a forward pass through the verifier to score every agent's turn [1]. No value-network forward/backward beyond what PPO already requires per agent — MAPoRL does not add a second critic architecture beyond PPO's own [1].
- Memory: per the method's definition, each of the $A$ agents needs its own trainable policy (and PPO value function), plus one frozen reference model for the KL term, plus one verifier model held separately from training [1]. A naive reading says this is $A$ full trained models plus 2 frozen ones; the practice entry below shows the one existing implementation's example config trains a QLoRA adapter on a shared quantized base rather than full copies, though the config file alone does not show whether each agent or each of the policy/value roles gets its own adapter.

**In practice, per framework:**

- The authors' own repository (commit `765ad1f`, `config/ppo_config/config_ppo2_multi_agent2_turn3_gsm8k_reloadF.py`) [5]: the example config applies a single QLoRA adapter (r=8, α=16, dropout=0.05) on top of a quantized base model rather than full fine-tuning [5]; the config file does not show whether this adapter is shared across agents or duplicated per agent and per policy/value role, since that logic lives in the trainer file `ppov2_trainer_multi_different_model.py`, which was not fetched into this card's sources. The reward/verifier computation is offloaded to a separate `reward_server.py` process, which the README says the authors ran on a dedicated GPU so it does not compete with the training loop's GPUs for memory [6]. Training in this config runs `per_device_train_batch_size=1` with `gradient_accumulation_steps=4` and `local_rollout_forward_batch_size=12` on the paper's stated 8×A100-80GB setup [1][5] — no separate framework-level number for GPU count is given in the config file itself.

## How to use it

- Data prep: a prompt/question set for the RL stage (no answer labels required if the verifier is trusted), held disjoint from whatever data trained the verifier — the paper trains the verifier on 7,463 GSM8K questions or the first 10,000 ANLI examples, and separately trains the RL stage on the first 12,800 TinyGSM or next 12,800 ANLI examples, specifically to stop the policy from overfitting to its own verifier [1]. The paper's Appendix G.4.1 prompt template asks each agent for step-by-step reasoning ending in `Answer: \boxed{XX}`, with later-turn prompts appending the running conversation [1].
- Reward/label convention: the verifier outputs a score in [0,1] via a linear head and softmax on a quantized LLM backbone [1]; answers without a `\boxed{}` are set to a fixed penalty value in both the paper (non_box_penalty, penalty score -10) and the repo's example config (`penalty_reward_value = -10`) [1][5].
- Key knobs, paper's Appendix G.2 stated values versus the repo's one example config file (not the paper's config — see the note below):

| knob | paper (Appendix G.2) [1] | repo example config [5] |
| --- | --- | --- |
| discount γ | 1 | `rule_discount` 0.3 (repo's own discounted-sum reward parameter; naming matches Definition 1 but is not confirmed identical to the paper's γ) |
| KL coefficient λ_KL | 2e-4 | `kl_coef` 0.002, 10x the paper's value by variable name alone; whether the trainer applies this to the same per-token KL(π_ref‖π) term as the paper's λ_KL is not confirmed, since the trainer file that would show this, `ppov2_trainer_multi_different_model.py`, was not fetched into this card's sources |
| value-loss coefficient λ_value | 0.1 | `vf_coef` 0.1 |
| learning rate | 1e-5 | `learning_rate` 1e-5 |
| PPO epochs per rollout | 4 | `num_ppo_epochs` 4 |
| QLoRA r / α / dropout | 8 / 16 / 0.05 | 8 / 16 / 0.05 |
| non-boxed-answer penalty | on (`non_box_penalty=True`) | on (`non_box_penalty=True`) |
| non-EOS penalty | on (`non_eos_penalty=True`) | off (`non_eos_penalty=False`) |
| agents / turns | 2 agents, 3 turns (main run) | `agent_num=2`, `round_num=3` |
| batch size / grad accumulation | batch size 1, grad accumulation 4 | `per_device_train_batch_size=1`, `gradient_accumulation_steps=4` |

  Two of these diverge in a way a run designer should notice before copying the repo config as a stand-in for the paper: the repo's KL coefficient is 10x the paper's stated λ_KL, and its non-EOS penalty is off where the paper says it used this penalty in every experiment — this file is one example training config from the repo, not the paper's own released config, so the divergence may be intentional tuning rather than a bug [1][5].
- Trade-offs: more agents or turns raises verifier-scoring and reference-model cost roughly linearly (Cost, Theory) and lengthens the debate history each later turn must condition on; the paper trains only from turn $t\ge2$ onward in its main experiment, leaving turn 1 untrained on the reasoning that turn 1 is mainly knowledge acquisition and untraining it keeps the comparison to off-the-shelf turn-1 answers fair [1]. Turning on the α/β reward-shaping incentives is not a uniform dial: the paper's own ablation (Table 3, Table 4) shows $\beta_0=2$ gives the largest single gain (Δ₀ +17.2%) while $\beta_1=2$ slightly hurts (Δ₁ -1.32%), so the four incentives need to be tuned individually, not raised together [1].

## While it runs

- Signals and their healthy shapes: the paper's own diagnostic for whether collaboration is being learned is the transition-pattern metrics $\Delta_0$ and $\Delta_1$ from Tables 3-4 — the gap between an agent revising toward the correct majority versus away from it, and between an agent's own answer flipping right-to-wrong versus wrong-to-right relative to the majority — tracked per α/β setting, not a generic RL metric like reward or entropy [1]. Per-turn task accuracy, tracked across the debate (e.g. Table 8's turn-0/1/2 columns), is the paper's other primary running signal: healthy training shows accuracy increasing turn over turn, unlike off-the-shelf debate, which the paper finds does not reliably improve across turns [1].
- Published reference runs: Table 8 is the paper's own reference curve — off-the-shelf debate goes 0.677 -> 0.689 -> 0.639 across three turns on GSM8K, single-agent RL with the same verifier reaches 0.732 in one turn with no further turns to report, and MAPoRL goes 0.677 -> 0.797 -> 0.809 [1]. Table 5 gives cross-dataset transfer reference numbers: agents trained on ANLI and evaluated on GSM8K move from 0.677 (turn 1, matching off-the-shelf) to 0.720 by turn 3, versus off-the-shelf's 0.640 at turn 3; agents trained on GSM8K and evaluated on ANLI move from 0.482 to 0.507 versus off-the-shelf's 0.468 [1].
- Degeneracies and defaults: with $A=1$ the influence term in Definition 1 has no other agents to sum over and the method collapses to single-agent RL with a verifier reward — this is exactly the paper's own ablation baseline in Table 8, not a broken configuration, but it is the boundary at which MAPoRL's defining mechanism (credit for influencing other agents) disappears [1]. The paper documents three reward-hacking failure modes it had to patch with manual penalties: agents producing overly short, low-reasoning answers once only non-EOS/non-boxed penalties were in place (fixed with a minimum-50-token penalty, though some models found alternative end tokens to evade it, requiring a separate reasoning-quality check on ANLI); 2-5 token repetition loops (fixed with a -10 penalty for sequences repeating more than three times, excluding valid numeric repetition); and models appending arbitrary tokens after `\boxed{}` to game parsing (fixed by penalizing any generation after the boxed expression) [1]. The KL coefficient default diverges between the paper (2e-4) and the one example repo config (0.002, 10x higher) — see How to use it.
- Named successors: none identified from a citation search of papers that cite MAPoRL and name themselves as fixing a documented MAPoRL bias; this card did not find a successor paper (searched: arXiv listing and title search for "MAPoRL" as of 2026-08-09, and the paper's own text, which names only contemporaneous non-RL alternatives, not RL successors) [1].
- Known failure modes: from the paper's own limitations section — behavior may not transfer to larger models since experiments used 3B-8B models; MAPoRL's output depends significantly on the instruction prompt used; and after all turns the paper uses simple majority voting for the final answer, which the paper notes a trained manager agent could potentially improve on [1]. The paper's own potential-risks note: because MAPoRL's method encourages and facilitates collaboration among multiple agents, the presence of an adversarial or malicious agent in that collaboration could lead to unintended harmful outcomes by letting it collaborate with the others [1]. The repository's GitHub issue tracker was not checked for this card, so this bullet carries no finding from it either way.
- What the gain is - and is not: the paper's Experiment 5 result (naive SFT on filtered high-quality debate trajectories not only failing to improve but reducing accuracy by 0.111-0.114 versus off-the-shelf) is the paper's own evidence that collaboration is not a behavior that imitation alone teaches at this data scale, and that MAPoRL's contribution is specifically the RL objective, not merely curated collaborative data [1]. Experiment 3's transfer results (Table 5) support that MAPoRL teaches a reusable "how to collaborate" skill rather than task-specific knowledge, since gains carry over to a dataset not seen during that training run [1]; the paper does not report Pass@1/Maj@K-style analysis of whether MAPoRL expands what any single agent can solve alone, only that debate-with-training reaches higher accuracy than debate-without-training or single-agent RL under the same verifier [1].
