# CODI

Turn one language model into its own teacher and student: fine-tune it to answer with the ground-truth chain-of-thought (teacher) while simultaneously teaching it to answer after emitting six continuous "thought" vectors instead of CoT tokens (student), and pull the two paths together with an L1 loss on the hidden state right before the answer.

**CODI** (Continuous Chain-of-Thought via Self-Distillation) is a training method for compressing an LLM's explicit chain-of-thought (CoT) reasoning into a small number of continuous "thought" vectors, defined by Shen et al. as "a novel framework that distills CoT into a continuous space, where a shared model acts as both teacher and student, jointly learning explicit and implicit CoT while aligning their hidden activation on the token generating the final answer" [1]. Its closest predecessor is Coconut, which trains a model to autoregressively feed its last hidden state back in as the next input embedding instead of decoding a token, defined by Hao et al. as a paradigm that uses "the last hidden state of the LLM as a representation of the reasoning state (termed 'continuous thought')" and feeds it back "as the subsequent input embedding directly in the continuous space" [2]. The paper is at https://arxiv.org/abs/2502.21074 [1]. CODI reuses Coconut's autoregressive continuous-thought mechanism and its `bot`/`eot` boundary tokens, but replaces Coconut's training objective — a multi-stage curriculum that gradually swaps CoT tokens for continuous ones — with a single-step self-distillation loss between a teacher pass (explicit CoT, teacher-forced) and a student pass (implicit continuous CoT) of the same shared weights [1]. The paper gives two reasons beyond removing curriculum learning's forgetting problem: an outcome-only student objective on its own gives the model "no supervision for the continuous thoughts," so the teacher's hidden state supplies a training signal; and using the same weights for teacher and student, rather than a separately pretrained teacher, gives a "warm-up effect" — both start from the same initialization and converge together, instead of the student chasing an already-fully-formed teacher [1].

CODI is not yet reported as adopted by a landmark production system; its own reported gains are that CODI is "the first implicit CoT method to match explicit CoT's performance on GSM8k while achieving 3.1× compression, surpassing the previous state-of-the-art [Coconut] by 28.2% in accuracy" [1], with GPT-2 GSM8k accuracy of 43.7% (vs. Coconut's 34.1%, iCoT's 30.1%, and CoT-SFT's 44.1%) and LLaMA-3.2-1B accuracy of 55.6% (Table 1) [1]. A follow-up paper, SIM-CoT, identifies a latent-collapse instability in implicit-CoT training at scale and reports that its step-level auxiliary supervision "boost[s] ... CODI by +3.0% on LLaMA-3.1 8B" [3]. Lineage: iCoT curriculum internalization (Deng et al., 2024) [4] -> Coconut autoregressive continuous thoughts (2024) [2] -> CODI self-distillation (2025) [1] -> SIM-CoT step-level supervision (2025) [3]. The name collides with an unrelated question-answering paper, "CoDi: Conversational Distillation for Grounded Question Answering" (arXiv:2408.11219); the CODI paper here is confirmed as the intended match by its far larger citation count (209 vs. 1, per this shortlist's own count) — the top-cited-collision-pick method.

**When to pick it**: pick CODI when you have CoT-annotated training data (question, rationale, answer) and want a model that reasons internally with far fewer decoded tokens than explicit CoT, without the multi-stage curriculum-learning schedule Coconut needs [2] and without training a separate reward or process-reward model. Prefer explicit CoT-SFT if token efficiency does not matter, since it remains the accuracy ceiling CODI is chasing rather than beating [1]. Prefer iCoT if you need a simpler curriculum-based baseline and can tolerate its complete inability to scale to more verbose CoT data, where the paper reports it "almost fails" [1]. Prefer Coconut only if you need its emergent breadth-first-search behavior over multiple alternative reasoning paths, a property specific to its curriculum training that CODI's paper does not claim to reproduce [2].

**Variant of**: Coconut's autoregressive continuous-thought mechanism [2], with Coconut's curriculum-learning training objective replaced by self-distillation [1].

**Data it needs**: (question, chain-of-thought, answer) triples — the repository's data loader reads exactly these three fields (`question`, `cot`, `answer`) per example, reformatting the answer into an `"The answer is: <n>"` template and, for the default `icot` data mode, truncating the CoT by a fixed number of trailing steps per training example [5]. The paper's main experiments use the GSM8k-Aug dataset, ~385k CoT-augmented GSM8k examples generated by GPT-4 [1]. Training is offline in the sense that every example is a static, pre-labeled (question, CoT, answer) triple — there is no fresh sampling from the current policy and no external reward signal; each forward pass reads training data in the same static batch fashion as ordinary supervised fine-tuning [5].

**Extra models**: none beyond the one model being trained. The teacher and student are the same shared weights run twice per step (teacher-forced on the CoT, then autoregressive on continuous thoughts) [1]; the KD loss uses a stop-gradient on the teacher branch's hidden state rather than a separately frozen copy of the model [1]. The official implementation additionally loads a LoRA adapter (rank 128 by default in its training scripts) rather than full fine-tuning [6], and a two-layer MLP + LayerNorm projection head on the continuous-thought hidden states, ablated to a 42.5% vs. 43.7% GSM8k accuracy drop if removed (Table 3) [1]. Details in Cost.

**Shipped by**: no general-purpose post-training library ships a CODI trainer. trl's `trl/trainer` directory (18 files at the `main` branch as of this check) has no CODI-related entry [7]. verl ships a generic `trainer/distillation` module (`losses.py`, plus fsdp/megatron backends) for output-level knowledge distillation, but it defines only generic distillation loss functions with no continuous-thought or teacher/student-same-weights mechanism, and does not name or implement CODI [8]. A Hugging Face model search for "CODI" separately surfaces only the paper authors' own checkpoints and independent research forks, not a library entry point [9]. The only implementation is the paper authors' own repository, `zhenyi4/codi`, run via its top-level `train.py` script (not a Python package with an import path) [6]. Building this on top of an existing trainer would mean writing a custom two-forward-pass loss (teacher CE + student CE + L1 distillation term) — not a drop-in modification of a standard PPO/DPO-style trainer, since it requires generating continuous thoughts step-by-step during training with a KV cache, not just changing a reward function [1][6].

## How it works

Each training step runs the same shared model twice on one example and combines three losses [1]:

$$ \mathcal{L}=\alpha\mathcal{L}_{\text{teacher}}+\beta\mathcal{L}_{\text{student}}+\gamma\mathcal{L}_{\text{KD}} \qquad (1) $$

where $\alpha$, $\beta$, $\gamma$ are hyperparameters weighting the three terms; the paper sets $\alpha=\beta=1$ always, and $\gamma=1$ for GPT-2 or $\gamma=20$ for LLaMA-3.2-1B, chosen because that model's distillation loss has a much smaller magnitude [1].

**Student task** (target task at inference): the model autoregressively emits continuous thoughts $Z$ by feeding each step's last hidden state back in as the next input embedding, then predicts the answer tokens $y$ with cross-entropy:

$$ \mathcal{L}_{\text{student}}=-\frac{1}{N}\sum_{i=1}^{N}\log P(y_{i}\mid y_{1:i-1},Q,Z) \qquad (2) $$

Two special tokens, `bot` and `eot`, mark the start and end of the continuous-thought block, borrowed from Coconut [2]; a two-layer MLP plus LayerNorm transforms each continuous-thought hidden state before it is fed back in [1].

**Teacher task**: ordinary teacher-forced language modeling over the ground-truth CoT and answer tokens $y$, conditioned on the question $Q$:

$$ \mathcal{L}_{\text{teacher}}=-\frac{1}{N}\sum_{i=1}^{N}\log P(y_{i}\mid y_{1:i-1},Q) \qquad (3) $$

**Distillation loss**: an L1 distance between the teacher's and student's hidden activation at one specific token — the token immediately preceding the answer (the ":" in the prompt "The answer is:"), chosen because prior work found this token's hidden state "encodes far more information than output logits" [1] — averaged across all $M$ transformer layers, with a stop-gradient (`sg`) on the teacher side:

$$ \mathcal{L}_{\text{KD}}=\frac{1}{M}\sum_{l=1}^{M}\left|\text{sg}[\mathbf{h}_{\text{teacher}}^{l}]-\mathbf{h}_{\text{student}}^{l}\right| \qquad (4) $$

The paper motivates this specific token choice with a first-order argument that CoT rationale $R$ shifts this token's attention output by an additive term relative to a no-CoT baseline, $\mathbf{h}^{l}_{\text{CoT}}\approx \mathbf{h}^{l}_{\text{no-CoT}}+f(W_V R (W_K R)^T \mathbf{q})$, with a full derivation in the paper's Appendix B [1]. Training data excludes the final CoT step (the one that directly states the numeric result) to prevent the teacher from taking a shortcut that copies the answer into the distillation token instead of encoding the reasoning [1]; the repository exposes this as the `include_last_cot` flag, `False` by default [5]. Worked example, GPT-2, 3 transformer layers, toy hidden values: if the teacher's stop-gradiented per-layer hidden values at the distillation token are $[2.0, -1.0, 0.5]$ and the student's are $[1.0, -1.5, 0.8]$, the per-layer absolute differences are $[1.0, 0.5, 0.3]$, so $\mathcal{L}_{\text{KD}} = (1.0+0.5+0.3)/3 \approx 0.60$; the repository's default training config additionally divides each layer's difference by the teacher's per-batch standard deviation at that layer before averaging, to correct for a documented cross-layer norm-scale mismatch [1][6].

The official implementation's default distillation loss is SmoothL1, not the plain L1 of Equation 4 — the code's `distill_loss_type` dataclass default is `"smooth_l1"`, with `"l2"` also available, and every training script in the repository leaves it at the default [6]. The paper's own ablations (Table 3) show every architectural choice matters: removing the L1/KD loss drops GPT-2 GSM8k accuracy from 43.7% to 24.5%, and replacing the shared-model teacher with an independent, static pre-trained teacher drops it to 27.1% [1].

## Cost

**Theory, from the method's own math**: at least two forward passes of the same model per training step — one teacher-forced pass over the CoT (Eq. 3) and one autoregressive pass generating continuous thoughts (Eq. 2) — with no second model's worth of parameters added, unlike PPO's separate value network [1]. The reference implementation actually runs the teacher-forced pass twice every step, once under `torch.no_grad()` to get the hidden states for the KD term and once with gradients enabled for the teacher's own cross-entropy loss, rather than reusing one pass with a stop-gradient; a maintainer confirmed in response to a question about this design that using `.detach()` on a single pass would be "a better choice" but noted an unresolved numerical difference observed between the two approaches in early experiments, possibly tied to PyTorch version [10]. Memory holds one set of trained weights (plus, in the reference implementation, LoRA adapter parameters rather than the full backbone) [6]; there is no frozen reference model and no reward model to hold in memory, since the "teacher" is the same live-trained weights run in a different mode [1]. A naive reading of the objective might assume decoding continuous thoughts step-by-step at training time is expensive relative to computing a token-level loss on a fixed sequence — the paper confirms this by noting continuous thoughts "are generated dynamically during training ... decoded step by step, with a cache storing previous keys and values" [1], so it costs one extra forward per continuous-thought step, not one pass over the whole sequence per step.

**In practice, per framework**: the reference implementation's GPT-2 configuration trains for 40 epochs at an effective batch size of 128 (per-device 64 × gradient accumulation 2), taking about 36 hours on a single A100-80GB; its LLaMA-3.2-1B configuration trains for 10 epochs at the same effective batch size (32 × 4), taking about 48 hours on a single A100-80GB [1]. Both configurations use LoRA rank 128, alpha 32, in bfloat16, rather than full fine-tuning [6]. No other framework ships a CODI trainer, so no comparative framework cost claim can be made here.

## How to use it

- Data prep: (question, CoT, answer) triples; the reference loader tokenizes `question + cot + answer` together and discards examples over a token-length cap (`max_token_num`, default 1000 in the code, overridden to 200 in the LLaMA-1B script) to avoid OOM [5][6]. The default `icot` data path additionally strips the final CoT step (`include_last_cot=False`) and, for GPT-2/LLaMA experiments on GSM8k-Aug, formats the answer as `"The answer is: <number>"`, skipping any example whose answer does not start with a digit (a documented limitation for negative answers, discussed below) [5].
- Answer/reward convention: there is no scalar reward; the student and teacher tasks are both plain cross-entropy over answer tokens, and the KD term is a hidden-state distance, not a scored generation [1].
- Knobs table — the reference repository is a single research codebase, not a multi-framework tool, so this table gives its code-level dataclass default against the values actually used in its published training scripts and against the paper's own stated values (paper values are anchors, not defaults):

| knob | repo dataclass default [6] | repo GPT-2 script [6] | repo LLaMA-1B script [6] | paper [1] |
| --- | --- | --- | --- | --- |
| number of continuous thoughts (`num_latent`) | 5 | 6 | 6 | 6 |
| $\alpha$ (teacher loss weight, code field `ref_loss_factor`) | 1.0 | 1.0 (unset) | 1.0 (unset) | 1 |
| $\beta$ (student loss weight) | 1.0 (hardcoded, no dataclass field) | 1.0 (hardcoded) | 1.0 (hardcoded) | 1 |
| $\gamma$ (distillation loss weight, `distill_loss_factor`) | 1.0 | 1.0 (unset) | 20 | 1 (GPT-2) / 20 (LLaMA-1B) |
| distillation loss type (`distill_loss_type`) | `smooth_l1` | `smooth_l1` (unset) | `smooth_l1` (unset) | L1 (Eq. 4) |
| divide distillation loss by teacher std (`distill_loss_div_std`) | `False` | `True` | `True` | not stated as a named flag, described in prose as layer normalization by teacher std |
| LoRA rank | 128 | 128 | 128 | 128 |
| learning rate | not stated | `3e-3` | `8e-4` | `3e-3` (GPT-2) / `8e-4` (LLaMA-1B) |
| effective batch size | not stated | 128 (64×2) | 128 (32×4) | 128 |
| include last CoT step (`include_last_cot`) | `False` | `False` (unset) | `False` (unset) | excluded (ablated in Table 3) |

  The dataclass default of `num_latent=5` never appears in a published run — both released training scripts override it to 6, matching Coconut's setup so the two methods are directly comparable [1][6]; a reader who trains from the bare code default would silently diverge from every published result.
- Continuous-thought count trade-off: the paper reports that accuracy peaks around six continuous thoughts and that CODI outperforms Coconut at every compression ratio tested (Figure 3), with more thoughts trading token efficiency for accuracy and vice versa [1].

## While it runs

- Signals and their healthy shapes: the reference implementation prints `loss`, `ce_loss` (student), `distill_loss`, and `ref_ce_loss` (teacher) every `logging_steps`, and the paper's own ablation shows what each is worth — dropping the distillation loss's contribution should be watched for since Table 3 shows GSM8k accuracy collapsing from 43.7% to 24.5% without it [1][6]. No published guidance beyond the code's own print statements was found on healthy loss trajectories or entropy/KL-style monitoring signals specific to CODI, unlike RL methods that expose a clip fraction or KL divergence — CODI has no clipping and no explicit reference-model divergence term to monitor.
- Published reference runs: the paper's own Table 1/Table 2 numbers (GPT-2 GSM8k 43.7% at 8 total reasoning tokens vs. CoT-SFT's 44.1% at 25.1 tokens; LLaMA-3.2-1B GSM8k 55.6% at 8 tokens vs. CoT-SFT's 61.6% at 25.4 tokens) are the reference curve to compare a reproduction against [1]; the training scripts and pretrained GPT-2/LLaMA-1B checkpoints used to produce them are published in the official repository [6].
- Degeneracies and defaults: an open, unresolved GitHub issue (as of 2026-08-09, no maintainer reply resolving it) reports that reproducing CODI on LLaMA-3.2-1B-Instruct with the current codebase (commit `2c23146`) yields roughly 3% GSM8k accuracy against the paper's reported 44–54%, while the same codebase reproduces the GPT-2 numbers correctly [11]. In a separate open reproduction report of GPT-2 accuracy landing at 37–37.6% instead of the paper's 43.7% on GSM8k-Aug, the maintainer's only lead was "I am not sure if you are using the correct transformers version. It may affect some accuracy because something may mistmatch in my modeling script" — i.e., the released code is not confirmed reproducible across `transformers` versions, and no pinned version is stated [12]. Separately, a maintainer reply to a different issue confirms that `fix_attn_mask` — a flag documented in the code as fixing "a known attention mask bug" — is left `False` in every released script because the author "didn't affect performance in my experiments" when testing it, i.e., a documented-but-unused bug fix ships off by default [6][13]. The code also silently skips any training example whose ground-truth answer does not start with a digit (e.g., answers beginning with "-"), which the paper's own Limitations section flags as a suboptimal choice affecting negative-valued answers specifically [1].
- Named successors: SIM-CoT adds an auxiliary decoder during training that aligns each continuous thought with its corresponding explicit reasoning step to fix a latent-representation collapse it identifies in implicit-CoT methods including CODI at scale, reporting a +3.0% gain when applied on top of CODI with LLaMA-3.1 8B [3].
- Known failure modes: from the paper's own Limitations section — the fixed choice of distillation token (the ":" before the answer) may be suboptimal, since some answers start with "-" and removing those cases improves performance; gradients to the earliest continuous thought must backpropagate through the full six-step (or more) autoregressive chain before reaching a loss, which the authors flag as a potential optimization difficulty that "could become more pronounced when scaling to more complex problems requiring longer continuous reasoning chains" [1]; and CODI as trained is fully deterministic, forgoing the self-consistency/tree-search benefits that explicit CoT's inherent stochasticity permits [1]. From the official repository's GitHub issues (checked 2026-08-09, all open/all-time issues listed): one open, unconfirmed reproducibility report of near-total accuracy collapse on LLaMA-3.2-1B-Instruct [11]; no maintainer reply resolving it was found in the fetched comment thread. Two other issues carry maintainer-confirmed numerical traps (detailed above): a `transformers`-version sensitivity the maintainer could not fully explain, offered as the only lead for a GPT-2 GSM8k-Aug accuracy gap [12]; and a confirmed-but-unexplained numerical difference between the code's two independent (non-`.detach()`-linked) teacher forward passes versus a single stop-gradient pass, which the maintainer called worth fixing but had not fixed as of the fetched thread [10].
- What the gain is — and is not: the paper's own contribution is token-efficient reasoning that matches, not exceeds, explicit CoT-SFT's accuracy on the datasets tested (99.1% of CoT-SFT's GPT-2 GSM8k accuracy, 90.3% of its LLaMA-1B accuracy) [1]; it is a compression method for a capability the base model already has via full CoT, not a method demonstrated to add new reasoning capability beyond what explicit CoT achieves.
