# SKD

Paper: https://arxiv.org/abs/2410.11325

On-policy distillation with the teacher policing the student's own rollout: the student proposes tokens, and whenever a proposed token falls outside the teacher's top-K, the teacher discards it and resamples from its own distribution, so training drifts from teacher-guided to student-guided as the student improves.

**Speculative Knowledge Distillation (SKD)** is a knowledge-distillation method for training a smaller student language model to imitate a larger teacher, introduced in "Speculative Knowledge Distillation: Bridging the Teacher-Student Gap Through Interleaved Sampling" (ICLR 2025): "the student proposes tokens, and the teacher replaces poorly ranked ones based on its own distribution, transferring high-quality knowledge adaptively" [1]. Its parent is On-Policy KD, introduced as Generalized Knowledge Distillation (GKD) by Agarwal et al., which trains the student on its own self-generated output sequences using teacher feedback on those sequences instead of a fixed dataset [2]. SKD keeps that self-generated-sample idea but adds a token-level check borrowed from speculative decoding: after the student samples a block of tokens, the teacher verifies each one against its own top-K set and re-samples any token it does not endorse, discarding the tokens generated after it in that block [1]. The paper gives three reasons for this design: supervised KD trains on a fixed dataset that mismatches the student's own inference-time distribution; on-policy KD trains on the student's self-generated samples, but early in training those samples can be out-of-distribution for the teacher, giving inaccurate teacher feedback; and imitation-learning theory (DAgger-style analyses) motivates gradually shifting sample generation from teacher to student rather than committing to one or the other [1].

Confirmation of the paper: an exact-title search for "Speculative Knowledge Distillation: Bridging the Teacher-Student Gap Through Interleaved Sampling" returns arXiv:2410.11325 as the sole match, and the paper's own text links its official code to `google-research/google-research/tree/master/speculative_kd`, which matches the shortlist row's method name and arXiv ID [1][5]. As of this check the paper carries no confirmed independent adoption by a landmark training system, and no citation-count field was available in the shortlist row to gauge downstream uptake; this card does not claim adoption beyond what is stated below. In the paper's own comparison, distilling supervised-FT Gemma-7B to Gemma-2B-IT, SKD improves over supervised fine-tuning by 41.8% on low-resource Assamese-to-English translation, 230% on dialogue summarization, and 160% on GSM8K arithmetic reasoning; training on math instruction-following data, SKD improves over SFT by 198% on held-out MATH and 360% on GSMplus (Figure 3, detailed results in Appendix E) [1]. Lineage in one line: speculative decoding (Leviathan et al., 2022 [3]) and On-Policy KD / GKD (Agarwal et al., 2024 [2]) -> SKD (2024/2025 [1]) -> no confirmed named successor found (search described in While it runs).

**When to pick it**: pick SKD when you can run the teacher live during training (it must score the student's proposed tokens every block) and you want the student to train on its own inference-time distribution without inheriting on-policy KD's out-of-distribution-sample problem [1]. Its parent, On-Policy KD / GKD, is cheaper per step (no teacher-side resampling or block discarding) but the SKD paper's own Table 1 shows On-Policy KD can score far below plain supervised fine-tuning when the student is weak (e.g., 36.1 vs. 72.5 COMET on translation) [1][2]. The nearest offline alternative is Supervised KD, which trains on a fixed teacher-labeled dataset and needs no live teacher generation loop, at the cost of the same train/inference distribution mismatch the SKD paper targets [1]. The nearest online neighbor is ImitKD, which also blends teacher and student data but does so by randomly drawing whole sequences from the ground-truth set or the student's own output with fixed 50/50 probability, rather than SKD's per-token, teacher-adaptive replacement [1].

**Variant of**: On-Policy KD / GKD [2].

**Data it needs**: prompts only (`x`) for the on-policy branch that SKD trains on; no fixed `(x, y)` pairs are required, since the response is generated on the fly and the training divergence is computed against the teacher's own token probabilities [1]. The paper's runs used prompt sets from ~100 (extreme low-data ablation) up to 1K (translation, summarization, GSM8K) to 10K (task-agnostic math instruction-following) [1]. On-policy: fresh student samples are drawn from the current policy at every training step, with the teacher intervening live during that same generation pass [1].

**Extra models**: a teacher model `Mt`, frozen, run live during every training step to supply top-K token sets and resampled tokens, plus token-level probabilities for both models over the finished sequence to compute the divergence loss [1]; no value network and no separate reward model. This is the same two-model footprint as its parent On-Policy KD, but the teacher does strictly more work per step (block verification and on-demand resampling) than in plain on-policy KD (see Cost) [1][2].

**Shipped by**: no widely-used training library implements SKD's token-level accept/resample loop. The paper's own reference code is the only available implementation: `google-research/google-research/tree/master/speculative_kd`, Apache-2.0 licensed, which documents needing 8x A100 80GB GPUs for its 7B-teacher/2B-student setup, and separately requires a patched `transformers==4.44.2` install (replacing `candidate_generator.py` and `utils.py`) for its vLLM-based inference/evaluation environment [5]. Building it inside an existing framework is a new-sampling-loop job, not a loss-on-top-of-an-existing-trainer job: it needs a modified generation loop that checks each student token against the teacher's top-K set and truncates/resamples mid-block, the same class of change as assisted/speculative-decoding candidate generation, before any distillation loss can be computed [1][5]. trl ships the parent method as `experimental.gkd.GKDTrainer` (On-Policy KD / GKD, `lmbda=1.0`), but it is exposed under trl's `experimental` namespace, and does not perform SKD's teacher-side token verification or resampling [2][4].

## How it works

Loop, one training step: the student samples a block of γ tokens on-policy; the teacher checks each token against its own top-K set; on the first rejected token, the remainder of that block is discarded and the teacher resamples from its own distribution at that position; the student resumes on-policy generation from there; once the full sequence is generated, both models' per-token probabilities over the finished sequence are used to compute the divergence loss and update the student [1].

**Training objective** [1, Eq. 1]:

$$ D(M_t \| M_s)(y|x) = \frac{1}{L_y}\sum_{i=1}^{L_y} D\big(M_t(\cdot|y_{<i}, x) \,\|\, M_s(\cdot|y_{<i}, x)\big) $$

$L_y$ is the length of the (possibly teacher-corrected) output sequence $y$, $i$ indexes decoding steps, and $D$ is a divergence metric between the teacher's and student's next-token distributions at that step; the paper's main experiments use KL divergence, $D_{KL}(P\|Q) = \sum_{c \in C} P(c)\log\frac{P(c)}{Q(c)}$ with $P$ the teacher's and $Q$ the student's distribution [1]. Training minimizes this quantity over the sampled sequence, i.e. it pulls the student toward the teacher at every position of the sequence actually produced, whether that token came from the student or from teacher resampling [1].

**Token acceptance / interleaved sampling** (paper's Algorithm 1, simplified to γ = 1; the paper's own runs use γ = 5) [1]: at decoding step `i`, sample $y_i \sim M_s(\cdot|y_{<i}, x)$; if $y_i$ is not among the teacher's top-K tokens under $M_t(\cdot|y_{<i}, x)$, discard it and resample $y_i \sim M_t(\cdot|y_{<i}, x)$ instead; after generating the full sequence (length $\alpha$), take a gradient step minimizing the batch's divergence loss from Eq. 1 [1]. The paper explicitly rejects the default speculative-decoding acceptance rule (which would make the final samples follow the teacher's distribution exactly, degenerating to supervised KD) and instead defines acceptance purely by top-K membership, drawing on top-k sampling rather than distributional matching [1].

Worked example: with K = 2 and a teacher distribution over four tokens $\{A{:}0.5, B{:}0.3, C{:}0.15, D{:}0.05\}$, the teacher's top-2 set is $\{A, B\}$. If the student proposes $C$, it is rejected (rank 3, outside top-2): everything sampled after $C$ in that γ-block is discarded, and the position is resampled from the teacher's full distribution (e.g. landing on $A$ or $B$). If the student had proposed $B$, it is accepted and generation continues on-policy from the student. Either way, the divergence loss in Eq. 1 is then computed over whichever tokens ended up in the final sequence, teacher- or student-sampled [1].

**Degenerate cases, by the paper's own definition**: if the student's samples are consistently rejected, every token is teacher-resampled and SKD reduces to supervised KD-like behavior; if the student's samples are consistently accepted, SKD reduces to on-policy KD [1]. K is the knob that controls which regime dominates (see While it runs for the paper's own sweep).

## Cost

**Theory, from the method's own definition**: each training step needs (a) autoregressive generation of the response, γ tokens at a time, same generation-length cost as plain on-policy KD; (b) at every γ-token boundary, a teacher forward pass to obtain its top-K set for verification, plus an extra teacher forward pass to resample whenever a token is rejected — structurally the same "draft, then verify" shape as speculative decoding, except the goal is training-data quality rather than serving latency [1][3]; (c) after the sequence is finished, one more forward pass of both models over the completed sequence to get the per-token probabilities that Eq. 1 needs [1]. Memory holds two models: the trained student (weights, gradients, optimizer state) and the frozen teacher (weights and activations only, no gradients, no optimizer state) — the same two-model footprint as the parent On-Policy KD, with no added value network or reward model [1][2]. A naive reading of the objective does not say how often rejection actually fires in practice, so it does not by itself tell you whether the extra teacher-resampling passes dominate wall-clock time; that depends on how often the student's tokens fall outside the teacher's top-K, which the paper does not report as a rate (see In practice below).

**In practice**: only the paper's own reference implementation exists, so this is the only "in practice" data point [5]. The repository documents running the 7B-teacher/2B-student configuration on 8x NVIDIA A100 80GB GPUs, and defines two separate environments: a Training Environment, whose setup is just installing `torch` and the repository's `requirements.txt`, and a distinct Inference Environment [5]. The requirement to pin `transformers==4.44.2` and replace two files (`candidate_generator.py`, `utils.py`) is documented under that Inference Environment section, for vLLM-based evaluation, not under the Training Environment section [5]. This card did not open the training-loop file itself (`train/ddp_skd.py`) [6], so it cannot say from source how the training-time teacher top-K verification and resampling are implemented, only that the README does not attribute the transformers patch to training. No trl- or verl-level cost data exists for SKD itself; do not carry trl's `GKDTrainer` cost profile over to SKD, since SKD's teacher does strictly more work (top-K verification plus conditional resampling) than GKD's teacher, which only scores a completed student sequence [2][4].

## How to use it

Data preparation: only prompts `x` are required for training (no ground-truth `y` is consumed by the on-policy branch); the paper's main results (Table 1) train the student end-to-end from an instruction-tuned checkpoint with no SFT warm-start, captioned "instruction tuned model (w/o SFT)" [1]. Training from an SFT-initialized student instead is a separate ablation (Section 5.3, Tables 2-3) [1]. Appendix I frames skipping the SFT stage as one of SKD's own advantages, stating that end-to-end methods like SKD, which can train from an arbitrary base model and bypass the SFT stage, offer significant benefits over two-stage approaches like on-policy KD [1]. Label/loss convention: there is no scalar reward; the "label" at each position is whichever token (student- or teacher-sampled) ended up in the finished sequence, and the loss is the KL divergence between the teacher's and student's next-token distributions at that position (Eq. 1) [1].

Knobs, paper values only — no framework ships this method, so there is no framework-default column to compare against; "not stated" means the paper text checked here does not give the value:

| knob | paper value [1] |
| --- | --- |
| top-K acceptance threshold | 25 in main experiments; a broad range of 5-50 outperforms both baselines (Appendix B) |
| speculation block length γ | 5 in practice (Algorithm 1 shows the simplified γ = 1 case) |
| divergence metric D | KL divergence (teacher \|\| student), Eq. 1 |
| teacher sampling temperature | 0.2, all tasks |
| teacher top-p | 0.5 for summarization, 1.0 for other tasks |
| student sampling temperature / top-p | 0.5 / 0.5, all tasks |
| learning rate | 1e-5 |
| batch size / grad. accumulation | 8 / 1 |
| training steps | 375 (summarization, GSM8K, math instruction-following at 1K prompts); 1225 (translation); 7500 (math instruction-following, full 10K-prompt data) |

Trade-offs a run designer faces: raising K moves SKD toward on-policy KD — more student tokens survive verification, which is cheaper per rejected-token event but risks the same out-of-distribution-sample problem SKD was built to avoid; lowering K moves SKD toward supervised KD — safer, teacher-endorsed tokens dominate, but the student practices less at correcting its own drift [1]. The paper found neither extreme optimal and settled on K = 25 without a parameter search, noting it is also a common top-k sampling default [1]. Block length γ trades verification granularity against overhead: a larger γ means fewer teacher-verification calls per sequence but a coarser rejection (discarding a longer already-generated suffix whenever one token in the block is rejected); the paper reports only its chosen γ = 5 and does not ablate this trade-off [1].

## While it runs

- **Signals and their healthy shapes**: the paper does not name a live training dashboard metric for SKD itself (e.g. no logged "acceptance rate" or "reward margin" is reported as a monitored curve). It does show, in an SFT-initialization ablation, that the student's SFT validation loss should be checked before starting KD: a converged SFT checkpoint (step 128) outperforms both an earlier (step 64) and an overfit (step 192) checkpoint when used to initialize on-policy KD or SKD (Figure 7) [1] — treat SFT validation loss, not final KD accuracy, as the pre-flight signal.
- **Published reference runs**: Table 1, distilling supervised-FT Gemma-7B to Gemma-2B-IT, K=25: GSM8K accuracy is 18.7 (SFT) / 22.5 (Supervised KD) / 25.3 (On-policy KD) / 26.2 (ImitKD) / 29.1 (SKD); Assamese-to-English translation COMET is 72.5 (SFT) / 73.3 (Supervised KD) / 36.1 (On-policy KD) / 74.8 (ImitKD) / 75.3 (SKD) [1]. The on-policy KD collapse to 36.1 COMET — well below the 72.5 that plain SFT reaches — is the deciding number here: naive on-policy KD can score worse than doing nothing, and SKD's teacher-side token correction is what recovers and then exceeds the SFT baseline.
- **Degeneracies and defaults**: both very low and very high K underperform the paper's own K = 5-50 range (Appendix B) — K is not a "smaller/larger is always better" knob [1]. There is no framework-vs-paper default divergence to report, since no framework ships a default configuration for this method.
- **Named successors**: none found. Search performed: GitHub code search for "speculative knowledge distillation" surfaced only small, independent third-party repositories (e.g. `adaspec`, `distillSpec`, both under 40 stars) rather than a maintained named successor method; a GitHub issue search scoped to `google-research/google-research` for `speculative_kd` returned zero results (checked 2026-09-03) [checked against GitHub search API].
- **Known failure modes**: from the paper's own ablations — extreme top-K settings (too low or too high) underperform the mid-range K = 5-50 (Appendix B) [1]; initializing from an overfit SFT checkpoint measurably degrades downstream KD performance for both on-policy KD and SKD (Appendix I / Figure 7) [1]; the paper also notes it only studied a top-K acceptance criterion and explicitly leaves top-p-based or combined top-K/top-p acceptance criteria to future work [1]. No maintainer-reported failure mode exists because no library ships a maintained trainer for this method (see Shipped by).
- **What the gain is — and is not**: the paper's own analysis attributes SKD's improvement to filtering out-of-distribution student tokens so that the teacher's feedback signal is computed on sequences the teacher can actually judge accurately, not to any new information beyond the same teacher model already available to the Supervised KD and On-Policy KD baselines it is compared against [1]. All of the paper's comparisons hold the teacher and student model pair fixed across methods (e.g. Gemma-7B to Gemma-2B, or Qwen2-7B to Qwen2-0.5B); this card cannot say whether SKD lets a student exceed what its base capacity would otherwise allow against a different, stronger teacher.
