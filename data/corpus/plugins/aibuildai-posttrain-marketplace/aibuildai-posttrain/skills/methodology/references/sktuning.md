# SK-Tuning

A calibration fine-tune, not a policy-alignment algorithm: fine-tune the model for one epoch on self-generated True/False question-answer pairs with a reference-free pairwise log-sigmoid loss, so its own "is this answer true?" confidence becomes accurate enough to serve as a reward signal for a separate downstream DPO stage.

**SK-Tuning** (Self-Knowledge Tuning) is a training step introduced in "Self-Alignment for Factuality: Mitigating Hallucinations in LLMs via Self-Evaluation" (https://arxiv.org/abs/2402.09267), which the paper defines as designed to augment the LLM's self-evaluation ability by improving the model's confidence estimation and calibration [1]. It is not itself the alignment algorithm: the parent pipeline, Self-Alignment for Factuality, first uses SK-Tuning to sharpen a self-evaluation module (called SELF-EVAL), then uses that module's factuality scores to build preference pairs and fine-tunes the policy with Direct Preference Optimization (DPO), whose own loss the paper reuses in a reference-free form for SK-Tuning itself [1][2]. Mechanically, SK-Tuning builds True/False training examples by having the model sample several candidate answers to a question, verifying each against a gold answer with a DeBERTa-Large-MNLI entailment model, and training the model to prefer the correct label with a pairwise log-sigmoid loss over the two answer-token log-probabilities [1]. The paper gives two reasons for the extra stage: its preliminary results show LLMs are overconfident when simply prompted for a True/False self-evaluation (SELF-EVAL-P(TRUE)), consistent with prior findings on self-evaluation overconfidence, and it needs the resulting confidence scores to be well calibrated so that preference labels derived from them are reliable [1].

No landmark downstream system was found to have adopted SK-Tuning by name: a query of the paper's citing-paper list (Semantic Scholar API, `arXiv:2402.09267/citations`, default ordering, first 50 of the paper's citations, fetched 2026-08-09) returned only hallucination-mitigation and calibration research papers, none of them a named production system. Within the paper's own experiments, adding SK-Tuning to the pipeline (SELF-EVAL-SKT) lifted TruthfulQA True*Info from 41.51 to 45.75 on LLaMA-7B and from 41.10 to 53.42 on LLaMA2-7B versus the un-tuned self-evaluator (SELF-EVAL-P(TRUE)), and BioGEN FActScore from 31.33 to 38.28 (LLaMA-7B) and 42.73 to 46.50 (LLaMA2-7B), all in Table 1 [1]. Lineage in one line: DPO's pairwise loss (2023, [2]) -> stripped of its reference-model term to make SK-Tuning's calibration loss (2024, [1]) -> feeds preference labels into a standard DPO alignment stage in the same paper [1]. The paper was confirmed as the right match for the shortlist's "SKTUNING" row by picking the higher-cited of the two name-colliding candidates under an exact-title/name search (119 citations here versus 30 for the unrelated "Semantic Knowledge Tuning" PEFT paper, arXiv:2410.08598).

**When to pick it**: pick SK-Tuning only as a preparatory stage inside a self-alignment-for-factuality pipeline, when you want to reduce hallucinations without human factuality annotations and are willing to run two fine-tuning stages (calibration, then DPO) instead of one [1]. The paper frames its motivation against two annotation-heavy alternatives it lists in related work: supervised fine-tuning on high-quality human-labeled factuality data, and RLHF as in Ouyang et al.'s InstructGPT, both of which need human labels that SK-Tuning avoids by using the model's own sampled answers [1][3]. Its nearest offline alternative inside the same paper's experiments is FactTune-MC, which also fine-tunes with DPO but derives its confidence scores from sampling-based response consistency rather than a dedicated calibration-training stage [4]; SELF-EVAL-SKT outperforms FactTune-MC on BioGEN FActScore for both LLaMA-7B and LLaMA2-7B in Table 1 [1]. Do not pick it if you need an online, resample-every-step method: SK-Tuning's own training set is built once and trained for a single fixed epoch [1], unlike online RL methods such as PPO [5] or GRPO [6] that resample from the live policy each step.

**Variant of**: a reference-free special case of DPO's pairwise loss [2]. Setting DPO's reference-policy term to a constant and its temperature β to 1 in DPO's loss $L_{DPO}=-\mathbb{E}[\log\sigma(\beta\log\frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)}-\beta\log\frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)})]$ (DPO's Eq. 7 [2]) yields exactly SK-Tuning's loss $L_\phi=-\mathbb{E}[\log\sigma(\log\pi_\phi(r_+|q,a)-\log\pi_\phi(r_-|q,a))]$ (Eq. 2 [1]) — no reference model appears in the paper's SK-Tuning formula [1].

**Data it needs**: True/False question-answer pairs, self-generated and self-labeled, not collected from humans. Construction: for each question, sample K candidate answers via few-shot prompting from the base model, verify each against the gold answer with bidirectional entailment using DeBERTa-Large-MNLI, then build a "prompt" / "chosen" / "rejected" example per sampled answer, where prompt is the few-shot True/False Q&A template and chosen/rejected are the letters "A"/"B", duplicated once per sampled answer so the training set mirrors how often the model itself produced that answer [1] — matching the public data schema `{"prompt": ..., "chosen": "A", "rejected": "B"}` in the paper's official repository [7]. At paper scale: 49,862 Wikipedia prompts plus 32,500 BIG-bench prompts, yielding 2,470,860 True/False training examples, trained for one epoch [1]. This is offline: the whole set is sampled and labeled once before training starts and is not regenerated during training, even though the answers it labels were themselves generated by the base model [1].

**Extra models**: by the paper's own equation, none — no value network, no reference model, no reward model; SK-Tuning trains the policy directly on its own two-token log-probabilities [1]. Building the training data needs one frozen external verifier, DeBERTa-Large-MNLI, used only offline for automatic True/False labeling, not during training or inference [1]. This diverges from what the paper's own code actually runs: the official repository's `dpo_trainer.py` implements SK-Tuning by reusing its generic DPO trainer, which loads a frozen reference model (`self.ref_model`) and applies DPO's `-log σ(β·logits)` loss with `self.beta = 0.5` by default [7] — i.e., the shipped code holds a reference model in memory for SK-Tuning that the paper's math does not require. See Cost for the memory consequence.

**Shipped by**: no packaged training library implements SK-Tuning — a search of trl's live `main`-branch documentation index page (huggingface.co/docs/trl, fetched 2026-08-09) found no reference to "self-knowledge," "SK-tuning," or "self-eval" trainers; this covers only that page's current, unpinned build, not any release version of trl. The only implementation is the authors' own research-code repository, `zhangxy-2019/Self-Alignment-for-Factuality` (`dpo_training/dpo_trainer.py`, commit `f51d8cd`, read 2026-08-09) [7], which is not an installable package and exposes no top-level trainer entry point; its README still states the code is being organized for upload even though the `dpo_training/` directory with a working trainer is already present in the repo at that commit [7]. Building SK-Tuning on top of an existing trainer needs no new sampling loop beyond what any DPO setup already has (sample K answers, verify with an NLI model, format as chosen/rejected pairs); the loss itself is a plain pairwise cross-entropy over two token log-probabilities, simpler than DPO's because it needs no reference-model forward pass by the paper's own definition [1].

## How it works

One loop, once: build a True/False dataset from the model's own sampled answers, then fine-tune on it for a single epoch with a pairwise ranking loss.

**Self-evaluation prompt.** Given a question $q$ and answer $a$, the model estimates the probability the answer is true via a True/False prompt, formalized as $p(\text{True}|q,a)=f_M(q,a)$ (Eq. 1 [1]); $f_M$ is realized by prompting the LLM with a True/False Q&A template and reading off the probability of token "A" [1].

**SK-Tuning's training-data construction.** For a question $q$, the model samples $K$ candidate answers $\{a_k\}_{k=1}^K$ via few-shot prompting; each is checked against the gold answer with bidirectional entailment (DeBERTa-Large-MNLI), labeling it correct ($a_c$) or incorrect ($a_i$) [1]. Each sampled answer becomes one True/False example: a correct answer is paired with positive prediction $R_+$ ("A") against negative prediction $R_-$ ("B"), and vice versa for an incorrect answer, with duplicates kept per sample to approximate the model's own confidence distribution over that question [1]. The paper's own worked figure: for "What is Westlife's first album?", 30 answers are sampled — the correct answer 20 times, one wrong answer ("Coast to Coast") 4 times, another wrong answer ("World of Our Own is their first studio album") 6 times — producing 20 (A,B) examples for the correct-answer question and 4 and 6 (B,A) examples for the two incorrect-answer questions, 30 examples total for that one question [1].

**SK-Tuning's loss** (Eq. 2 [1]), over the resulting dataset $D_\psi=\{(q,a,r_+,r_-)\}$:

$$ L_\phi = -\mathbb{E}_{(q,a,r_+,r_-)\sim D_\psi}\left[\log\sigma\big(\log\pi_\phi(r_+\mid q,a) - \log\pi_\phi(r_-\mid q,a)\big)\right] $$

$\pi_\phi$ is the LLM being trained for factuality estimation, and $\sigma$ is the logistic function [1]; there is no reference-policy term and no temperature $\beta$ in this equation, unlike DPO's own loss below [1].

**Downstream DPO stage** (Eq. 3 [1]), used after SK-Tuning to align the policy on preference pairs $D=\{(x,y_w,y_l)\}$ built from SELF-EVAL-SKT's factuality scores:

$$ L_\theta = -\mathbb{E}_{(x,y_w,y_l)\sim D}\left[\log\sigma\Big(\beta\log\frac{\pi_\theta(y_w\mid x)}{\pi_{ref}(y_w\mid x)} - \beta\log\frac{\pi_\theta(y_l\mid x)}{\pi_{ref}(y_l\mid x)}\Big)\right] $$

matching DPO's own Eq. 7 form [2]; $\pi_\theta$ is initialized from $\pi_{ref}$, and $\beta$ controls deviation from it [1]. The paper does not state a numeric value for this $\beta$ in the sections read for this card [1].

## Cost

**Theory, from the method's own math**: SK-Tuning's Eq. 2 needs no reference-model forward pass and no value network — one policy forward/backward pass over a short few-shot-plus-Q&A prompt whose loss depends only on the log-probabilities of two candidate output tokens ("A"/"B"), not on generating new text during training [1]. That makes the per-step compute of SK-Tuning's own definition close to a token-classification fine-tune, not to a generation-heavy RL loop. Memory in theory: one trained model, no frozen copy. Building the training data is a one-time offline cost (sampling K answers per question, running a separate entailment model) paid before training starts, not during it [1].

**In practice, per implementation**: the only available implementation is the paper's own repository, not a framework, so this is a single-source reading, not a documented default. `dpo_training/dpo_trainer.py` at commit `f51d8cd` instantiates a frozen `ref_model` from the RLHF engine and computes `-F.logsigmoid(self.beta * logits)` with `self.beta = 0.5` [7] — the same generic DPO trainer the repository uses for the downstream alignment stage. Run through this code, SK-Tuning's actual training cost includes one extra frozen model held in memory and one extra forward pass per step for it, which the paper's own Eq. 2 does not require [1][7]. No installable framework (trl checked against its live docs index, see [8]) offers an alternative implementation to compare against.

## How to use it

- Build the True/False dataset first, offline: for each question in your pool, sample K answers from the base model with few-shot prompting, and label each True/False by comparing to a gold answer with an entailment model (the paper uses DeBERTa-Large-MNLI [1]). Keep duplicate (prompt, label) pairs per sampled answer rather than deduplicating, since the paper credits this duplication with helping confidence calibration [1].
- Reward/label convention: labels are the literal answer letters "A" (true) and "B" (false) from the SELF-EVAL-P(TRUE) prompt template, not a scalar reward [1]; the official repo's training file format is `{"prompt": ..., "chosen": "A"/"B", "rejected": the other letter}` [7].
- Knobs, with each source's own value ("not stated" means the source was checked and does not give it; official repo values are a single research-code reading, not a framework default):

| knob | paper, SK-Tuning stage [1] | paper, downstream DPO stage [1] | official repo `dpo_trainer.py` default [7] |
| --- | --- | --- | --- |
| epochs | 1 | 5 | not stated (script-configurable) |
| learning rate | 5e-7 | 5e-6 | not stated (script-configurable) |
| batch size | 8 | 8 | not stated (script-configurable) |
| loss temperature $\beta$ | none (no $\beta$ in Eq. 2) | not stated | 0.5 |
| training examples | 2,470,860 | not stated exactly (per-prompt candidate count, ranked and paired) | not stated |
| hardware | 8x 32GB V100 | 8x 32GB V100 | not checked |

  The gap between SK-Tuning's own learning rate (5e-7) and the downstream DPO stage's (5e-6) is a full order of magnitude in the paper's own setup [1] — carrying one stage's learning rate into the other is a live mistake if reusing a single training script.
- Trade-off: more candidate answers K per question during data construction gives a better empirical estimate of the model's own answer-confidence distribution but multiplies both sampling and entailment-verification cost per question. The paper's own Appendix C states its paper-wide value: 30 candidate response samples per task prompt via 10-shot prompting at temperature $T=1$ [1], matching the Westlife illustrative figure's 20+4+6=30 [1].

## While it runs

- **Signals and their healthy shapes**: the paper's own diagnostic is a calibration curve — confidence bucket versus the empirical frequency that predictions in that bucket are correct — plotted for SELF-EVAL-P(TRUE) and SELF-EVAL-SKT on LLaMA2-7B/CommonsenseQA; SELF-EVAL-P(TRUE) shows substantial overconfidence (predicted confidence exceeds the empirical correctness frequency in most bins), while SELF-EVAL-SKT tracks the diagonal more closely [1]. The paper also reports Accuracy (does the correct answer get the top confidence score among the choices) and AUROC (does the correct answer outrank a random incorrect one) as the two numbers to track calibration quality on held-out MCQA tasks [1].
- **Published reference runs**: Table 3 gives SELF-EVAL-SKT versus the un-tuned SELF-EVAL-P(TRUE) across five MCQA datasets — e.g. Selection Accuracy on CommonsenseQA rises from 64.95 to 70.43, and Discrimination AUROC from 79.76 to 84.65 [1]; Table 1's TruthfulQA and BioGEN numbers (quoted above) are the reference curves for the full downstream pipeline [1].
- **Degeneracies and defaults**: the paper's own SK-Tuning loss defines no $\beta$ and no reference model, but the only available implementation trains it with the repository's generic DPO trainer, which does load a reference model and uses $\beta=0.5$ by default [1][7] — running the shipped code is not running the paper's stated equation unless that default is overridden.
- **Named successors**: no paper citing arXiv:2402.09267 that explicitly names itself a fix to a documented SK-Tuning bias was found in the first 50 citing papers returned by Semantic Scholar's default-ordered citation list for this arXiv ID, fetched 2026-08-09 [9].
- **Known failure modes**: the paper's own Limitations section calls its results preliminary, notes it only ran 7B-scale LLaMA models, and — citing Kadavath et al.'s finding that self-evaluation ability tends to improve with model scale — states it expects but did not test larger models such as 13B/70B or RLHF-tuned checkpoints like LLaMA2-Chat [1]. A search of the official repository's GitHub issues (`zhangxy-2019/Self-Alignment-for-Factuality`, all 5 open issues, fetched 2026-08-09) found no technical failure report; four issues ask when code/data will be released and one is unrelated outreach, and the repository's single maintainer comment (on issue #4) only apologizes for delay and promises a release, with no numerical or implementation caveat [10].
- **What the gain is - and is not**: the paper's own analysis (Section 5) finds SK-Tuning's gain is in making the model's stated confidence match its actual correctness rate — calibration — not in making the model know more facts; the entailment-verified answers used to build training data still come from the base model's own sampling, so SK-Tuning cannot correct hallucinations on questions the base model never answers correctly in any sample [1].
