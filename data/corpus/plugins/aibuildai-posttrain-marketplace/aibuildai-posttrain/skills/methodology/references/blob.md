# BLoB

LoRA where the A matrix is Bayesian from the first fine-tuning step: sample A from a learned Gaussian throughout training (not after it), keep B deterministic and initialized at zero, and average logits over N posterior samples at inference for calibrated predictions.

**BLoB** (Bayesian Low-Rank Adaptation by Backpropagation) is a variational-Bayesian fine-tuning method for LLMs, introduced by Wang, Shi, Han, Metaxas, and Wang, whose abstract states that it goes "beyond post-training Bayesianization" to propose "an algorithm that continuously and jointly adjusts both the mean and covariance of LLM parameters throughout the whole fine-tuning process" [1]. The paper is at https://arxiv.org/abs/2406.11675 [1]. Its parent is LoRA, which decomposes a weight update as $\Delta W = BA$ for low-rank matrices $B \in \mathbb{R}^{m\times r}$, $A \in \mathbb{R}^{r\times n}$ [2]. BLoB treats the LoRA update as Bayesian only in $A$: $A$ gets a Gaussian variational posterior with mean $M$ and standard deviation $G^2$, while $B$ stays a deterministic zero-initialized matrix, and both are trained jointly by minimizing a variational free energy (data likelihood plus a KL term to a prior) at every step [1]. The paper gives two reasons for the design beyond memory: prior post-training Bayesian methods (e.g., Laplace-LoRA) are capped by whatever the point-estimate fine-tuning already learned, since they add uncertainty only after training finishes [1]; and Bayesianizing both $A$ and $B$ together is impractical because $B$'s zero initialization (needed to preserve the pretrained model's behavior at the start of fine-tuning) forces its posterior variance toward zero anyway, so leaving $B$ deterministic costs nothing while halving the added parameter and memory cost [1].

BLoB was introduced and evaluated in the paper itself (NeurIPS 2024 [1], confirmed by the official code repository's own citation, which lists it as "Thirty-eighth Conference on Neural Information Processing Systems, 2024" [3]); no landmark downstream system's adoption of BLoB was found in a search of the paper's own citations or the implementing repository's README [1][3]. In the paper's own Llama2-7B experiments, fine-tuning with BLoB and N=10 inference samples cut ECE on OpenBookQA (OBQA) from 12.55±0.46 (MLE) to 3.77±1.47, and NLL from 0.73±0.03 to 0.50±0.01, while ACC stayed essentially unchanged (81.52±0.25 for MLE versus 81.52±0.74 for BLoB N=10; Table 1, in-distribution results) [1]. Lineage in one line: LoRA (2021 [2]) + Bayes By Backprop (2015 [4]) -> BLoB (NeurIPS 2024 [1]) -> named successor TFB (Training-Free Bayesianization, NeurIPS 2025 [5]), from the same authors and repository [3].

**When to pick it**: supervised fine-tuning of an LLM on a small or domain-specific labeled dataset where calibrated confidence (not just accuracy) matters, and where post-hoc Bayesian correction is not enough because the point-estimate weights it would correct are already overconfident [1]. Prefer standard LoRA [2] (MLE/MAP fine-tuning) when calibration is not a requirement, since BLoB roughly doubles training time relative to LoRA on the paper's own Llama2-7B benchmark (Cost, below) [1]. Prefer Laplace-LoRA [6] as the nearest post-training alternative when compute is tight and only a single already-fine-tuned LoRA checkpoint is available to Bayesianize after the fact — but the paper's own in-distribution Table 1 shows Laplace-LoRA's ACC collapsing to 29.73±12.02 on ARC-C, versus BLoB's 70.83±1.57 at N=0, and the paper attributes this to Laplace-LoRA's inconsistent performance specifically on ARC-C and ARC-E [1], so accuracy under this baseline is a live risk on some datasets. The nearest online neighbor for uncertainty-aware LoRA is BBB (Bayes By Backprop applied to LoRA's $A$ as a baseline), which the paper reports converges far more slowly than BLoB's own square parameterization because it uses the softplus parameterization instead, and lacks BLoB's Flipout-based sampling speed-up [1].

**Variant of**: LoRA [2], with a Bayesian variational posterior added only on the $A$ matrix.

**Data it needs**: the same data LoRA needs for supervised fine-tuning — labeled (prompt, correct-answer) pairs for the target task; the paper's in-distribution experiments use six common-sense reasoning datasets (Winogrande-small, Winogrande-medium, ARC-Challenge, ARC-Easy, OpenBookQA, BoolQ) with next-token logits over answer choices as the fine-tuning signal [1]. No preference pairs, reward model, or reward function are required — the method needs only the standard supervised label per example. It is not RL-style on-policy sampling: gradients come from labeled data forward passes, and inference-time posterior sampling ($N$ forward passes with different weight draws) is a separate step used only for calibration, not for generating new training data [1].

**Extra models**: none beyond the base model being fine-tuned. Unlike PPO-style RL, BLoB needs no separate value network, reference model, or reward model — uncertainty comes entirely from sampling the LoRA $A$ matrix's own posterior at inference [1]. The official implementation loads only the base pretrained model plus the LoRA adapter; the added standard-deviation matrix $G$ is extra parameters on top of the adapter itself, not a second model. The paper states that keeping $B$ deterministic (rather than Bayesianizing both $A$ and $B$) reduces the additional memory cost by approximately 50% per layer compared to the symmetric alternative [1]. See Cost for the resulting memory and time overhead.

**Shipped by**: no PEFT-standard library (trl, peft) ships BLoB as of this reading. The method's own authors ship a reference implementation in the GitHub repository Wang-ML-Lab/bayesian-peft, whose top-level layout has no `setup.py` or `pyproject.toml` (confirmed by listing the repo root — files are `.gitignore, LICENSE, README.md, dataset, models, modelwrappers, requirements.txt, run, scripts, utils`) [3][7], so it is not pip-installable; it is run as research code via `bash scripts/blob/blob-llama-all-single-gpu.sh` after a manual conda/pip environment setup [3]. The entry point is `class BLoB(WrapperBase)` in `modelwrappers/blob.py`, read at commit `7bdafeb` (2025-08-11) [8]. No support status is stated by the maintainers beyond the repo existing to reproduce the paper and its NeurIPS 2025 successor TFB [3]. Building BLoB on top of an existing LoRA trainer (e.g., trl's `SFTTrainer`) would mean replacing the adapter's forward pass with a sampled-weight forward pass and adding the KL term to the loss — a modification to the trainer's loss and layer forward, not a new sampling loop, since training stays fully supervised and on-policy generation is never needed.

## How it works

Each training step: sample a mini-batch, draw $K$ noisy versions of $A$ from its current Gaussian posterior via the reparameterization trick (accelerated with Flipout), compute the free-energy loss averaged over the $K$ samples, and update $M$, $G$, and $B$ by backpropagation [1].

**LoRA's forward pass**, the object being Bayesianized [1] (Eqn. 2, citing LoRA's own decomposition [2]):

$$ z = W_0 h + \Delta W h = W_0 h + BA h $$

**The variational free energy** being minimized, standard for Variational Bayesian Networks and equivalent to minimizing $\mathrm{KL}[q(W|\theta) \| P(W|\mathcal{D})]$ [1] (Eqn. 3):

$$ \min_{\theta} \mathcal{F}(\mathcal{D}, \theta) \triangleq -\mathbb{E}_{q(W|\theta)}[\log P(\mathcal{D}|W)] + \mathrm{KL}[q(W|\theta) \,\|\, P(W)] $$

The first term is the likelihood cost (fit the data); the second is the complexity cost (stay close to the prior) [1]. BLoB restricts $W$'s Bayesian treatment to $A$: it sets $q(A|\theta) = \mathcal{N}(A \mid M_A, \Omega_A^2)$ and keeps $B$ deterministic by fixing $\Omega_B = 0$ throughout fine-tuning, because an initially-random Bayesian $B$ combined with Bayesian $A$ produces large-variance gradient noise early in training unless $B$'s variance is driven to zero anyway [1] (asymmetric Bayesianization, Sec. 3.1). The parameterization of the per-entry standard deviation is $\Omega_{ij} = G_{ij}^2$ (a "square parameterization"), which the paper's Fig. 2 shows converging to the target variance in about 5,000 SGD iterations, versus roughly 100,000 iterations for Bayes By Backprop's softplus parameterization $\sigma_q = \log(1+e^\rho)$ in the same setting [1] (Appendix A.2).

**Full training loop (Algorithm 1)** [1]: initialize $G \sim \mathcal{U}(\epsilon/\sqrt{2}, \epsilon)$, $M$ with the usual LoRA-style uniform init, $B \leftarrow 0$; each iteration $t$, for each of $K$ samples draw noise $E_k \sim \mathcal{N}(0, I)$, pass it through `BLoBFlipout` (Eqn. 12, a pseudo-independent per-example perturbation adapted from Flipout [9]) to get $\tilde{E}_k$, form $A_k = M + G^2 \circ \tilde{E}_k$, and accumulate the empirical free energy:

$$ \widehat{\mathcal{F}}_t = -\frac{1}{K}\sum_{k=1}^{K}\log P(\mathcal{D}_t \mid A_k, B) + \frac{1}{2\sigma_p^2}\left(\|M\|_2^2 + \|G\|_2^4\right) - 2\sum_{ij}\log G_{ij} $$

then backpropagate to update $M$, $G$, and $B$ [1]. The paper's own default is $K=1$ sample during training (to show BLoB's sampling efficiency), with $N$ samples averaged at inference, and $N=0$ meaning prediction uses the mean $M$ directly with no sampling [1].

**Worked example** (paper's own numbers, KL-warm-up mini-batch $i$ out of $M$ total): the reweighted loss for mini-batch $i$ is $\mathcal{F}(\mathcal{D}_i,\theta) = -\mathbb{E}_q[\log P(\mathcal{D}_i|W)] + \lambda_i\,\mathrm{KL}[q(W|\theta)\|P(W)]$ with $\lambda_i = 2^i/(2^M-1)$ so early mini-batches weight the KL term near zero and later ones weight it near its full value, letting the model fit the data first and regularize its complexity later [1] (Eqn. 70; the paper contrasts this against $\lambda_i = 1/M$ from [10] and $\lambda_i = 2^{M-i}/(2^M-1)$ from Bayes By Backprop [4]). To keep this warm-up schedule comparable across datasets of very different sizes $L_0$, the paper pseudo-rescales the effective dataset size to $L^{*} = 100 \cdot L_0^{\pi/\gamma}$ with $\gamma=8$ fixed across all experiments [1] (Eqn. 71).

## Cost

**Theory, from the method's own math:**
- Time: each training step needs $K$ forward/backward passes through the Bayesianized layers (the paper's own default $K=1$ keeps this equal to one pass, unlike methods that need many samples per step) [1], plus the extra KL-divergence computation and the extra per-entry log term $-2\sum_{ij}\log G_{ij}$ in the loss, both cheap relative to a transformer forward pass [1]. At inference, calibrated prediction needs $N$ forward passes per input (BLoB's own ablation compares $N=0,5,10$) [1], so inference cost scales linearly with $N$; a reading that assumes a single sample suffices would miss that the paper's calibration gains only appear once $N\geq5$ (see the deciding numbers in While it runs).
- Memory: BLoB stores one extra parameter matrix $G$ the same shape as $A$ on top of the LoRA adapter. The paper states that keeping $B$ deterministic instead of Bayesianizing both $A$ and $B$ reduces the additional memory cost by approximately 50% per layer relative to that symmetric alternative [1]; the card found no comparison in the paper of BLoB's parameter count against plain (non-Bayesian) LoRA. No separate value network, reference model, or reward model is held, unlike PPO-style RL methods [1].

**In practice, per the paper's own benchmark** (there is no third-party framework's cost report; the only measurement found is the paper's own, run on two NVIDIA RTX A5000 GPUs, 5,000 training steps, Llama2-7B) [1]:
- The paper states that BLoB increases memory cost by only about 3% to 13% compared to standard LoRA, and increases training time by about 15% [1]. On WG-S specifically, standard LoRA took 1544 seconds and 14688 MB versus BLoB's 1812 seconds and 15015 MB (Table 9) [1].
- A symmetric variant the paper calls "BLoB without Asymmetric Bayesianization" (Bayesianizing both $A$ and $B$) roughly doubles both memory growth and more than doubles total training time relative to standard LoRA — on WG-S, 3211 seconds and 15054 MB (Table 9) [1] — which is the paper's own justification, by measurement, for keeping $B$ deterministic.
- The official repository documents no separate cost or memory profile beyond running the paper's own scripts; the "in practice" numbers above are the paper's, not a framework's [3].

## How to use it

Data preparation matches standard LoRA supervised fine-tuning: a labeled classification-style or next-token-answer dataset. In the paper's common-sense reasoning setup, the model's next-token logits at the position of each candidate answer letter/token are used to maximize the likelihood of the correct one [1]. The official repository organizes each dataset/method pair as a `WrapperBase`-derived class and a shell script under `scripts/<method_name>/` [3].

Key knobs, with the paper's own value (there is no separate framework default to compare against since no third-party library ships BLoB):

| knob | paper's Llama2-7B setting [1] |
| --- | --- |
| LoRA rank $r$ | 8 |
| LoRA $\alpha$ | 16 |
| learning rate (likelihood term) | 1e-4 |
| learning rate of KL term | 0.01 (SGD optimizer) |
| batch size | 4 |
| max sequence length | 300 |
| prior std $\sigma_p$ | 0.2 |
| init scale $\epsilon$ | 0.05 |
| rescaling coefficient $\gamma$ | 8 |
| samples during training $K$ | 1 |
| samples at inference $N$ | 0, 5, or 10 (ablated) |

Trade-offs a run designer faces: $N=0$ (use the posterior mean only, no sampling) already beats MLE's ACC on some smaller in-distribution datasets in the paper's own results, but calibration (ECE) only improves sharply once $N \geq 5$ — e.g., on WG-S, ECE drops from 20.62±0.83 at $N=0$ to 10.89±0.83 at $N=5$ and 9.35±1.37 at $N=10$, against MLE's 29.83±0.58 (Table 1) [1] — so choosing $N$ trades inference-time compute against calibration quality, with most of the ECE gain already captured at $N=5$. The KL learning rate and the pseudo-rescaling coefficient $\gamma$ are held fixed across all six datasets in the paper's experiments, which the paper presents as evidence the schedule generalizes without per-dataset tuning [1].

## While it runs

**Signals and their healthy shapes**: the paper's own Table 1 is the calibration signal to track — ECE and NLL should fall as $N$ increases from 0 to 10 while ACC stays roughly flat; on OBQA, ACC moves 82.73±0.41 (N=0) to 81.52±0.74 (N=10) while ECE falls from 8.36±0.38 to 3.77±1.47 and NLL from 0.56±0.02 to 0.50±0.01 as $N$ goes 0 to 10, which the paper reads as evidence that jointly learned mean and covariance mutually improve both accuracy and uncertainty quality [1]. No BLoB-specific framework logging convention (e.g., a named metric string) was found, since no third-party framework ships it; monitoring is whatever the reference repo's training script prints [3].

**Published reference runs**: the paper's own Table 1 (six in-distribution datasets, Llama2-7B) and Table 2/9 (OOD and cost) are the only known-good reference numbers found; there is no separately published training curve or logged run beyond the paper's aggregate result tables [1]. On the OBQA-to-OOD generalization test (models fine-tuned on OBQA, evaluated on ARC-C/ARC-E as a smaller shift and MMLU college Chemistry/Physics as a larger shift), BLoB (N=10) reaches ACC 44.79±1.47 on Chemistry versus MLE's 40.62±2.25 and Laplace-LoRA's 42.36±1.77 (Table 2) [1]. On ECE for the smaller-shift ARC-C column, Laplace-LoRA scores 5.84±0.64, the lowest (best) value among all rows in that column of Table 2 (MLE, MAP, MCD, ENS, BBB, LAP, and BLoB at N=0/5/10), versus BLoB (N=10)'s 9.55±0.40, so Laplace-LoRA's post-hoc calibration can still beat BLoB on this particular OOD slice even though it loses badly to BLoB on the in-distribution ARC-C accuracy noted above [1] (Table 2).

**Degeneracies and defaults**: the paper does not describe a degenerate configuration analogous to GRPO's uniform-reward group, but two settings the paper itself flags as consequential. First, setting $N=0$ recovers plain point-estimate-style prediction with no calibration benefit from sampling, so a run configured for $N=0$ inference sacrifices the ECE gains that are the method's main selling point (Table 1 shows the ECE gap between $N=0$ and $N\geq5$ is often larger than the gap between MLE and $N=0$) [1]. Second, abandoning asymmetric Bayesianization by giving $B$ the same initialization and prior as $A$ is not merely slower or costlier: the paper's Appendix C.2 ablation (Table 8) reports that using identical initialization and prior for the standard-deviation matrix $G$ on both $A$ and $B$ causes training failures from "NaN" loss across all datasets [1]. The paper's partial fix is to additionally scale $B$'s standard-deviation matrix by $1/100$; with that fix plus KL Re-Weighting and Re-Parameterization, the ablated BLoB variant without asymmetric Bayesianization (BLoB w/o AB) converges and reaches runner-up performance, but the corresponding BBB variant without asymmetric Bayesianization (BBB w/o AB) still fails to converge, since the paper states its NaN loss "cannot be solved by using scaled standard deviation" [1]; even where the fix works, abandoning asymmetric Bayesianization more than doubles total training time and roughly doubles the added memory cost relative to standard LoRA (Appendix C.3) [1].

**Named successors**: TFB (Training-Free Bayesianization for Low-Rank Adapters of LLMs), from the same authors and repository, NeurIPS 2025 [5], targets the cost of retraining a Bayesian adapter from scratch by Bayesianizing an already-trained LoRA adapter without further training — the repository's README documents it as evaluable directly on BLoB, MLE, or MAP LoRA weights via `scripts/tfblora/<method_name>.sh` [3].

**Known failure modes**: the paper's own Appendix C.2 (Table 8 ablation) reports that removing asymmetric Bayesianization — giving $B$ the same initialization and prior as $A$ instead of keeping it deterministic — causes training failures from unbounded NaN loss across all datasets tested [1]. When the paper's scaled standard-deviation fix (plus KL Re-Weighting and Re-Parameterization) is applied, this failure is resolved for the ablated BLoB variant (BLoB w/o AB converges to runner-up performance), so it is not a failure mode of BLoB run with its default configuration; the same fix does not resolve it for the analogous BBB w/o AB variant, whose NaN loss the paper states "cannot be solved by using scaled standard deviation" [1]. Beyond this ablation-only finding, this card found no BLoB-specific failure mode stated in the paper's Section 6 (Conclusion) or in the repository's README — that is the extent of the search performed for this card; the repository's GitHub Issues were not queried [1][3]. The paper's own Table 2 does note that BLoB's uncertainty estimation "remains comparable to baselines such as ENS and LAP" but shows "a slight performance drop with larger distribution shifts" (Chemistry/Physics) relative to the smaller ARC shift [1].

**What the gain is - and is not**: the paper's own analysis is that BLoB improves calibration (ECE, NLL) and, on smaller in-distribution datasets, can also improve ACC over MLE by mitigating overfitting-driven overconfidence, because jointly learning the mean and covariance "mutually improve" each other during fine-tuning [1]. The paper does not claim BLoB adds new task capability beyond what standard LoRA fine-tuning can reach — its comparisons are entirely about calibration quality and accuracy parity, not capability gains beyond the fine-tuning task itself [1].
