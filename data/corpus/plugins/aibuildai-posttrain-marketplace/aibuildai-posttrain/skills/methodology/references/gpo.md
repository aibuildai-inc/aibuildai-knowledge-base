# GPO

A family of offline preference-optimization losses: pick any convex function of the log-ratio-difference and you get a training objective, with DPO, IPO, and SLiC falling out as three particular choices of that function.

**Paper**: https://arxiv.org/abs/2402.05749

**GPO** (Generalized Preference Optimization) is an offline-alignment framework introduced by Tang et al. (Google DeepMind) as "a family of offline losses parameterized by a general class of convex functions," built to give "a unified view over preference optimization, encompassing existing algorithms such as DPO, IPO and SLiC as special cases, while naturally introducing new variants" [1]. It generalizes DPO (Direct Preference Optimization), which reparameterizes the RLHF reward model so the optimal regularized policy can be extracted in closed form and trained with a binary classification loss instead of RL [2]. GPO's mechanism: reward learning is cast as supervised binary classification on a pair of responses, so any convex surrogate loss $f$ for that classification problem (logistic, hinge, squared, exponential, ...) can be substituted for the reward difference to produce an offline preference-optimization loss over the policy directly [1]. Two motivations the paper gives: unifying existing offline losses under one lens exposes which choices are arbitrary and which encode different implicit regularization strengths, and analyzing the convex function's tail behavior explains how strongly each variant constrains the policy relative to the reference, in contrast to the KL constraint the RLHF objective nominally intends [1].

This card's search - the GPO paper's own full text, trl's and verl's documentation, and one Semantic Scholar query on the paper's record - found no landmark system that names GPO itself as its trainer; the practical footprint found is that DPO, IPO, and SLiC (SLiC-HF) already existed as separately named methods before this paper, and GPO's contribution is the unifying framework plus the previously-untried convex functions (exponential/AdaBoost, truncated quadratic, Savage) it introduces alongside them [1][5][7][8]. The paper's own experiments are diagnostic rather than a headline benchmark result: on a synthetic bandit/summarization setup with a T5X policy, all six convex-loss variants trace similar KL-divergence-vs-win-rate trade-off curves, but the regularization coefficient $\beta$ that peaks each variant differs by an order of magnitude - squared and truncated-squared loss peak near $\beta \sim 1$ while logistic (DPO), exponential, hinge, and Savage peak near $\beta \sim 10$ [1, Fig. 7]. Lineage: RLHF regularized policy optimization (Ouyang et al., 2022, cited within [1]) -> DPO/IPO/SLiC as independently published instances [2][3][4] -> GPO unifies them and adds new convex-function variants (2024) [1]; no successor method built specifically on top of GPO was found in this card's search (Semantic Scholar API lookup on the paper's own record, 2026-08-09) [5].

**When to pick it**: pick GPO as an analysis lens, not as a single trainer to reach for - it tells you that DPO, IPO, and SLiC are one family with a shared derivation, so choosing among them is choosing a convex function $f$ and its matching $\beta$, not choosing between unrelated algorithms [1]. If you just want offline pairwise-preference training, pick DPO directly - among the family's instances it is the one trl ships as its default `loss_type` [7], and it is the instance GPO's own derivation is built around [1][2]. If you have a way to keep sampling from the live policy (fresh generations scored by a reward model), the nearest online neighbor is GRPO, an online RL method with a group-relative baseline in place of GPO/DPO's fixed offline dataset [6].

**Variant of**: none in the sense of a single parent - GPO is the generalization, with DPO as the instance it most directly builds its derivation around [1][2]; IPO [3] and SLiC [4] are the other two named special cases.

**Data it needs**: offline pairwise preference data - a prompt with a chosen (win) and rejected (loss) response per example, collected without any live sampling from the model being trained [1]. This is the same column shape DPO needs (prompt, chosen, rejected) [2]. Training scale in the paper's own experiments: an 11B-parameter T5X model used as the golden preference judge, and a 110M-parameter T5X policy trained for $2\times10^4$ steps per $\beta$ sweep on a summarization preference dataset with human-feedback labels (Stiennon et al., 2020, cited within [1]) [1]. The method is offline: no fresh rollouts are drawn from the policy during training, only precomputed likelihoods on the fixed dataset [1].

**Extra models**: a frozen reference policy $\pi_{ref}$ is required by every GPO variant's log-ratio term, exactly as in DPO [1][2]; no separate reward model or value network is trained, since the reward is implicitly parameterized through the policy's own log-ratio to the reference [1].

**Shipped by**: no framework ships a trainer literally named "GPO." trl's `DPOTrainer` implements three of the paper's named instances as a single `loss_type` config switch: `"sigmoid"` (DPO's logistic loss, the default), `"hinge"` (the SLiC-derived hinge loss), and `"ipo"` (IPO's squared loss) [7]; `from trl import DPOTrainer` is the entry point [7]. verl's documentation index carries no GPO, IPO, or hinge-loss entries at all - only a DPO reference was found in a targeted index search on 2026-08-09 [8]. Building the paper's other three variants (exponential, truncated-quadratic, Savage) that no framework ships would mean adding a new `loss_type` branch to an existing DPO-style trainer - a loss-function swap on top of the existing log-ratio computation, not a new sampling loop [1][7].

## How it works

The loop in one line: initialize the policy from the reference (SFT) checkpoint, then minimize a convex loss of the win/loss log-probability-ratio difference over a fixed offline preference dataset - no generation, no reward model training [1].

**Setup.** The canonical KL-regularized RLHF objective is

$$ \max_{\pi_\theta}\; \mathbb{E}_{y \sim \pi_\theta}\big[r_\phi(y)\big] - \beta\, \mathbb{KL}(\pi_\theta, \pi_{ref}) \tag{1} $$

whose closed-form optimal policy satisfies $\pi_\theta^*(y) \propto \pi_{ref}(y)\exp(\beta^{-1} r_\phi(y))$, so the reward difference between a win and loss response can be rewritten as a scaled log-ratio difference [1, Eq. 2]:

$$ r_\phi(y_w) - r_\phi(y_l) = \beta\left[\log\frac{\pi_\theta^*(y_w)}{\pi_{ref}(y_w)} - \log\frac{\pi_\theta^*(y_l)}{\pi_{ref}(y_l)}\right] \tag{2} $$

**The GPO objective.** Treating reward learning as binary classification (win vs. loss) lets any convex surrogate $f:\mathbb{R}\to\mathbb{R}$ for that classification problem be substituted for the reward difference, giving the general offline loss [1, Eq. 4]:

$$ \mathbb{E}_{(y_w,y_l)\sim\mu}\Big[f\big(\beta\,\rho_\theta\big)\Big], \qquad \rho_\theta \;=\; \log\frac{\pi_\theta(y_w)}{\pi_{ref}(y_w)} - \log\frac{\pi_\theta(y_l)}{\pi_{ref}(y_l)} \tag{4} $$

where $\mu$ is the (offline) distribution the preference pairs were collected under, $\pi_\theta$ is the policy being trained, $\pi_{ref}$ is the frozen reference policy, and $\rho_\theta$ is the log-ratio difference between the win and loss response [1]. $\beta$ controls the strength of the implicit regularization toward $\pi_{ref}$ [1].

**The three shipped instances** [1, Table 1]: DPO uses $f(\beta\rho_\theta) = -\log\sigma(\beta\rho_\theta) = \log(1+\exp(-\beta\rho_\theta))$, the logistic loss; SLiC uses $f(\beta\rho_\theta) = \max(0, 1-\beta\rho_\theta)$, the hinge loss; IPO uses $f(\beta\rho_\theta) = (\beta\rho_\theta - 1)^2$, the squared loss. The paper also defines three variants with no prior offline-preference-optimization counterpart: exponential loss $f=\exp(-\beta\rho_\theta)$ (AdaBoost's loss), truncated quadratic $f = (\max(0,1-\beta\rho_\theta))^2$, and Savage loss $f = 1/(1+\exp(\beta\rho_\theta))^2$ [1, Table 1]. Only the first three (DPO, hinge/SLiC, IPO) are shipped, as `loss_type` options of trl's `DPOTrainer` [7].

**Worked example.** Take $\beta = 1$ and suppose after a training step the win response's log-ratio to reference is $\log[\pi_\theta(y_w)/\pi_{ref}(y_w)] = 0.5$ and the loss response's is $\log[\pi_\theta(y_l)/\pi_{ref}(y_l)] = -0.3$, so $\rho_\theta = 0.5 - (-0.3) = 0.8$. The DPO (logistic) loss is $\log(1+\exp(-0.8)) \approx 0.371$; the IPO (squared) loss is $(0.8-1)^2 = 0.04$; the SLiC (hinge) loss is $\max(0, 1-0.8) = 0.2$. All three losses fall as $\rho_\theta$ grows past the boundary near $\rho_\theta=1$ (or $\rho_\theta=0$ for logistic/exponential), but at different rates - this is the differing "tail behavior" the paper says sets each variant's effective regularization strength [1].

## Cost

**Theory, from the method's own math**: GPO's objective (Eq. 4) needs only two log-probability evaluations per pair (win and loss) under $\pi_\theta$ and under the frozen $\pi_{ref}$ - no sampling loop, no value network, no learned reward model [1]. Memory holds two models: the trained policy (weights + gradients + optimizer state) and the frozen reference (forward-pass only, no gradients) [1]. This is identical in shape to DPO's own cost profile, since DPO is one instance of the same objective [1][2]; the choice of $f$ (logistic vs. hinge vs. squared) changes only the scalar loss computation on top of the same two log-ratios, not the memory or pass count.

**In practice, per framework**: trl's `DPOTrainer` loads the policy and a separate frozen reference model - if `ref_model` is not passed explicitly, the trainer automatically uses the initial policy corresponding to `model` as that reference [7] - with `loss_type` selecting among `"sigmoid"` (DPO), `"hinge"` (SLiC), `"ipo"` (IPO), and several other variants (`exo_pair`, `nca_pair`, `robust`, `bco_pair`, `sppo_hard`, `aot`/`aot_unpaired`, `apo_zero`/`apo_down`, `discopop`, `sft`, `sigmoid_norm`) not defined in the GPO paper [7]. verl's documentation index, searched directly on 2026-08-09, surfaces no page for IPO, hinge loss, or GPO by name, so this card does not carry a verl cost entry for the non-DPO GPO instances [8].

## How to use it

Data preparation is the same as DPO's: a preference dataset of (prompt, chosen, rejected) triples, with no reward-model scores or per-token labels needed - GPO's reward is implicit in the policy's own log-ratio to the reference [1][2][7]. Choosing among the shipped variants (trl's `loss_type`) is choosing which convex $f$ to minimize; the paper's own hyperparameter finding is the key one to carry over: squared-type losses (`ipo`) need a smaller $\beta$ to peak (around $\beta\sim1$ in the paper's sweep) than logistic-type losses (`sigmoid`, i.e. DPO), which peak around $\beta\sim10$ in the same sweep [1, Fig. 7]. trl's own `beta` default of 0.1 [7] sits roughly two orders of magnitude below the paper's own peak-performance value for that same logistic loss ($\beta\sim10$) - a gap worth checking before trusting the framework default on a `"sigmoid"`/DPO run [1][7].

| knob | trl default [7] | paper's finding [1] |
| --- | --- | --- |
| convex function $f$ (`loss_type`) | `"sigmoid"` (DPO) | six named instances (Table 1); only logistic/hinge/squared are adopted downstream |
| regularization coefficient $\beta$ | `0.1` | peaks near $\beta \sim 1$ for squared-family losses, $\beta \sim 10$ for logistic/exponential/Savage (Fig. 7, synthetic summarization sweep) |
| model-based side-by-side eval, best $\beta$ range | not checked | $\beta \in [0.1, 1]$ across variants (Sec. 5.2, PaLM-2-judged summarization) |

The gap between trl's single fixed `beta` default and the paper's own $\beta\sim10$ peak for the same logistic loss means the framework default cannot be trusted as a tuned value for this method; the paper itself is a theory-and-diagnostics study and does not prescribe a single recommended $\beta$ [1].

## While it runs

- **Signals and their healthy shapes**: the paper tracks two offline-training-time quantities directly - the sample-based KL divergence $\mathbb{KL}(\pi_\theta,\pi_{ref})$ and the $\mu$-weighted convex loss $\mathbb{E}_{y\sim\mu}[\tfrac12\rho_\theta^2]$ (for the squared-loss instance). At small $\beta$, once the weighted loss grows quickly during optimization, its relationship to the KL divergence grows harder to pin down [1]; at large $\beta$, where the two quantities stay well correlated, the paper reports that the KL divergence still swings roughly an order of magnitude more ($10^{-0.5}\to10^{1.5}$) than the weighted loss does ($10^{-1.5}\to10^{0.5}$) over the same training run - so even in the well-behaved regime, small movements in the offline loss can correspond to large movements in KL [1]. A run at small $\beta$ where the offline loss is climbing fast is in the regime the paper flags as hardest to read from the loss curve alone [1].
- **Published reference runs**: the paper's own Figs. 5-7 (KL-vs-loss trajectories and win-rate-vs-KL trade-off curves on the summarization T5X setup) are the reference curves; no external log files were published alongside the arXiv paper as far as this card's fetch found [1].
- **Degeneracies and defaults**: the paper documents Goodhart's-law over-optimization directly - as KL divergence increases during training, golden-judged performance rises then falls for every one of the six convex-loss variants, with the peak occurring at a similar KL level across variants but at a $\beta$ that differs by up to an order of magnitude between loss families [1, Sec. 5.1]. A run using a single fixed $\beta$ across loss-type switches (e.g., moving from `"sigmoid"` to `"ipo"` in trl without re-tuning $\beta$) will silently land on the wrong side of that peak for one of the two [1][7].
- **Named successors**: none found - a Semantic Scholar API lookup on the GPO paper's own record (arXiv:2402.05749) on 2026-08-09 returned only the citation count (166), not a citing-methods list, and this card's search did not surface a paper that names itself as GPO's successor [5].
- **Known failure modes**: the paper names its own limitations directly - because the framework is still built on the reward-maximization formulation of RLHF, it inherits that formulation's theoretical trouble whenever the true preference structure is not well modeled by a single scalar reward; and the framework only covers offline, contrastive-pair losses, so it does not extend to SLiC's separate supervised-learning loss component [1]. No maintainer-issue-level failure mode was searched for, since no framework ships a trainer literally named GPO.
- **What the gain is - and is not**: the paper's own conclusion is that different convex-loss variants reach similar peak win-rate performance and similar KL-divergence levels at that peak, so switching the convex function is not itself a performance lever; the lever is retuning $\beta$ correctly for whichever function is chosen [1, Sec. 6].
