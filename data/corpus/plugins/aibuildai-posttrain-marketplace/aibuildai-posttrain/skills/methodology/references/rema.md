# ReMA

Split the reasoning LLM into two agents that generate together and train separately: a high-level agent that writes meta-thinking instructions and a low-level agent that follows them, each optimized with its own reward using an off-the-shelf single-agent RL algorithm (PPO, GRPO, or REINFORCE++).

**ReMA** (Reinforced Meta-thinking Agents) is a multi-agent-RL method for eliciting meta-thinking in LLM reasoning, introduced in "ReMA: Learning to Meta-think for LLMs with Multi-agent Reinforcement Learning," which decomposes reasoning into "a high-level meta-thinking agent responsible for generating strategic oversight and plans, and a low-level reasoning agent for detailed executions," structured as a multi-agent RL problem and trained with reinforcement learning [1]. Its parent is single-agent RL for chain-of-thought reasoning, which the paper calls the vanilla reasoning process (VRP): one policy autoregressively emits meta-thinking and detailed steps in a single forward pass, trained with GRPO [2] or REINFORCE++ [3] on an outcome reward [1]. ReMA decouples that single pass into a joint hierarchical policy $\pi_{(\theta_h,\theta_l)}(y|x) := \pi_{\theta_l}(y|x,m)\cdot\pi_{\theta_h}(m|x)$, trains the two agents with separate rewards $R_h$, $R_l$, and updates them by alternating gradient steps while treating the other agent as a frozen part of the environment [1]. The paper gives three reasons to split the pass: single-pass RL forces one model to master meta-thinking and detailed problem-solving simultaneously, which prior work found leads to inefficient exploration and early convergence to local optima; splitting the exploration space across two agents lets each explore more structurally; and each agent can specialize in what it does well (meta-think or follow instructions) in the presence of the other [1]. The single-turn convergence argument treats the two-agent update as block coordinate ascent over a practical TRPO surrogate, so each block update does not decrease the joint objective under that approximation [1].

The method has no reported adoption by named landmark systems as of this card; the paper is its own first deployment, evaluated on math reasoning and LLM-as-a-Judge tasks [1]. On math benchmarks, RL under ReMA raised the average pass@1 over CoT (VRP) prompting by up to 6.68 points (Llama3-8B-Instruct, Table 1a), including a 20-point jump on AMC23 and 11.9 points on GSM8K, versus 2.85 points average gain for the strongest base model tested, Qwen2.5-7B-Instruct [1]. On LLM-as-a-Judge (RewardBench970/JudgeBench), Table 1b's strict-setting main result gives a 7.92-point average gain for Llama3.1-8B-Instruct, and a separate appendix run on the same RewardBench970 split under a "loose setting" (Table 2) gives an 8.49-point average gain for the same model [1]. Lineage in one line: TRPO (2015 [4]) / PPO (2017 [5]) / GRPO (DeepSeekMath, 2024 [2]) / REINFORCE++ (2025 [3]) -> ReMA (2025 [1]), with a documented multi-turn training instability ("Echo Trap") also reported independently in the concurrent multi-turn-RL paper RAGEN [1]. The paper was confirmed by an exact-title search on arXiv (2503.09501) against a name collision with an unrelated multi-agent RL paper on ride-sharing fleet rebalancing that shares only the acronym MARL, not the method [1].

**When to pick it**: pick ReMA when a single-pass reasoning policy under RL (VRP-RL, using GRPO [2] or REINFORCE++ [3]) shows the inefficient-exploration/early-convergence failure mode the paper describes, and the task can be scored with an outcome reward (a verifiable answer or a judge label) so both agents can be rewarded from the same rollout [1]. It is strictly heavier to run than single-agent VRP-RL, since it needs two forward-and-backward passes per rollout instead of one; do not pick it if the base model is already strong on the target task, where the paper's own results show diminishing gains (2.85-point average gain on Qwen2.5-7B-Instruct versus 6.68 on Llama3-8B-Instruct) [1]. The nearest offline alternative is SFT on meta-thinking traces distilled from a stronger teacher model (GPT-4o Mini); the paper uses this only inside a separate single-agent ablation (Sec. 4.2.1, "RL from SFT" / "RL under Meta-thinking" in Fig. 3, on Qwen2.5-Math-7B), not as a warm-start for its main ReMA/MAMRP pipeline, which trains directly on instruct-tuned models with no SFT stage [1]. DPO is not used by the paper's own method anywhere; it appears only as a related-work citation for other authors' approaches [6]. The nearest single-agent online neighbor is R1-like RL, i.e., VRP-RL or MRP-RL (single-agent RL with an explicit meta-thinking step in the prompt but no second trainable agent) [1].

**Variant of**: single-agent RL for LLM reasoning (VRP-RL / MRP-RL), decomposed into a two-agent Markov game and optimized per-agent with PPO [5], GRPO [2], or REINFORCE++ [3] as the underlying gradient estimator [1].

**Data it needs**: prompts with a verifiable outcome (math problems with a ground-truth answer) or a preference/judge label (RewardBench-style instruction plus two candidate responses); no separate chosen/rejected pairs are required beyond what the reward function scores at rollout time [1]. Training scale in the paper: 7.5K MATH training problems for math reasoning, 5K instruction-response-pair training items (RewardBench970 split) for the judge task [1]. On-policy: both agents' rollouts are generated fresh from the current policies each training iteration; Algorithm 1 filters prompts by success rate before building each iteration's training batch [1].

**Extra models**: the method's own definition needs two trainable LLM copies (high-level and low-level agents), which may be separate parameter sets or one shared-parameter model distinguished by system prompt in the multi-turn variant [1]. A reference model is needed only if the chosen per-agent RL algorithm uses a KL penalty against a frozen policy (PPO/GRPO do; the paper's multi-turn GRPO runs drop the KL loss term for numerical stability) [1]. No separate value network is required when the per-agent algorithm is GRPO or REINFORCE++, both critic-free [1][2][3]; the paper's single-turn runs use REINFORCE++ [1]. No reward model is required for math tasks (rule-based correctness); the LLM-as-a-Judge task reward is likewise rule/label-based on RewardBench answers, not a learned reward model [1]. Cost details below.

**Shipped by**: trl's and verl's documentation carry no "ReMA" entry point as of this card (verl's README lists "ReMax," a different method, not "ReMA") [7][8]; OpenRLHF, which the paper's own single-turn code is built on top of, and VeRL, which its multi-turn code uses for its single centralized training-pipeline controller [1], were not checked here for a ReMA entry point, so this card cannot claim no library anywhere ships it - only that the two frameworks checked do not. Building it requires a new two-agent rollout loop (interleave two policies' generations, route the reward to each agent's own advantage computation) on top of an existing single-agent trainer (PPO/GRPO/REINFORCE++) that framework already ships - not a new loss, but a new orchestration layer around generation and credit assignment. The paper's own GitHub link (`ziyuwan/ReMA-public`) returned HTTP 404 at check time (2026-08-09), so no first-party reference implementation could be inspected beyond what the paper's Algorithm 1 and Appendix D describe [1].

## How it works

Each iteration: sample a training batch by prompt filtering, generate a rollout from the joint hierarchical policy, score it with per-agent rewards, and update the high-level and low-level agents with separate gradient steps [1].

**Single-turn joint policy** [1]:

$$ \pi_{(\theta_h,\theta_l)}(y \mid x) := \pi_{\theta_l}(y \mid x, m)\cdot\pi_{\theta_h}(m \mid x) $$

$x$ is the prompt, $m$ is the high-level agent's meta-thinking output, $y$ is the low-level agent's final response. The joint objective is $J(\theta_h,\theta_l) = \mathbb{E}_{x,y^*}\mathbb{E}_{y\sim\pi_{(\theta_h,\theta_l)}}R(y,y^*)$, and each agent's own training target substitutes its own reward for $R$ [1]:

$$ \theta_h^{*} = \arg\max_{\theta_h}\ \mathbb{E}_{(x,y^*)\sim D,\ m\sim\pi_{\theta_h},\ y\sim\pi_{\theta_l^{*}}}\left[R_h(m,y,y^*)\right], \qquad \theta_l^{*}(\theta_h) = \arg\max_{\theta_l}\ \mathbb{E}_{(x,y^*)\sim D,\ m\sim\pi_{\theta_h},\ y\sim\pi_{\theta_l}}\left[R_l(m,y,y^*)\right] $$

**Algorithm 1 (single-turn MAMRP)** [1]: while not converged, (a) build a training subset for the low-level agent by prompt-filtering on success rate, sample $y\sim\pi_l(x,m)$, compute $R_l(y,y^*)$, and update $\theta_l$ by policy gradient; then (b) build a training subset for the high-level agent, sample $m\sim\pi_h(x)$ and $y\sim\pi_l(x,m)$, compute $R_h(m,y,y^*)$, and update $\theta_h$ by policy gradient. Both updates plug into whatever single-agent RL algorithm is chosen (PPO, GRPO, or REINFORCE++ all fit the $\nabla_\theta\mathbb{E}[R]$ form) [1].

**Base reward setting** [1]: the low-level agent gets $+1.0$ for a correct final answer, $-0.5$ if incorrect but formatted correctly (e.g., boxed), and $-1.0$ if incorrect and unformatted. The high-level agent gets the low-level agent's average correctness over its sampled responses as its reward, with a $-1.0$ penalty if its meta-thinking output itself contains an explicit boxed answer (to stop it from short-circuiting the reasoning agent). A worked example with the paper's own numbers: for a group of 4 low-level samples with rewards $\{+1.0,+1.0,-0.5,-1.0\}$ under one meta-thought, the high-level agent's reward for that meta-thought is the average, $0.125$ [1].

**Multi-turn extension** [1]: agents alternate over $T$ turns, $y_T \sim \prod_{t=1}^{T}\pi_l(y_t\mid x,\{m,y\}_{<t},m_t)\,\pi_h(m_t\mid x,\{m,y\}_{<t})$, with parameter sharing (one model, two system prompts $S_h$, $S_l$) to avoid GPU model-swapping during rollout. The paper's multi-turn training objective is a multi-turn GRPO with a turn-level probability ratio in place of GRPO's token-level ratio:

$$ r_{i,t}(\theta) = \frac{1}{|y_{i,t}|}\sum_{j=1}^{|y_{i,t}|} \frac{\pi_\theta(y_{i,t,j}\mid x,\{m_{i,\cdot},y_{i,\cdot}\}_{<t},m_{i,t},y_{i,t,<j})}{\pi_{\theta_{old}}(y_{i,t,j}\mid x,\{m_{i,\cdot},y_{i,\cdot}\}_{<t},m_{i,t},y_{i,t,<j})} $$

used inside the same clipped-surrogate-minus-KL form as GRPO's objective, but averaged over turns $t=1..T_i$ before averaging over tokens within a turn, rather than averaging directly over all tokens in the trajectory [1]. The paper's own stated reasons: token-level averaging over a whole multi-turn trajectory over-weights long turns and can encourage excessively long single-turn responses, and clipping each token independently is less stable than clipping one ratio per turn, which better matches the underlying MDP where a turn is one action [1]. The paper reports the turn-level-ratio loss reaches higher training reward with fewer steps than the token-level variant on a 133-sample MATH subset (Fig. 6) [1].

## Cost

**Theory, from the method's own math**: two trainable policies instead of one means, at minimum, two backward passes per training iteration when parameters are separate (Algorithm 1's two update loops), or one shared backward pass over a longer combined sequence when parameters are shared, as in the multi-turn setting [1]. Rollout requires two sequential generation calls per sample even in the single-turn case ($m\sim\pi_h(x)$, then $y\sim\pi_l(x,m)$), so wall-clock generation at minimum doubles versus single-agent VRP-RL, before accounting for the paper's prompt-filtering step, which itself costs extra rollout samples (10 high-level candidates x 1 low-level sample, then 1 high-level candidate x 10 low-level samples, per prompt, to estimate success rate) [1]. Memory for the base per-agent algorithm follows whatever PPO/GRPO/REINFORCE++ needs (Cost sections of those methods' own cards); ReMA adds a second trained-model footprint only when parameters are not shared.

**In practice, per framework**: the paper does not name a framework that ships ReMA; its own single-turn implementation runs on OpenRLHF using REINFORCE++, on 8 NVIDIA A100 GPUs with bf16, ZeRO-2, Flash-Attention, and gradient checkpointing, rollout batch size 1000, 4 samples per prompt, max generation length 2048, mini-batch size 500, learning rate 5e-7, clip ratio 0.2 [1]. Its multi-turn implementation runs on veRL with FSDP, learning rate 1e-6, bfloat16, KL loss term dropped for numerical stability, and pre-clipping log-probs to an upper bound of 3.0 before exponentiating, for numerical stability [1]. The paper's main multi-turn result (Fig. 5) used 32 NVIDIA A800 GPUs for up to about 40 hours per run, training for 500 steps with max prompt length 4096 [1]; its smaller ablation (Fig. 6, 133 MATH samples) used 8 NVIDIA A800 GPUs for about 30 hours over 300 steps [1]. Neither of these is a framework default - both are this paper's own run configuration on top of OpenRLHF and veRL, neither of which exposes a ReMA entry point of its own (see Shipped by).

## How to use it

- Prompts: a task where the final response can be scored by a rule (correctness on math) or a label (judge accuracy on RewardBench-style pairs); the paper trains on MATH (7.5K problems) for math and a 5K-item split of RewardBench for judging [1].
- Reward: implement the base setting's two reward functions directly - low-level agent scored on final-answer correctness with a format-compliance penalty when wrong, high-level agent scored on the low-level agent's average correctness under its meta-thought, with a penalty for leaking an explicit answer [1]. The paper also reports a consistency-based alternative reward for the high-level agent (majority-vote agreement rate among low-level samples instead of correctness), used only in an ablation, not the main results [1].
- Key knobs, with the paper's own single-turn (OpenRLHF/REINFORCE++) values as the only published anchor - no framework ships default values to compare against:

| knob | paper, single-turn [1] | paper, multi-turn [1] |
| --- | --- | --- |
| learning rate | 5e-7 (MAMRP runs; the VRP single-agent baseline uses 2e-7 for Llama3-8B-Instruct) | 1e-6 |
| rollout batch size | 1000 | not stated |
| samples per prompt | 4 | 16 (128 prompts x 16 trajectories, Sec. 4.3 experiment) |
| clip ratio $\epsilon$ | 0.2 | not stated (inherits GRPO's clip form) |
| KL coefficient | 1e-2 (VRP/MRP/MAMRP single-turn runs) | KL loss term dropped |
| prompt-filter range $[\epsilon_{min},\epsilon_{max}]$ | 0.2-0.8 (0.1-0.9 for one Llama3.1-8B-Instruct judge run) | not checked |
| #Update Iteration | 3 (Llama3/Llama3.1-8B) or 10 (Qwen2.5-7B), math MAMRP | not stated |

- Trade-off unique to this method, at inference time (Appendix C.1, "Inference-time Scaling of ReMA," not part of training): allocating a sampling budget between agents when using the trained ReMA policy to answer a query. With $k_1$ high-level samples each feeding $k_2$ low-level samples, total inference calls scale as $k_1\times k_2$; more high-level samples increases strategy diversity, more low-level samples yields more refined solutions per strategy, and the paper treats this split, plus the choice between hierarchical reranking (rank low-level responses within each high-level branch, then rank branches) and flat reranking (rank all sampled responses together), as an open design question rather than giving a fixed recommendation [1].
- Parameter sharing vs. separate agents: shared parameters with simultaneous updates avoid GPU model-swapping and converge faster in the paper's multi-turn ablation than separate-parameter, alternating-update training [1].

## While it runs

- Signals and their healthy shapes: the paper's own multi-turn training-reward curves (Fig. 6) show the turn-level-ratio loss reaching high training reward in fewer steps than the token-level-ratio loss on a 133-sample MATH subset - the comparison to watch when validating that the turn-level ratio, not the paper's Eq. 2 token-level ratio, is what is running [1]. In the paper's multi-turn main result (Fig. 5, turn30/token512 rollout config), test accuracy rises from about 55% to about 70% over training, with an average 5-point gain across seven OOD math benchmarks [1].
- Published reference runs: Fig. 3 is a separate, single-agent motivating ablation on Qwen2.5-Math-7B (not the two-agent MAMRP/ReMA method itself), comparing three training schemes on MATH500/GSM8K/AIME2024 over 250 steps - RL from base, RL from SFT, and RL under meta-thinking (SFT on GPT-4o meta-thinking plans, then RL) - showing RL from SFT ahead on the easier MATH500/GSM8K but RL under meta-thinking generalizing better to the harder AIME2024 [1]. Fig. 5 and Fig. 6 (Sec. 4.3) are the paper's own multi-turn reference curves for the actual ReMA/MAMRP method, at the run settings listed under Cost.
- Degeneracies and defaults: a group of prompt-filtering samples with all successes or all failures ($\epsilon_{min}$/$\epsilon_{max}$ excludes them) is dropped from the training batch by design, not trained on [1]. In multi-turn rollouts, the paper reports that for certain max-response-length/max-num-turns settings, the model collapses into massive single-turn repetition or produces empty responses after only a few turns [1].
- Named successors: none found - this is a 2025 method with no citing paper on the shortlist that proposes a named bias-correcting successor to ReMA specifically (searched: the shortlist's own confirmation record for this row, which lists no successor method; not a broader literature search).
- Known failure modes: the paper's own limitations section states it is evaluated only on math and LLM-as-a-Judge tasks, not on tasks that naturally need multi-turn interaction among several interleaved agents, and that a comprehensive understanding of multi-turn RL/MARL learning dynamics for LLMs is still needed [1]. The multi-turn instability described above (single-turn repetition collapse, premature empty responses) is attributed by the paper, and independently by the concurrent RAGEN paper, to a lack of fine-grained, reasoning-aware guidance during long-horizon rollouts, producing reduced exploration diversity that the paper terms an "Echo Trap" [1]. No GitHub issue tracker could be checked: the paper's linked repository (`ziyuwan/ReMA-public`) returned HTTP 404 at check time (2026-08-09) [1].
- What the gain is - and is not: the paper's Sec. 4.2.1 motivating ablation (Fig. 3, single-agent, not ReMA itself) attributes the meta-thinking split's advantage to out-of-distribution generalization, not raw in-distribution accuracy - RL-from-SFT beats it on the in-distribution-adjacent MATH500/GSM8K but RL under meta-thinking generalizes better to AIME24 [1]. The paper separately notes, of its main ReMA results, that gains from RL training are smaller on instruction-tuned models than on base models, attributing this to instruction-tuned models' higher starting accuracy and more fixed output distribution limiting further RL improvement [1]. Do not expect ReMA to lift an already-strong instruction-tuned model's peak accuracy as much as it lifts generalization to harder, out-of-distribution problems.
