# allenai/tulu-3-pref-personas-instruction-following

19,890 synthetic preference pairs for precise instruction following - a persona-grounded prompt paired with a GPT-4o chosen response that satisfies every stated constraint and a GPT-4o rejected response written for a version of the prompt with one constraint relaxed.

**allenai/tulu-3-pref-personas-instruction-following** was built by the Allen Institute for AI as part of the Tulu 3 post-training release, introduced in "Tulu 3: Pushing Frontiers in Open Language Model Post-Training" [1]. It is constructed from a subset of the sibling SFT dataset `allenai/tulu-3-sft-personas-instruction-following`, whose rows are (prompt, constraints, response) tuples generated with personas and a constraint taxonomy [2][8]; for each subset example the paper's pipeline prompts GPT-4o to rewrite the prompt so that it relaxes one constraint category, generates a new response to that modified prompt, and uses that response as the `rejected` side, keeping the original (prompt, response) as `chosen` [1]. **The served rows store the original, unmodified prompt as the shared user turn on both the `chosen` and `rejected` sides; the constraint-relaxed prompt text used to generate the rejected response is not itself a column and is not recoverable from the served row.** It lives at https://huggingface.co/datasets/allenai/tulu-3-pref-personas-instruction-following .

**Use it for**: preference-pair training targeting instruction-following/constraint-satisfaction skill (DPO or a similar preference-optimization method), not SFT - the chosen side alone is not a curated SFT target here (use the SFT sibling dataset for that). The rows are the conversational, implicit-prompt preference format: `chosen` and `rejected` are each a full `[user, assistant]` message list sharing the same user turn and differing only in the assistant reply [3]. A DPO-style trainer that wants the explicit-prompt form (separate `prompt`/`chosen`/`rejected` columns) needs to split the shared user turn out first - trl ships `extract_prompt` for exactly this conversion [3]. See the DPO method card.

**Licence**: stated as ODC-BY in the card's prose ("License: ODC-BY") [2], but the repository's machine-readable `cardData` carries no `license:` key and no `license:` tag - unlike the SFT sibling repo, whose `cardData` does set `license: odc-by` [2][8][4]. Treat the licence as ODC-BY on the strength of the prose statement alone.

**Shape**: 19,890 rows, one config (`default`), one split (`train`), 7 columns [5][6].

**Hold out**: no evaluation-benchmark overlap is flagged by any source, and the repository ships only a `train` split with no companion test split [2][6]. There is a different, construction-level overlap to manage: this dataset's prompts are a subset of the 29,980-row SFT sibling `allenai/tulu-3-sft-personas-instruction-following`'s prompts [1][8], so do not additionally treat this dataset's `chosen` side as separate SFT data when also training on that sibling - see Neighbors.

**Origin**: built by the Allen Institute for AI; both the `chosen` and `rejected` assistant replies are generated by GPT-4o-2024-08-06 per the paper's synthesis pipeline, matching the `chonsen_model`/`rejected_model` value of `"gpt-4o"` on every one of the 104 rows read from this repository (54 at offset 0, 50 at offset 19,840) [1][6][7]. Hub API at the check date: `downloads` 417, `downloadsAllTime` 12,936, `likes` 17 [4][13].

**Trained-on-by**: the Tulu 3 8B DPO preference mix. Table 15 of the origin paper lists a "Persona IF" component of exactly 19,890 examples, checked for inclusion in the Tulu 3 8B DPO mix column and explicitly not checked for the 70B DPO mix column [1]. The paper's ablation compares three persona preference sets, one per targeted skill (instruction following, math, code): among the three, only the instruction-following set raised both the average development-evaluation score and the targeted IFEval score, while the math and code sets were dropped from the final mix because they slightly lowered the average score without improving their own targeted evaluations [1]. The published `allenai/llama-3.1-tulu-3-8b-preference-mixture` and `allenai/llama-3.1-tulu-3-70b-preference-mixture` repositories list their constituent dataset links in their READMEs; neither README's link list names this repository directly, so that adoption evidence rests on the paper's Table 15, not on those mixture cards [9][10].

**Introduced by**: [1] (Lambert et al., "Tulu 3: Pushing Frontiers in Open Language Model Post-Training").

## Quality

- Every one of the 104 rows read from this repository (the 54 rows at offset 0 and 50 rows at offset 19,840, both from `train`) has `chonsen_model` equal to `rejected_model` equal to `"gpt-4o"`, consistent with the paper's statement that GPT-4o-2024-08-06 generated the persona-driven data [1][6][7].
- The top-level `prompt` column and the first (user-role) turn of both `chosen` and `rejected` are identical, and equal to the ORIGINAL, unmodified instruction - verified on the row shown below and true across the 104 rows read [6][7]. The paper's construction method describes generating a separate, constraint-relaxed rewrite of the prompt to elicit the rejected response [1], but that rewritten prompt text is not stored in any served column; only the original prompt and the two candidate responses are.
- No source states a measured contamination rate, duplicate rate, or human-agreement figure for this dataset - it is fully synthetic, with no human labeling step described anywhere in the paper's construction of Persona IF [1].
- The `constraints` column values sampled across the 54 rows at offset 0 span at least 24 distinct categories (e.g. `length constraints:number of words`, `keywords:exclude words`, `format:use json format`, `response language`), consistent with the SFT sibling's stated sourcing of its constraint taxonomy from the IFEval benchmark [8][6].

## Where it came from

Built by the Allen Institute for AI as one of the Tulu 3 targeted preference datasets [1][2]. The paper describes the construction in three steps: start from `If-Persona-Sft`, the 29,980-example persona-grounded instruction-following SFT set (each example a prompt/constraints/response tuple generated with GPT-4o-2024-08-06 from a persona and a data-synthesis prompt); take a subset of it; prompt GPT-4o to rewrite each prompt so that it coherently relaxes one constraint category, such that the correct response to the rewritten prompt no longer satisfies the original prompt's constraints; and use the response to the rewritten prompt as `rejected`, pairing it with the original response as `chosen`, to form "If-Persona-Pref," which the paper describes as containing approximately 20,000 examples [1]. In the paper's ablations over persona-derived preference sets for instruction following, math, and code, only the instruction-following set improved both the average development-evaluation score and the targeted IFEval score, so only it was kept in the final Tulu 3 8B DPO preference mix [1].
