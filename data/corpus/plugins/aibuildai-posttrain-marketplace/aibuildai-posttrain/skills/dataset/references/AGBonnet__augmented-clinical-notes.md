# AGBonnet/augmented-clinical-notes

30,000 clinical-note/dialogue/summary triplets - each row pairs a real PubMed Central case note with a GPT-3.5-generated synthetic doctor-patient dialogue and a GPT-4-generated structured patient summary, in one `train` split.

**AGBonnet/augmented-clinical-notes** was built by Antoine Bonnet and Paul Boulenger's team at EPFL to fine-tune the MediNote clinical-note generators, and is introduced by their MediNote preprint, hosted in the dataset repository as `report.pdf` [1]. Each row starts from a real clinical note drawn from PMC-Patients, a large-scale collection of patient summaries extracted from open-access PubMed Central case studies [3]; NoteChat had already generated a synthetic patient-doctor dialogue from that note with ChatGPT (`gpt-3.5-turbo-0613`) [4], and the MediNote authors added a GPT-4 (`gpt-4-turbo-0613`)-generated structured patient-information summary built from a custom medical template [2]. It lives at https://huggingface.co/datasets/AGBonnet/augmented-clinical-notes . **The MediNote report fine-tuned on the 28,000 longest of these notes and held out 1,000 more from the same pool as its own evaluation set, but that split is not marked anywhere in the shipped file - training on all 30,000 released rows risks overlapping the notes the report's own benchmark numbers were computed on [1].**

**Use it for**: supervised fine-tuning of a clinical-note or patient-summary generator - dialogue-to-note, dialogue-to-summary, or note-to-summary - not chat-formatted and not a preference-pair format; build the prompt/response pairs yourself from the `conversation`, `note`/`full_note`, and `summary` columns before handing them to the SFT method card's trainer. Be aware of the eval-overlap risk stated above.

**Licence**: MIT (`cardData.license` is `"mit"`, tag `license:mit`), ungated, not private [5]. The one catch: no source states whether this MIT grant, which covers the repository's own content, also extends to the embedded PMC-Patients case-study text and NoteChat dialogues this release redistributes inside `full_note` and `conversation`.

**Shape**: 30,000 rows, one config (`default`), one split (`train`), five string columns [6][7].

**Hold out**: not identifiable from the shipped file. The source report describes reserving 1,000 of these notes as its own held-out evaluation set (see the bold restriction above), but no index or flag distinguishes those rows in the released `train` split, so they cannot be excluded without the report's original (unpublished) split [1].

**Origin**: built by Antoine Bonnet and Paul Boulenger's MediNote team at EPFL; the dialogues are ChatGPT (`gpt-3.5-turbo-0613`) generations from NoteChat, the summaries are GPT-4 (`gpt-4-turbo-0613`) generations from the curators, and the notes themselves are real PubMed Central case text [1][2]. Hub API at the check date: `downloads` 916, `downloadsAllTime` 28,758, `likes` 74 [5].

**Trained-on-by**: MediNote-7B and MediNote-13B, fine-tuned from Meditron, are the report's own models trained on this dataset - the Hub model card for MediNote-7B carries the `dataset:AGBonnet/augmented-clinical-notes` tag [8]. The report's Table 1 gives the deciding comparison, reporting ROUGE-1 / BLEU / BERTScore on the same 1,000-note test set for direct dialogue-to-note generation: MediNote-7B (trained on this data) scores 0.730 / 0.439 / 0.900, against untrained-on-this-data baselines Mistral-7B at 0.588 / 0.224 / 0.852, Llama-2-7B at 0.480 / 0.200 / 0.847, and GPT-3.5 Turbo at 0.588 / 0.187 / 0.849 [1].

**Introduced by**: [1] (Bonnet, Boulenger et al., "MediNote: Automated Clinical Notes") - an unpublished EPFL preprint hosted in the dataset repository, no arXiv id; the dataset card also documents the release [2].

## Quality

- The dataset card's only stated dialogue-quality caveat: ChatGPT-generated dialogues tend to lack realism, often reducing to the doctor restating facts from the note as questions the patient answers with a simple affirmative [2].
- The report explains why: notes were truncated before NoteChat generated dialogues from them, so information from the end of a note - frequently treatment and discharge details - is missing from both the truncated `note` and the resulting `conversation`; the curators chose to fine-tune on the truncated notes anyway, to avoid training models that hallucinate note endings [1].
- The report also found that some ChatGPT dialogues about a patient's death, followed by a conversation with a family member, contained a leaked copy of the dialogue-generation prompt; the authors say they manually removed these leaks only from their own 1,000-note evaluation set, not from the training data, so leaked-prompt dialogues may remain among the 30,000 released rows [1].
- No source states a measured contamination rate, duplicate rate, or annotator-agreement figure for this release.
- All five columns are self-contained strings served directly by the dataset; no field requires an outside fetch to use.

## Where it came from

Built by Antoine Bonnet and Paul Boulenger's MediNote team at EPFL, released alongside the MediNote report and codebase at `EPFL-IC-Make-Team/ClinicalNotes` on GitHub [2]. The pipeline chains three sources: real clinical notes from PMC-Patients, extracted by simple heuristics from open-access PubMed Central case studies [3]; synthetic patient-doctor dialogues that NoteChat had already generated from those notes with ChatGPT (`gpt-3.5-turbo-0613`) [4]; and structured patient-information summaries that the MediNote curators generated themselves by prompting GPT-4 (`gpt-4-turbo-0613`) zero-shot with each clinical note and a custom medical-information template [1][2].

### Screening verdict

Usable as SFT data for clinical-note or patient-summary generation, with the eval-overlap caveat carried above: the report's own held-out test notes are not distinguishable inside the released 30,000-row file.
