# FreedomIntelligence/ApolloMoEDataset

292,914 multilingual medical question-answer conversations (human/gpt turn pairs) spanning 12 major and 38 minor languages, served under a single, misleadingly-named Hub config.

**ApolloMoEDataset** is FreedomIntelligence's multilingual medical training corpus, introduced by "Efficiently Democratizing Medical LLMs for 50 Languages via a Mixture of Language Family Experts" [1], the paper behind the Apollo-MoE model family; the dataset's own README additionally links a sibling Apollo2 dense model family that the paper text does not name [1][2]. The paper describes collecting medical text from seven categories - books, papers, encyclopedias, doctor-patient dialogues, exams, websites, and practical guidelines - plus general-instruction and math/code data, then using `gpt-3.5-turbo-16k-0613` to turn that text into question-answer pairs, yielding a compiled training set the paper states holds 2.5 billion tokens across all languages and sources [1]. **The repository's only declared config is named `pretrain_text`, but it does not serve raw pretraining text: every row fetched for this card, at 16 offsets spanning the full row range, is a two-turn human/gpt conversation, the same shape used for SFT chat data [2][3]. The config also does not serve the complete corpus: its `data_files` entry points only at `ApolloMoEDataset_sample.json` (609 MB, the same 292,914 rows returned by the API); the file the README calls "the complete data", `ApolloMoEDataset.json` (13.5 GB, same schema, confirmed by reading its first bytes), is not wired into any config and is not reachable through `load_dataset` [2][3].** It lives at https://huggingface.co/datasets/FreedomIntelligence/ApolloMoEDataset .

**Use it for**: SFT-shaped medical instruction data - each row is one `human`/`gpt` turn pair on a medical or general topic, tagged by source category (`type`), language, and major/minor language class; this maps to the SFT method card, converting `conversations` (`from`/`value`) into the trainer's chat-message schema. Restriction: what `load_dataset` actually returns is the 292,914-row *sample* file, not the 13.5 GB "complete" corpus the README describes; the sample's row count and content are what this card's numbers below cover [2][3].

**Licence**: MIT (`cardData.license` is `"mit"`, tag `license:mit`) [4]. No further catch stated.

**Shape**: 292,914 rows, one config (`pretrain_text`), one split (`train`), six columns [5][6].

**Hold out**: no split ships to hold out (the repo has only `train`, no `test`/`validation`) [5]. The paper's own leakage screen already removed benchmark-overlapping items before this release: of 621,291 exam exercises examined, 3,479 were removed as leakage (a 0.56% screening rate), and other sources were filtered at under 0.01% [1]. The paired evaluation set, `FreedomIntelligence/ApolloMoEBench` (45,663 rows, a separate repository), is where evaluation is meant to happen - do not sample rows out of this training set to build an eval set [1][7].

**Origin**: built by FreedomIntelligence; question-answer pairs were machine-generated by `gpt-3.5-turbo-16k-0613` from collected source text, with the underlying text itself human- and institutionally-authored (books, papers, exams, etc.) [1]. Hub API at the check date: 389 downloads, 6,969 all-time downloads, 6 likes [4].

**Trained-on-by**: the paper's own Apollo-MoE models (0.5B/1.5B/7B, mixture-of-language-family-experts, trained on Qwen2 base models) are trained on this corpus [1]. The dataset's own README additionally links a sibling Apollo2 dense model family (0.5B/1.5B/2B/3.8B/7B/9B) under the same "Models" collection, though the paper text itself does not name "Apollo2" or state these dense sizes [2]. No source found reporting an independent, non-FreedomIntelligence model trained on it.

**Introduced by**: [1] (Zheng, Wang, Liang, Chen, Zheng, and Wang).

This sample of offsets does not cover the paper's full stated set of seven source categories (no `medicalGuideline` or doctor-patient dialogue rows were seen) nor its 50-language coverage, so those categories may exist elsewhere in the file; the claim above is bounded to what was read.

## Quality

- The QA pairs are machine-generated: the paper states they were produced by prompting `gpt-3.5-turbo-16k-0613` to transform source text into question-answer pairs [1]. No source states a measured error or hallucination rate for the resulting pairs.
- The paper's own ablation shows the general/math/code portion of this corpus is load-bearing, not filler: a Gemma-2B model trained on the full multilingual mix scores an average of 48.6 across 12 languages, against 42.7 for the same setup with math and code data removed (`-Math&Code`) - a 5.9% average performance loss the paper attributes to weaker reasoning capability without that data [1].
- The paper's own leakage check against evaluation-set overlap ("if an entire question or at least 64 consecutive characters overlapped with any data item, we classify that data item as a leakage instance") is quantified above under Hold out [1].
- No source states an annotator-agreement figure (the pairs are not human-annotated preference judgments; they are single-pass model generations).
- Every row read across the 16 sampled offsets carried exactly two conversation turns (one `human`, one `gpt`) [3]; whether longer, multi-turn dialogues occur elsewhere in the 292,914 rows is not established by this sample.

## Load it

Pin `load_dataset` to the revision the Hub API reports for `main` at the check date (the repo was last modified 2024-10-18) [4]:

```python
import datasets

REV = "45075ce81754ac0012a74a24ba8ab4a5ed8620d0"  # main at the check date
ds = datasets.load_dataset(
    "FreedomIntelligence/ApolloMoEDataset",
    "pretrain_text",
    revision=REV,
    split="train",
)  # 292,914 rows - despite the config name, these are chat-shaped QA pairs
```

This pin covers only what `load_dataset` itself resolves at that commit. The row counts, byte sizes, column list, and example row on this card were read from the datasets-server API (`/size`, `/info`, `/rows`), which is a live endpoint: it does not accept or honor a `revision` parameter - passing an invalid one still returns HTTP 200 with today's data unchanged, confirmed by querying `/size` with a nonexistent revision string. So those figures are only guaranteed current as of the check date, not pinned by `REV`; if the repo is force-pushed, `load_dataset(..., revision=REV)` still returns the historical file, but the datasets-server numbers above would no longer match it.

**Trap**: the config is named `pretrain_text`, but nothing about the returned rows is raw pretraining text - they are `human`/`gpt` conversation pairs, confirmed by reading rows at 16 offsets across the full row range [3]. A second, separate trap: this call returns only the *sample* file (`ApolloMoEDataset_sample.json`, 609 MB on disk); the README's "complete data", `ApolloMoEDataset.json` (13.5 GB on disk, confirmed by an HTTP HEAD against its LFS-redirected URL), shares the same schema (confirmed by reading its first bytes) but is not wired into any `configs` entry, so `load_dataset` cannot reach it - it would need a direct file download instead [2][3].

## Neighbors

- `FreedomIntelligence/ApolloMoEBench` - the paired evaluation benchmark for this corpus, 45,663 rows across per-language, per-source multiple-choice medical QA splits; a separate repository, not for training [7].
- `FreedomIntelligence/ApolloCorpus` - the predecessor corpus behind the earlier 6-language Apollo project, 3,741,196 rows. Unlike this repository, its own `pretrain_text` config genuinely serves raw text per language/source split (e.g. `medicalBook_en`, `medicalWiki_hi`), with a QA-pair config (`pretrain_qa`) present in the README but commented out of the live config list - the opposite division of labor from ApolloMoEDataset, where the sole config serves QA pairs under a `pretrain_text` name [9]. Prefer this repository (ApolloMoEDataset) for the wider 12-major/38-minor-language coverage; prefer ApolloCorpus only if genuine raw pretraining text is needed.

## Where it came from

Built by FreedomIntelligence. The paper groups source text into seven categories - books, papers, encyclopedias, doctor-patient dialogues, exams, websites, and practical guidelines - collected "from the Internet across 12 languages, selected based on population coverage", plus added general-instruction and math/code data to preserve non-medical skills; it then used `gpt-3.5-turbo-16k-0613` to convert that source text into question-answer pairs [1]. Before release, the paper ran a leakage check against its evaluation benchmark modeled on the Med-PaLM2 detection strategy, removing exam items with any full-question or 64-consecutive-character overlap, and reports the resulting compiled set at 2.5 billion tokens [1].

## Appendix: screening record

### Screening verdict

Usable as SFT-shaped medical QA data, with a caution the screening note does not fully capture: the served `pretrain_text` config is not raw corpus text as its name and the screening flag suggest - every row read is a two-turn chat pair - but it also only exposes the 292,914-row sample, not the 13.5 GB file the README calls the complete dataset [2][3]. Train on the served `train` split; no in-repo split needs holding out, and evaluate on the separate ApolloMoEBench repository rather than any subset of this one [1][7].

### The screening row

The row's own note [10]: "Multilingual medical training data for 12 major and 38 minor languages; also carries a `pretrain_text` config, which is raw corpus rather than post-training data. Its eval sibling is ApolloMoEBench, a separate repo." Its flag: "partly not post-training data: carries a `pretrain_text` config alongside its QA data."
