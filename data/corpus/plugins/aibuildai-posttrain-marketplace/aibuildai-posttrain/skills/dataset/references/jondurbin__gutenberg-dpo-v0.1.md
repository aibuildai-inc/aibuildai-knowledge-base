# jondurbin/gutenberg-dpo-v0.1

918 novel-writing DPO pairs, one train split, where the chosen side is an unmodified chapter from a public-domain Project Gutenberg novel and the rejected side is an LLM's attempt at the same chapter.

**jondurbin/gutenberg-dpo-v0.1** was built by Jon Durbin from 16 public-domain novels on Project Gutenberg, to teach novel-writing style to language models via direct preference optimization [1]. Each book was parsed and split into chapters; an LLM then wrote a synthetic prompt that would plausibly produce each chapter, plus a summary of the prior chapter for context, and a second LLM (one of llama-2-13b-chat, bagel-7b-v0.1, or dolphin-2.2-34b) used that prompt and summary to generate its own version of the chapter; the original human-written chapter became `chosen` and the LLM-written chapter became `rejected` [1]. There is no separate paper - the dataset card is the only description of the construction [1]. It lives at https://huggingface.co/datasets/jondurbin/gutenberg-dpo-v0.1 . **The rows carry no held-out eval split of their own [2], and the source text is well-known classic fiction (Huckleberry Finn, Pride and Prejudice, Moby Dick, and 13 others) [1], so anyone scoring against literary or reading-comprehension benchmarks built on these public-domain novels should check for overlap before using this set for training.**

**Use it for**: preference-pair (DPO) training for novel/creative-writing style - the DPO method card. Rows already carry an explicit `prompt` column alongside `chosen` and `rejected` [3], so no prompt-extraction step is needed before a standard DPO trainer consumes prompt/chosen/rejected triples. Not evaluated here for any other training shape (SFT, reward modeling).

**Licence**: CC BY 4.0 (`cardData.license` is `"cc-by-4.0"`), ungated, not private [4]. The one catch: the `chosen` text is copied verbatim from public-domain Gutenberg chapters, not authored for this release, and the README states no distinction between what the CC BY 4.0 grant covers on the `chosen` side versus the synthetically generated `prompt`/`rejected` side [1][4].

**Shape**: 918 rows, one config (`default`), one split (`train`), six string columns [2][3].

**Hold out**: nothing declared - the dataset ships a single `train` split with no test/eval split [2], and no source here flags an overlap with any published evaluation set; the risk noted above is a source-text overlap with future literary benchmarks, not a held-out portion inside this release [1].

**Origin**: built by Jon Durbin; `chosen` text is human-authored by the original novelists whose out-of-copyright books Project Gutenberg hosts, `rejected` text is machine-generated by one of three LLMs per row (llama-2-13b-chat, bagel-7b-v0.1, or a dolphin 2.2 34B variant), and the `prompt`/summary text is also LLM-generated [1]. Hub API at the check date: `downloads` 997 [4], `downloadsAllTime` 33,839 [5], `likes` 167 [4].

**Trained-on-by**: Jon Durbin's own bagel-dpo model family lists it as DPO training data - `jondurbin/bagel-dpo-7b-v0.4`'s model card lists `jondurbin/gutenberg-dpo-v0.1` twice under `datasets:` and describes it in its data-sources section as "DPO pairs meant to increase the models novel writing abilities, using public domain books" from Project Gutenberg [6]. No other model card or training report was found citing it.

**Introduced by**: no paper - the dataset card [1].

## Quality

- The construction is a matched pair by design, not a rated or filtered corpus: for each chapter, `chosen` is the unaltered original text and `rejected` is a same-prompt LLM rewrite, so the preference signal is "human novel prose beats LLM novel prose on this chapter," not a graded quality score [1].
- Of the first 10 rows served (`config=default`, `split=train`, offset 0, all from the source "gutenberg A Study in Scarlet"), `rejected_model` was `bagel-7b-v0.1` in 4 rows, `dolphin-2_2-yi-34b` in 5 rows, and `llama-2-13b-chat` in 1 row [7]. The README's process text names the third generator "dolphin-2.2-34b" [1], but the value actually stored in the served `rejected_model` column for that generator is `dolphin-2_2-yi-34b` [7] - the two do not match character-for-character, so a reader filtering rows by generator name should use the served string, not the README's prose name.
- No source states a measured contamination rate, duplicate rate, or an ablation/benchmark score isolating this dataset's contribution to a trained model; none is invented here.

## Where it came from

Built and released by Jon Durbin. Sixteen public-domain novels were selected from Project Gutenberg's popular section, chosen partly because they worked correctly with the "chapterize" library used to split them into chapters: Huckleberry Finn, Treasure Island, Anna Karenina, Uncle Tom's Cabin, Wuthering Heights, Madame Bovary, The Turn of the Screw, The War of the Worlds, A Study in Scarlet, Middlemarch, Pride and Prejudice, The Brothers Karamazov, Through the Looking Glass, Moby Dick, Frankenstein, and A Tale of Two Cities [1]. For each chapter, the process ran: (1) parse and clean the raw text (strip superfluous newlines, illustration tags, and similar formatting artifacts); (2) prompt an LLM to write a synthetic instruction that would plausibly produce that chapter, plus a summary of the chapter so later chapters' prompts can include prior context; (3) prompt a second LLM - llama-2-13b-chat, bagel-7b-v0.1, or dolphin-2.2-34b - with that synthetic prompt and prior-chapter summary to generate its own version of the chapter; (4) keep the original human chapter as `chosen` and the LLM chapter as `rejected` [1].

The dataset's own card gives no measured quality signal beyond the construction method itself (human original vs. LLM rewrite), and no held-out split ships with the repository, so a reader who needs an eval set must carve one out before training.
