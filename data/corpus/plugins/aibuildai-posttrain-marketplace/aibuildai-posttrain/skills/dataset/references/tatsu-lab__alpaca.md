# tatsu-lab/alpaca

52,002 instruction/input/output triples, generated end-to-end by OpenAI's `text-davinci-003`, the Stanford Alpaca instruction-tuning dataset.

**tatsu-lab/alpaca** is Stanford's instruction-following dataset released alongside the Stanford Alpaca project [1], built by prompting `text-davinci-003` with a modified version of the Self-Instruct data-generation pipeline [2] - generating instructions in larger batches and producing only a single output per instruction, among other changes detailed below [1][2]. Each row also carries a `text` field, the instruction/input/output pre-rendered into the exact prompt template the authors used to fine-tune the original Alpaca-7B model [2], so the dataset serves supervised instruction-tuning directly. **The data is licensed CC BY-NC 4.0, restricting it to non-commercial, research use [2][3]; separately, because the outputs were generated through the OpenAI API, the release is also bound by OpenAI's terms of use, which at the time of release prohibited using the outputs to develop models that compete with OpenAI [3].** It lives at https://huggingface.co/datasets/tatsu-lab/alpaca .

**Use it for**: single-turn instruction-following SFT (not chat, not preference pairs) - the `instruction`/`input`/`output` triple maps to a standard prompt-completion SFT format, or the pre-rendered `text` field can be used directly as the causal-LM training string; the CC BY-NC 4.0 and OpenAI-terms restrictions above mean research-only use, no commercial deployment. See the SFT method card.

**Licence**: CC BY-NC 4.0 (`cardData.license` is `"cc-by-nc-4.0"`, repo tag `license:cc-by-nc-4.0`), ungated [4]. The catch: this is a non-commercial-only licence, and the Stanford blog post that accompanied the release separately states the instruction data's origin in OpenAI's `text-davinci-003` output means it also falls under OpenAI's terms of use, which the blog says "prohibit developing models that compete with OpenAI" [3].

**Shape**: 52,002 rows, one config (`default`), one split (`train`), four string columns (`instruction`, `input`, `output`, `text`) [5][6].

**Hold out**: nothing - no source states or implies an evaluation-set overlap for this release; it ships one `train` split with no held-out portion of its own [5].

**Origin**: built and released by the Stanford Alpaca team (Rohan Taori et al.); every instruction, input, and output was generated by OpenAI's `text-davinci-003` model, not by human annotators [2]. Hub API at the check date: `downloads` 81,297, `downloadsAllTime` 2,288,450, `likes` 1,089 [4].

**Trained-on-by**: the original Stanford Alpaca-7B model, fine-tuned from LLaMA-7B on this data [1]. Community replications on the Hub include `maicomputer/alpaca-native`, whose card describes it as "a replica of Alpaca by Stanford' tatsu... [t]rained using the original instructions" [7], and `tloen/alpaca-lora-7b`, a LoRA adapter whose card states it was "fit on the Stanford Alpaca dataset" (its Hub metadata separately lists `yahma/alpaca-cleaned`, the cleaned neighbor, as its recorded `datasets` field) [8].

**Introduced by**: no paper - the dataset card [2] (plus the introducing Stanford CRFM blog post [3]).

## Quality

- Every output was generated by `text-davinci-003`, a single non-human teacher model; there is no human-authored ground truth [2].
- The dataset card's only stated quality caveat: "the `alpaca` data is generated by a language model (`text-davinci-003`) and inevitably contains some errors or biases," and it advises users to "use this data with caution" [2].
- No source states a measured error rate, duplicate rate, or contamination figure for this release.
- A downstream cleaning effort, `yahma/alpaca-cleaned`, documents specific defects found in this exact release by manual review: instructions referencing URLs or images the model could not see (causing hallucinated answers), instructions and outputs merged together from adjacent generated items, and entries with empty outputs [10]. These are third-party-reported defects in this dataset, not this card's own measurement.


**Trap**: `instruction`/`input`/`output` and the pre-rendered `text` field encode the same content twice - `text` already concatenates the other three fields into the exact training prompt template [2]. Building a prompt from `instruction`/`input`/`output` with a different template AND also training on `text` duplicates the example under two different renderings; pick one path.

## Neighbors

- `yahma/alpaca-cleaned` - a manual cleanup of this exact release: 51,760 rows (242 fewer), three columns (`instruction`, `input`, `output`, no `text` field), CC BY 4.0 rather than CC BY-NC 4.0. Its card documents the specific defects it fixed, listed under Quality above [10]. Prefer this neighbor over the original when the cleaning matters more than reproducing the original paper's exact data; `tloen/alpaca-lora-7b`'s Hub metadata lists it as the dataset actually used for that adapter [8][10].
- `vicgalle/alpaca-gpt4` - the same 52,002 instructions and inputs, re-answered by GPT-4 instead of `text-davinci-003`, from "Instruction Tuning with GPT-4" [11]; same four-column schema as this release. Prefer this neighbor when a stronger teacher's outputs matter more than reproducing the original Alpaca recipe; do not mix it with this release for the same instructions, since the two differ only in which model's completion is `output` and combining both would duplicate the same 52,002 prompts under two answers.

Both variants share the same four-column schema.

## Where it came from

Built by the Stanford Alpaca team and released alongside the Stanford Alpaca project [1]. The authors built on the Self-Instruct data-generation pipeline [12] and modified it: they switched the generating engine from `davinci` to `text-davinci-003`, wrote a new prompt that explicitly stated the instruction-generation requirement, generated 20 instructions per batch instead of one at a time, dropped the classification/non-classification split used by Self-Instruct, and generated only one output per instruction instead of two to three [2]. The card states this produced the 52K-example dataset for under $500 in API cost, and that the authors found the resulting data more diverse than Self-Instruct's own released seed data in a preliminary comparison [2]. The Stanford blog post accompanying the release states the resulting Alpaca-7B model was fine-tuned from Meta's LLaMA-7B on this data [1][3].
