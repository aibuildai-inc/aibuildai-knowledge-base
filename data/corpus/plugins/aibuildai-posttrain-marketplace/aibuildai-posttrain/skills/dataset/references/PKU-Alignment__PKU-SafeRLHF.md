# PKU-Alignment/PKU-SafeRLHF

82,118 red-teaming safety preference pairs - a shared prompt with two candidate responses, each carrying independent helpfulness and harmlessness preference labels plus a 19-category harm annotation - served across a merged `default` config and three per-response-model configs.

**PKU-SafeRLHF** is a human-and-AI-annotated preference dataset built by the PKU-Alignment team and introduced in "PKU-SafeRLHF: Towards Multi-Level Safety Alignment for LLMs with Human Preference" [1]. Prompts targeting 19 harm categories are mostly generated by Alpaca3-70B (63.6%) and WizardLM-30B-Uncensored (14.0%), and candidate responses come from three Alpaca-family models the authors SFT'd on the Alpaca 52K set: Alpaca-7B (Llama2-7B base), Alpaca2-7B (Llama2-7B base), and Alpaca3-8B (Llama3-8B base) [1]. Each Q-A-B triple is annotated for a 19-category harm label and severity level per response, then ranked twice - once for helpfulness and once for harmlessness - forming what the paper calls dual-preference data, distinct from the single-preference (trade-off) annotations hosted in a sibling repository [1]. It feeds reward/cost-model training and safety-constrained RLHF (the paper trains its own reward and cost models and a PPO-Lagrange policy on this data) [1]. **The data is released under CC-BY-NC-4.0, a non-commercial licence** [2]. It lives at https://huggingface.co/datasets/PKU-Alignment/PKU-SafeRLHF .

**Use it for**: preference-pair training for a reward model, a cost/safety model, or single-dimension preference optimization (DPO-style) - never load `default` together with any of the three per-model configs, since `default` is exactly their concatenation (row counts and first rows match; see Shape). The rows are an explicit-prompt preference format: `prompt` is separate from `response_0`/`response_1`, and the row carries two independent preference-selector columns, `better_response_id` (helpfulness) and `safer_response_id` (harmlessness), so a chooser must pick one dimension and build `chosen`/`rejected` from that id before handing rows to a standard preference or DPO trainer; maps to the DPO method card for a single dimension, or a dual reward+cost recipe like the paper's own for both. `is_response_0_safe`/`is_response_1_safe` and the harm-category/severity columns support a reward-model or safety-classifier method card instead.

**Licence**: cc-by-nc-4.0 (`cardData.license`), ungated (`"gated": false`, `"private": false`) [2]. The one catch: non-commercial use only, restated in the origin paper's ethics section [1][2].

**Shape**: 4 configs sharing one 16-column schema; `default` (union of the three model subsets) 82,118 rows (train 73,907 / test 8,211); `alpaca-7b` 30,429 (27,393 / 3,036); `alpaca2-7b` 28,412 (25,564 / 2,848); `alpaca3-8b` 23,277 (20,950 / 2,327); 164,236 rows served in total across all four configs [3][4].

**Hold out**: each config ships its own disjoint `test` split - hold out `default/test` (8,211), or the matching per-model `test` split if training on a single-model config, per the screening row's note [5]. No source states row overlap with any external evaluation benchmark; none is claimed here.

**Origin**: built by the PKU-Alignment team (Peking University); responses are Alpaca-family model generations, prompts are mostly Alpaca3-70B/WizardLM-30B-Uncensored generations, and the harm-category, severity, and helpfulness/harmlessness preference labels are joint human-and-AI (GPT-4-assisted) annotations from a team of over 28 annotators [1]. Hub API at the check date: `downloads` 17,040, `likes` 193 [2].

**Trained-on-by**: the origin paper's own reward and cost models, and its PPO-Lagrange-based Safe RLHF policy training, are fit to this dual-preference data [1]. No other independently confirmed adoption was found; a Hub dataset-to-models query returned entries (e.g. large unrelated model releases) whose own model cards and tags do not mention this dataset, so that listing is not usable as evidence and is not cited as adoption here [6].

**Introduced by**: [1] (Ji et al., "PKU-SafeRLHF: Towards Multi-Level Safety Alignment for LLMs with Human Preference").

`default/train` (73,907) equals `alpaca-7b/train` + `alpaca2-7b/train` + `alpaca3-8b/train` (27,393 + 25,564 + 20,950), and `default/test` (8,211) equals the matching sum of the three test splits (3,036 + 2,848 + 2,327); the repository's own `configs` metadata defines `default`'s data files as the concatenation of the three per-model JSONL file pairs, in that order [2]. Reading the first 71 rows of `default/train` and of `alpaca-7b/train` at offset 0 returns identical `response_0_source`/`response_1_source` values (`Alpaca-7B` in both), confirming `default` opens with the `alpaca-7b` rows first [7]. The dataset card's own summary states "83.4K preference entries" for this repository [2]; the measured `default` row count read here is 82,118, about 1,300 rows fewer than that stated figure.

All four configs share the same 16 columns [4]: `prompt`, `response_0`, `response_1`, `prompt_source`, `response_0_source`, `response_1_source`, `is_response_0_safe`, `is_response_1_safe`, `response_0_harm_category` and `response_1_harm_category` (19-key boolean structs, one per harm category [2]), `response_0_severity_level` and `response_1_severity_level` (integers; a sample of the first 71 `default/train` rows shows values 0-3 [7]), `better_response_id`, `safer_response_id`, `response_0_sha256`, `response_1_sha256`. Byte sizes for the whole repository: 465,351,510 bytes original download, 146,216,146 bytes as Parquet, 237,373,292 bytes decoded in memory [3]. No source states sequence-length or token-count statistics for this dataset; none is invented here. The paper states response generation covered "44.6k unique prompts" using the Alpaca-(1,2,3) models [1], matching the sibling `PKU-Alignment/PKU-SafeRLHF-prompt` repository's measured 44,578 rows [8].

## Quality

- Harm-category and severity labels, and both the helpfulness and harmlessness preference rankings, are produced by a joint human-and-AI annotation process involving over 28 annotators, and helpfulness and harmlessness are ranked as two separate dimensions rather than one combined score [1]. The dataset card additionally states that the harmlessness ranking enforces a logical constraint: a response classified as harmless across all 19 harm categories is always ranked above one classified as harmful in at least one category [2].
- The paper's Table 8 reports pairwise agreement between GPT-4 and four human annotation roles (crowdworker, quality-control team, project manager, researcher); GPT-4's agreement with each human role ranges from 82.3% to 86.2%, while the highest cell in the table overall, 88.2%, is a project-manager-versus-researcher (human-human) pair, not a GPT-4-versus-human one [1].
- The paper states response generation drew on lessons from the sibling BeaverTails project, noting that raising the generation temperature "could lead to garbled and meaningless content," and describes a pipeline (default-parameter response first, then higher-temperature variants) built to control for that [1]. It separately reports "a 32% reduction in garbled and semantically unclear content compared to the BeaverTails dataset" [1].
- No source states a measured contamination or duplicate-row rate against external evaluation benchmarks for this dataset; none is invented here.
- The dataset card's safety warning states the data "may be offensive or harmful" and that it is "intended for research purposes, especially research that can make models less harmful" [2].

## Load it

The repo commit is pinned below to the Hub API's `sha` for `main` at the check date (the repository was last modified 2024-10-18) [2], which covers what `load_dataset(..., revision=REV)` actually loads. This card's row and shape counts, however, come from the datasets-server size/info/first-rows endpoints [3][4][7][10], which take no revision parameter and return the same live payload regardless of any revision passed to them - so those counts are current as of the check date, not pinned to `REV`, even though `REV` is what a reproducible load should still specify:

```python
import datasets

REV = "9421ffafec3fa40a1f1a7d567b4d525079477ecb"  # main at the check date
train = datasets.load_dataset("PKU-Alignment/PKU-SafeRLHF", revision=REV, split="train")  # 73,907 rows
test = datasets.load_dataset("PKU-Alignment/PKU-SafeRLHF", revision=REV, split="test")    # 8,211 rows - hold out
```

**Trap**: with no `name`/`data_dir` argument this loads the `default` config, which is the concatenation of the three per-response-model subsets; passing `name="alpaca-7b"` (or `alpaca2-7b`, `alpaca3-8b`) loads only that model's rows, already included in `default` [2][3]. Loading `default` and then separately loading any one of the three named configs on top of it duplicates that config's rows in training data. The card also documents `revision="v0"` to load the older `PKU-SafeRLHF-v0` sibling snapshot through the same repository ID; that is a different revision with a different row set, not covered by this card's counts [2].

## Neighbors

All row counts below were read live at the check date [8].

- `PKU-Alignment/PKU-SafeRLHF-single-dimension` - the paper's single-preference counterpart to this dual-preference release: 81,105 rows, with a 9-column schema (`prompt`, `response_0`, `response_1`, `prompt_source`, `response_0_source`, `response_1_source`, `better_response_id`, `response_0_sha256`, `response_1_sha256`) that drops the harm-category, severity, safety-boolean, and `safer_response_id` columns this release has - it carries one preference id trading off helpfulness and harmlessness together, not two independent ones [8][9].
- `PKU-Alignment/PKU-SafeRLHF-QA` - 265,223 Q-A pairs with harm-category and severity meta-labels but no response ranking; the paper describes this as the safety-meta-label pool this and the single-dimension release were annotated from [1][8].
- `PKU-Alignment/PKU-SafeRLHF-prompt` - 44,578 prompts, the prompt-only pool behind both preference releases [1][8].
- `PKU-Alignment/BeaverTails` - 364,170 rows, described in the dataset card as this project's sibling and the predecessor whose annotation pipeline this release improved on for response quality [1][2][8].
- `PKU-Alignment/PKU-SafeRLHF` at `revision="v0"` - an older snapshot of this same repository, reachable through the standard `load_dataset` revision argument rather than a separate repo id [2].
- This project prefers the dual-preference `default`/per-model configs documented here when a chooser needs independent helpfulness and harmlessness rankings; reach for `-single-dimension` only when a single combined preference id is wanted.

## Where it came from

Built by the PKU-Alignment team. Prompts targeting 19 harm categories are generated with severity-level rules fed into the prompt-generation model so it produces prompts spanning minor to severe harm, then expanded for diversity by Alpaca3-70B; 63.6% of prompts are attributed to Alpaca3-70B and 14.0% to WizardLM-30B-Uncensored, with a third prompt-source value, `Beavertails`, also observed in the served rows and not separately quantified in the paper's text [1][7]. Candidate responses to the resulting 44.6k unique prompts are generated by three Alpaca-family models the authors SFT'd from Llama2-7B and Llama3-8B on the Alpaca 52K instruction set: Alpaca-7B, Alpaca2-7B, and Alpaca3-8B [1]. Each Q-A-B triple is then annotated - by a joint human-and-AI process involving over 28 annotators - for a 19-category harm label and severity level per response, and ranked twice, once for helpfulness and once for harmlessness, yielding this repository's dual-preference structure; a single combined preference id is instead recorded in the sibling `-single-dimension` release [1][2].

This rests on the dataset card's own licence and usage statement [2] and on the screening row's note, which the appendix quotes below [5].
