# ise-uiuc/Magicoder-OSS-Instruct-75K

75,197 single-turn code problem/solution pairs, machine-generated by `gpt-3.5-turbo-1106` from real open-source code snippets, the OSS-Instruct training set behind the Magicoder models.

**ise-uiuc/Magicoder-OSS-Instruct-75K** is the dataset introduced by "Magicoder: Empowering Code Generation with OSS-Instruct" [1]: starting from short snippets drawn out of the starcoderdata corpus, the authors prompted `gpt-3.5-turbo-1106` to invent a self-contained coding problem and a correct solution inspired by each snippet, then decontaminated the result against five code-eval benchmarks - HumanEval, MBPP, APPS, DS-1000, and GSM8K [1]. The dataset card names the generating model and points to OpenAI's usage policy for anyone adopting the data [2]. **The problems and solutions are OpenAI-model outputs, not human-written or human-licensed text, and the card's own usage-policy pointer is a usage-shape restriction on that basis [2].** It lives at https://huggingface.co/datasets/ise-uiuc/Magicoder-OSS-Instruct-75K .

**Use it for**: single-turn instruction-following SFT for code generation - each row is a `problem` (a self-contained coding task) paired with one `solution` (a fenced code block), the same shape used to fine-tune the Magicoder models with a fixed instruction/response prompt template [3]. Map `problem` to the instruction turn and `solution` to the response turn, the same shape the SFT method card expects. No preference or reward-model fields are present.

**Licence**: MIT (`cardData.license` is `"mit"`; repo tag `license:mit`), ungated (`"gated": false`, `"private": false`) [4]. The one catch: MIT covers the repository's own text, but the dataset content is OpenAI-model output, and the card separately points to OpenAI's usage policy for the generated data itself [2].

**Shape**: 75,197 rows, one config (`default`), one split (`train`) [5][6].

**Hold out**: nothing declared. The origin paper decontaminates the dataset by removing coding problems that overlap HumanEval, MBPP, APPS, DS-1000, or GSM8K before release, and reports filtering out 9 problems in the process [1]; the screening row's note carries no flag and states no overlap risk either [7].

**Origin**: built by the Magicoder authors (UIUC); problems and solutions are `gpt-3.5-turbo-1106` generations, not human-written [1][2]. Hub API as of 2026-08-11: 27,218 downloads, 167 likes [4].

**Trained-on-by**: `ise-uiuc/Magicoder-CL-7B`, `ise-uiuc/Magicoder-S-CL-7B`, `ise-uiuc/Magicoder-DS-6.7B`, and `ise-uiuc/Magicoder-S-DS-6.7B` all list this dataset in their own model cards' `datasets:` metadata and "Training Data" section [3][8]. `dphn/dolphin-2.6-mistral-7b`'s Hub API record also lists it in `cardData.datasets` [9]; no other dolphin release was checked.

**Introduced by**: [1] (Wei et al., "Magicoder: Empowering Code Generation with OSS-Instruct").

## Quality

- The paper's own decontamination pass removed 9 problems that overlapped HumanEval, MBPP, APPS, DS-1000, or GSM8K, leaving the 75,197 rows served today; the repository's only data file is named `data-oss_instruct-decontaminated.jsonl`, consistent with that pass [1][10].

## Where it came from

Built by the Magicoder authors at UIUC. The paper's OSS-Instruct method draws 1-15 consecutive lines from each of 80,000 code documents sampled from starcoderdata (a permissively-licensed, decontaminated filtering of The Stack), split roughly 40K Python and 5K each across C++, Java, TypeScript, Shell, C#, Rust, PHP, and Swift [1]. Each snippet is fed to `gpt-3.5-turbo-1106`, chosen for cost-effectiveness, with greedy decoding, and the model is prompted to imagine a self-contained coding problem and a correct solution inspired by the snippet [1]. The authors then decontaminate the generated set by removing coding problems that overlap HumanEval, MBPP, APPS, DS-1000, or GSM8K, filtering out 9 problems to reach the released 75,197 rows [1]. On the origin paper's own benchmark, a 7B CodeLlama-Python model fine-tuned on this dataset alone (Magicoder-CL) scores 60.4% (55.5% on the stricter HumanEval+) pass@1 on HumanEval, against 37.8% (34.1%) for the same base model with no fine-tuning on this data [1].

## Appendix: screening record

### Screening verdict

Usable as instruction/response SFT data for code generation, sourced entirely from `gpt-3.5-turbo-1106` generations over open-source seed snippets. The screening row's note states the origin and licensing consideration, and the origin paper's own decontamination pass against five benchmarks (established above) supports treating the released rows as clean of those specific evaluation sets [1][7].

### The screening row

The row's own note [7]: "OSS-Instruct problems and solutions generated by gpt-3.5-turbo-1106 from real open-source snippets; OpenAI usage terms apply." The row carries no flag.
