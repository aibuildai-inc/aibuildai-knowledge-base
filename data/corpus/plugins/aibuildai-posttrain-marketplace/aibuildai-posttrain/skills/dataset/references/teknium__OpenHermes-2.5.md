# teknium/OpenHermes-2.5

1,001,551 instruction/chat examples in ShareGPT-style conversation lists, compiled from roughly fifteen open synthetic and human-sourced datasets, most of it GPT-4-generated.

**teknium/OpenHermes-2.5** is a compilation built by Teknium (Nous Research) from many existing open datasets plus custom-generated synthetic sets; it is the training data behind the OpenHermes 2/2.5 and Nous Hermes 2 model series [1]. The dataset's own README lists its component sources by name, including Airoboros 2.2, CamelAI, "ChatBot Arena (GPT-4 Only)" (drawn from LMSYS's `lmsys-chat-1m`), Collective Cognition, CoT Alpaca GPT4, Evol Instruct 70K/140K, Glaive Code Assistant, GPT4-LLM, GPTeacher, OpenGPT medical tasks, MetaMath 40k, SlimOrca 550K, Open-Platypus, ShareGPT (GPT4-only), and Unnatural Instructions GPT4 [1]. Rows follow a "sharegpt" structure: each row holds a `conversations` list of `{from, value}` turns [1]. It lives at https://huggingface.co/datasets/teknium/OpenHermes-2.5 . **The compilation's component list names "ChatBot Arena (GPT-4 Only)" as sourced from `lmsys/lmsys-chat-1m` [1]; Arena-Hard-Auto's 500 benchmark prompts are themselves described as sourced from Chatbot Arena [2], though neither [1] nor [2] states that the two draw from the identical released pool. This dataset's own screening record flags that possible overlap as a risk [3]; decontaminate against Arena-Hard before using this dataset for a benchmarked run (see Hold out and Quality for what can and cannot be filtered out).**

**Use it for**: SFT chat/instruction training - the served `conversations` field is already turn-structured, mapping directly to the SFT method card's chat-list input; there is no chosen/rejected pair anywhere in the schema, so this is not preference data. Decontaminate against Arena-Hard-Auto before a benchmarked run, per the restriction above.

**Licence**: not stated. The Hub API's `cardData` carries no `license` key, and the README states none [1][4]. The card names each component's own upstream (Airoboros, CamelAI, WizardLM, Glaive, MetaMath, SlimOrca, Platypus, ShareGPT, LMSYS, etc.) but does not restate their licences, so a licence claim for any one component has to be checked at that component's own source, not here [1].

**Shape**: one config (`default`), one split, `train` = 1,001,551 rows, 16 columns [5][6].

**Hold out**: no held-out split exists (all 1,001,551 rows sit in `train`) [5]. The "ChatBot Arena (GPT-4 Only)" component's row count and the boundary between it and the other unlabeled components (SlimOrca, Platypus, GPTeacher, Collective Cognition, ShareGPT) are not recoverable from the served `source` column - see Quality for the sampling that established this. Because that component cannot be isolated by the `source` field, filtering it out for Arena-Hard decontamination requires matching row content against `lmsys-chat-1m` directly, not the `source` value.

**Origin**: built and released by Teknium; conversations are drawn from prior open datasets plus custom synthetic sets, most flagged as GPT-4-generated by the repo's own tags [1][4]. Hub API at the check date: 17,861 downloads (30-day), 276,185 downloads all-time, 888 likes [4][7].

**Trained-on-by**: `teknium/OpenHermes-2.5-Mistral-7B`'s model card lists `teknium/OpenHermes-2.5` under `datasets` and states the model was trained on "1,000,000 entries of primarily GPT-4 generated data, as well as other high quality data from open datasets" [8]. `NousResearch/Nous-Hermes-2-Mistral-7B-DPO`'s model card states it was DPO'd from `teknium/OpenHermes-2.5-Mistral-7B`, whose pre-DPO SFT stage was "trained on 1,000,000 instructions/chats of GPT-4 quality or better... available from the repository teknium/OpenHermes-2.5" [9].

**Introduced by**: no paper - the dataset card [1].

## Quality

- The README's only stated quality claim is the builder's own: OpenHermes 2.5 is described as "a much larger scale, much more diverse, and much higher quality compilation" than the earlier OpenHermes 1 dataset [1] - a compiler's characterization, not a measured metric; no source states a duplicate rate, contamination rate, or annotation-agreement figure for this dataset.
- Most of the 16 columns are populated only for some component datasets and null elsewhere: sampling 920 rows at 22 offsets spread across the full row range (0, 100k, 150k, 200k, 250k, 300k, 350k, 400k, 450k, 500k, 550k, 600k, 650k, 700k, 750k, 800k, 850k, 900k, 950k, 990k, 1001500, and 1001531-1001550) found the `source` column populated with one of `airoboros2.2`, `CamelAI`, `cot_alpaca_gpt4`, `EvolInstruct_70k`, `glaive-code-assist`, `GPT-4 Comparison Data`, or `metamath` at every offset from 0 through 500,000, and `null` at eleven of the twelve sampled offsets from 550,000 onward (550k, 600k, 650k, 700k, 750k, 800k, 850k, 900k, 990k, 1001500, and 1001531-1001550) - except at offset 950,000, where all 20 sampled rows instead carry `source = "UnnaturalInstructions"` [10]. So the `source` field past 500,000 is mostly but not uniformly null; a reader cannot assume every row past that point is unlabeled. In the null rows, some instead carry a populated `idx` field holding a short alphanumeric code consistent with a ShareGPT share id, but most carry no populated metadata field beyond `conversations` at all [10]. None of the 920 sampled rows carried a `source` value naming "ChatBot Arena," "lmsys," or "SlimOrca," "Platypus," or "GPTeacher" by name, so this reference card cannot state which specific unlabeled rows come from the Arena component versus the other four unlabeled components named in the README [1][10].

## Load it

Only `train` exists, so there is nothing to hold out by split. Pin the revision this card's numbers were read at (the Hub API's `sha` for `main` at the check date; the repo was last modified 2024-04-15) [4]:

```python
import datasets

REV = "b82037821055c377bed0d495e72e46de3bc72e84"  # main at the check date
train = datasets.load_dataset("teknium/OpenHermes-2.5", revision=REV, split="train")  # 1,001,551 rows
```

**Trap**: this loads the raw `sharegpt`-structured rows as-is - most metadata columns (`topic`, `model_name`, `category`, `source`, etc.) are null for a large share of rows (see Quality), and there is no chosen/rejected pairing anywhere, so a preference trainer cannot consume this data unmodified.

## Neighbors

- `teknium/openhermes` - the predecessor, OpenHermes 1: 242,831 rows, smaller and at an earlier compilation stage than this 1,001,551-row 2.5 release [11].
- `argilla/OpenHermes2.5-dpo-binarized-alpha` - the card describes it as a DPO dataset built with distilabel atop this dataset, using PairRM for preference selection instead of OpenAI models; 9,793 rows, 28 columns, an alpha release for community feedback, not a straight reformat of this dataset [12][13].
- `HuggingFaceH4/OpenHermes-2.5-1k-longest` - a curated 2,000-row subset (`train_sft` 1,000 rows plus a second split), 4 columns; a small filtered slice, not a full-corpus reformat [14].
- `HuggingFaceH4/OpenHermes-2.5-preferences-v0-deduped` and its size-bucketed derivatives (`-50k` through `-500k`) - deduplicated preference-format derivatives built by Hugging Face's H4 team from this dataset [13].
- Prefer this original release for full-scale SFT; reach for the DPO/preference derivatives only when the training shape is preference pairs, and for the H4 curated slices only when a small filtered sample is what is wanted.

## Where it came from

Built and released by Teknium (Nous Research), as a compilation and curation of many pre-existing open datasets plus custom-generated synthetic sets, described in the README as the corpus behind the OpenHermes 2/2.5 and Nous Hermes 2 model series [1]. The README's own "Dataset Sources" section names each component with a link or attribution, including third-party creators (Jon Durbin's Airoboros 2.2, CamelAI, LMSys's ChatBot Arena / `lmsys-chat-1m`, WizardLM's Evol Instruct sets, Sahil/Glaive's Glaive Code Assistant, the GPT4-LLM authors, CogStack's OpenGPT medical tasks, MetaMath, Open-Orca's SlimOrca, Garage-bAInd's Open-Platypus, and an unfiltered ShareGPT GPT-4-only scrape) alongside Teknium's own Collective Cognition, GPTeacher, and CoT Alpaca GPT4 sets, for which the source page is stated as lost [1]. The generating models named across these components (via the repo's model-mention tags) are GPT-4, Hermes, and WizardLM [1].

## Appendix: screening record

### Screening verdict

Usable as SFT chat data, with a stated decontamination caveat: the corpus screening note flags that the README's "ChatBot Arena (GPT-4 Only)" component is sourced from `lmsys/lmsys-chat-1m` [3]; Arena-Hard-Auto's 500 benchmark prompts are themselves described as sourced from Chatbot Arena [2], though neither [1] nor [2] states that the two draw from the identical released pool - so a benchmarked run should decontaminate against Arena-Hard first as a precaution. That component's rows cannot be isolated via the served `source` column (see Quality), so filtering has to work at the content level against `lmsys-chat-1m` rather than by a `source` value.

### The screening row

The row's `flag`, in its own words: "rule-risk: arenahardwriting - Component list names 'ChatBot Arena (GPT-4 Only)' sourced from lmsys/lmsys-chat-1m, the pool Arena-Hard prompts are curated from." The row's `note`: "1M instruction/chat samples compiled from many synthetic sets; card tags it GPT-4 distillation."
