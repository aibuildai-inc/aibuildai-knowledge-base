# camel-ai/ai_society

https://huggingface.co/datasets/camel-ai/ai_society

25,000 synthetic multi-turn role-play dialogues between two gpt-3.5-turbo agents, shipped as archived per-conversation files rather than a queryable table, under a non-commercial licence.

**camel-ai/ai_society** is one of the two large role-playing datasets released with "CAMEL: Communicative Agents for 'Mind' Exploration of Large Language Model Society" [1]. Two gpt-3.5-turbo instances hold a scripted "Inception Prompting" conversation, one instance fixed as an AI assistant and the other as an AI user, over every combination of 50 automatically generated assistant roles, 50 automatically generated user roles, and 10 tasks per role pair, yielding 25,000 conversations [1]. The repository ships two file formats rather than a single loadable config: a `.tar.gz` (and a duplicate `.zip`) of per-conversation chat transcripts, and a separate JSON file that flattens each conversation into one row per assistant turn in an instruction/input/output shape [2]. **The dataset card restricts use to research purposes only, warning the data was synthetically generated by gpt-3.5-turbo and "might contain incorrect information" [2], and it is licensed CC-BY-NC-4.0, a non-commercial licence [3].** The Hub API reports the repository as ungated despite the card's gated-request front matter fields [3].

**Use it for**: multi-turn SFT on the chat-format transcripts (map each `message_k` turn to a chat message list for the SFT method card), or single-turn instruction SFT on the `instructions` file's `instruction`/`input`/`output` triples (an Alpaca-style shape) - never for a commercial deployment, per the CC-BY-NC-4.0 licence restated above [2][3]. Neither format is a preference pair; there is no chosen/rejected column.

**Licence**: CC-BY-NC-4.0 (`cardData.license` is `"cc-by-nc-4.0"`), and the Hub API marks the repo `"gated": false` even though the README front matter defines `extra_gated_prompt` and `extra_gated_fields` [2][3]. The one catch: the card's own disclaimer limits the data to research use only [2].

**Shape**: the card declares 25,000 conversations in one `train` split, but the repository has no loading script and datasets-server cannot build a single table from it - `config-size` and `config-info` both fail, and probing `/rows` surfaces a `DatasetGenerationCastError` because the per-conversation JSON files inside the archives carry different sets of `message_k` columns [4][5][6]. A `first-rows` preview of the chat format returned 50 rows before that failure surfaces; the `instructions.json` format is not covered by any working datasets-server endpoint at all.

**Hold out**: nothing. No source consulted for this card - the paper, the dataset card, or the screening note - flags any overlap between this dataset and an evaluation set.

**Origin**: built and released by the CAMEL project (Guohao Li, Hasan Abed Al Kader Hammoud, Hani Itani, Dmitrii Khizbullin, Bernard Ghanem) [1]; every conversation turn, plus the assistant/user roles and tasks that seed each conversation, is generated by prompting an LLM (gpt-3.5-turbo for the conversations themselves), with no human labeling [1][2]. Hub API as of the check date: `downloads` 534, `downloadsAllTime` 4,157, `likes` 47 [3].

**Trained-on-by**: `camel-ai/CAMEL-13B-Role-Playing-Data`, a LLaMA-13B finetune, whose model card states it was trained on "a total of 229K conversations created through our role-playing framework proposed in CAMEL" [7]; `camel-ai/CAMEL-13B-Combined-Data` [8] and `camel-ai/CAMEL-33B-Combined-Data` [9] each add 100K ShareGPT conversations and 52K Alpaca instructions on top of the same 229K figure. None of these three model cards breaks down how many of the 229K conversations come from this AI Society release specifically, versus the paper's other role-playing set (Code) or its Math/Science datasets, so this is adoption evidence for the CAMEL role-playing framework rather than a confirmed exact-file match.

**Introduced by**: [1] (Li et al.).

## Shape

The dataset card states the release is "composed of 25K conversations" from "a combination of 50 user roles and 50 assistant roles with each combination running over 10 tasks" (50 x 50 x 10 = 25,000) [2]. Datasets-server cannot confirm a row count: both `/size` and `/info` return a `failed` status for the `default` config, each citing a `config-size`/`config-info` job failure [4][5]. Calling `/rows` directly returns the underlying error: building the table raises `DatasetGenerationCastError` because, while scanning the per-conversation JSON files packed inside `ai_society_chat.zip`, "there are 2 new columns ({'message_6', 'message_5'})" not present in the schema inferred from earlier files - conversations vary in length (the paper caps a conversation at 40 messages [1]), so later files need more `message_k` columns than earlier ones [6]. A `first-rows` preview (which pads missing `message_k` fields with null rather than failing) did return 50 rows at offset 0 of `config=default`, `split=train`, with `num_messages` in those 50 rows ranging from 4 to 24 [10].

The repository's tree lists five files (Hub API `siblings`, sizes from the tree endpoint) [3][11]:

| file | bytes |
| --- | --- |
| `ai_society_chat.tar.gz` | 30,421,378 |
| `ai_society_chat.zip` | 43,908,125 (same conversations as the tar.gz, zip-packed) |
| `ai_society_instructions.json` | 150,678,866 |

No source states sequence-length or token statistics for this release. The paper does give per-conversation message-count limits: a conversation ends after 3 rounds of the user not issuing an instruction, after the assistant issues an instruction (a role reversal), when the user emits an end-of-task token, when either agent hits gpt-3.5-turbo's token limit, or after a hard cap of 40 messages set "to keep the cost of generated chats in check" [1].

## Quality

- The paper reports a human and a GPT-4 evaluation comparing the CAMEL role-play solutions against a gpt-3.5-turbo single-shot baseline on the same tasks. For the AI Society scenario: human evaluation scored a 13.3% draw, 10.4% baseline win, 76.3% CAMEL win; GPT-4 evaluation scored a 4.0% draw, 23.0% baseline win, 73.0% CAMEL win [1].
- The paper names four recurring generation failure modes it observed across the role-playing datasets: role flipping (the assistant starts issuing instructions instead of following them), the assistant simply repeating the user's instruction back, "flake replies" where the assistant promises action ("I will...") without following through, and infinite loops of non-progressing pleasantries [1]. It does not give a measured rate for any of the four.
- No source states a duplicate-rate or contamination figure for this dataset.

## Load it

The README's own recommended way to use this repository is to download one of its two raw files directly, not to call `load_dataset` with no arguments [2]:

```python
from huggingface_hub import hf_hub_download
hf_hub_download(repo_id="camel-ai/ai_society", repo_type="dataset",
                 filename="ai_society_chat.tar.gz", revision="a493cd1636808cbe3cf2389dec79471a1db9e6bc",
                 local_dir="datasets/", local_dir_use_symlinks=False)
```

The commit `a493cd1636808cbe3cf2389dec79471a1db9e6bc` is `main`'s `sha` at the check date and is what every number on this card was read at [3].

**Trap**: `datasets.load_dataset("camel-ai/ai_society")` with no `data_files` argument will raise the same `DatasetGenerationCastError` documented in Shape above, because the generic JSON builder tries to union every per-conversation file inside the archives into one schema and the files disagree on how many `message_k` columns they carry [6]. Loading `ai_society_instructions.json` on its own works with a plain JSON loader, but note that file is a flattened, one-row-per-assistant-turn table, not one row per conversation - a conversation with `num_messages: 24` (12 assistant turns) contributes 12 rows to that file, each repeating the same `id`, `role_1`, `role_2`, `original_task` and `specified_task` [12].

## Neighbors

- `camel-ai/ai_society_translated`, from the same builder: the identical English conversations, machine-translated by prompting gpt-3.5-turbo into ten languages (Arabic, Chinese, Korean, Japanese, Hindi, Russian, Spanish, French, German, Italian), packaged as one `.zip` per language rather than the tar.gz/json pair here [13]. Prefer this release for English training; reach for the translated one only for a non-English run.
- `camel-ai/code`, the paper's second large role-playing dataset: 50,000 conversations simulating a programmer paired with a domain expert across 20 languages and 50 domains, built with the same role-playing method and under the same licence [1][14].
- No cleaned or binarized re-release of this dataset was found on the Hub.

These two shapes need different collators: the chat format is a per-conversation record with a variable number of `message_k` struct columns to reassemble into a turn sequence, while the instructions format is already one training example per assistant turn, with `role_1_response`/`role_1_message_id` marking which turn of the source conversation it came from.

## Where it came from

Built by the CAMEL project team and released on the Hub by the `camel-ai` organization. The conversations come from the "role-playing" framework in the origin paper: an LLM first generates candidate assistant roles, user roles, and tasks; a task-specifier prompt turns a generic task into a specific one; then a fixed AI-assistant agent and AI-user agent (both gpt-3.5-turbo) exchange instruction/solution turns automatically under "Inception Prompting" until one of several termination conditions fires [1][2]. No human wrote or labeled any conversation content; humans only appear in the paper's separate evaluation of conversation quality (the Table 1 numbers in Quality above) [1].
