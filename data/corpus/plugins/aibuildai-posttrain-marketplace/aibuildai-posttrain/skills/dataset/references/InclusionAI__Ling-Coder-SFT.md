# InclusionAI/Ling-Coder-SFT

A code-instruction SFT dataset of over 5 million English and Chinese samples, spanning more than 20 programming languages, released as the open-sourced subset of the fine-tuning data behind the Ling-Coder-Lite model.

**Ling-Coder-SFT** was built and released by the Codefuse/Ling Team (InclusionAI) as a subset of the supervised fine-tuning data used to train their Ling-Coder-Lite code model, introduced in the technical report "Every Sample Matters: Leveraging Mixture-of-Experts and High-Quality Data for Efficient and Accurate Code LLM" [1]. The rows are single-turn instruction/response pairs (`HUMAN`/`ASSISTANT` messages) covering text-to-code, code completion, code execution reasoning, complex algorithm Q&A, and popular Python library usage [2]. **This repository is only a subset of what the model was actually trained on: the paper states the full Ling-Coder-Lite SFT stage used 18.8 million instruction samples (11.7 million code-related), while this released repository holds over 5 million of them** [1][2]. It lives at https://huggingface.co/datasets/inclusionAI/Ling-Coder-SFT .

**Use it for**: SFT chat data — the SFT method card. Each row is one `HUMAN`→`ASSISTANT` exchange rather than a multi-turn `user`/`assistant` chat-template list, so a role-name mapping (`HUMAN`→`user`, `ASSISTANT`→`assistant`) precedes template-based SFT training [3]. Only a subset of the builder's full SFT mix was released, not the whole 18.8M-sample training set [1][2].

**Licence**: Apache-2.0 (`cardData.license` and the `license:apache-2.0` tag both read `apache-2.0`), ungated (`"gated": false`, `"private": false`) [4]. No further usage restriction is stated; the builder only asks that the technical report be cited if the dataset is used [2].

**Shape**: 1 config (`default`), 1 split (`train`); no source states an exact total row count. The dataset card states the total exceeds 5 million samples [2]; the Hub repository lists 26 parquet shards (25 near-equal at about 244 MB each, the last about 146 MB, totalling 6,259,605,417 bytes) [5]; the datasets-server viewer has only fully processed 7 of those 26 shards (1,400,000 rows, exactly 200,000 per processed shard) and extrapolates an estimated 4,480,166 rows for the whole dataset [6][7].

**Hold out**: not stated. No source names a specific evaluation split or benchmark to hold out. The paper describes a deduplication and decontamination step during data construction, but does not name which benchmark sets were checked against [1]; no overlap with a named eval set was found in any source read for this card.

**Origin**: built by the Codefuse/Ling Team at InclusionAI/Ant Group; both the seed questions and the answers in each pair are generated by state-of-the-art code LLMs [1]. Hub API at the check date: `downloads` 1,028, `downloadsAllTime` 14,097, `likes` 45 [4].

**Trained-on-by**: the origin paper's own Ling-Coder-Lite model, fine-tuned for 5 epochs on the full 18.8-million-sample SFT set that this repository is a subset of [1]. No adoption by any other named model or recipe was found in the sources read for this card.

**Introduced by**: [1] (Codefuse and Ling Team), plus the dataset card itself [2].

## Quality

- The dataset card describes the synthesis pipeline: each seed is broken into key points and explanations, an LLM expands those into seven divergent key-point combinations, ten questions are generated per combination, an LLM generates the answers, and the resulting pairs then pass through rule-based filtering, detoxification, decontamination, quality checking, and ablation selection [2].
- The paper's general SFT data-cleaning description states the pipeline includes rule-based anomaly detection, cleansing, detoxification, quality inspection, and ablation study, and, for the broader data pipeline the SFT stage follows, a composite quality score below a threshold (its example: 85 out of 100) sends data back for reprocessing [1].
- No source states a measured contamination rate, duplicate rate, or inter-annotator/inter-model agreement figure for this specific released repository; none is invented here.
- As external evidence the paper's own benchmark table for the model trained on the full SFT set (of which this repository is a subset) shows Ling-Coder-Lite (16.8B total / 2.75B active parameters) scoring 88.41 Pass@1 on HumanEval and 78.97 average EvalPlus, ahead of the comparable-size Qwen2.5-Coder-7B-Instruct (87.20 HumanEval, 78.72 EvalPlus avg.) and other open baselines of similar parameter count [1].

## Where it came from

Built by the Codefuse/Ling Team at InclusionAI. The dataset card describes the construction method as similar to OSS-Instruct and Evol-Instruct: LLMs first extract key points and explanations from each code-related seed, then expand those key points into seven divergent key-point combinations, generate 10 programming questions per combination, and generate answers to each question with LLMs; the resulting question/answer pairs then pass through rule-based filtering, detoxification, decontamination, quality checking, and ablation selection to produce the released dataset [2]. The paper's fuller description of the SFT-stage pipeline (applied to the larger 18.8-million-sample set this repository is drawn from) adds that the data undergoes near-deduplication, toxic-content removal, and a three-part quality assessment (rule-based verification, LLM-based scoring, and manual scoring) before being accepted [1].
