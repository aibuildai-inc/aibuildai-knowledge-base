# openbmb/UltraInteract_sft

288,579 single-turn instruction/response rows for math, coding, and logic reasoning, each a "correct action" pulled from a preference tree built over 86k instructions.

**openbmb/UltraInteract_sft** is the supervised-fine-tuning slice of UltraInteract, the alignment dataset introduced in "Advancing LLM Reasoning Generalists with Preference Trees" [1]. For each of 86k instructions drawn from twelve established math, coding, and logic datasets, the authors grew a preference tree whose nodes are reasoning-chain "actions" generated by an actor model (GPT-3.5 Turbo by default) interacting with a code/search environment and critiqued by GPT-4; a node is correct when it reaches the ground-truth answer [1]. This repository serves only the correct nodes/leaves, flattened to one `instruction`/`response` pair per row, dropping interaction history - the multi-turn pairwise data lives in the sibling `UltraInteract_pair` repository instead [1][2]. **A caution on the math slice: the paper's own held-out evaluation reuses the MATH benchmark, which is also one of this dataset's training sources (70,671 rows carry `dataset`="MATH"), and the paper states plainly that "except for MATH, none of the training datasets is used in our evaluation" [1]; see Hold out below.** It lives at https://huggingface.co/datasets/openbmb/UltraInteract_sft .

**Use it for**: SFT on instruction/response pairs for math, code, and logic reasoning - maps to the SFT method card's plain instruction-response format (no chat turns; `instruction` and `response` are single strings, not message lists). Not preference or reward-model data - that shape is the separate `UltraInteract_pair` repository [2].

**Licence**: MIT (`cardData.license` is `"mit"`, tag `license:mit`), ungated (`"gated": false`, `"private": false`) [3]. The one catch: the MIT grant covers OpenBMB's compiled instructions/responses; the underlying instructions are drawn from twelve third-party source datasets (codecontest, TACO, MATH, GSM8K, MathQA, and others, per the `dataset` column) whose own licences are not restated in this card [1][4].

**Shape**: 288,579 rows, one config (`default`), one split (`train`); six string columns (`task`, `dataset`, `instruction`, `response`, `id`, `parent_id`) [3][5].

**Hold out**: the 70,671 rows where `dataset`="MATH", when evaluating a model trained on this data against the MATH benchmark - the origin paper names MATH as the sole training source it also evaluates on, decontaminated only by 8-gram exact matching against the MATH test set, not held out entirely [1]. This does not extend to AIME2025-style benchmarks: MATH's own competition-sourced problems and this April 2024 release both predate the 2025 AIME competitions that such benchmarks draw on, so no row-level overlap with a 2025 competition is plausible on chronology alone [1][6][7]. GSM8K (33,089 rows), the other math source in this repository, is not named as an evaluation-set overlap by the paper [1].

**Origin**: built and released by OpenBMB; responses are LLM-generated (GPT-3.5 Turbo as the default actor model producing the correct action, checked against ground-truth answers, with GPT-4 as critique model), not human-written [1]. Hub API at the check date: `downloads` 1,671, `downloadsAllTime` 100,201, `likes` 128 [3].

**Trained-on-by**: the origin paper's own Eurus-7B-SFT and Eurus-70B-SFT models, fine-tuned from Mistral-7B and CodeLLaMA-70B respectively on "all correct actions (287K) in UltraInteract" [1]; the Hub's own dataset-filtered model list also surfaces community fine-tunes built on this repository, including `aigcode/AIGCodeGeek-DS-6.7B` and several `JayHyeon/Qwen2.5-0.5B_ultrainteract_sft_*` checkpoints [8].

**Introduced by**: [1] (Yuan et al.).

## Quality

- No source states a measured contamination or duplicate rate for this SFT release as a whole. The one contamination note the origin paper does give is scoped, not general: an appendix says the authors "conduct careful decontamination," using exact substring matching against LeetCode and 8-gram exact matching for other sources against "test sets of the same task," and separately states MATH is the sole training source also used in evaluation [1] - see Hold out.
- Responses are model-generated, not human-written: GPT-3.5 Turbo (or, per the paper's Appendix A.2, one of Mistral-7B-Instruct-v0.2, DeepSeek-Coder-33B-Instruct, Mixtral-8x7B-Instruct, or DeepSeek-LLM-67B-Chat for incorrect actions not served here) produced the action, checked against a ground-truth answer, with GPT-4 producing critique text fed back into the tree [1]. No independent annotator-agreement or human-quality-rating figure is stated for the correct-action rows this repository serves.
- The paper's own ablation isolates what this dataset contributes to downstream SFT quality: on Eurus-7B-SFT, training on the full data mixture (UltraInteract plus UltraChat/ShareGPT/OpenOrca) scores 53.6 average across Coding/Math/BBH/IFEval, versus 44.0 when the generated actions are replaced by original ground-truth rationales, 37.0 for open-source instruction data alone, and 47.7 for UltraInteract alone [1].
- No fetch-before-training step is required: `instruction` and `response` are served as complete strings, not references to an external corpus.

## Neighbors

- `openbmb/UltraInteract_pair` - the same builder's preference-pair release over the same instruction pool: 219,522 rows with `trajectory`, `chosen`, `rejected` columns instead of a single `response`, covering "all multi-turn trajectory pairs" the paper used for DPO/KTO/NCA and reward-model training [1][11]. Prefer this repository for SFT and `UltraInteract_pair` for preference optimization; they are complementary, not overlapping in row shape.
- `RLHFlow/UltraInteract-filtered-standard` - a third-party dataset carrying UltraInteract in its name, with 161,927 rows of `chosen`/`rejected` message-list columns [12]; its README states only this schema and row count, with no description of which UltraInteract repository it was built from, so its lineage to either `UltraInteract_sft` or `UltraInteract_pair` is not stated [12]. Its chosen/rejected shape makes it a preference dataset, not SFT-shaped like this repository.
- `pharaouk/UltraInteract_sft` - an unofficial mirror of this exact repository, found by Hub search but with far lower usage (40 downloads, 2 likes versus 1,671/128 here at the check date) [13]; prefer the OpenBMB original.

## Where it came from

Built and released by OpenBMB. The authors pooled instructions from twelve established datasets spanning math, coding, and logic tasks, then for each instruction grew a "preference tree": an actor model (GPT-3.5 Turbo by default, or one of four alternative open models for incorrect-action sampling) generates a step-by-step action, a Python-interpreter or Wikipedia-search environment returns observations, and GPT-4 supplies critique text referencing a ground-truth answer, across up to several turns and multiple sampled branches per node [1]. This repository serves the resulting correct actions and correct-leaf trajectories, discarding interaction history, as flat `instruction`/`response` pairs for SFT; the same tree's paired correct/incorrect branches feed the separate `UltraInteract_pair` preference release [1][2].

## Appendix: screening record

### Screening verdict

Usable for SFT, with a scoped math-contamination caution rather than a blocking flag. The dataset serves flat instruction/response rows generated and self-checked against ground truth, not human-written [1]; the only overlap the origin paper itself admits is between the MATH-sourced training rows and its own MATH evaluation set, which the card resolves above by naming the 70,671 affected rows and pointing at the paper's stated (8-gram-only) decontamination [1]. The screening row's flag names a specific downstream benchmark, AIME2025, and a one-hop chain from `dataset`="MATH" to AIME/AMC sourcing; this card finds that chain does not resolve to an actual overlap, because AIME2025's problems postdate both the MATH corpus and this April 2024 release by chronology alone [1][6][7].

### The screening row

The row's own note [in the shortlist row supplied with this request]: "86k instructions expanded into preference trees with model reasoning chains, environment observations and critique turns for math, code and logic (Eurus). Single `train` split." Its flag: "rule-risk: aime2025 - One hop: `dataset` field shows MATH 70,671 rows; Hendrycks MATH problems are drawn from AMC/AIME competitions; gsm8k rows probe clean."
