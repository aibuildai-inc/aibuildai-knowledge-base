# nvidia/OpenCodeInstruct

5 million synthetic Python coding question-answer pairs, each carrying generated unit tests, execution pass/fail results, and an LLM-judge quality assessment - NVIDIA's largest published open-access code instruction-tuning set.

**OpenCodeInstruct** was built by NVIDIA and introduced in "OpenCodeInstruct: A Large-scale Instruction Tuning Dataset for Code LLMs" [1] as data for supervised fine-tuning (SFT) of code-generation models. Each sample pairs a coding question with a solution, ten generated assertion-style unit tests, the pass/fail execution result of the solution against those tests, and an LLM-as-judge score covering requirement conformance, logical correctness, and edge-case handling [1][2]. Instructions were produced by the Genetic-Instruct framework, which combines a mutation operation (mimicking Evol-Instruct) and a crossover operation (mimicking Self-Instruct) over two seed pools - 25,443 competitive-programming questions from TACO, and 1.43 million OSS-Instruct-generated instructions seeded from GitHub Python functions [1]. It lives at https://huggingface.co/datasets/nvidia/OpenCodeInstruct . **The Hub datasets-server endpoint currently serves and estimates statistics from only 1,400,000 of the 5,000,000 rows the dataset card declares (`partial: true`); row and byte figures below are marked live-partial where they come from that endpoint, and declared where they come from the card's own YAML metadata** [3][4].

**Use it for**: reasoning-trace-free coding SFT (the `input`/`output` pair is a direct instruction-response chat turn) or, using the bundled unit tests and execution status, reward-model or RL data with execution feedback; not multi-turn dialogue. Maps to the SFT method card's chat-format loading, feeding `input` as prompt and `output` as target. Restriction: this is not the reasoning-CoT sibling described below - `output` here is direct code, not a chain-of-thought trace.

**Licence**: CC BY 4.0 (`cardData.license` is `cc-by-4.0`; the README's own governing-terms clause names the Creative Commons Attribution 4.0 International License), ungated (`"gated": false`, `"private": false`) [3][2]. The README additionally states the dataset is cleared for both commercial and non-commercial use [2]; no other licence (e.g. MIT) is stated in the card body - a naive substring search for "mit" also matches the word "submit" in the security-reporting link, which is not a licence mention.

**Shape**: declared on the card: one config (`train`), one split (`train`), 5,000,000 rows, 9 string columns [2]. Live-partial via datasets-server at the pinned commit: only 1,400,000 rows scanned/served (`partial: true`), estimated 4,969,570 rows for the full file set [4].

**Hold out**: not stated as a required split - the dataset ships a single `train` split with no held-out portion [2][4]. The origin paper states it ran n-gram-based decontamination to remove overlap between the generated instructions and its evaluation benchmarks (HumanEval, MBPP, LiveCodeBench, BigCodeBench) before the response-generation stage [1]; no source states a residual contamination rate.

**Origin**: built by NVIDIA; solutions, unit tests, and quality judgments were all generated by Qwen2.5-Coder-32B-Instruct, with Qwen2.5-32B-Instruct used to generate OSS-Instruct seed instructions and skill-tag metadata - the Hub card itself does not name these models, only the paper does [1]. Hub API at the check date: `downloads` 14,172 (`downloadsAllTime` 72,660), `likes` 108 [3].

**Trained-on-by**: the origin paper's own SFT runs - LLaMA-3.2 (1B, 3B), LLaMA-3.1-8B, and Qwen2.5-Coder (1.5B, 3B, 7B) - each finetuned on OpenCodeInstruct and benchmarked against their instruction-tuned base checkpoints [1]. No other adoption found.

**Introduced by**: [1] (Ahmad et al.).

## Quality

- The paper reports its unit-test pass-rate distribution as bimodal, skewed toward both 1.0 and 0.0, and attributes the high pass-rate mass to self-consistency bias in the generating model and the high failure mass to incorrect test cases or non-executable solutions (e.g. timeouts) [1].
- An ablation (Table 4) finetuned Qwen2.5-Coder-7B on four 500k-row selections from OpenCodeInstruct: random selection (72.4% mean unit-test pass rate, HumanEval 82.9/77.8 base/plus), rows whose unit tests all failed ("UTE Failures", 0% pass rate, HumanEval 80.0/75.3 - the worst of the four), rows whose unit tests all passed ("UTE Passes", 100% pass rate, HumanEval 83.1/78.4), and rows with a perfect LLM-judge score of 5.0 (77.4% pass rate, HumanEval 84.8/80.5 - the best of the four) [1]. The judge-filtered subset outperforms both the unfiltered random draw and the pass/fail-execution-filtered subsets, and the all-failing subset is the clear floor - the gap that shows the bundled execution and judge metadata are worth filtering on, not just descriptive.
- Filtering removed instructions containing Python code snippets, which the paper says were noisy and mostly artifacts of one Evol-Instruct code-repair/refactoring task [1]; after this and n-gram deduplication/decontamination, ~5 million of the ~9 million Genetic-Instruct-generated instructions were retained for response generation [1].
- No source states an annotator-agreement figure (labels are LLM-generated, not human) or a measured duplicate-row rate for the released set.

## Where it came from

NVIDIA built the dataset between January and March 2025 [2], collecting two seed pools in parallel: 25,443 algorithmic questions drawn from TACO's competitive-programming problem sets (AIZU, AtCoder, CodeChef, CodeForces, Codewars, GeeksForGeeks, HackerEarth, HackerRank, Kattis, LeetCode), and 1.43 million "generic" instructions produced by prompting Qwen2.5-32B-Instruct with the OSS-Instruct method over Python functions with docstrings extracted from GitHub (type-checked with Pyright, filtered for documentation quality, deduplicated, and benchmark items removed) [1]. From these seeds, the Genetic-Instruct framework's mutation (Evol-Instruct-style) and crossover (Self-Instruct-style) operations generated roughly 9 million candidate instructions in a single generation pass; instructions containing noisy embedded Python code, near-duplicates, and any n-gram overlap with the evaluation benchmarks were removed, leaving about 5 million retained questions [1]. For each retained question, Qwen2.5-Coder-32B-Instruct generated the code solution, ten assertion-style unit tests (following the methodology of a companion NVIDIA paper), and an LLM-as-judge assessment of requirement conformance, logical correctness, and edge-case handling; the generated tests were then executed against the generated solutions and the pass/fail results stored alongside the pass-rate metadata [1].
