# HuggingFaceH4/ultrachat_200k

515,311 multi-turn ChatGPT-written dialogues (both the human and the assistant side), split across an SFT pair of splits and a generation-ranking pair of splits, released as a heavily filtered ~200k-example subset of the original UltraChat corpus.

**HuggingFaceH4/ultrachat_200k** is a Hugging Face H4 team release built from UltraChat, a large-scale multi-turn instructional-conversation dataset introduced in "Enhancing Chat Language Models by Scaling High-quality Instructional Conversations" as containing 1.5 million dialogues [1], and described by the Zephyr technical report as a 1.47M-dialogue self-refinement dataset generated by prompting `gpt-3.5-turbo` over 30 topics and 20 text-material types [2], with two separate ChatGPT Turbo API calls used per turn - one playing the user role to generate queries, the other generating the response [3]. The dataset card states it applied truecasing (the card estimates around 5% of the original had grammatical errors) and removed assistant turns that refuse to have opinions or emotions even on fact-based prompts, cutting the corpus down for faster supervised fine-tuning [4]. It supplies two dialogue-shape pairs of splits: `train_sft`/`test_sft` for supervised fine-tuning, and `train_gen`/`test_gen`, described by the card as for "Generation ranking ... via techniques like rejection sampling or PPO" [4]. It lives at https://huggingface.co/datasets/HuggingFaceH4/ultrachat_200k .

**Use it for**: SFT chat training on `train_sft`/`test_sft`, where every row ends on a completed assistant turn ready to train on directly. The `train_gen`/`test_gen` rows instead end on a user turn with no assistant reply, matching the card's stated generation-ranking use (rejection sampling or PPO rollouts, not direct SFT) [4]; this maps to the SFT method card only for the `_sft` splits. Format is HuggingFaceH4's own OpenAI-style `messages` list of `{content, role}` structs, already usable in a standard chat SFT collator for the `_sft` splits.

**Licence**: MIT (`cardData.license` is `"mit"`; repo tag `license:mit`) [5]. The one catch: this dataset carries no restriction of its own in the card beyond the intended-use split between the sft and gen splits described above [4][5].

**Shape**: 515,311 rows in one config (`default`), four splits: `train_sft` 207,865, `test_sft` 23,110, `train_gen` 256,032, `test_gen` 28,304; three columns (`prompt`, `prompt_id`, `messages`) [4][6][7].

**Hold out**: `test_sft` (23,110 rows) and `test_gen` (28,304 rows); train on `train_sft` and `train_gen`. No source flags any overlap with a named evaluation benchmark beyond the dataset's own held-out test splits.

**Origin**: built by the Hugging Face H4 team from UltraChat; both sides of every dialogue are ChatGPT (`gpt-3.5-turbo`) generations, not human-written [1][2][4]. Hub API at the check date: `downloads` 72,044, `downloadsAllTime` 1,126,037, `likes` 866 [5][8].

**Trained-on-by**: Zephyr-7B-β, whose model card states it "was initially fine-tuned on a filtered and preprocessed" version of UltraChat before DPO alignment on UltraFeedback [9]; the Zephyr technical report gives the filtering recipe (truecasing plus helpfulness filters) that produced "approximately 200k examples" and states the team made the pre-processed dataset available on the Hub [2] - this repository is that release.

**Introduced by**: no dedicated paper for the 200k filtered release itself; the dataset card [4] credits the original UltraChat corpus to [1], and the filtering recipe used to derive this 200k subset is described in the Zephyr technical report [2].

`prompt` holds the first user turn's text and `prompt_id` a hex digest of it. Across the 128 rows returned by the first-rows endpoint for all four splits (28 `train_sft`, 25 `test_sft`, 35 `train_gen`, 40 `test_gen`), `prompt` matched the first element of `messages` in 117 rows (91%); the 11 mismatches (2 `train_sft`, 2 `test_sft`, 3 `train_gen`, 4 `test_gen`) were mid-string capitalization differences, not a different turn (see A row, below) [10]. No source states token-length or sequence-length statistics for this release; the card gives only the row counts above and per-split byte sizes: `train_sft` 1,397,058,554 bytes, `test_sft` 154,695,659, `train_gen` 1,347,396,812, `test_gen` 148,276,089, for a 1,624,049,723-byte total download and 3,047,427,114 bytes decoded, as declared in `cardData.dataset_info` [4]. datasets-server reports a slightly different total decoded size, 3,007,301,125 bytes in memory, for the same 1,624,049,723-byte download [6].

## Quality

- The card's only stated quality actions are the two filtering steps in the opening paragraph: truecasing (with the roughly-5% estimate) and removal of assistant non-opinion refusals [4]. No measured post-filter error rate, duplicate rate, or annotator-agreement figure is stated for this release; none is invented here.
- The Zephyr technical report adds the underlying reason for filtering: dSFT trained directly on the whole 1.47M-dialogue UltraChat corpus produced a chat model with "a tendency to respond with incorrect capitalization" and a habit of prefacing answers with disclaimers like "I don't have personal experiences" even on straightforward questions, which the truecasing and helpfulness filters were built to fix [2].
- No fetch-to-recover step applies to any split here: `messages` is a fully materialized list of role/content turns served directly by the config, not a pointer requiring an external join.

## Load it

Train on `train_sft` and `train_gen`, hold out `test_sft` and `test_gen`, and pin the revision this card's numbers were read at (the Hub API's `sha` for `main` at the check date; the repo was last modified 2024-10-16) [5]:

```python
import datasets

REV = "8049631c405ae6576f93f445c6b8166f76f5505a"  # main at the check date
train_sft = datasets.load_dataset("HuggingFaceH4/ultrachat_200k", revision=REV, split="train_sft")  # 207,865 rows
test_sft = datasets.load_dataset("HuggingFaceH4/ultrachat_200k", revision=REV, split="test_sft")    # 23,110 rows - hold out
train_gen = datasets.load_dataset("HuggingFaceH4/ultrachat_200k", revision=REV, split="train_gen")  # 256,032 rows
test_gen = datasets.load_dataset("HuggingFaceH4/ultrachat_200k", revision=REV, split="test_gen")    # 28,304 rows - hold out
```

**Trap**: the `_sft` and `_gen` splits are not interchangeable despite sharing all three columns and dtypes. Every sampled `_sft` row (28 of `train_sft`, 25 of `test_sft`) ends on a completed `assistant` turn, ready to train on as-is; every sampled `_gen` row (35 of `train_gen`, 40 of `test_gen`) ends on a `user` turn with no assistant reply, matching the card's stated generation-ranking use rather than SFT [4][10]. A collator built for `_sft` will silently train on an incomplete, prompt-only conversation if pointed at `_gen`.

## Neighbors

`stingning/ultrachat`, the original repository the card names as the source it filtered [4], now redirects Hub API and README requests to `openbmb/UltraChat` [11]. That repository's own card describes an "open-source, large-scale, and multi-round dialogue data powered by Turbo APIs" of unfiltered dialogues, `size_categories: 1M<n<10M`, stored as ten `train_*.jsonl` files rather than this repository's `default` parquet config [3] - the pre-filter pool this 200k release was drawn from, not a substitute for it. The Zephyr technical report states the H4 team also released the DPO-stage dataset, UltraFeedback (`openbmb/UltraFeedback`, 64k prompts with four GPT-4-scored completions each), as a separate, non-overlapping resource for the alignment stage that follows SFT on this dataset [2][9]. No other same-builder re-release, cleaned variant, or binarized form of this specific 200k filtered corpus was found.

## Where it came from

Built by the Hugging Face H4 team from UltraChat, itself generated by prompting `gpt-3.5-turbo` over 30 topics and 20 text-material types, as described in the corpus's origin paper [1][2], using two separate ChatGPT Turbo API calls per turn - one playing the user role to generate queries, the other generating the response [3]. The H4 team's dataset card states they took a subset of this original corpus, applied truecasing to fix grammatical errors the card estimates at around 5% of the data, and removed dialogues where the assistant deflects with phrases like "I do not have emotions" or "I don't have opinions" even on fact-based prompts [4]. The Zephyr technical report, from the same team, gives the resulting size as approximately 200k examples and states the team made this pre-processed dataset available on the Hub [2].
