# Magpie-Align/Magpie-Pro-MT-300K-v0.1

300,000 fully synthetic, two-turn instruction-response conversations, extended from a filtered 300K single-turn Magpie-Pro selection by generating a second question and answer for each.

**Magpie-Align/Magpie-Pro-MT-300K-v0.1** was built by the Magpie-Align team and introduced by "Magpie: Alignment Data Synthesis from Scratch by Prompting Aligned LLMs with Nothing" [1]. Magpie's core method prompts an already-aligned instruction model (here Llama-3-70B-Instruct) with only its own left-side chat template up to the user-turn slot, letting the model self-generate a user instruction, and then completes the same model's response to that instruction, with no human prompts and no external LLM API calls [1]. This release takes the paper's filtered 300K single-turn Magpie-Pro subset and extends every instance with a synthesized second question and answer, using the same generating model conditioned on the first turn's transcript [1][2]. **The dataset card explicitly warns against combining this release with `Magpie-Pro-300K-Filtered` in the same fine-tuning run, since the two datasets are largely the same in their first turn** [2]. It lives at https://huggingface.co/datasets/Magpie-Align/Magpie-Pro-MT-300K-v0.1 .

**Use it for**: multi-turn SFT chat data - each row is a two-turn dialogue meant to fine-tune a base or instruct model on instruction-following, not preference optimization; **do not mix with `Magpie-Pro-300K-Filtered` in the same SFT run** [2]. The data maps to the SFT method card's chat format: the `conversations` column already holds the ShareGPT-style `{"from": ..., "value": ...}` turn list that most SFT trainers expect directly, while `input1`/`output1`/`input2`/`output2` hold the same two turns as flat strings for pipelines that want them unmerged [2][5].

**Licence**: tagged `license: llama3` in the dataset card's front matter (not an SPDX id; this is Hugging Face's tag for the Meta Llama 3 Community License), repo is ungated (`"gated": false`) [2][3]. The one catch: no body text in the card elaborates the license's terms beyond the tag itself, and no source states that a specific commercial-use or attribution clause applies to this dataset's rows [2][3].

**Shape**: 300,000 rows, one config (`default`), one split (`train`) [2][4].

**Hold out**: nothing found. Neither the dataset card nor the origin paper states any decontamination step, benchmark-overlap check, or held-out split for this release, and the paper's own multi-turn ablation (Table 8) evaluates fine-tuned models on AlpacaEval 2 and Arena-Hard without mentioning removal of overlapping prompts [1][2].

**Origin**: built by Magpie-Align; every field (instructions and responses in both turns) is generated by `meta-llama/Meta-Llama-3-70B-Instruct`, with no human-written or human-labeled content [1][2][6]. Hub API as of the check date: 1,013 downloads, 15,974 all-time downloads, 32 likes [3].

**Trained-on-by**: the dataset card itself links a model the Magpie-Align team fine-tuned on this exact release, `Llama-3-8B-Magpie-Pro-MT-SFT-v0.1` [2]. No adoption by parties outside Magpie-Align was found in the sources fetched for this card.

**Introduced by**: [1] (Xu et al., "Magpie: Alignment Data Synthesis from Scratch by Prompting Aligned LLMs with Nothing").

## Quality

- The card's stated filter, applied before the multi-turn extension, selected the underlying 300K single-turn instances by: input quality "good" or better, input difficulty "easy" or better, an "Instruction Reward" of -12 or above, removal of repetitive or incomplete instructions (e.g., ending in ":"), then choosing the 300K instances with the longest responses [2].
- The paper defines the reward-based filter as a "reward difference" - the score a reward model (FsfairX-LLaMA3-RM-v0.1) assigns the dataset's own response minus the score it assigns a response elicited from the un-aligned Llama-3 base model via URIAL for the same instruction; a positive value indicates the dataset's response is judged higher quality than the base model's [1].
- The paper's own multi-turn ablation (Table 8) compares this MT release against its single-turn counterpart on models fine-tuned from a Llama-3-8B base, reporting AlpacaEval-2 length-controlled (LC) win rate against two separate baseline models plus Arena-Hard win rate against a GPT-4 (0314) baseline: against a GPT-4-Turbo (1106) baseline on AlpacaEval-2, Magpie-Pro MT scores 24.21 LC versus 25.15 for single-turn; against a Llama-3-8B-Instruct baseline on the same benchmark, MT scores 52.92 LC versus 50.52 for single-turn; and on Arena-Hard, MT scores 20.4% win rate versus 18.9% for single-turn - the paper reports the multi-turn extension raises the Llama-3-8B-Instruct-baseline AlpacaEval-2 score and the Arena-Hard score while slightly lowering the GPT-4-Turbo-baseline AlpacaEval-2 score [1].
- No source states a measured duplicate-row rate, contamination rate, or human-annotator agreement figure for this release; none is invented here.

## Where it came from

Built by Magpie-Align, released alongside "Magpie: Alignment Data Synthesis from Scratch by Prompting Aligned LLMs with Nothing" [1]. The paper's method feeds an aligned model only the pre-query portion of its own chat template, so the model auto-regressively completes a plausible user instruction, then the same model is prompted to answer that instruction, yielding an instruction-response pair with no human or third-party LLM involvement [1]. This release applies the paper's multi-turn extension (Appendix A.1): starting from the paper's filtered 300K single-turn Magpie-Pro selection, each row's first turn is kept, the pre-query template is appended to the end of the prior turn's full prompt, and the same generating model is prompted again to produce a second instruction and response, with a system prompt added to keep the model in the user role for the second turn [1]. The generating model throughout is Llama-3-70B-Instruct [1][2].
