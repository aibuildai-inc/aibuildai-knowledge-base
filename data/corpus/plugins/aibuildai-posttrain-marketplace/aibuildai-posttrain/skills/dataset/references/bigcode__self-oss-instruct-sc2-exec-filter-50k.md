# bigcode/self-oss-instruct-sc2-exec-filter-50k

50,661 single-turn Python instruction/response pairs, self-generated and self-validated by StarCoder2-15B, where every kept response passed execution against a self-generated test in a sandbox.

**bigcode/self-oss-instruct-sc2-exec-filter-50k** is BigCode's final SFT set for StarCoder2-15B-Instruct-v0.1, produced by the SelfCodeAlign pipeline introduced in "SelfCodeAlign: Self-Alignment for Code Generation" [1] and first described for this StarCoder2 run in the Hugging Face blog post "StarCoder2-Instruct: Fully Transparent and Permissive Self-Alignment for Code Generation" [2]. The pipeline mines well-documented Python functions from The Stack v1 as seeds, has StarCoder2-15B self-generate coding concepts and an instruction from each seed, then self-generate ten (response, test) samples per instruction and keeps only responses whose test passed in a sandboxed execution, finally deduplicating to one passing response per unique instruction [2]. The dataset's own card states its seed Python functions are derived from the MultiPL-T pipeline introduced in "Knowledge Transfer from High-Resource to Low-Resource Programming Languages for Code LLMs" [3][12], and the blog similarly describes the seed-filtering process as highly inspired by MultiPL-T's data-collection method [2]. It lives at https://huggingface.co/datasets/bigcode/self-oss-instruct-sc2-exec-filter-50k .

**The builder decontaminated the underlying seed functions against the benchmarks it evaluates on (exact substring match of both solution and prompt) before generating instructions from them [4], so no additional holdout is stated as required.**

**Use it for**: single-turn SFT on Python code instructions, feeding an `instruction` -> `response` pair per row; this is not a preference-pair or reasoning-trace format, and the `response` field already interleaves natural-language explanation with a code block and self-generated tests, matching the reasoning-plus-code-plus-tests shape the pipeline targets [2]. See the SFT method card.

**Licence**: `odc-by` (Open Data Commons Attribution License), ungated, `"gated": false` [5]. The one catch: this only covers the dataset repository itself - the sibling model `bigcode/starcoder2-15b-instruct-v0.1` trained on it is released under a separate `bigcode-openrail-m` licence [6].

**Shape**: 50,661 rows, one config (`default`), one split (`train`) [7][8].

**Hold out**: nothing named by any source read for this card. The builder states it decontaminated the seed pool against its own evaluation benchmarks by exact substring match before instructions or responses were generated [4]; no source flags residual overlap with any external eval set.

**Origin**: built by the BigCode project; both the instructions and the responses are self-generated by StarCoder2-15B, with the response-selection step being a sandboxed test-execution filter rather than a human or external-model judgment [2]. Hub API at the check date: `downloads` 11,173, `downloadsAllTime` 61,081, `likes` 106 [5].

**Trained-on-by**: `bigcode/starcoder2-15b-instruct-v0.1`, whose model card lists this dataset as its training data [6]; downstream quantizations of that model (e.g. `bartowski/starcoder2-15b-instruct-v0.1-GGUF`, `mlx-community/starcoder2-15b-instruct-v0.1-4bit`) inherit the same training data through that base model [9]. Separately, `ibm-granite/granite-3b-code-instruct-128k` and `ibm-granite/granite-8b-code-instruct-128k` list it as one of nine training datasets [10], and `HuggingFaceTB/SmolLM-1.7B-Instruct` (and its 360M/135M siblings) list it as one of four training datasets [11].

**Introduced by**: [1] (Wei et al., SelfCodeAlign), with the StarCoder2-specific pipeline and this exact dataset first described in the BigCode blog post [2].

## Quality

- Every response in this release passed execution against a self-generated test in a sandbox; the pipeline sampled 10 (response, test) pairs per instruction across 238k instructions (2.4M samples total), of which 500k passed, and one passing response per instruction was kept, then deduplicated down to the 50,661 rows here [2].
- The seed pool (five million Python functions with docstrings from The Stack v1) was filtered to 250k functions by Pyright static type-checking, exact-substring decontamination against the benchmarks evaluated on, StarCoder2-15B-as-judge docstring-quality filtering, and MinHash/LSH near-deduplication at a 0.5 Jaccard threshold [2].
- The paper's own ablation isolates the effect of execution filtering: on a matched 15.6k-instruction subset, pairing each instruction with a response that had actually passed its test scored 65.2 pass@1 on HumanEval+, against 61.6 for a random (unfiltered) response and 57.9 for a response that was known to have failed its test [1].
- The StarCoder2-15B-Instruct model trained on this exact dataset scored 72.6 on HumanEval, ahead of CodeLlama-70B-Instruct's 72.0, despite being trained purely on this self-generated, non-distilled data [2].
- No source states an annotator-agreement figure (there is no human annotation) or a measured duplicate rate for the final 50,661-row set beyond the near-dedup step described above.

## Where it came from

Built by the BigCode project as the SFT data for `bigcode/starcoder2-15b-instruct-v0.1` [6]. The pipeline: extract well-documented Python functions from The Stack v1 as seeds, using a method the dataset's own card says derives these seed functions from the MultiPL-T pipeline [3][12] and that the blog describes as highly inspired by MultiPL-T's data-collection method [2]; filter the seeds by static type-checking, benchmark decontamination, docstring-quality judging, and near-dedup, to get 250k seed functions [2]; have StarCoder2-15B self-generate concepts and then an instruction from each seed, yielding 238k instructions [2]; have StarCoder2-15B self-generate 10 (natural-language response, test) samples per instruction at temperature 0.7 (2.4M samples total), execute each test in a sandbox, and keep one randomly chosen passing response per instruction, of which 500k samples passed [2]; deduplicate the resulting instruction/response pairs to reach the 50,661 rows in this release [6]. Both the instructions and the responses are generated by StarCoder2-15B itself, with no distillation from a larger proprietary model and no human annotation [1][2].
