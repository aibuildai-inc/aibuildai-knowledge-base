# blue-blues/medical_cot

403,269 single-turn medical question/answer rows - a system prompt, a question, and a long chain-of-thought response - built by merging multiple-choice exam questions with yes/no biomedical-abstract questions.

**blue-blues/medical_cot** is a Hugging Face dataset whose card describes it as a collection of medical questions and detailed answers meant for training and evaluating medical question-answering systems, with each row presenting a clinical scenario or biomedical question paired with a detailed explanation [1]. It carries no origin paper. Reading rows across the full split shows the question field is not one template: it blends three distinct exam/abstract sources behind a shared instructional wrapper, and every sampled row's question text matches only the *train* portion of its source, never a held-out benchmark split [5][6][7][8]. **In every one of 900 rows read across the full split (offsets spanning row 0 to row 403,268), the multiple-choice items match rows in MedMCQA's or MedQA-USMLE's train splits and the yes/no items match PubMedQA's train-only `pqa_artificial` config - never MedMCQA's test (6,150 rows) or validation (4,183 rows), MedQA's test (1,273 rows), or PubMedQA's expert-labeled `pqa_labeled` set (1,000 rows) [5][6][7][8]. That is evidence from a sample, not an exhaustive check of all 403,269 rows: hold out those four benchmark splits before scoring a run against them.** It lives at https://huggingface.co/datasets/blue-blues/medical_cot .

**Use it for**: reasoning-trace SFT - each row is a flat (system_prompt, question, response) instruction/answer pair, not a chat-turns list, so map it to a single system+user+assistant triple before training; see the SFT method card. The stated restriction above (decontaminate against MedMCQA/MedQA/PubMedQA's benchmark splits first) applies whenever those benchmarks are part of an evaluation plan.

**Licence**: apache-2.0 (repo `cardData.license` is `"apache-2.0"`, tag `license:apache-2.0`, ungated, not private) [2]. The catch: that label covers this repackaging only. The ~10,000-row MedQA-style segment textually matches the train split of GBaker/MedQA-USMLE-4-options, whose own Hub record tags itself `cc-by-4.0`, not apache-2.0 - a different, attribution-carrying licence than the one this repo carries [7].

**Shape**: one config, one split (`train`), 403,269 rows, 3 string columns (`system_prompt`, `question`, `response`); no split is held out inside this repo [3][4].

**Hold out**: this repo ships no held-out split of its own. Before scoring against MedMCQA's test (6,150) or validation (4,183), MedQA-USMLE's test (1,273), or PubMedQA's `pqa_labeled` (1,000), decontaminate against those - the 900 rows read here matched only the corresponding train-side sources, but the remaining rows were not checked [5][6][7][8].

**Origin**: built by the Hugging Face account `blue-blues`, contact `Blue@vaibhavgavade.com` in the card [1]; the multiple-choice questions are human-authored MedMCQA/MedQA-USMLE exam items and the yes/no questions are human-authored PubMedQA biomedical-abstract items, while the long chain-of-thought responses are machine-generated by a model the card does not name [1][5]. Hub API at the check date: `downloads` 180, `downloadsAllTime` 3,521, `likes` 6 [2].

**Trained-on-by**: none found - the Hub's models-by-dataset filter for `blue-blues/medical_cot` returns no results [9].

**Introduced by**: no paper - the dataset card [1].

## Quality

- **Three question templates, not one, laid out back-to-back rather than shuffled.** Reading single rows at offsets spaced across the whole split (roughly every 1,000-50,000 rows from 0 to 403,268) shows rows 0 through at least 182,000 follow a MedMCQA-style template ending "Question: ... \nOptions: A. ... B. ..."; rows from at least 184,000 through at least 192,000 follow a MedQA-USMLE clinical-vignette template ending "Question: ... \nChoices: A. ... B. ..."; and rows from at least 193,000 through the final row 403,268 follow a PubMedQA-style template, "Context: <abstract> ... Question: <question>?", answered yes or no in the response [5]. The boundaries were located by bisection between sampled offsets, not read exhaustively, so the exact switch-over rows are not pinned tighter than that; a 50-row sample at offset 182,000 still reads as MedMCQA-style, so the MedMCQA-to-MedQA switch falls somewhere between rows 182,000 and 184,000.
- **Overlap check against the sources' held-out splits.** 900 rows were read and their embedded question text compared against the source datasets' own served splits: 250 MedMCQA-style rows (offsets 0, 100,000, and 182,000 - 100, 100, and 50 rows) against MedMCQA's `train` (182,822), `test` (6,150), and `validation` (4,183) [6]; 250 MedQA-style rows (offsets 184,000-192,000, 50 rows each) against MedQA-USMLE's `train` (10,178) and `test` (1,273) [7]; and 400 PubMedQA-style rows (offsets 200,000-403,169, 50 rows each) against PubMedQA's `pqa_labeled` (1,000, the expert-labeled benchmark set), `pqa_artificial` (211,269, silver-standard, train-only), and `pqa_unlabeled` (61,249) [8]. Every one of the 900 matched a row in the corresponding source's `train` split (or, for PubMedQA, its train-only `pqa_artificial` config); none matched `test`, `validation`, or `pqa_labeled` [5][6][7][8].
- **Response format does not match the prompted format.** Every sampled `system_prompt` instructs the model to answer inside `<|begin_of_thought|>`/`<|end_of_thought|>` and `<|begin_of_solution|>`/`<|end_of_solution|>` tags [5]. Of 500 sampled responses (offsets 0, 100,000, 200,000, 300,000, 400,000, 100 rows each), 0 contain those tags; every sampled response is plain prose ending in a line such as "Answer: Yes." or a restated option letter [5].
- **The card's own data-format section is stale against the served schema.** The README lists a `choices` field as one of four columns [1], but the served schema has only three columns (`system_prompt`, `question`, `response`) [4]; the multiple-choice options are embedded inside the `question` string, not in a separate field.
- No source states a measured contamination rate, an annotation or review process for the generated responses, or a known-complaints list; none is invented here.
