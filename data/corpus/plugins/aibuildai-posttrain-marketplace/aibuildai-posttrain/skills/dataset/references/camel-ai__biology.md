# camel-ai/biology

20,000 GPT-4-generated biology problem-solution pairs, one train split, produced by a two-agent role-play pipeline over 25 topics.

**camel-ai/biology** is one of the CAMEL project's synthetic science datasets, released alongside "CAMEL: Communicative Agents for 'Mind' Exploration of Large Language Model Society," which proposes a role-playing framework where two chat agents cooperate autonomously under inception prompting to complete a task [1]. The dataset card states the 20K pairs were obtained using GPT-4 across 25 biology topics, 25 subtopics per topic, and 32 problems per topic/subtopic pair, with one agent (`role_1`, an assistant persona) posing the problem (`message_1`) and providing the solution (`message_2`) [2]. **The card's own gated-access consent notice says the dataset "may contain inaccuracies due to its artificial generation through ChatGPT" and restricts use to research purposes [2].** It lives at https://huggingface.co/datasets/camel-ai/biology .

**Use it for**: reasoning-trace / instruction SFT on a question-answer shape (`message_1` as the prompt, `message_2` as the target response) - the SFT method card - with the research-only restriction above in force. Not a preference-pair or reward-model dataset: there is no rejected/chosen side.

**Licence**: CC-BY-NC-4.0 (`cardData.license` is `"cc-by-nc-4.0"`) [2][3]. The repo's `gated` flag reads `false` in the Hub API despite the card carrying `extra_gated_prompt`/`extra_gated_fields` metadata, so no click-through gate currently blocks download [3]. The one catch: the card's gated-consent text limits use "solely for research purposes" [2].

**Shape**: 20,000 rows, one config (`default`), one split (`train`), five string columns [4][5].

**Hold out**: nothing. No source here states or implies overlap with any evaluation set; the card's only stated caveat is that GPT-4 generation may be factually inaccurate, not that the rows duplicate a benchmark [2].

**Origin**: built and released by the CAMEL-AI project; both the problem and the solution in every row are GPT-4 generations produced through the role-play pipeline, with no human authoring or verification step described in the card [1][2]. Hub API at the check date: `downloads` 12,199 (`downloadsAllTime` 40,946), `likes` 58 [3].

**Trained-on-by**: Weyaxi's Einstein-v6.1-Llama3-8B lists `camel-ai/biology` among its training datasets [6]. jondurbin's bagel series (e.g. `bagel-dpo-7b-v0.4`, `bagel-34b-v0.4`) lists it too [7]. The `openaccess-ai-collective/minotaur-13b` family also declares it as a training dataset [8].

**Introduced by**: [1] (Li et al.).

## Quality

- Every row is machine-generated: the card states the pairs were "obtained using gpt-4" and separately describes the generation as happening "through ChatGPT" in its gated-consent text - both terms appear only in the dataset's own README, with no distinction drawn between them there [2].
- The card's only stated quality caveat is the accuracy warning in the gated-consent prompt: users "acknowledge and agree to utilize it solely for research purposes, recognizing that the dataset may contain inaccuracies due to its artificial generation" [2]. A separate disclaimer at the foot of the card repeats that the data "was synthetically generated by GPT4 and might contain incorrect information," and that it is "there only for research purposes" [2].
- No source states a measured error rate, duplicate rate, or annotator-agreement figure; none is invented here.
- Of the first 68 served rows (offset 0, `train`), all carried `role_1` value `"Biologist_RoleType.ASSISTANT"` and `topic;` value `"Taxonomy"`, spanning 3 distinct topic/subtopic pairs - consistent with the card's stated per-subtopic block size of 32 problems, but this observation covers only the first block of topics, not the full 20,000-row split [9].

## Load it

The data ships as a single `biology.zip` file rather than a Hub-native Parquet layout the card documents loading through `hf_hub_download` [2]; `datasets.load_dataset` also works directly against the repo's converted Parquet. Pin the revision the shortlist's `commit` and this card's Origin and Licence figures were read at, matching the Hub API's `sha` for `main` at the check date (the repo was last modified 2023-05-23) [3] - this pin does not cover the Shape section's row/column/byte figures, which come from the unpinned `/size` and `/info` endpoints described above:

```python
import datasets

REV = "47548972e88339ce263dd4b3efe234cfebfbbd64"  # main at the check date
train = datasets.load_dataset("camel-ai/biology", revision=REV, split="train")  # 20,000 rows
```

**Trap**: the second column's key is `"topic;"`, not `"topic"` - code that does `row["topic"]` raises a `KeyError` against the served schema [5].

## Neighbors

CAMEL-AI released sibling science datasets built with the same 25-topics/25-subtopics/32-problems pipeline and the same CC-BY-NC-4.0 licence, each on its own topic and not overlapping this one in content: `camel-ai/chemistry` and `camel-ai/physics` (also 20K problem-solution pairs each) [10], and `camel-ai/math` (50K pairs, 25 topics x 25 subtopics x 80 problems) [10]. None of these duplicates biology's rows, so there is no dedup concern between them.

Reformatted re-releases of this exact biology corpus exist and should not be mixed with this one in the same training run if this one is already in use: `dim/camel_ai_biology` (20,000 rows, identical column names and dtypes: `role_1`, `topic;`, `sub_topic`, `message_1`, `message_2`, all string) [11][13], `mlfoundations-dev/camel-ai-biology` (20,000 rows, the same identical schema) [11][13], and `PJMixers/camel-ai_biology-ShareGPT` (20,000 rows, reshaped into a `conversations` message-list column alongside `sub_topic`, `topic`, and `role_1`) [11][12]. All three were read live at the check date and each reports 20,000 rows, matching this release's row count [11].

## Where it came from

Built and released by the CAMEL-AI project as one of several subject-area datasets generated with the role-playing agent framework introduced in the CAMEL paper, in which an assistant agent and a user agent cooperate under inception prompting to produce task-solving dialogues [1]. For this release, the card states the pipeline was run over 25 biology topics with 25 subtopics per topic and 32 generated problems per topic/subtopic pair, using GPT-4 to produce both the problem statement and its solution, with no human authoring or verification step described [2].
