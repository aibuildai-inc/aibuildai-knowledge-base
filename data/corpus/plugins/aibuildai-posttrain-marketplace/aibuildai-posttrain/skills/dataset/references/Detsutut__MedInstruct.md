# Detsutut/MedInstruct

A gated Hub mirror of MedInstruct, a 52k-example synthetic medical instruction-response dataset plus a 216-row clinician-authored evaluation set, both generated for the AlpaCare project.

**Detsutut/MedInstruct** is a re-upload, on a different Hub account, of the data released alongside "AlpaCare: Instruction-tuned Large Language Models for Medical Application" [1]: a supervised instruction-tuning set (`MedInstruct-52k`) whose instructions were generated by GPT-4 from a 167-item clinician-written seed set and whose responses were generated by GPT-3.5-turbo, together with a held-out clinician-authored evaluation set (`MedInstruct-test`) carrying reference answers from four separate models [1][2]. It lives at https://huggingface.co/datasets/Detsutut/MedInstruct . **The repository is gated with manual approval and sets no licence field on the Hub, but its two data files carry the identical git blob hashes of the ungated `xz97/MedInstruct` repository, whose card and upstream `DATA_LICENSE` file state the data is CC BY-NC 4.0 (non-commercial) [3][4][5][6][7] - treat this mirror as carrying the same non-commercial restriction. Hold out the `test`/`MedInstruct-test` rows (216 rows, evaluation-only with model-generated reference answers), never train on them [3][8].**

**Use it for**: SFT chat / instruction-tuning on the `train` rows (52,002 instruction/input/output triples) - the shape AlpaCare itself was fine-tuned on [1][2]. The `test` rows are an evaluation set, not training data. Maps to the SFT method card's instruction-response format. **This card cannot be verified as identical to the exact bytes served by Detsutut/MedInstruct itself, since the repo returns "access restricted" for every unauthenticated fetch; every number below comes from the byte-identical `xz97/MedInstruct` files, confirmed by matching git blob hash [4][6][9].**

**Licence**: no SPDX id in this repo's Hub metadata (`cardData` carries no `license` key) [3]; gated, manual approval required. The catch: the byte-identical original, `xz97/MedInstruct`, is tagged `license:cc-by-nc-4.0` on the Hub, and the AlpaCare GitHub repository's `DATA_LICENSE` file is the CC BY-NC 4.0 text ("Attribution-NonCommercial 4.0 International") [5][7].

**Shape**: one config (`default`), two splits mapped by this repo's own `cardData.configs` - `train` from `data/MedInstruct-52k.json`, `test` from `data/MedInstruct-test.jsonl` [3]. The byte-identical files (read via `xz97/MedInstruct`) hold 52,002 and 216 rows respectively [8][10].

**Hold out**: `test` (216 rows) - an evaluation set with model-generated reference answers and clinician difficulty scores, not training data [1][10][2]. The screening row's note calls it "a held-out MedInstruct-test.jsonl" [11].

**Origin**: built by Xinlu Zhang and coauthors (UC Santa Barbara) for the AlpaCare project; instructions are GPT-4 generations, responses are GPT-3.5-turbo generations [1][2]. This mirror, uploaded by Hub user Detsutut, shows 182 downloads and 0 likes as of the check date [3].

**Trained-on-by**: AlpaCare's own four instruction-tuned models - LLaMA-7B, LLaMA2-7B, LLaMA-13B, and LLaMA2-13B - were fine-tuned on `MedInstruct-52k` [1][2]. No adoption by any other named model or recipe was found.

**Introduced by**: [1] (Zhang et al., "AlpaCare: Instruction-tuned Large Language Models for Medical Application").

## Quality

- The `train` rows (`instruction`, `input`, `output`) are unfiltered GPT-4/GPT-3.5-turbo generations; no source states a measured contamination, duplicate, or filtering rate for this file. The `xz97/MedInstruct` repository does separately host two raw, non-deduplicated generation logs (`instructions/machine_medical_instructions_filtered.jsonl` and `..._wofiltered.jsonl`), but neither is a sibling of Detsutut/MedInstruct and neither is `MedInstruct-52k.json` itself [6].
- The `test` rows carry a clinician-assigned `difficulty` field scaled 1-5 and four separate reference answers (`gpt-4-answer`, `gpt-3.5-turbo-answer`, `text-davinci-003-answer`, `claude-2`) per instruction, generated for downstream LLM-judge evaluation, not for training [1][10][2].
- The `test` file's served schema (`id`, `instruction`, `difficulty`, four answer columns) differs from the simpler `instruction`/`input`/`output`/`difficulty` schema both READMEs describe in prose; the actual columns are as fetched here [1][10][2]. `xz97/MedInstruct`'s own datasets-server `/info` endpoint auto-detects only this `test` split from `MedInstruct-test.jsonl` (216 rows, 7 columns); it does not surface `MedInstruct-52k.json` as any split at all, since a bare JSON array is not auto-recognized the way `cardData.configs` recognizes it for Detsutut/MedInstruct [12].

## Where it came from

Built by Xinlu Zhang and coauthors at UC Santa Barbara for the AlpaCare project [1]. The generation pipeline, as described in the GitHub repository and the (byte-identical) `xz97/MedInstruct` card: starting from a 167-task clinician-written seed set, GPT-4 is prompted to generate 12 new instructions per call after three random seed tasks are sampled from the set; GPT-3.5-turbo then generates one response per instruction, independently [2]. The `MedInstruct-test` evaluation set is separately clinician-authored free-form instructions, each carrying a clinician-assigned 1-5 difficulty score and four reference answers generated by GPT-4, GPT-3.5-turbo, text-davinci-003, and Claude-2 for later LLM-judge scoring [1][2]. Detsutut/MedInstruct itself is a re-upload of these same two files onto a separate Hub account, behind a manual-approval gate, with no licence field set [3][4].
