# camel-ai/physics

20,000 physics problem-solution pairs, single-turn (one problem, one worked solution), generated entirely by GPT-4 through a two-agent role-play pipeline.

**camel-ai/physics** is built by the CAMEL team and released as part of "CAMEL: Communicative Agents for 'Mind' Exploration of Large Language Model Society" [1], which proposes a role-playing framework where two GPT-4 agents cooperate to complete a task and uses that framework to generate domain conversational data. The card states the physics data was produced across 25 physics topics, 25 subtopics per topic and 32 problems per topic/subtopic pair, giving 20,000 problem-solution pairs [2]; the served rows record the assistant role as a physicist in every case checked [3][4]. Each pair serves single-turn instruction/response SFT. **The card restricts the data to research use, under CC-BY-NC-4.0, and its own disclaimer warns the GPT-4-generated content may contain incorrect information [2].** It lives at https://huggingface.co/datasets/camel-ai/physics .

**Use it for**: single-turn SFT on physics problem-solving traces (`message_1` as the prompt, `message_2` as the completion) — the SFT method card; **research-use only**, non-commercial [2][5]. The data ships as one JSON file per example inside `physics.zip`, not as a chat-templated dialogue; each file maps directly to a single prompt/completion pair with no turns to split.

**Licence**: `cc-by-nc-4.0` (`cardData.license`) [2][5]. The repo's `cardData` also carries `extra_gated_prompt` and `extra_gated_fields` asking users to agree to research-only use, but the Hub API's top-level `gated` field reads `false` [5] — so that click-through agreement is not Hub-enforced; the binding restriction is the licence's non-commercial term plus the card's research-only disclaimer [2].

**Shape**: 20,000 rows, one `train` split, one config, five columns; delivered as `physics.zip` (23,544,181 bytes), not natively Parquet-converted on the Hub [2][5][6][7][8].

**Hold out**: Nothing — the datasets-server splits endpoint lists a single `default`/`train` split with no companion eval/test file, and no source read states any overlap with an evaluation set [2][5][9].

**Origin**: built by the CAMEL team (`camel-ai`); both the problem and the solution in every row are GPT-4 role-play generations, with the responding role recorded as `Physicist_RoleType.ASSISTANT` in every sampled row — no human labeling is stated [2][3][4]. Hub API at the check date: `downloads` 15,902, `downloadsAllTime` 72,597, `likes` 112 [5][10].

**Trained-on-by**: none found — no source read (the CAMEL paper, the dataset card, or the neighbor cards) states that a named model or training recipe trained on this physics subset specifically [1][2].

**Introduced by**: [1] (Li et al., CAMEL).

## Shape

The repository's only data file is `physics.zip` (23,544,181 bytes, per the Hub tree listing) [8]; downloading and inspecting it confirms it holds exactly 20,000 individual `.json` files, one per problem-solution pair, named by three zero-padded indices (e.g. `009_021_028.json`) that match the topic/subtopic/problem-index structure the card describes [4][2]. Each file — and so each served row — has five string fields (confirmed both from one downloaded file and from the datasets-server preview) [3][4]:

| column | dtype |
| --- | --- |
| `role_1` | string |
| `topic;` | string |
| `sub_topic` | string |
| `message_1` | string |
| `message_2` | string |

The `topic;` column name carries a stray trailing semicolon in both the served preview and the downloaded files [3][4]. No config- or split-level byte/row totals are available from the datasets-server `/size` or `/info` endpoints: both return a `failed` entry of kind `config-size` / `config-info` for `camel-ai/physics`, meaning the Hub's automatic Parquet conversion did not succeed for this repository [6][7][8]. Not every sibling release shares this gap — see Neighbors. No source states sequence-length or token statistics for this dataset.

## Load it

The repository has no working `datasets`-library loading path: because Hub Parquet conversion failed for this repo (see Shape), a plain `load_dataset("camel-ai/physics")` call has no converted rows or loading script to fall back on. The card's own recommended path is to download the zip and read the per-example JSON files directly [2], which is what was done to inspect the shape above. Pin the revision the repository file (`physics.zip`) and its own metadata were read at — the commit `a7a962cb4da69bc7c9d1a41231066cffc5eec93d`, last modified 2023-05-23 [5][4]. The datasets-server endpoints used elsewhere on this card ([6] size, [7] info, [3] first-rows, [9] splits) take no revision parameter and so serve the current `main` state regardless of any pin; they are live figures, not covered by this commit:

```python
from huggingface_hub import hf_hub_download
import zipfile, json, io

REV = "a7a962cb4da69bc7c9d1a41231066cffc5eec93d"  # main at the check date
path = hf_hub_download(repo_id="camel-ai/physics", repo_type="dataset",
                        filename="physics.zip", revision=REV)
z = zipfile.ZipFile(path)
rows = [json.load(z.open(name)) for name in z.namelist()]  # 20,000 dicts
```

**Trap**: `datasets.load_dataset("camel-ai/physics")` will not silently give you a subset — it has no Parquet files or loading script to read, so it fails outright rather than returning partial data; the zip-and-parse path above is the only route that reads all 20,000 rows.

## Where it came from

Built and released by the CAMEL team (`camel-ai`), from the role-playing agent framework introduced in "CAMEL: Communicative Agents for 'Mind' Exploration of Large Language Model Society" [1]. The framework pairs two GPT-4 agents — an inception prompt assigns each a role and a task, and the two converse until the task is solved [1]. For this release, the card states problems were generated across 25 physics topics, 25 subtopics per topic, and 32 problems per topic/subtopic combination, entirely by GPT-4 [2]; the served `role_1` field records that responding role as a physicist in every row checked [3][4]. No human curation, filtering, or labeling step is stated anywhere in the card.
