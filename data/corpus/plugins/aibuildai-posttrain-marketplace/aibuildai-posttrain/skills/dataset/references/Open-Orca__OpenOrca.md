# Open-Orca/OpenOrca

2,942,029 single-turn instruction rows - a FLAN-sourced prompt paired with a GPT-4 or GPT-3.5 explanation-style completion - built to reproduce the training distribution of Microsoft's Orca paper, whose own data was never released.

**Open-Orca/OpenOrca** is a community reconstruction, by the Open-Orca project, of the instruction-tuning data described in "Orca: Progressive Learning from Complex Explanation Traces of GPT-4" [1]: prompts drawn from the FLAN Collection [2] are resubmitted to GPT-4 or GPT-3.5 with a system prompt, and the model's step-by-step response is recorded [3]. The card states this "aligns, as best as possible, with the distributions outlined in the Orca paper" and is "a partial completion of the full intended dataset, with ongoing generation to expand its scope" [3]. **The card itself flags two known shortfalls against the Orca paper's target distribution: it has "~75K" zero-shot CoT rows against the paper's claimed 150K, and it draws FLAN2021/T0 data from a HuggingFace mirror that is itself short of the full FLAN Collection by "~1.25M and 200k respectively," for a combined shortfall of "~1.5M fewer datapoints than in the original Orca paper"** [3]. It lives at https://huggingface.co/datasets/Open-Orca/OpenOrca .

**Use it for**: single-turn reasoning-trace SFT - fine-tuning a base model to produce step-by-step explanations for FLAN-style tasks, the same shape the SFT method card expects. Each row maps directly to a system/user/assistant chat turn (`system_prompt`, `question`, `response`); there is no preference pair and no held-out split to route around. The stated shortfall above is a data-completeness caveat, not a usage restriction.

**Licence**: MIT (`cardData.license` is `"mit"`, tag `license:mit`), ungated (`"gated": false`, `"private": false`) [4]. The one catch: the MIT grant is Open-Orca's own release; no source here states whether it extends to the underlying FLAN prompts or to the GPT-4/GPT-3.5 completions themselves, and the card does not address that question.

**Shape**: 2,942,029 rows in one config (`default`), one split (`train`), four string columns (`id`, `system_prompt`, `question`, `response`) [5][6].

**Hold out**: nothing named. The data is a single unsplit `train` collection - the card itself says "the data is unsplit" [3] - and no fetched source here flags an evaluation-set overlap for this release specifically.

**Origin**: built by the Open-Orca project (Wing Lian, Bleys Goodson, Eugene Pentland, Austin Cook, Chanvichet Vong, Teknium, and named contributors) [3]; completions are generated by OpenAI's GPT-4 and GPT-3.5, prompts and system-prompt pairing chosen by the builders. Hub API at the check date: `downloads` 19,411, `downloadsAllTime` 630,539, `likes` 1,579 [4].

**Trained-on-by**: the Open-Orca project's own official model line, each cited in the dataset card - Mistral-7B-OpenOrca ("98% of Llama2-70b-chat's performance, in a completely open 7B"), OpenOrca-Platypus2-13B ("the first 13B model to score higher than LLaMA1-65B on the HuggingFace Leaderboard"), LlongOrca-7B-16k and LlongOrca-13B-16k, OpenOrcaxOpenChat-Preview2-13B, and OpenOrca-Preview1-13B (trained "in less than a day, for <$200, with <10% of our data") [3]. No adoption outside the Open-Orca project itself is stated in the fetched sources.

**Introduced by**: no paper of its own - the dataset card [3], which frames the release as reconstructing the distribution of "Orca: Progressive Learning from Complex Explanation Traces of GPT-4" [1], built from prompts sourced via the Flan Collection paper's public mirrors [2].

## Quality

- The `id` field carries a `niv`, `t0`, `cot`, or `flan` prefix marking which FLAN Collection submix the prompt came from; a 100-row sample read at `train` offset 0 held all four prefixes (`flan` 47, `t0` 31, `cot` 13, `niv` 9) [8].
- `system_prompt` can be empty: the first served row (`id: niv.242684`) has `system_prompt: ""` [8].
- The card states no measured duplicate rate, contamination rate, or human-quality check for the GPT-4/GPT-3.5 completions; none is invented here. Its only stated quality caveat is the completeness shortfall quoted in the opening paragraph [3].
- The card recommends streaming given file size, and says to "regularly check for updates and improvements" since the release was, at the time of its writing, a work in progress [3].

The row, byte, and shard-length figures on this card (Shape, `Sources` [5][6][8]) come from the datasets-server `/size`, `/info`, and `/first-rows` endpoints, none of which accept a `revision` parameter - they answer for whatever the Hub currently serves, not for the pinned `REV` above. The `sha` pin only guarantees what `load_dataset(..., revision=REV)` resolves to; it does not guarantee that a fresh call to those live endpoints will still report 2,942,029 rows.

**Trap**: this loads both parquet files (`1M-GPT4-Augmented.parquet` and `3_5M-GPT3_5-Augmented.parquet`) into one undifferentiated `train` split with no column marking which completion model produced a given row - splitting GPT-4 rows from GPT-3.5 rows for e.g. curriculum or cost-quality filtering requires locating the shard boundary (994,896 / 1,947,133) yourself, since neither the schema nor the card exposes it directly [6][3].

## Neighbors

All Open-Orca releases share the MIT licence and English-only scope; row counts below were read live at the check date [9].

- `Open-Orca/1million-gpt-4` - the GPT-4 half of this release served standalone: same sibling file name (`1M-GPT4-Augmented.parquet`), same row count (994,896), and its own served row 0 is byte-identical to this dataset's row 0 (`id: niv.242684`, same `question`/`response`) [9][10]. Use it only if you want the GPT-4-only subset without also downloading the larger GPT-3.5 file.
- `Open-Orca/SlimOrca` - 517,982 rows, reformatted into a single `conversations` (ShareGPT-style) column; its card says GPT-4 was used for "an additional pass" to remove FLAN-annotation-inconsistent answers, cutting the set "to only ~500k entries" while claiming comparable training quality at "2/3 the compute" [9][11].
- `Open-Orca/SlimOrca-Dedup` - 363,491 rows, one further step from SlimOrca: its card describes it as "a deduplicated, unfiltered subset of the SlimOrca dataset, excluding RLHF instances," using minhash/Jaccard deduplication [9][12].
- `Open-Orca/FLAN` - 377,759,274 rows, six columns, a separate large release from the same Open-Orca org that mirrors the upstream FLAN Collection [9]. The OpenOrca README does not name this repository as its prompt source - it says the `question` prompts came from the `conceptofmind` FLAN Collection mirrors on the Hub instead [3] - so no fetched source ties this specific repository to OpenOrca's own prompt pipeline; treat it only as a related FLAN mirror, not a confirmed upstream.
- This corpus prefers the full `Open-Orca/OpenOrca` release over the SlimOrca variants when the training budget can absorb 2.9M rows; SlimOrca and SlimOrca-Dedup trade row count for a GPT-4-verified, deduplicated subset at a different schema.

## Where it came from

Built by the Open-Orca project (credited in the card as Wing Lian, Bleys Goodson, Eugene Pentland, Austin Cook, Chanvichet Vong, and Teknium, with additional named contributors) [3]. The pipeline starts from prompts in the FLAN Collection [2], drawn from HuggingFace mirrors under `conceptofmind` because, the card says, those are "referenced by the official FLAN Collection repo... as the preferred data source" - though the card notes these mirrors are themselves a subset of the full FLAN Collection, short of the flan2021 and t0 submixes by about 1.25M and 200k rows respectively [3]. Each prompt is submitted, with a system prompt, to either GPT-4 or GPT-3.5, and the model's reply is stored as `response`; the `id` prefix (`niv`, `t0`, `cot`, `flan`) records which FLAN submix the prompt came from [3]. The card frames the whole exercise as reproducing the training-data distribution described in the Orca paper [1], since Microsoft did not release Orca's own training data.
