# camel-ai/chemistry

20,000 GPT-4-generated chemistry problem-and-solution pairs, spread across 25 chemistry topics, distributed as a single zip archive rather than as loadable rows.

**camel-ai/chemistry** (https://huggingface.co/datasets/camel-ai/chemistry) is one of the CAMEL project's Hub-hosted STEM datasets, generated with GPT-4 and released alongside "CAMEL: Communicative Agents for 'Mind' Exploration of Large Language Model Society" [1]; the project's GitHub README lists this repository as the "Chemistry" entry in its table of chat-format, Hugging-Face-hosted datasets [2]. The dataset card describes it as "20K problem-solution pairs obtained using gpt-4", drawn from 25 chemistry topics, 25 subtopics per topic, and up to 32 problems per topic/subtopic pair [3]. **The card's own gated-access prompt restricts use to research purposes, warning the data "may contain inaccuracies due to its artificial generation through ChatGPT" [3], and every row's `role_1` field carries the value `Chemist_RoleType.ASSISTANT` [4].**

**Use it for**: SFT on single-turn problem/solution pairs (`message_1` prompt, `message_2` response), restricted to research use per the card's own gated-access notice [3]; not a preference or reward-model format. Maps to the SFT method card.

**Licence**: CC-BY-NC-4.0 (`cardData.license` is `cc-by-nc-4.0`) [5]. The repository is ungated in practice - the Hub API reports `"gated": false` - despite the card defining an `extra_gated_prompt` and gated-access form fields (Name, Email, agreement checkbox) [5][3]; the one catch is non-commercial use plus the card's own "research purposes" restriction [3].

**Shape**: one split, `train`, 20,000 rows, each a JSON object with five string fields (`role_1`, `topic;`, `sub_topic`, `message_1`, `message_2`) [4][6]; the data is not distributed as loadable Parquet rows but as a single `chemistry.zip` of 20,000 individual `.json` files [6].

**Hold out**: Nothing - no source read (dataset card, paper, or screening note) names an evaluation-set overlap risk for this dataset.

**Origin**: built and released by the CAMEL project (`camel-ai`); all problems and solutions are GPT-4 generations, with no human-authored or human-labeled content stated on the card [3]. Hub API at the check date: `downloads` 12,388, `downloadsAllTime` 48,909, `likes` 68 [5].

**Trained-on-by**: `openaccess-ai-collective/minotaur-13b` and its GGML/GPTQ/AWQ/GGUF derivatives list `camel-ai/chemistry` among their training datasets [7]. `Weyaxi/Einstein-v6.1-Llama3-8B`, `Weyaxi/Einstein-7B`, and `Weyaxi/Newton-7B` likewise list it in their Hub metadata [7].

**Introduced by**: [1] (Li et al.), current arXiv title read from the live abs page - the paper's abstract describes the role-playing agent framework used to generate CAMEL data generally; the dataset card [3] is the direct source for this release's own generation description ("obtained using gpt-4").

## Shape

The Hub datasets-server `/size` and `/info` endpoints both fail for this repository (`"failed":[{"kind":"config-size", ...}]` and `"failed":[{"kind":"config-info", ...}]`), returning zero rows and no schema [8][9]. The repository's file tree explains why: it holds only `.gitattributes`, `README.md`, and one 21,755,545-byte `chemistry.zip`, with no Parquet or CSV sibling [6]. Downloading and opening that archive shows it contains exactly 20,000 files, each named `<topic>_<subtopic>_<n>.json` and holding one problem/solution pair with the five fields named above [4][6]. The `/first-rows` preview endpoint, unlike `/size` and `/info`, does succeed and returns a 100-row sample with the same five-field schema [4].

| field | dtype |
| --- | --- |
| `role_1` | string |
| `topic;` | string (trailing semicolon in the key itself) |
| `sub_topic` | string |
| `message_1` | string (problem) |
| `message_2` | string (solution) |

No source states token counts. Reading all 20,000 files in the archive directly: `message_1` (problem) runs a mean of 193 and median 173 characters (max 1,077); `message_2` (solution) runs a mean of 2,035 and median 2,239 characters (max 5,230) [4][6].

## Quality

- Every one of the 20,000 rows carries `role_1` equal to the single value `Chemist_RoleType.ASSISTANT`; no other role value occurs [4][6].
- Across all 20,000 rows there are exactly 25 distinct `topic;` values, matching the card's "25 chemistry topics" claim, and 613 distinct (topic, sub_topic) pairs - short of the 25 x 25 = 625 the card's per-topic subtopic count would imply [3][6].
- Among all 20,000 rows, 145 `message_1` values are exact duplicates of an earlier row's `message_1` (0.7% of the archive) [6].
- The card's only stated quality caveat is its own disclaimer: the data "was synthetically generated by GPT4 and might contain incorrect information" and is "there only for research purposes" [3]. No source states a measured factual-error rate.
- No loading script or nesting keys reference an external fetch; the JSON files inside the zip are the complete rows, so there is no missing-field or join-key problem for a would-be trainer to solve.

## Load it

There is no config for `load_dataset` to resolve directly - both `config-size` and `config-info` jobs failed on the Hub datasets-server, so `datasets.load_dataset("camel-ai/chemistry")` has no viewer-backed split to build from [8][9]. The card's own load path is a manual file download, not `load_dataset` [3]:

```python
from huggingface_hub import hf_hub_download
import zipfile, json, glob

REV = "16b27e68de06f5ae6958111834efb7a90a8b8d81"  # main at the check date
path = hf_hub_download(repo_id="camel-ai/chemistry", repo_type="dataset",
                        filename="chemistry.zip", revision=REV,
                        local_dir="datasets/")
with zipfile.ZipFile(path) as z:
    z.extractall("datasets/chemistry")

rows = [json.load(open(f)) for f in glob.glob("datasets/chemistry/*.json")]  # 20,000 rows
```

**Trap**: calling `load_dataset("camel-ai/chemistry", split="train")` will fail or silently return nothing useful, because the repository ships no Parquet/Arrow-convertible data - only a zip of 20,000 loose JSON files that the Hub's automatic Parquet conversion could not process [8][9][6].

## Where it came from

Built by the CAMEL project (`camel-ai`) and released on the Hub as part of its family of role-playing-generated datasets, linked from the project's GitHub README alongside its Math, Physics, and Biology siblings [2]. The dataset card states the pairs were "obtained using gpt-4" across 25 chemistry topics, 25 subtopics per topic, and up to 32 problems per topic/subtopic pair, with no human authorship or labeling stated [3]. The origin paper's abstract describes CAMEL's general framework as a "role-playing" setup that uses "inception prompting to guide chat agents toward task completion while maintaining consistency with human intentions" [1]; the paper's full text was not successfully fetched (its ar5iv HTML rendering failed to convert), so no claim beyond the abstract is made here about how that framework operates internally. Every row's `role_1` field carries the string `Chemist_RoleType.ASSISTANT`, directly observed in the served data [4][6].
