# glaiveai/glaive-function-calling

52,893 synthetic function-calling dialogues, each row a single plain-text block of `SYSTEM`/`USER`/`ASSISTANT`/`FUNCTION RESPONSE` turns rather than a structured chat field - the original ("v1") Glaive function-calling release.

**glaiveai/glaive-function-calling** was built by Glaive, a synthetic-data-generation platform, and released on the Hub; the card states the 52k samples were "generated through Glaive" for the task of function calling, with each sample following a fixed `SYSTEM:` (function definitions) / `USER:` / `ASSISTANT:` text template, function calls rendered as `ASSISTANT: <functioncall> {json}`, and their results rendered as `FUNCTION RESPONSE: {json}` [1]. There is no separate paper; the dataset card is the only source [1]. It lives at https://huggingface.co/datasets/glaiveai/glaive-function-calling . **The whole conversation - including any `FUNCTION RESPONSE:` turns - sits in one string column with no message-role or loss-mask field, so it must be parsed into turns and the `FUNCTION RESPONSE` spans excluded from the training loss before use; training on the raw string verbatim would teach the model to also generate tool-execution results.**

**Use it for**: SFT on function-calling dialogues - maps to the SFT method card, but only after parsing: the single `sample` string must be split on the `SYSTEM:`/`USER:`/`ASSISTANT:`/`FUNCTION RESPONSE:` markers into a role-tagged turn sequence (`chat_dialect` is "none" - no chat-template metadata ships with the row) [1]. Not preference data; no chosen/rejected fields exist.

**Licence**: Apache-2.0 (`cardData.license` is `"apache-2.0"`, repo tag `license:apache-2.0`), ungated (`"gated": false`, `"private": false`) [2]. No catch beyond the standard permissive grant is stated anywhere in the card [1][2].

**Shape**: 52,893 rows, one config (`default`), one split (`train`), one string column (`sample`) [3][4].

**Hold out**: Nothing. No source - the dataset card, the Hub record, or the sampled rows - states or implies any evaluation-set overlap, and the card ships no `test` split to hold out [1][3].

**Origin**: built and released by Glaive (`glaiveai` on the Hub); every dialogue, including the function-call arguments and their responses, is model-generated by Glaive's generation pipeline, not human-written [1]. Hub API at the check date: `downloads` 1,681, `downloadsAllTime` 9,769, `likes` 105 [2].

**Trained-on-by**: Glaive's own `glaiveai/glaive-function-calling-v1` model, an MPT-architecture checkpoint tagged `dataset:glaiveai/glaive-function-calling` [5]; and `xiaol/RWKV-toolformer-translation-japanese-chinese-english-7B-World-128k`, also tagged with this dataset [5]. The Hub model-search filter for this dataset id returns no other matches [5].

**Introduced by**: no paper - the dataset card [1].

- The card's only stated quality note is compositional balance: it says there are "samples which do not have any function invocations, multiple invocations and samples with no functions presented and invoked to keep the data balanced" [1].
- Of the first 100 rows read (offset 0, `train` split, `default` config) [6]: 17 contain no `<functioncall>` turn, 23 contain more than one `<functioncall>` turn, and 15 have a `SYSTEM:` preamble with no function definition before the first `USER:` turn - consistent with the card's balance claim over that sample, but not checked beyond these 100 rows.

Those numbers are corroborated, not pinned, by the fact that the repo's `lastModified` date (2023-09-27) predates the check date - no push has landed since the commit this card pins, so the live and pinned states happen to coincide. **Trap**: `ds[0]["sample"]` is one raw string holding the entire multi-turn conversation, including `FUNCTION RESPONSE:` turns - there is no per-turn role field and no loss mask. Feeding the string to an SFT trainer as-is trains the model to also emit `FUNCTION RESPONSE:` content, which should come from real tool execution, not model generation; split on the `SYSTEM:`/`USER:`/`ASSISTANT:`/`FUNCTION RESPONSE:` markers first and exclude `FUNCTION RESPONSE:` spans from the loss [1].
