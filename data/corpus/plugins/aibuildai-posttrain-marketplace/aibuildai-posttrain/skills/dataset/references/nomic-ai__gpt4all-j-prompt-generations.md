# nomic-ai/gpt4all-j-prompt-generations

808,812 single-turn prompt/response pairs, mostly assistant replies generated by OpenAI's GPT-3.5-Turbo over prompts pulled from StackOverflow, LAION OIG subsets, Bigscience/P3 and custom creative templates - the v1.0 release of Nomic AI's GPT4All-J training corpus.

**nomic-ai/gpt4all-j-prompt-generations** is Nomic AI's training set behind GPT4All-J and GPT4All-J-LoRA, introduced in the technical report "GPT4All-J: An Apache-2 Licensed Assistant-Style Chatbot" [1]. The paper describes an 800k-point superset of the earlier 400k-point GPT4All corpus, assembled from LAION OIG subsets (`unified_chip2`, `unified_unifiedskg_instruction`, `unified_hc3_human`, `unified_multi_news`, `unified_abstract_infill`), a random subsample of StackOverflow questions, an instruction-tuning subsample of Bigscience/P3, and custom-generated creative-writing prompts, then curated with Nomic's Atlas tool to remove exact-duplicate prompts/responses and prompts under 10 characters [1]. It lives at https://huggingface.co/datasets/nomic-ai/gpt4all-j-prompt-generations . The Hub repository serves several versions selected by git revision - `main` (this card's pinned commit), a separately-named `v1.0` branch, `v1.1-breezy`, `v1.2-jazzy`, and `v1.3-groovy`, the last of which adds human ShareGPT and Dolly examples and removes about 8% semantic duplicates found via Atlas [2]. **The report's own Use Considerations section states that the assistant response data was gathered from OpenAI's GPT-3.5-Turbo, whose terms of use prohibit developing models that commercially compete with OpenAI - a restriction on any downstream use of this data, separate from the Apache-2 license on the release itself [1].**

**Use it for**: single-turn SFT on prompt/response pairs - the SFT method card's chat format, with `prompt` as the user turn and `response` as the assistant turn - subject to the OpenAI-competition restriction above.

**Licence**: Apache-2.0 (`cardData.license` is `"apache-2.0"`, repo tags include `license:apache-2.0`), ungated (`"gated": false`, `"private": false`) [3]. The one catch is the OpenAI ToS restriction above: the paper states it applies to the GPT-3.5-Turbo-derived assistant data even though the dataset and model are released under Apache-2 [1].

**Shape**: 808,812 rows, one split (`train`), one config, three string columns (`prompt`, `response`, `source`) [3][4].

**Hold out**: nothing found. No source states a contamination or evaluation-overlap risk for this release; the report's common-sense-reasoning benchmarks (BoolQ, PIQA, HellaSwag, WinoGrande, ARC-e/c, OBQA) and its Self-Instruct-based perplexity evaluation are external held-out benchmarks, not drawn from this corpus [1].

**Origin**: built by Nomic AI; responses are OpenAI GPT-3.5-Turbo generations per the report [1], prompts are drawn from the mixed sources above. Hub API at the check date: `downloads` 349, `downloadsAllTime` 24,846, `likes` 221 [3].

**Trained-on-by**: GPT4All-J and GPT4All-J-LoRA - the GPT4All-J model card's YAML front matter lists `datasets: - nomic-ai/gpt4all-j-prompt-generations` [5]. No adoption by other named third-party models or recipes was found.

**Introduced by**: [1] (Anand et al., "GPT4All-J: An Apache-2 Licensed Assistant-Style Chatbot").

## Quality

- The report's only stated curation steps are: removing exact-duplicate prompts and responses "characterized by homogeneous clusters" in the Atlas map, and removing prompts under 10 characters (for example single words like "The" or "And") [1]. No measured duplicate rate or contamination rate is stated for the `v1.0` release served here.
- Reading 80 rows across four offsets of `train` (0-19, 100000-100019, 400000-400019, 800000-800019, via datasets-server `/rows`) [6], the `source` column took the values `pacovaldez/stackoverflow-questions`, `laion/unified_chip2` / `unified_chip2`, `unified_unifiedskg_instructions`, `unified_multi_sum`, `unified_abstract_infill_output-*`, `unified_hc3_human`, `nomic-ai`, and an empty string - 2 of the 80 sampled rows (both in the offset-0 block) had an empty `source` value. This spread is consistent with the report's stated source mix [1], but the empty-string count applies only to the 80 rows read, not the full 808,812-row split.
- The report's own Table 1 gives raw per-task zero-shot common-sense-reasoning scores for "GPT4All-J 6.7B" (BoolQ, PIQA, HellaSwag, WinoGrande, ARC-e, ARC-c, OBQA: 73.4/74.8/63.4/64.7/54.9/36.0/40.2) with no averaged column [1]. The GPT4All-J model card reproduces these same seven scores for "GPT4All-J 6B v1.0" and adds its own Avg. column of 58.2, against 58.4 for the base GPT-J 6.7B checkpoint before finetuning on this data [5] - the finetune does not clearly move that model-card-computed average, and the report attributes the dataset's value instead to creative-writing competence (poems, songs, stories) that these benchmarks do not measure [1].

## Load it

Pin the revision this card's numbers were read at (the Hub API's `sha` for `main` at the check date; the repo was last modified 2023-04-24) [3]:

```python
from datasets import load_dataset

REV = "ec687c3a67653405f42d18c0be6f13f66bd4a813"  # main at the check date
train = load_dataset("nomic-ai/gpt4all-j-prompt-generations", revision=REV, split="train")  # 808,812 rows
```

**Trap**: `load_dataset` with no `revision` argument defaults to `main` - the least-filtered version, still containing "AI language model" boilerplate refusals the later branches strip out [2]. `main` is a different git ref from the separately-named `v1.0` branch (commit `44e8d067bfe831e375a46a511f866f8882ab8466`), even though both declare the same 808,812 rows and three-column schema [2]. To get a filtered or ShareGPT/Dolly-augmented version, pass `revision='v1.1-breezy'`, `'v1.2-jazzy'`, or `'v1.3-groovy'` explicitly [2]; `v1.3-groovy` also adds a fourth `id` column not present on `main`, so a `prompt`/`response`/`source`-only collator will not break on it but will silently ignore the extra field.

## Where it came from

Built and released by Nomic AI to train GPT4All-J and GPT4All-J-LoRA [1][2]. The report describes the prompt sources as: several LAION OIG subsets (`unified_chip2`, `unified_unifiedskg_instruction`, `unified_hc3_human`, `unified_multi_news`, `unified_abstract_infill`), a random subsample of StackOverflow coding questions, an instruction-tuning subsample of Bigscience/P3, and custom-generated creative-writing prompts built from templates in the style of Mad Libs (for example "Write a [creative story type] about [NOUN] in the style of [PERSON]") [1]. Responses were generated against these prompts using OpenAI's GPT-3.5-Turbo API, at a combined GPT4All + GPT4All-J cost of about $800 in OpenAI API credits by the time of the report [1]. The report states the team began from roughly 1,000,000 curated points and produced this 808,812-row `v1.0` release, later post-processing it down to 437,605 examples actually used to finetune the released GPT4All-J LoRA checkpoint, with the full GPT-J finetune trained for one epoch [1].
