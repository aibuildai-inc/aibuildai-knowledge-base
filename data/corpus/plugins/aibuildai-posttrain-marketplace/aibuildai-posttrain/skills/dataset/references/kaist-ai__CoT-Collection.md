# kaist-ai/CoT-Collection

1.84 million machine-generated chain-of-thought rationales attached to 1,060 human-designed Flan Collection tasks, a single-split instruction-tuning dataset for reasoning-trace fine-tuning.

**kaist-ai/CoT-Collection** was built by the KAIST AI team behind "The CoT Collection: Improving Zero-shot and Few-shot Learning of Language Models via Chain-of-Thought Fine-Tuning" [1], which augments the Flan Collection's task pool - said in the paper to include only 9 tasks with rationales - with 1.84 million additional rationales spanning 1,060 tasks drawn from P3, SuperNaturalInstructions (SNI), Flan, and additional dialogue and code datasets [1]. Each row pairs a Flan-style `source`/`target` instance with a `rationale` explaining how the target follows from the source, so the dataset feeds reasoning-trace SFT: fine-tuning a language model to emit a chain-of-thought before its answer [2]. **The dataset's own GitHub repository - linked from the Hub card as the homepage - states a restriction the Hub card does not: "CoT Collection is only for non-commercial use and is subject to OpenAI's Terms of Use for the generated data," because the rationales were written by OpenAI Codex [3].** This contradicts the Hub card's `cc-by-4.0` licence tag [2][4]; treat the more restrictive statement as binding. **The training tasks also overlap a common zero-shot evaluation benchmark: the paper itself states that its FLAN- and SNI-sourced training tasks overlap the P3 Eval datasets, and for that reason excludes its own Flan-T5 and CoT-T5 models from a P3-benchmark comparison table, saying doing so would break the "unseen task" assumption [1].** It lives at https://huggingface.co/datasets/kaist-ai/CoT-Collection .

**Use it for**: reasoning-trace SFT - training a model to generate a rationale (optionally followed by an answer) - not preference pairs or reward-model attributes; the schema is a single `source`/`target`/`rationale` row, not a chosen/rejected pair, so it maps directly to the SFT method card's plain-text or single-turn format once `rationale` and `target` are concatenated as the paper does (`{rationale}\n[RESULT]\n{target}`) [2]. Non-commercial use only, per the GitHub licence note above [3].

**Licence**: Hub card tag is `cc-by-4.0` (`cardData.license`, `license:cc-by-4.0` tag) [4], repo is ungated and public (`"gated": false`, `"private": false`) [4]. The catch: the project's GitHub README - the Hub card's own listed "Repository" and "Homepage" link - states the data is for non-commercial use only and subject to OpenAI's Terms of Use, since an OpenAI Codex model wrote the rationales [1][3]. No source reconciles this conflict; the card records it rather than resolving it.

**Shape**: 1,837,928 rows, one split (`train`), one config (`en`); five string columns (`source`, `target`, `rationale`, `task`, `type`) [4][5][6].

**Hold out**: the dataset ships one `train` split with no held-out portion of its own, but P3 is not a clean external evaluation target for a model trained on it: this release draws 30.85% of its sampled training instances from P3 by the paper's own reported proportions, and the paper's authors exclude their own Flan-T5 and CoT-T5 models from a P3-benchmark comparison table for exactly this reason [1], as stated in bold above. Hold out any P3-derived evaluation split before scoring a model trained on this release against it; the paper does not name a row-level deduplication procedure that would make such an evaluation clean.

**Origin**: built by the KAIST AI team; `source`/`target` pairs come from human-designed Flan Collection tasks, and every sampled `rationale` was generated by OpenAI's Codex model, filtered by the authors' own rule-based criteria [1][3]. Hub API at the check date: `downloads` 1,072, `downloadsAllTime` 36,954, `likes` 163 [4][7].

**Trained-on-by**: the origin paper's own CoT-T5 models (Flan-T5 3B and 11B fine-tuned on this dataset) [1]; no further adoption by other named models or training recipes was found in the fetched sources.

**Introduced by**: [1] (Kim et al.).

## Quality

- The paper's own ROSCOE evaluation (13 label-free metrics across semantic alignment, semantic similarity, logical inference, and language coherence) compares this dataset's machine-generated rationales against human-authored rationales collected during the paper's prompt-creation stage; the paper reports the machine-generated rationales scored as more faithful, less repetitive, and more informative than the human-authored comparison set on most metrics, but with higher perplexity and correspondingly lower language-coherence scores [1].
- The paper describes four filtering rules applied before release: dropping rationales that omit the ground-truth answer, dropping rationales where the combined rationale-plus-target length exceeds 512 tokens, dropping rationales that duplicate an already-augmented one, and dropping rationales with repetitive sentences; it further applies a trigger-token filter to strip cases where Codex "degenerates and starts writing code after the rationale" [1].
- No source states a measured contamination rate or annotator-agreement figure for this dataset; the "diversity" and "reproducibility" analyses in the paper's appendix are qualitative/ROSCOE-based rather than measured-rate statistics beyond the quality comparison above [1].
- The paper's own deciding comparison: on the BIG-Bench-Hard benchmark, fine-tuning Flan-T5 on this dataset (yielding "CoT-T5") raised CoT-Evaluation accuracy by +4.34 points for the 3B model and +2.60 points for the 11B model over the un-fine-tuned Flan-T5 baselines, at the cost of a 0.96-point drop in Direct-Evaluation accuracy for the 3B model, while the 11B model's Direct-Evaluation accuracy improved as well, for a +2.57-point total-average gain [1].

The row counts, byte sizes, column dtypes, and the sampled row in this card's Shape and A row sections instead come from the `/size`, `/info`, `/first-rows`, and `/rows` datasets-server endpoints [5][6][9], none of which accept a `revision` parameter - they always serve whatever is on the repository's default branch at query time. ## Where it came from

Built by the KAIST AI team. `source` and `target` come from 1,060 human-designed tasks drawn from the Flan Collection [1]; for each instance, the team prompted OpenAI's Codex model, using in-context demonstrations conditioned on the ground-truth label, to generate a rationale explaining how the target follows from the source [1][3]. The paper describes this Codex-based augmentation as producing roughly 51 times more rationales and roughly 118 times more task variants than the four Flan-T5 subsets (ExQA, Arithmetic, MCQA, NLI) that already carried human- or template-written rationales [1]. The GitHub repository's data-extraction scripts name the merged per-subset output files `codex_rationale_{split}_{phase}.json`, and its README states the licence catch quoted above [3].
