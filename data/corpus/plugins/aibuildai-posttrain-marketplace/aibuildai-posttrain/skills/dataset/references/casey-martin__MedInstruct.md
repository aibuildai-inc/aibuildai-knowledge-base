# casey-martin/MedInstruct

52,002 medical instruction-input-output triples for supervised fine-tuning - instructions generated by GPT-4, responses by ChatGPT - plus a separate 216-item clinician-written free-form evaluation set with candidate answers from four LLMs, a mirror of the data behind the AlpaCare medical instruction-tuned LLaMA models.

**casey-martin/MedInstruct** packages the two data releases from "AlpaCare: Instruction-tuned Large Language Models for Medical Application" [1]: *MedInstruct-52k*, a machine-generated medical instruction-following dataset built by prompting GPT-4 for new medical tasks from a 167-item clinician-curated seed set and then having ChatGPT (GPT-3.5-turbo) generate the responses, and *MedInstruct-test*, a 216-item clinician-authored free-form medical instruction evaluation set used to benchmark the resulting AlpaCare models [1]. The train file (`data/MedInstruct-52k.json`) is instruction-tuning data; the test file (`data/MedInstruct-test.jsonl`) is an evaluation set carrying pre-generated answers from four reference LLMs rather than a single ground-truth response, so it is **not for training - it feeds evaluation, and its 216 rows must be held out of any training run built from this repository**. The dataset card states no license for either file, unlike the authors' own upstream copy of the same data, which is CC BY-NC 4.0 [2][3]. It lives at https://huggingface.co/datasets/casey-martin/MedInstruct .

**Use it for**: single-turn instruction SFT on `MedInstruct-52k` (instruction/input/output triples in Alpaca style - concatenate `instruction` and `input` into the prompt before training). Do not train on `MedInstruct-test`; it holds no single reference answer per row, only four models' candidate answers for benchmarking [1]. Maps to the SFT method card's plain instruction-response format, not a preference or chat-multiturn format.

**Licence**: not stated in this repository - no `license` field in the card metadata and no license text in the body [4]. The catch: the authors' own upstream copy of the same files, `xz97/MedInstruct`, states CC BY-NC 4.0 (non-commercial) [2][3], and this mirror repeats none of that restriction.

**Shape**: one config (`default`), two splits - `train` 52,002 rows (`instruction`, `input`, `output`, all string) and `test` 216 rows (`id`, `instruction`, `difficulty`, `gpt-4-answer`, `claude-2`, `gpt-3.5-turbo-answer`, `text-davinci-003-answer`) [5][1].

**Hold out**: `test` (216 rows) - it is the paper's own evaluation set, not training data, and its schema has no single-answer `output` column to train on [1][5].

**Origin**: `train` instructions come from GPT-4, seeded from clinician-written tasks, with responses generated by ChatGPT (GPT-3.5-turbo); `test` instructions are clinician-written, graded for difficulty by a clinician, with candidate answers from GPT-4, Claude 2, GPT-3.5-turbo and text-davinci-003 [1]. Uploaded by Hub user casey-martin, mirroring the paper authors' release; Hub API at the check date: 98 downloads, 1,311 all-time downloads, 7 likes [4].

**Trained-on-by**: the paper's own AlpaCare-LLaMA/LLaMA-2 7B/13B models, fine-tuned on `MedInstruct-52k` [1]. A reformatted copy, `lavita/AlpaCare-MedInstruct-52k`, is tagged as the training dataset on the community model `Svngoku/Llama-3.1-8B-AlpaCare-MedInstruct-GGUF` [6]. No adoption evidence found for `casey-martin/MedInstruct` specifically, as opposed to the authors' own or `lavita`'s copies.

**Introduced by**: [1] (Zhang et al., "AlpaCare: Instruction-tuned Large Language Models for Medical Application").

## Shape

One config, `default`, with two splits, read directly from the two data files since the Hub's automatic viewer fails to parse them (`config-info`/`config-size` both report `failed` for this repository) [7][8][9]:

| split | file | rows | columns |
| --- | --- | --- | --- |
| `train` | `data/MedInstruct-52k.json` | 52,002 | `instruction`, `input`, `output` (string) |
| `test` | `data/MedInstruct-test.jsonl` | 216 | `id` (int64), `instruction`, `difficulty`, `gpt-4-answer`, `claude-2`, `gpt-3.5-turbo-answer`, `text-davinci-003-answer` (string) |

Row counts above are from directly downloading and parsing both files at the pinned revision [9]; `datasets-server`'s `first-rows` endpoint independently returns the same three train columns and the same seven test columns [10][11]. `data/MedInstruct-52k.json` is 68,740,963 bytes; `data/MedInstruct-test.jsonl` is 1,137,791 bytes [12]. No source states token or sequence-length statistics for either file.

The card and README call the test set "217" items [13][4], but the served file holds 216 records with `id` values 0-216 and `143` missing, and the paper's own per-difficulty breakdown (Table 12: 44/46/41/41/44 across difficulty levels 1-5) sums to exactly 216, matching what this repository serves [1][9]. Treat 216 as the reliable count.

## Quality

- The paper's only stated quality check on `MedInstruct-52k` is a clinician spot-check of 50 randomly sampled instances, of which 49 were graded correct [1].
- Near-duplicate instructions were removed after GPT-4 generation and before ChatGPT response generation, per the paper's pipeline description; no deduplication rate is stated [1].
- `MedInstruct-test`'s 216 clinician-written tasks are spread across five difficulty levels (1 lowest to 5 highest), with counts 44/46/41/41/44, "approximately equal" by the paper's own description [1].
- No source states a measured contamination rate against other benchmarks for either split.

**Trap**: `datasets-server`'s automatic viewer cannot parse this repository (`config-info` and `config-size` both fail) [7][8], so the Hub's dataset-preview page and any tool that relies on it (row counts, size estimates, the online viewer) will report nothing useful; `load_dataset` still works because the card's own `configs:` metadata points directly at `data/MedInstruct-52k.json` and `data/MedInstruct-test.jsonl` [4]. A second trap: `test` has no single ground-truth `output` field - it carries four separate model-answer columns (`gpt-4-answer`, `claude-2`, `gpt-3.5-turbo-answer`, `text-davinci-003-answer`) for benchmarking, so a collator built for `train` will not run on `test` unmodified [1][5].

[...] Overall, any interference with the normal flow of air in the lungs caused by a mass can result in inadequate oxygen exchange and subsequent shortness of breath.\n\nThe answer is: A mass in the lung can obstruct air passages, cause inflammation, damage lung tissue, and compress adjacent structures, leading to shortness of breath."

`config="default"`, `split="test"`, `row_idx=0` [11]:

```json
{
  "id": 0,
  "instruction": "My sister has just returned from a trip to the tropics and she keeps getting bouts of high fever, chills and vomiting. Can you figure out what's going on?",
  "difficulty": "3",
  "gpt-4-answer": "While I strongly recommend your sister sees a healthcare professional for an accurate diagnosis, her symptoms suggest she could be suffering from malaria. [...] Please remind your healthcare provider about her travel history, which will guide them towards appropriate testing.",
  "claude-2": " Based on the information provided, it sounds like your sister may have contracted a tropical infectious disease during her recent trip. [...] Let me know if you have any other questions!",
  "gpt-3.5-turbo-answer": "Based on the symptoms you have described, it is possible that your sister may be experiencing a tropical disease or infection. [...] It is crucial to prioritize her health and seek proper medical advice promptly.",
  "text-davinci-003-answer": "\nIt is possible that your sister has contracted a tropical disease. It is important to take her to a doctor as soon as possible to get a proper diagnosis and treatment. Some tropical diseases can be serious and require prompt medical attention."
}
```

The `train` rows carry no `id` field and use a literal `"<noinput>"` string when a task has no context input [10]; the `test` rows carry an integer `id`, a string `difficulty` level, and four separate model-answer fields instead of a single `output`, so the two splits need different collators [1][11].

## Where it came from

The paper's pipeline: clinicians curated a 167-instance medical task seed set; GPT-4 was prompted with three random seed instructions at a time to generate 12 new medical instructions per call, after which near-duplicate instructions were filtered, leaving 52,000 instructions; ChatGPT (GPT-3.5-turbo) then generated one response per instruction to form `MedInstruct-52k` [1]. Separately, clinicians authored 216 free-form medical instructions spanning five difficulty levels to form `MedInstruct-test`, and four reference systems (GPT-4, Claude 2, GPT-3.5-turbo, text-davinci-003) were each run over the test instructions to produce the candidate answers used for benchmarking [1]. AlpaCare, the LLaMA/LLaMA-2 7B/13B model family fine-tuned on `MedInstruct-52k`, reports up to a 38.1% absolute gain over the best baselines on medical free-form instruction evaluation and 6.7% averaged over general-domain benchmarks, with a human study showing +12% correctness and +49% helpfulness over the best medical-LLM baselines [1]. This Hub repository (`casey-martin/MedInstruct`) mirrors the two data files without the seed-set or unfiltered-instruction-pool files that the authors' own repository additionally carries [2][3].
