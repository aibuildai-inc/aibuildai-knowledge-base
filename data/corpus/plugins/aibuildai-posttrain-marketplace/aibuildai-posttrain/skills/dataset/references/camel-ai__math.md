# camel-ai/math

50,000 GPT-4-generated math problem-solution pairs, single-turn, produced by direct GPT-4 prompting within the CAMEL project; shipped only inside a zip archive, so the Hub viewer serves no rows directly.

**camel-ai/math** is one of two single-turn question-answer datasets ("Math" and "Science") that the CAMEL paper, "CAMEL: Communicative Agents for 'Mind' Exploration of Large Language Model Society", collects using its role-playing agent framework to provide data for studying LLM ability emergence [1]. Each pair is produced by a direct, sequential GPT-4 prompting pipeline distinct from the paper's AI-user/AI-assistant role-play mechanism used elsewhere in the project: GPT-4 is first prompted to generate 25 math topics, then prompted to generate 25 subtopics per topic, then prompted to generate and solve 80 problems per topic-subtopic pair, for 25 x 25 x 80 = 50,000 pairs [1]. **The dataset card's disclaimer says the data were synthetically generated by GPT-4, might contain incorrect information, and are there only for research purposes [2].** It lives at https://huggingface.co/datasets/camel-ai/math .

**Use it for**: single-turn reasoning-trace SFT (problem in, worked solution out); not a preference or chat-multi-turn format. Map `message_1` to the prompt and `message_2` to the target response for the SFT method card. The README's disclaimer restricts use to research purposes only, given the data's synthetic, GPT-4-generated, possibly-incorrect content; a separate gated-style acknowledgement field asks the user to confirm research-only use, citing possible inaccuracies from the data's generation through ChatGPT [2].

**Licence**: CC-BY-NC-4.0 (`cardData.license` is `"cc-by-nc-4.0"`) [3]. The repo is not access-gated (`"gated": false` at the Hub API) [3], but the card still carries an acknowledgement-style prompt asking the user to confirm research-only use before treating the data as a training source [2].

**Shape**: one config, one `train` split, 50,000 rows, five columns (`role_1`, `topic;`, `sub_topic`, `message_1`, `message_2`); the data ship inside a single zip file, not as loose rows [4][5].

**Hold out**: not stated. No source here or in the paper flags overlap with an evaluation benchmark; the screening row assigns no such risk [6].

**Origin**: built and released by the CAMEL-AI team (`camel-ai`); the problems, roles, and solutions are GPT-4 generations, with no human labeling step described [1][2]. Hub API at the check date: 3,940 downloads, 118 likes [3]; `downloadsAllTime` (all-time counter) is 77,178 [7].

**Trained-on-by**: EleutherAI's `llemma_7b_muinstruct_camelmath` is an instruction fine-tune of Llemma 7B trained on `EleutherAI/muInstruct` combined with this dataset; on its own reported Hungarian Math Exam benchmark it scores 25% versus 23% for few-shot Llemma 7B, the model it starts from [8]. Multiple `mlfoundations-dev` OpenThoughts/DCFT checkpoints (mirrored as GGUF quantizations, e.g. `oh_v1-2_only_camel_math`, `oh_v1.3_camel_math_x2`) name this dataset in their model ids as an isolated data-mix ablation component, though their own model cards were not reachable to confirm training details [9].

**Introduced by**: [1] (Li et al.), Appendix F, "Math and Science Datasets Generation Details".

## Quality

- The datasets-server `/size` and `/info` endpoints both fail for this dataset with `"failed":[{"kind":"config-size", ...}]` and `"failed":[{"kind":"config-info", ...}]` respectively, and `/size` reports `"num_rows":0"` [4]. This is because the served content is a zip archive rather than loose data files, so the Hub's parquet-conversion ("viewer") pipeline cannot build a table from it; the screening row's note independently describes the same fact in prose, that the data ship inside a zip file and that is why the size endpoint serves no rows [6]. The `/first-rows` preview endpoint (`is-valid` reports `"preview":true, "viewer":false`) still succeeds by sampling rows directly out of the zip [10][11], and that preview is what all row and column facts above are read from.
- Of the 100 rows returned by that preview (`config=default`, `split=train`, offset 0), all 100 carry `topic;` = `"Algebra"` across 2 distinct subtopics, and all 100 carry `role_1` = `"Mathematician_RoleType.ASSISTANT"` [10]. This says only that the file begins with a run of Algebra rows before moving to the next topic in sequence; it is not a claim about the other 24 topics or about the dataset's overall topic balance, which was not read.
- The dataset card's only stated quality caveat is that the data were "synthetically generated by GPT4 and might contain incorrect information", which is why it restricts use "solely for research purposes" [2]. No source states a measured error rate, duplicate rate, or contamination check.

## Load it

The repository's own README load snippet names a file, `math50k.zip`, that does not exist in the tree (the actual file is `math.zip`); a literal copy of that snippet will 404 [4][5]. Downloading the real file and pinning the revision this card's numbers were read at:

```python
from huggingface_hub import hf_hub_download

REV = "c1b9a23cfbb77b34668df5705b6e8832a06046c1"  # main at the check date
path = hf_hub_download(
    repo_id="camel-ai/math",
    repo_type="dataset",
    filename="math.zip",          # not "math50k.zip" as the README's snippet has it
    revision=REV,
    local_dir="datasets/",
)
```

**Trap**: `datasets.load_dataset("camel-ai/math")` does not work out of the box the way it does for a parquet-backed repo - the datasets-server pipeline that backs `load_dataset`'s fast path fails on this repo (see Quality), so a reader who only tries `load_dataset` and gets an error may wrongly conclude the dataset is broken rather than zip-packaged. Download and unzip `math.zip` directly, or use the parquet mirror in Neighbors below, which loads with plain `load_dataset`.

## Where it came from

Built and released by the CAMEL-AI team, the group behind the CAMEL role-playing agent framework, though this specific dataset was not generated through that framework's AI-user/AI-assistant role-play mechanism [1]. The generation recipe, per the paper's Appendix F: GPT-4 is prompted to list 25 diverse math topics; for each topic, GPT-4 is prompted to list 25 subtopics; for each of the resulting 625 topic-subtopic pairs, GPT-4 is prompted to generate and solve 80 problems, yielding 25 x 25 x 80 = 50,000 problem-solution pairs, all authored and solved by GPT-4 with no separate human-labeling step described [1]. The paper applies the identical recipe, with 32 problems per pair instead of 80, to produce the sibling 20,000-pair Physics, Biology, and Chemistry datasets that make up its "Science" release [1].
