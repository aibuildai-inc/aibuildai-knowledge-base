# nickrosh/Evol-Instruct-Code-80k-v1

78,264 single-turn instruction/output pairs for code generation, an independent open reimplementation of the WizardCoder Evol-Instruct data-generation process applied to CodeAlpaca.

**nickrosh/Evol-Instruct-Code-80k-v1** applies the Evol-Instruct method described in "WizardCoder: Empowering Code Large Language Models with Evol-Instruct" [1] to the 20k-row CodeAlpaca seed set, evolving each seed instruction three times to increase its complexity before generating a response, and yields flat `instruction`/`output` pairs for supervised instruction fine-tuning of a code model [2]. The generation code is released separately as the Evol-Teacher repository, which the dataset's own Hub card names as the process behind this release [3]; the WizardCoder authors' own project repository states that although the model weights were released, the training data is undergoing legal review and the researchers are not authorized to release it publicly, so this Hub release is an independent, open reimplementation rather than the authors' own data [4]. It lives at https://huggingface.co/datasets/nickrosh/Evol-Instruct-Code-80k-v1 . **The Hub dataset card names only the Evol-Teacher code as the source of this data and never names a generating model** [2]; the Evol-Teacher repository's own README, one hop away, states GPT-3.5 was used both to evolve instructions and to generate responses, over 120,000 OpenAI API calls in total [3].

**Use it for**: single-turn SFT on code-generation instructions - `instruction` as the prompt, `output` as the target response; see the SFT method card. No usage-shape restriction beyond the licence below is stated on the card [2].

**Licence**: CC-BY-NC-SA-4.0 (`cardData.license` is `"cc-by-nc-sa-4.0"`, repo tag `license:cc-by-nc-sa-4.0`), ungated (`"gated": false`, `"private": false`) [5]. The catch: CC-BY-NC-SA-4.0 is a non-commercial, share-alike licence by its own SPDX definition - the card states only the licence id and adds no separate usage note [2][5].

**Shape**: 78,264 rows, one config (`default`), one split (`train`), two string columns (`instruction`, `output`) [6][7].

**Hold out**: not stated. No source here - the dataset card, the Evol-Teacher repository, or the WizardCoder paper's abstract - names an evaluation set this release overlaps, and the paper's own benchmarks (HumanEval, HumanEval+, MBPP, DS-1000) are not built from CodeAlpaca [1][2][3].

**Origin**: built and released by Hub user `nickrosh`, using the Evol-Teacher code the same author released on GitHub [2][3]. Instructions are evolved and responses generated by GPT-3.5, per the Evol-Teacher README - not stated on the Hub dataset card itself [3]. Hub API at the check date: `downloads` 10,928, `downloadsAllTime` 54,609, `likes` 251 [5].

**Trained-on-by**: the author's own `nickrosh/Evol-Replit-v1`, an instruction-tuned ReplitLM checkpoint trained on the full 80k set - the Evol-Teacher README reports it scored 31.1% Pass@1 on HumanEval under greedy decoding, up from 21% for the un-fine-tuned base ReplitLM, against 34% for the original WizardCoder/StarCoder model it reimplements [3]; `aiplanet/panda-coder-13B`, whose card lists `nickrosh/Evol-Instruct-Code-80k-v1` in its `datasets:` field and describes itself as built on this set [8]; and the `hpcgroup/hpc-coder-v2` family (e.g. `hpc-coder-v2-6.7b`), whose card lists this dataset among its fine-tuning mix [9]. The Hub's own "datasets that use this" listing names 76 downstream models in total, mostly quantized re-releases of the checkpoints above [10].

**Introduced by**: no paper describes this specific release - the Hub dataset card [2] and the companion Evol-Teacher repository [3]; it reimplements the method of the WizardCoder paper [1].

## Where it came from

Built by Hub user `nickrosh`, using the Evol-Teacher code released on GitHub by the same author [2][3]. The process takes the 20k-row CodeAlpaca seed dataset and evolves each instruction through a randomly chosen evolution prompt - one of a set covering complexity increases, added requirements, and deliberately erroneous code for robustness - repeated three times with pruning between rounds to drop low-quality instructions and prevent them from evolving further; both the evolution step and the response-generation step use GPT-3.5, and the full run took roughly three days and over 120,000 OpenAI API calls [3]. The method follows the Evol-Instruct approach introduced for code models in the WizardCoder paper [1]. The paper's authors released their model weights but, per their own project repository, held their training data back pending legal review, so this repository is a separate, independent reimplementation rather than the authors' own data [4].
