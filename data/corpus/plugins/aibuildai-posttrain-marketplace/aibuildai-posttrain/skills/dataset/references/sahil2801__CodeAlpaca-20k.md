# sahil2801/CodeAlpaca-20k

20,022 single-turn instruction/input/output rows for code-generation tasks, the Hugging Face mirror of the original Code Alpaca project's self-instruct dataset.

**sahil2801/CodeAlpaca-20k** is a Hub upload, by an account named `sahil2801`, of the `code_alpaca_20k.json` file from the Code Alpaca GitHub project, which built an instruction-following code-generation dataset with the Self-Instruct technique [1] adapted from Stanford Alpaca's pipeline, seeding and prompting it toward code tasks instead of general ones [2]. Each of the 20,022 instructions is unique, and the answer to every instruction was generated by prompting OpenAI's `text-davinci-003` [2]. It lives at https://huggingface.co/datasets/sahil2801/CodeAlpaca-20k, where the dataset card is YAML front matter only, with no prose body [5]. **So the description above, the generation method, and the licence catch below all come from the GitHub project this repository mirrors, not from this repository's own card [2][3].**

**Use it for**: single-turn SFT on code-generation instructions - the row shape is Stanford-Alpaca-style `instruction`/`input`/`output`, mapping to the SFT method card once `instruction` and `input` are combined into a prompt (empty-`input` and non-empty-`input` rows use different prompt templates) [2]. **Licence catch below - the GitHub project's own data licence is non-commercial, which this Hub repo's `cc-by-4.0` tag does not carry forward.**

**Licence**: Hub card field is `cc-by-4.0`, ungated (`"gated": false`, `"private": false`) [4]. The catch: the upstream GitHub project that produced this exact file ships two separate licence files - `LICENSE` (Apache-2.0, for the repo's code) and a distinct `DATA_LICENSE` for the data itself, which is Creative Commons Attribution-NonCommercial 4.0 International, not the permissive Attribution-only licence this Hub repo's tag states [3][5].

**Shape**: 20,022 rows, one split (`train`), one config (`default`), three string columns (`instruction`, `input`, `output`) [6][7].

**Hold out**: nothing - no source read for this card states or flags a benchmark-overlap risk for this dataset.

**Origin**: uploaded to the Hub by `sahil2801`; the underlying data was built by the Code Alpaca GitHub project (author Sahil Chaudhary), with `text-davinci-003` generating every `output` and human-written seed tasks steering the self-instruct loop [2][3]. Hub API at the check date: `downloads` 17,137, `downloadsAllTime` 248,842, `likes` 238 [4].

**Trained-on-by**: the Tulu family of models (`allenai/tulu-7b`, `-13b`, `-30b`, `-65b`) list `sahil2801/CodeAlpaca-20k` in their Hub `datasets:` metadata and describe themselves as finetuned on a mixture that includes Code-Alpaca; they were trained for "How Far Can Camels Go? Exploring the State of Instruction Tuning on Open Resources" [8][9].

**Introduced by**: no paper - the Code Alpaca GitHub project's README [2], which builds on the Self-Instruct paper's method [1].

## Load it

Single split, no reformatting needed. Pin the revision this card's numbers were read at (the Hub API's `sha` for `main` at the check date; the repo was last modified 2023-10-03) [4]:

```python
import datasets

REV = "152bb5e9a29651266b018106053980070a0521a1"  # main at the check date
train = datasets.load_dataset("sahil2801/CodeAlpaca-20k", revision=REV, split="train")  # 20,022 rows
```

This `sha` pins what `load_dataset` reads - the file content and thus the row/column counts on this card. It does not pin the datasets-server `/size`, `/info`, and `/first-rows` responses this card's Shape, Quality, and A row sections draw on [6][7][10]: that API takes no revision parameter, so those responses are read live at the check date and could change on a later fetch even at the same commit.

**Trap**: the loaded `output` field is `text-davinci-003` output, not a curated or human-verified answer - it can contain code with runtime errors or hallucinated behavior, since the GitHub README documents no correctness check on the generated answers [2]. Also, the licence field this loader reports (`cc-by-4.0`) omits the non-commercial clause the upstream `DATA_LICENSE` file states for the same data [3][5] - see Licence above.

## Where it came from

The data originates from the Code Alpaca GitHub project (author Sahil Chaudhary), which set out to reproduce Stanford Alpaca's instruction-tuning recipe for code-generation tasks: it reused Stanford Alpaca's Self-Instruct-based generation pipeline [1] with a prompt modified to target code generation, editing, and optimization, and with seed tasks restricted to code, producing 20,000 instruction/input/output triples for under $200 by prompting `text-davinci-003` [2]. This Hub repository packages that project's `code_alpaca_20k.json` file as a single `train` split, uploaded by the account `sahil2801`; the Hub card itself states none of this - it has no body text, only YAML front matter [5].
