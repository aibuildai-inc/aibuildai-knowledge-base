# notbadai/python_functions_reasoning

206,299 Python-function prompt/reasoning/answer triples, self-improved chain-of-thought SFT data for a 24B coding-and-math reasoning model, in one `train` split.

**notbadai/python_functions_reasoning** is the Python-functions reasoning dataset behind notbadai's Notbad v1.0 Mistral 24B reasoning model [1]. The prompts and instructions were sourced from the OpenCoder Stage1 SFT dataset and from open-source GitHub projects, and the `reasoning`/`answer` traces were sampled from an RL-based self-improved Mistral-Small-24B-Instruct-2501 - the notbadai team's own reinforcement-learned checkpoint, not the base Mistral release [1]. There is no separate paper for this dataset; the description above is the dataset card itself [1]. It lives at https://huggingface.co/datasets/notbadai/python_functions_reasoning . **In every one of the 115 rows sampled across two offsets, the `answer` value ends with a literal `</s>` string token carried over from the generating model's stop token; strip or handle it before using the field as SFT target text (see Quality for the exact rows checked).**

**Use it for**: reasoning-trace SFT on Python function-writing tasks - `prompt` is the coding instruction, `reasoning` is the chain-of-thought, `answer` is the final code; concatenate `reasoning` and `answer` (after stripping the trailing `</s>`) as the target for a standard instruction-SFT / reasoning-distillation recipe. Maps to the SFT method card's completion-only format (mask the `prompt` tokens, train on `reasoning`+`answer`).

**Licence**: Apache-2.0 (`cardData.license` is `"apache-2.0"`, repo tag `license:apache-2.0`), ungated [2]. No further catch stated in the card body.

**Shape**: 206,299 rows, one config (`default`), one split (`train`), four string columns (`prompt`, `reasoning`, `answer`, `source`) [3][4].

**Hold out**: nothing - no source states a held-out split or an evaluation-overlap risk for this dataset; there is only one split and no test/eval file in the repository [4][2].

**Origin**: built and released by notbadai; prompts drawn from OpenCoder Stage1 and GitHub, reasoning/answer traces generated by notbadai's own RL-tuned Mistral-Small-24B-Instruct-2501 [1]. Hub API at the check date: `downloads` 328, `downloadsAllTime` 3,280, `likes` 13 [2].

**Trained-on-by**: Notbad v1.0 Mistral 24B, notbadai's own reasoning model built on Mistral-Small-24B-Instruct-2501 - this dataset's own card states it was used to train that model [1]. The model's own card does not name this dataset; it only says the model was fine-tuned from data sampled from multiple of notbadai's RL models in general terms [5].

**Introduced by**: no paper - the dataset card [1].

## Quality

- No source states a measured contamination rate, duplicate rate, or human-review figure for this dataset.
- Every sampled row's `answer` field ends with a literal `</s>` string, confirmed in all 95 rows read at offset 0 and all 20 rows read at offset 100,000 of `train` (115 of 206,299 rows total, 0.06%) [4]. This is the generating model's end-of-turn token rendered as text, not a training-ready terminator for a different tokenizer; whether it holds for the rest of the split is not established by this sample.
- The origin dataset's sibling model card gives one reference comparison for what training with data like this (as part of notbadai's RL self-improvement pipeline) does to the base model: against Mistral-Small-24B-Instruct-2501, Notbad v1.0 Mistral 24B's humaneval score rises from 0.848 to 0.869 and its math score from 0.706 to 0.752, but its ifeval score falls from 0.829 to 0.514 and its mmlu_pro and gpqa_main scores also drop slightly, from 0.663 to 0.642 and from 0.453 to 0.447 [5]. This benchmark table is for the finished model, not an ablation isolating this dataset's own contribution.
- The `source` column names either an upstream dataset id (e.g. `OpenCoder-LLM/opc-sft-stage1`) or a GitHub repository (e.g. `cuthbertLab/music21`, `forseti-security/forseti-security`, `numenta/nupic-legacy`), confirming the card's statement that prompts come from both OpenCoder Stage1 and GitHub projects [1][4]. Of the 95 rows read at offset 0, 93 carry the OpenCoder source id and 2 carry a GitHub repo name; of 20 rows read at offset 100,000, 19 carry the OpenCoder source id and 1 carries a GitHub repo name.
- The OpenCoder Stage1 dataset's own card notes that the `filtered_infinity_instruct` portion of its outputs is often low quality and recommends regenerating responses with a stronger model - a caveat about that upstream pool's original outputs, not about the reasoning/answer traces regenerated for this release [6].

## Load it

Single split, single config; pin the revision this card's numbers were read at (the Hub API's `sha` for `main` at the check date; the repo was last modified 2025-04-07) [2]:

```python
import datasets

REV = "6d29a9120e4cc3b1e6f6823b5148daa775b2ebb7"  # main at the check date
train = datasets.load_dataset("notbadai/python_functions_reasoning", revision=REV, split="train")  # 206,299 rows
```

**Trap**: every `answer` string sampled (115 of 206,299 rows, across offsets 0 and 100,000) carries a trailing `</s>` literal; if you feed this into a tokenizer whose EOS token uses a different string or id, the literal text is either duplicated as ordinary tokens or left dangling in the label - strip it (or map it explicitly to your tokenizer's EOS) before building SFT targets.

## Where it came from

Built and released by notbadai. Prompts and function instructions come from two pools: the OpenCoder Stage1 SFT dataset, and open-source Python projects on GitHub [1]; the `source` column names which pool (and, for GitHub, which repository) each row's prompt came from [4]. The `reasoning` and `answer` fields were generated by sampling from an RL-based self-improved Mistral-Small-24B-Instruct-2501 - notbadai's own reinforcement-learning-tuned checkpoint of the Mistral base model, described by the sibling model card as trained with reinforcement learning techniques continuing from the team's Quiet-STaR work and similar to Dr. GRPO, with reasoning capability coming from self-improvement rather than distillation from another model [1][5].
