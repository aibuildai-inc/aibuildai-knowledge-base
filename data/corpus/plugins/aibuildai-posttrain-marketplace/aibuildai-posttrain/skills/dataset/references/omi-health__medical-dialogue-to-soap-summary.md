# omi-health/medical-dialogue-to-soap-summary

10,000 synthetic patient-clinician dialogues paired with GPT-4-generated SOAP notes, pre-split into train/validation/test and pre-formatted as chat messages.

**omi-health/medical-dialogue-to-soap-summary** was built by Omi from the GPT-4-generated dialogues in the NoteChat dataset, itself built on PubMed Central case reports and introduced by "NoteChat: A Dataset of Synthetic Doctor-Patient Conversations Conditioned on Clinical Notes" [1]; Omi generated the accompanying SOAP summaries with GPT-4 and split the result into 9,250 train / 500 validation / 250 test rows [2]. **The dataset card states usage is permitted for any purpose, including commercial, by Omi, but that permission from the original NoteChat authors is required for any further use beyond that [2].** It lives at https://huggingface.co/datasets/omi-health/medical-dialogue-to-soap-summary [3].

**Use it for**: SFT on medical dialogue-to-SOAP-note summarization - the `messages` column is a ready-made chat-format SFT example (system + user + assistant turns), and `messages_nosystem` folds the system instruction into the user turn instead; both map to the SFT method card. The stated further-use restriction above applies to any reuse beyond Omi's own permitted scope [2].

**Licence**: not stated as an SPDX id on the dataset card or repo tags (`cardData` and tags carry no license field) [2][4]; the card's own terms are the custom-permission clause quoted above, not a standard licence grant. Ungated, public repo [4].

**Shape**: 10,000 rows in one config (`default`), three splits - `train` 9,250, `validation` 500, `test` 250 - five columns per row [5][6].

**Hold out**: `test` (250 rows) and `validation` (500 rows) are the card's own held-out splits [2]; no source flags overlap with an external evaluation set.

**Origin**: built by Omi (omi.health); dialogues come from NoteChat's GPT-4 generations over PMC case reports, and the SOAP summaries were generated by GPT-4 [1][2]. Hub API at the check date: `downloads` 761, `downloadsAllTime` 14,010, `likes` 78 [4].

**Trained-on-by**: Omi's own `omi-health/sum-small`, a Phi-3-mini-4k-instruct fine-tune, lists this dataset as its training data [7]; the Hub's model-filter-by-dataset listing returns 24 models tagged with this dataset id, including GGUF/MLX re-quantizations of `sum-small` and several unrelated third-party fine-tunes [8].

**Introduced by**: no paper for this derived release - the dataset card [2]; the upstream dialogue source, NoteChat, was introduced by [1].

## Quality

- The dialogues and SOAP notes are both LLM-generated (GPT-4), not human-authored or human-verified; the card states this explicitly and adds that the data are "synthetically generated and not designed for direct clinical application without appropriate guardrails and validation" [2].
- No source states a measured error rate, duplicate rate, or annotator-agreement figure for this dataset; the upstream NoteChat paper reports that models trained on NoteChat-augmented dialogues outperform other state-of-the-art models on the MTS-dialogue clinical-note benchmark, and that NoteChat's own dialogue generation beats ChatGPT and GPT-4 by up to 22.78% per domain-expert human evaluation - but neither figure is a quality measurement of this repository's rows [1].
- All rows load directly from the served JSON/Parquet files; no source states that any split requires an external fetch to complete a row.

**Trap**: `messages` and `messages_nosystem` encode the same `prompt`/`soap` pair twice - `messages` keeps the system turn as a separate list entry, `messages_nosystem` merges the same system instruction into the user turn instead - so treat them as two renderings of one training example, not as two independent rows, when building an SFT set [9].

## Where it came from

Omi built this release by taking the GPT-4-generated patient-clinician dialogues from the NoteChat dataset - itself constructed from PubMed Central case reports by a multi-agent LLM framework described in "NoteChat: A Dataset of Synthetic Doctor-Patient Conversations Conditioned on Clinical Notes" [1] - and generating a SOAP-format clinical summary for each dialogue with GPT-4 [2]. Omi then split the resulting pairs into 9,250 train, 500 validation, and 250 test rows and added the `prompt`, `messages`, and `messages_nosystem` columns as ready-to-train renderings of the same dialogue/SOAP pair [2]. The card credits and thanks the NoteChat authors for permission to build on their dataset [2].
