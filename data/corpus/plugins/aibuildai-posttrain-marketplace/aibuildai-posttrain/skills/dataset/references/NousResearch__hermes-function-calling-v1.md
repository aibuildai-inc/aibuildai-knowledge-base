# NousResearch/hermes-function-calling-v1

11,578 synthetic sharegpt-style conversations across five JSON files - single-turn and multi-turn function calling, an updated Glaive function-calling subset, and agentic/single-turn JSON-mode structured output - the function-calling and JSON-mode training data behind Nous Research's Hermes 2 Pro models.

**NousResearch/hermes-function-calling-v1** is Nous Research's compilation of function-calling and structured-output conversations used to train the Hermes 2 Pro model series; the dataset's own card states the synthetic data generation was led by @interstellarninja in collaboration with @NousResearch, @teknium and @THEODOROS [1]. It packages five separate files - single-turn function calls, multi-turn function calls, an "updated and cleaned" version of Glaive AI's Glaive Function Calling 5k dataset, agentic JSON structured-output samples, and single-turn JSON structured-output samples - each loaded as its own config, in the sharegpt convention of a `conversations` list of `{"from", "value"}` turns with roles `system`, `human`, `gpt`, and (for some function-calling turns) `tool` [1]. **There is no dataset-wide default config that unions all five files: the card's own YAML config list marks only `func_calling_singleturn` as `default: true`, so a load with no config name silently returns just that one 1,893-row file** [1]. **A companion Hub evaluation set from the same builder, `NousResearch/func-calling-eval-glaive`, shares an identical user-turn prompt with 25 of its 100 rows against a row in this dataset's own `glaive_func_calling` training config - confirmed this session by joining the full parquet of both on prompt text - so a scoring run against that eval set must first exclude those 25 matching training rows** [2]. It lives at https://huggingface.co/datasets/NousResearch/hermes-function-calling-v1 .

**Use it for**: SFT on chat-formatted function-calling and JSON-mode dialogues - the `conversations` field is already the sharegpt turn format most SFT chat trainers consume directly. A `tool` role turn carrying an executed function response appears in some rows of `func_calling` (1,100/1,893) and `glaive_func_calling` (4,344/5,209), but never in `func_calling_singleturn`, `json_mode_agentic`, or `json_mode_singleturn` [2]. Hold out the 25 `glaive_func_calling` rows that match `NousResearch/func-calling-eval-glaive` before evaluating against that companion set (see Hold out below). Map to the SFT method card. Load one config at a time (see Load it below and its default-config trap).

**Licence**: apache-2.0 (SPDX id, from the repo's `license` tag), ungated, not private [3]. The one catch: the `glaive_func_calling` config (5,209 of the 11,578 rows) is described in the card only as an "Updated and cleaned Glaive Function Calling 5k dataset by Glaive AI" [1] - no separate licence terms for that upstream Glaive content are restated here, so the apache-2.0 tag covers this repository's release, not an independently confirmed licence chain for the Glaive-sourced rows.

**Shape**: 11,578 rows across 5 configs, each with a single `train` split: `func_calling_singleturn` 1,893, `func_calling` 1,893, `glaive_func_calling` 5,209, `json_mode_agentic` 1,342, `json_mode_singleturn` 1,241 [4].

**Hold out**: none of this dataset's own five configs overlap each other, but 25 of the 100 rows in the companion Hub set `NousResearch/func-calling-eval-glaive` share an identical user-turn prompt (and a matching or near-matching completion) with a row in `glaive_func_calling` - confirmed by joining the full parquet of both on prompt text this session [2]. Hold out those 25 `glaive_func_calling` training rows before scoring against `func-calling-eval-glaive`; the other three companion eval sets showed 0 matching prompts each against their likely training-config counterpart in the same check [2] (see Neighbors).

**Origin**: built and released by Nous Research; the function-calling and JSON-mode rows are synthetic, generated by a model the card does not name, while the `glaive_func_calling` config's underlying data originates as Glaive AI's own dataset, cleaned and updated by Nous [1]. Hub API at the check date: `downloads` 34,535, `downloadsAllTime` 152,420, `likes` 443 [3].

**Trained-on-by**: Nous Research's own Hermes 2 Pro models. The Hermes-2-Pro-Llama-3-8B model card states the model is "an upgraded, retrained version of Nous Hermes 2 ... as well as a newly introduced Function Calling and JSON Mode dataset developed in-house", and points to the same `NousResearch/Hermes-Function-Calling` GitHub project that this dataset's own card links as its usage guide - strong circumstantial evidence this is that dataset, though the model card does not name this Hub dataset ID directly [5].

**Introduced by**: no paper - the dataset card [1].

## Quality

- The card states the synthetic generation was "led by @interstellarninja in collaboration with @NousResearch, @teknium, @THEODOROS and many others who provided guidance" [1], but gives no measured error rate, contamination check, or annotator-agreement figure for any config.
- The `glaive_func_calling` config is described only as "Updated and cleaned Glaive Function Calling 5k dataset by Glaive AI" [1]; the card does not describe what the cleaning changed or measure its effect.
- A live sample of the first 5 rows of `func_calling_singleturn` and the first 5 of `json_mode_agentic` (offset 0 of each, via datasets-server `/first-rows`) confirms every sampled row's `conversations` list is non-empty and every turn's `value` is non-empty text; no empty-field issue was found in this range, but this covers only these ten rows, not the splits as a whole [7].
- Reading the full parquet of every config this session (via the `refs/convert/parquet` resolve links behind datasets-server's `/parquet` endpoint, not a first-rows sample) shows the `tool` role turn is rare-to-absent, not universal: 0 of 1,893 `func_calling_singleturn` rows carry one, 1,100 of 1,893 `func_calling` rows do, and 4,344 of 5,209 `glaive_func_calling` rows do [2].

## Load it

Each of the five files is its own config; there is no dataset-wide default union. Pin the revision this card's numbers were read at (the Hub API's `sha` for `main` at the check date; the repo was last modified 2026-01-03) [3]:

```python
import datasets

REV = "dae3e1d28cfbcf4b915c04ea1e072030529b4bda"  # main at the check date
func_calling_singleturn = datasets.load_dataset("NousResearch/hermes-function-calling-v1", "func_calling_singleturn", revision=REV, split="train")  # 1,893 rows
func_calling            = datasets.load_dataset("NousResearch/hermes-function-calling-v1", "func_calling",            revision=REV, split="train")  # 1,893 rows
glaive_func_calling     = datasets.load_dataset("NousResearch/hermes-function-calling-v1", "glaive_func_calling",     revision=REV, split="train")  # 5,209 rows
json_mode_agentic       = datasets.load_dataset("NousResearch/hermes-function-calling-v1", "json_mode_agentic",       revision=REV, split="train")  # 1,342 rows
json_mode_singleturn    = datasets.load_dataset("NousResearch/hermes-function-calling-v1", "json_mode_singleturn",    revision=REV, split="train")  # 1,241 rows
```

**Trap**: `load_dataset("NousResearch/hermes-function-calling-v1")` with no config name does not load all 11,578 rows - the repo's YAML marks `func_calling_singleturn` as `default: true`, so an unqualified load silently returns only that 1,893-row file and drops the other four [1]. Train on the union of all five configs you intend to use only by loading each config name explicitly and concatenating.

## Neighbors

Nous Research publishes four small companion evaluation sets on the Hub, matched one-to-one to this dataset's configs by name: `NousResearch/func-calling-eval` (100 rows, columns `system`/`user`/`prompt`/`completion`/`tools`), `NousResearch/func-calling-eval-singleturn` (112 rows, columns `prompt`/`completion`/`tools`), `NousResearch/func-calling-eval-glaive` (100 rows, columns `prompt`/`completion`/`tools`/`category`/`task`/`source`), and `NousResearch/json-mode-eval` (100 rows, columns `prompt`/`completion`/`schema`); none carries a licence tag on the Hub [8]. Joining each eval set's user-turn prompt text against the human-turn prompt text of its likely matching training config, using the full parquet of both sides fetched this session, finds real overlap in exactly one pair: `func-calling-eval-glaive` shares an identical prompt with 25 of its 100 rows against `glaive_func_calling`, e.g. the prompt "Hi, I need to convert a temperature from Fahrenheit to Celsius. The temperature is 98.6 degrees." appears verbatim on both sides with a matching completion [2]. The other three pairs show no overlap in this same check: `func-calling-eval` against `func_calling` (0 of 100 prompts match), `func-calling-eval-singleturn` against `func_calling_singleturn` (0 of 112), and `json-mode-eval` against the union of `json_mode_agentic` and `json_mode_singleturn` (0 of 100) [2]. No `hermes-function-calling-v2` exists on the Hub as of the check date [8].

The `glaive_func_calling` config's upstream traces to Glaive AI's own public releases, but neither is the same processed table: `glaiveai/glaive-function-calling-v2` (112,960 rows, apache-2.0, ungated) serves rows with columns `system` and `chat`, and `glaiveai/glaive-function-calling` (52,893 rows, apache-2.0, ungated) serves rows with a single `sample` column - both different column shapes from this dataset's sharegpt-style `conversations` list, confirmed by fetching one row from each [9]. Neither Glaive repo's row count matches the "5k" figure this dataset's card uses to describe the source it cleaned [1], so the exact Glaive release version behind `glaive_func_calling` is not identifiable from these sources; treat these two as the closest public Glaive datasets, not confirmed exact upstream matches.

## Where it came from

Built and released by Nous Research, with synthetic data generation led by @interstellarninja in collaboration with @NousResearch, @teknium, @THEODOROS "and many others who provided guidance" [1]. The card groups the five files into two provenance strands. The function-calling and JSON-mode files (`func-calling-singleturn.json`, `func-calling.json`, `json-mode-agentic.json`, `json-mode-singleturn.json`) are synthetic conversational scenarios "designed to train LLM models in performing function calls and returning structured output based on natural language instructions", generated by a model the card does not name [1]. The fifth file, `glaive-function-calling-5k.json`, is described as "Updated and cleaned Glaive Function Calling 5k dataset by Glaive AI" - an existing third-party dataset Nous revised rather than generated from scratch [1]. The card points to a companion GitHub repository, `NousResearch/Hermes-Function-Calling`, for the full inference and prompt-formatting code used with this data [1].
