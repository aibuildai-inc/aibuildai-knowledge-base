# allenporter/assist-llm-function-calling

Hub page: https://huggingface.co/datasets/allenporter/assist-llm-function-calling

2,357 synthetic Home Assistant voice-assistant examples - a system prompt, a Home Assistant intent-tool schema list, a user utterance, and either a plain-text reply or a structured tool call - built to fine-tune Llama-family models for device control.

**allenporter/assist-llm-function-calling** is built by Hub user allenporter by running other conversation-agent pipelines as teachers over the `device-actions-v2` task set from the `allenporter/home-assistant-datasets` GitHub repository, whose `datasets/device-actions-v2` directory holds 40 per-home task subdirectories (`home1-ca`, `home2-us`, `beach-bungalow-us`, ...) [1][2]. There is no paper - the dataset card itself introduces it, describing the release as built to support fine-tuning of Llama-family models [1]. **Rows are already split into function calls and plain-text answers rather than a single chat-message shape: of the 100 rows read at offset 0 in `train` and the 100 read at offset 0 in `test`, 86 in each carry a populated `tool_calls` list and an empty-string `output`, and the other 14 carry a null `tool_calls` and non-empty `output` text [3].** The same builder also publishes this content pre-converted into a chat-`messages` shape and into rendered Llama-3 chat-template text; see Neighbors.

**Use it for**: SFT on Home Assistant tool-calling plus plain-text fallback replies. The served shape is one row per turn - `instructions` (system prompt), `tools` (nested JSON-schema list), `input` (user utterance), `output` (assistant text, empty on tool-call rows), and `tool_calls` (name/arguments pairs, null on text-reply rows) - not a chat-message list; the SFT method card's collator needs `instructions`+`input` assembled into a prompt and either `output` or the serialized `tool_calls` as the target. The sibling `-messages` release repackages `messages` and `tools` as JSON-encoded strings rather than native lists, so its collator still needs a `json.loads()` step before use [4].

**Licence**: Apache-2.0 (`cardData.license` is `"apache-2.0"`, tag `license:apache-2.0`), ungated (`"gated": false`, `"private": false`) [5]. No further catch stated.

**Shape**: 2,357 rows, one config (`default`), splits `train` 2,124 / `test` 233, 5 columns [6][7].

**Hold out**: `test` (233 rows) [8].

**Origin**: built by Hub user allenporter; both the tool calls and the text replies are generated by other conversation-agent pipelines acting as teachers, not by human annotators [1]. Hub API at the check date: `downloads` 102, `likes` 1 [5].

**Trained-on-by**: none found. A Hub model search for "assist-llm-function-calling" returned no results, and a Hub dataset search for the same string returned only this release's own siblings and mirrors, not a downstream fine-tuned model repo [9].

**Introduced by**: no paper - the dataset card [1].

## Quality

- Both the tool-call arguments and the text replies are teacher-model generations; no source states a human review or annotation step over them [1].
- The 25 rows returned by `/first-rows` for each split share one instructions template (the same Home Assistant system prompt, with a per-example device inventory appended), and no other instructions template appears in that sample [3].
- Of the 100 rows read at offset 0 of `train`, 86 have `tool_calls` populated and `output` == "" and 14 have `tool_calls` == null and non-empty `output`; the same 86/14 split holds in the 100 rows read at offset 0 of `test` [3]. This is a sample of the first 100 rows of each split, not a claim about the full 2,124/233 rows.
- No source states a measured contamination or duplicate rate for this release; none is invented here.

## Load it

Train on `train`, hold out `test`, and pin the revision this card's numbers were read at (the shortlist's commit, which matches the Hub API's `sha` for `main` at the check date; the repo was last modified 2024-08-18) [5]:

```python
import datasets

REV = "bae5ba0b43764dc1765e3ee880c97e7f3ca32121"  # main at the check date
train = datasets.load_dataset("allenporter/assist-llm-function-calling", revision=REV, split="train")  # 2,124 rows
test = datasets.load_dataset("allenporter/assist-llm-function-calling", revision=REV, split="test")    # 233 rows - hold out
```

**Trap**: `tools` is a nested struct/list column holding the Home Assistant intent-tool JSON schemas, not preformatted text - it must be serialized before use as a prompt. On function-call rows `output` is an empty string rather than null, and on plain-text rows `tool_calls` is null rather than an empty list, so a filter that checks only one of the two fields (e.g. `if output:`) will misclassify rows; both fields must be checked together [3][7].

## Neighbors

Two same-builder, same-row-count reformattings of this exact content [10][11]:

- `allenporter/assist-llm-function-calling-messages` - the same 2,357 rows (2,124/233 split) reformatted into `messages` and `tools` columns; both are declared `dtype: string` in the served schema and the sampled row's `messages` value is a JSON-encoded string (`"[{\"role\": \"system\", \"content\": ...}]"`), not a native list, so it needs `json.loads()` before it feeds a chat-message collator [10].
- `allenporter/assist-llm-function-calling-llama3-chat` - the same 2,357 rows pre-rendered into a single `text` column of Llama-3 chat-template text (`<|begin_of_text|><|start_header_id|>system<|end_header_id|>...`), for training directly on rendered text rather than a message list [10].

A separate Hub user, rayliuca, hosts same-schema copies under the identical README text (`assist-llm-function-calling`, `-messages`, `-llama3-chat`, created 2025-07-31), but these are not the same corpus: each carries 6,097 rows (5,489 train / 608 test) against 2,357 (2,124/233) here, so they are a larger, separately generated re-run of the same pipeline over an expanded `device-actions-v2` set, not a mirror of these exact rows [11]. This release is the original and the one this corpus prefers; reach for a neighbor only for its reformatted shape or its larger row count.

## Where it came from

Built by Hub user allenporter using other conversation-agent pipelines as teachers over the `device-actions-v2` task set in the `allenporter/home-assistant-datasets` GitHub repository [1]. That repository's `datasets/device-actions-v2` directory holds 40 subdirectories, each named for a distinct simulated home (`amalfi-coast-villa-it`, `home1-ca`, `home1-nl`, `rustic-retreat-us`, ...), which is the per-home task structure this release's device inventories and intent-tool lists are drawn from [2]. The dataset card links a notebook, `generation/device-actions.ipynb` in the same GitHub repository, as the construction process for this dataset and the related `device-actions` dataset, but the card does not itself describe what that notebook does [1].
